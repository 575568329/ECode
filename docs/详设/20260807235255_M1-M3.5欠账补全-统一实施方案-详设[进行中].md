## 一、🔴-A 工具集(write_file / delete_file / move / ls)

### 1.1 现状(实证)

- `registry.ts`:5 工具(read_file/bash/edit_file/grep/glob),声明式 `ToolDefinition[]`;新增工具在数组末尾加一条 + 新建实现文件,executor(`find + execute`)零改。
- `bash` 是唯一 `dangerous:true`(registry.ts 模板);read_file/edit_file/grep/glob 均 undefined(视为 false,放行)。
- `ToolDefinition`(types.ts):`name / description / parameters / execute? / parallelizable? / dangerous?`。
- `ToolResult`(types.ts):`{ content: string; isError: boolean }`。
- dangerous 传递路径:registry 标记 → agent.ts `find` 读取 → `shouldAsk` 二元判断 → 档 A 弹窗审批。

### 1.2 接口契约

| 工具 | input schema | 返回 content | dangerous |
|------|-------------|-------------|:---------:|
| `write_file` | `{ file_path: string; content: string }` | 成功:「wrote N chars to <path>」;失败:错误原因 | ✅ true |
| `delete_file` | `{ file_path: string; recursive?: boolean }` | 成功:「deleted <path>」;失败:错误原因 | ✅ true |
| `move` | `{ source: string; destination: string }` | 成功:「moved <source> → <dest>」;失败 | ✅ true |
| `ls` | `{ path: string; pattern?: string }` | 成功:条目列表(每行一项);失败 | ❌ false |

### 1.3 实现策略

- **统一 Node `fs`**(writeFileSync / rmSync / renameSync / readdirSync),绕开 shell——呼应支点21②,跨平台免审批。
- 每工具一个文件:`src/tools/write-file.ts` / `delete-file.ts` / `move.ts` / `ls.ts`,导出 `executeWriteFile(input): ToolResult` 等。
- 注册:`registry.ts` 末尾加 4 条(write/delete/move 照搬 bash 的 `dangerous:true`;ls 照 read_file 不标)。
- **ESM**:import 带 `.js`(CLAUDE.md §九红线)。
- 路径解析:相对路径基于 `process.cwd()`(对齐 bash 工具),用 `path.resolve`。

### 1.4 TDD 步骤

1. 先写 4 工具契约测试(`tests/tools/write-file.test.ts` 等),tmpdir 隔离,不碰真实文件。
2. Node `fs` 最小实现(正常 + 异常:路径不存在/权限/递归删)。
3. 注册进 `registry.ts`。
4. 验证 executor 能分发(集成测:executeTool('write_file', {...}))。

### 1.5 边界(YAGNI)

- 工具层只**忠实执行**写/删/移;防误删/防覆盖留 M4 权限兜底(dangerous=true → 现有档 A 弹窗审批)。

- `ls` 默认一层(不递归),`pattern` 做简单 `minimatch` 或 `includes` 过滤(不引重依赖,先 `String` 匹配)。
- `delete_file` `recursive` 默认 false(只删文件/空目录),true 才递归(对标 `rm -r`)。

### 2.2 C2 新建 `src/errors.ts`(结构化错误)

```ts
// 常量放底层 errors.ts,retry.ts 从这里 import(单一来源,无循环依赖)
export const RETRYABLE_STATUS = new Set([408, 425, 429, 500, 502, 503, 504, 529]);

export type ApiHeaders = Record<string, string | string[] | undefined> | Headers;

// 共享基类(供 retry.ts 用 instanceof 统一判 ECode 错误)
export class ECodeError extends Error {
  constructor(message: string) { super(message); this.name = 'ECodeError'; }
}

export class ECodeAPIError extends ECodeError {
  constructor(
    public status: number,
    message: string,
    public headers?: ApiHeaders,  // SDK headers 是 Headers 实例 / 值可 string[]
    public code?: string,         // GLM/DeepSeek error body 的 code(如 'context_length_exceeded')
  ) {
    super(message);
    this.name = 'ECodeAPIError';
  }
  get isRetryable(): boolean { return RETRYABLE_STATUS.has(this.status); }
  /** 大小写无关取 header,值是数组取首元素(兜底 SDK 多值头) */
  getHeader(name: string): string | undefined { /* 实现:lowercase 匹配 + 取首 */ }
}

// 独立继承 ECodeError(非 API 调用错误,是上下文超限的业务约束);retry 优先判它(不可重试)
export class ContextWindowError extends ECodeError {}
```

- claude.ts/openai.ts:catch SDK 错误 → 包成 `ECodeAPIError`(带 `status` + `headers` + 可选 `code`);context window 错误抛 `ContextWindowError`。
- retry.ts:删本地 `RETRYABLE_STATUS`,改 `import { RETRYABLE_STATUS, ECodeAPIError, ContextWindowError } from './errors.js'`;`shouldRetry` 用 `instanceof ContextWindowError` 优先(不可重试)→ 再 `ECodeAPIError.isRetryable`;无 status 的裸错误不重试。
- context-manager.ts:`isContextWindowError` 改判 `ContextWindowError` 类型 + 保留字符串兜底(过渡期,直至全链路抛结构化错误)。

### 2.3 C3 retry 读 Retry-After

- retry.ts catch 块:经 `ECodeAPIError.getHeader('retry-after')` 取值;`Number.parseFloat` 防小数、`Number.isFinite` 校验、负值忽略;HTTP-date 形式(`Date.parse(v) - now`)fallback;有则 `delay = retryAfterMs`,否则指数退避 `BASE_DELAY_MS * 2^attempt + jitter`。
- **注意**:HTTP 标准头是 `retry-after`(delta-seconds 或 HTTP-date);`retry-after-sec` 非标准——Anthropic 用 `anthropic-ratelimit-reset`、OpenAI 用 `x-ratelimit-reset-*`(均秒)。**优先 `retry-after`,其余作辅助**(不主动解析 reset,避免复杂度)。
- Anthropic/OpenAI SDK 错误对象均带 `headers`(类型 `Headers`,经 `getHeader()` 统一兜底)。

扩展统一类型(7 处同步改):

interface ECodeUsage {

  cacheReadTokens?: number;

  reasoningTokens?: number;

**防御**:五项中 cacheRead/cacheWrite/reasoning **全部 optional**——GLM/DeepSeek 走 OpenAI 协议**不返回** `prompt_tokens_details`/`completion_tokens_details`,链式访问缺失返回 undefined,**不抛错、不影响 inputTokens/outputTokens 主路径**;测试覆盖 GLM 不返回 details 场景。字段命名保持内部 camelCase(`cacheReadTokens`,非 SDK 的 `cache_read_input_tokens`),避免 IDE 自动补全失效。

### 3.3 D2 `/compact`(用户主动触发 forceCompact)

5. 仿 `switchSession` 重置其余渲染态(completedMessages/streamingText/activeTools/pendingReadSearch/usage/latestInputTokens)。

- app.tsx `case 'compact'`:`addMessage('正在压缩…')` → `await api.compact()` → 提示「已压缩 N→M 条」。
