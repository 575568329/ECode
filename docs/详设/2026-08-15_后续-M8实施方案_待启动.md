# ECode 后续 M8 实施方案：交互与上下文智能（懂你 · 会问你 · 能查证）

> 日期：2026-08-15 · 状态：**已完成（v1.2 定稿后全量实施，见文末实施记录）**
> 主题一句话：让 Agent **记得住**（AGENTS.md/memory）、**问得准**（ask_user 选项框）、**查得到**（WebFetch）。
> 来源：用户提出 memory 系统 + 提问选项框；经四家调研（提问机制 + 功能差距盘点）补齐选型后成稿。参考实现集中附录 B，正文只写 ECode 自己的设计。

## 0. 目标与验收

**目标**：补齐「Agent 与用户之间的信息通道」——指令进得来（AGENTS.md）、偏好记得住（memory）、歧义问得清（选项框）、外部信息查得到（WebFetch）；顺带清偿 M5 遗留小额债。

**验收**：
- **指令注入**：项目级 ECODE.md 优先、CLAUDE.md 回退（findUp 首个命中）；用户级 ~/.ecode/ECODE.md 先注入；各 32KB 截断有提示；两级都无文件零开销
- **ask_user**：LLM 遇模糊需求调 `ask_user` → overlay 选项面板（↑↓ 选择+回车确定/Other 自由输入/多选/Esc 取消）；argv 单次模式不挂死（非交互守卫）；回传格式 `User has answered...`
- **auto-memory**：`~/.ecode/memory/MEMORY.md`（用户级）与 `.ecode/memory/MEMORY.md`（项目级）索引注入 system prompt；模型用现有读写工具维护，零新工具
- **WebFetch**：LLM 可抓公开网页转文本（30KB 截断）；私网/回环地址拦截（SSRF 防护）；重定向 ≤3、超时 15s
- **分段化**：system prompt = 静态前缀 + 动态后缀，动态内容变化不击穿前缀（cache 友好）
- **债**：pricing 从 models.dev 同步 + config 覆盖定价；preserveToolPairs O(n²) 收敛

**不做**（后置）：WebSearch（需外部搜索 API/key）、memory 管理命令（/memory 等，文件即真相）、ask_user preview 分栏、跨进程事件总线（单进程用不上）、**流式 markdown + OSC8（2026-08-15 砍掉 → 2026-08-16 二次拍板 CLI 上彻底放弃，不入观察区，M8-D12）**。

## 1. ECODE.md / CLAUDE.md 指令注入（P0，~1 天）

**问题**：ECode 的指令文件写得极完整（通用原则 + TS/Node 规范），却从未喂给 LLM——用户在每个项目里的工作区指令全部失效。

**流程图（先看懂再读详解）**：

```
ECode 构建 system prompt 时，按两级查找指令文件：

第 1 步：查用户级文件 ~/.ecode/ECODE.md
  ├─ 有 → 读出内容（超 32KB 截断，并标注原文路径）
  └─ 没有 → 跳过（用户级不是必需的）

第 2 步：查项目级文件（从当前目录逐层向上找，每一层按顺序检查）
  ├─ 这一层有 ECODE.md？  ── 有 → 读取，停止向上找（★首个命中即止）
  ├─ 这一层有 CLAUDE.md？ ── 有 → 读取，停止向上找（兼容回退）
  └─ 都没有 → 到上一层继续找
       （到 home 目录 / git 根为止，不再向上）

第 3 步：把两级内容拼进 system prompt，最终结构自上而下是：
  1. 静态前缀：身份 / 平台 / 工具指引（永不变，缓存友好）
  2. 用户指令：个人偏好（先注入，来自用户级文件）
  3. 工作区指令：项目约定（后注入，更具体、可覆盖上面）
  4. 技能清单 / memory 索引 / 路由行
```

**详细讲解**：

- **命名决策**：自有命名用 **ECODE.md**（避免与 AGENTS.md 生态的其他工具冲突）；**兼容 CLAUDE.md**——项目级每层先找 ECODE.md、没有再回退 CLAUDE.md（Claude 生态的存量指令文件直接可用）。用户级只认 `~/.ecode/ECODE.md`（自家地盘无需兼容）。
- **两级分工**：用户级放跨项目个人偏好（语言/风格/背景），项目级放 repo 约定（可进 git 团队共享）；项目级居后注入，语义上「更具体的覆盖更泛的」。
- **边界规则**：findUp 首个命中即止（不学 codex 多级全叠加——monorepo 子目录约定场景少，复杂度先不付）；边界同 skill 的 findUpDir（home 停、非 home 树收在最近 git 根），避免两套边界漂移。
- **大小守卫**：两级各 32KB 上限（config `maxInstructionsKB` 可调，memory 同限）；截断时 ① 注入尾注给 LLM（可 read_file 读全文）② **用户提示**——启动底部一行/argv stderr 告知哪级被截与调大方法（注入内容对用户不可见，截断必须可行动）；注入在 system 内 → 天然计入压缩估算（`estimateContextTokens` 已含 system）。
- 注入位置选 system（而非 user-context 消息）：Provider 接口 system 是单字符串，拼接成本最低；分段化（§5）后归动态段，缓存语义不损。

## 2. ask_user 提问选项框（P0，~2-3 天）

**问题**：模糊需求只能纯文本追问（用户要重新读一段话再打字）；ConfirmPrompt 只有二元 y/n，且语义是「授权」不是「收集」。

**流程图（一次完整提问长什么样）**：

```
用户：「帮我加个登录功能」
  │
  ▼
LLM 判断：需求模糊吗？自己调查（读代码/grep）后仍无法推断？
  ├─ 否，可推断 ──► 直接采用合理默认并说明，不问
  └─ 是 ──► 调用 ask_user 工具（带上问题 + 选项）
              │
              ▼
           弹出选项面板（overlay），长这样：
                登录方式用哪种？
                ❯ 1. 账号密码 (Recommended)
                  2. 手机验证码
                  3. OAuth 第三方
                  4. Other（自由输入）
                ↑↓ 选择 · 回车 确认 · Esc 取消
              │
              ├─ 用户 ↑↓ 移动 + 回车 ──► 面板把答案 resolve 给工具
              │                        （ConfirmPrompt 同款 Promise 桥）
              │                          │
              │                          ▼
              │                     工具返回：User has answered:
              │                     「登录方式」=「账号密码」
              │                          │
              │                          ▼
              │                     LLM 拿着明确答案继续干活，不再来回追问
              │
              └─ Esc ──► 返回「用户取消了提问」，LLM 换思路或用默认值

另一条路：argv 单次模式（无界面）──► 不弹面板，返回提示让 LLM 用合理默认
```

**详细讲解**：

**工具定义**（`src/tools/builtin/ask_user.ts`，`readonly: true`——信息收集免确认、可与只读工具并行）：

```jsonc
{
  "questions": { "type": "array", "minItems": 1, "maxItems": 4, "items": {
    "question":    "完整问句，清晰具体，以？结尾；multiSelect 时措辞相应调整（选哪些 vs 选哪个）",
    "header":      "短标签，≤12 字符（多问题时 ←→ 导航 chip 用；Tab 已专职沙箱档位 2026-08-16）",
    "options":   { "type": "array", "minItems": 2, "maxItems": 4, "items": {
      "label":       "1-5 词显示文本；推荐项放第一个并加 (Recommended) 后缀",
      "description": "选项含义 / trade-off 说明" } },
    "multiSelect": "boolean，默认 false"
  }}
}
```

- **AJV 追加两条校验**：问题文本全局唯一、每题内 label 唯一（防模型生成重复项）；`header` 加 `maxLength: 12` 硬约束
- **Other 不由模型生成**：description 明令「用户始终可选 Other 自由输入，不要生成兜底选项」，UI 端自动追加
- **并发独占**（审阅补）：ask_user 是 `readonly: true` 会被 executeTools 与其它只读工具 `Promise.all` 并行——同轮多个 ask_user 会抢 overlay。修法：工具内**会话级排队锁**（先到先弹，后到 await 排队；~5 行）+ description 约束「一轮最多问一组问题」

**TUI**（`QuestionPanel.tsx`，PanelShell + Promise resolve 桥——ConfirmPrompt 同款机制，心脏零感知）：
- **交互基线（用户拍板）：↑↓ 选择 + 回车确定**——与 PanelShell 及全部既有面板一致；选项前缀印序号（1. 2. 3.）仅供视觉定位，**不做数字键直选**（PanelShell 可打印字符已被即时搜索占用，直选与搜索互斥——M6 T4 已裁决，不回退）
- 单问题单选：**回车即提交**（无确认页，chips 导航 ←→——Tab 已专职沙箱档位）；多问题/多选：header chips **←→ 导航**（已答/未答变色；QuestionPanel 无 tabs，与页签键位不冲突）+ 末尾 Review 页列 `问题 → 答案`；多选 space toggle（`[✓] label`）
- Other 恒居末位，↑↓ 选中 Other 后展开内联 TextInput（输入态下面板搜索让位，输入即打字）
- `Esc` = 取消提问 → tool_result「用户取消了提问」（明确信号，不挂死）

**非交互守卫**：argv 单次模式 / 非 TTY → execute 检测后直接返回「非交互环境无法弹出选项，请基于上下文选择合理默认并说明」——模型自行决策，不阻塞。

**回传格式**（两家独立实现共识，对模型最友好）：`User has answered your questions: "q"="a, b". You can now continue with the user's answers in mind.`（多选逗号连接）。

**防滥用三支柱**（写进工具 description）：能推断就别问（合理默认直接采用并说明）/ 先调查再问（读代码 grep 之后真卡住才问）/ 不重复问。**职责分界**：ConfirmPrompt = 副作用授权（框架拦截发起）；ask_user = 模型主动信息收集（不进审批语义）。

## 3. auto-memory（P1，~2-3 天）

**问题**：跨会话零记忆——上个会话定下的偏好（「这个项目用 vitest 别用 jest」）每次重新教。

**流程图（记忆怎么存、怎么回来）**：

```
【存：会话中记下偏好】
  LLM 觉得某偏好值得长期记住（例：这个项目用 vitest 别用 jest）
    └─► 用现有 write_file 工具（★不需要任何新工具）
          └─► 写 ~/.ecode/memory/MEMORY.md —— 索引文件，一行一条：
                - [测试框架偏好](testing.md) — 用 vitest 别用 jest
                细节写同目录的 testing.md（topic 文件）

      ……下次启动 ECode……

【取：下次启动生效】
  buildSystemPrompt 读两级 MEMORY.md（用户级 + 项目级）
    └─► 只把索引注入 system prompt（很小，就几行）
          └─► LLM 看到索引：用户偏好 vitest（详见 testing.md）
                └─► 需要细节时用 read_file 读 topic 文件（按需，不预载）
```

**详细讲解**（零新基建，约定 + 注入）：
- 两级目录：`~/.ecode/memory/MEMORY.md`（用户级偏好）+ `.ecode/memory/MEMORY.md`（项目级，可进 git 团队共享）——**只注入索引文件全文**，topic 文件（同目录 `*.md`）由模型按需 read_file
- 索引格式：每条一行 `- [主题](文件名.md) — 一句话钩子`（与 Claude Code MEMORY.md 惯例同构，用户可直接手写）
- 维护：模型用现有 write_file/edit_file 操作（无新工具、无新权限面）；AGENTS.md 里已要求「重要偏好写入 memory」——注入后模型自然遵循
- 注入点：system prompt 动态段（`--- 记忆索引 ---`），受 32KB 级守卫；memory 在 system 不进 messages → **不受压缩影响、不进 HistoryStore**（边界清晰）

## 4. WebFetch 工具（P1，~2 天）

**问题**：模型对「最新的库 API / 端点行为」只能凭训练记忆猜——四家成熟 CLI 全有 web 工具，ECode 唯一没有的硬缺口之一。

**流程图（一次抓取的四道关卡）**：

```
LLM：需要查最新文档 ──► 调用 web_fetch(url)
  │
  ▼
第①道：安全检查 —— 域名解析成 IP，是内网/回环地址吗？
  ├─ 是 ──► 拒绝：返回错误（防 SSRF 内网探测）
  └─ 否 ──► 第②道：发起 GET 请求（15 秒超时 · 重定向最多跟 3 跳）
               │
               ├─ 遇到重定向 ──► 回到第①道重新做安全检查
               └─ 拿到页面 ──► 第③道：网页 HTML → 纯文本
                               （去掉脚本/样式/导航，保留标题、正文、代码块）
                                │
                                ▼
                             第④道：内容超上限（默认 30KB，config `webFetchMaxKB` 可调）？
                                ├─ 是 ──► 头尾保留、中间截断
                                └─ 否 ──► 原文返回
                                │
                                └────► 作为工具结果回喂 LLM
```

**详细讲解**（基础版，无头浏览器后置）：
- `src/tools/builtin/web_fetch.ts`（`readonly: true`）：Node 原生 fetch GET → HTML→文本（去 script/style/nav，保留标题/正文/代码块）→ 头尾中截（默认 30KB，`setWebFetchLimits` 从 config `webFetchMaxKB` 注入）→ `<fetched_web_content>` 包裹带截断标记返回（截断提示面向 LLM——LLM 据此换更具体 URL 或告知用户；用户展开工具输出亦可见，不主动弹窗）
- **SSRF 防护**（必须）：DNS 解析后校验目标 IP——私有段（10/172.16-31/192.168）/ 回环 / 链路本地 / .local 一律拒绝（is_error 提示「内网地址禁止抓取」）；重定向逐跳复检，≤3 跳；超时 15s；仅 GET
- 免确认（只读公开网页，与 bash curl 同级但更受限）；M9 沙箱统一收口
- prompt 教学：优先读本地代码/文档，线上信息不确定时才 fetch

## 5. system prompt 分段化（P2，~1-2 天）

**设计**：`buildSystemPrompt` 内部结构化为**静态前缀**（身份/平台/工具指引）+ **动态后缀**（AGENTS.md / memory 索引 / skills 清单 / 路由行）以 `\n\n` join——对外仍返回单字符串（Provider 协议不动，四个调用点零改动）。收益：动态内容变化（skills 增删、memory 更新）不击穿静态前缀的 prompt cache。

## 9. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| ECODE.md/CLAUDE.md/memory 过大吃窗口 | 中 | 两级各 32KB 上限 + 计入压缩估算（system 已在估算内）|
| ask_user 被滥用（每轮都问）| 中 | prompt 三支柱 + 1-4×2-4 硬上限 + Esc 明确信号 |
| WebFetch SSRF/隐私 | 中 | 私网拦截（含 IPv4-mapped IPv6 十六进制形态与 NAT64 内嵌——审阅 P1-1 修复）+ GET only + 重定向复检 + 截断；**已知接受风险（审阅 P1-2）：校验与建连两次独立 DNS 解析存在 rebinding 窗口（需攻击者控制 DNS 且诱导 fetch，单用户 CLI 威胁模型下接受；M9 沙箱收口时重评）**；抓取内容以 `<fetched_web_content>` 包裹 + description 防注入提示（审阅 P2-1） |
| memory 与压缩边界混淆 | 低 | memory 只在 system（不进 messages），文档明示 |
| 分段化击穿既有 prompt 断言 | 低 | 纯构造层重构，系统测试锁全文 |

## 11. 权限系统（设计储备——**2026-08-16 拍板前移 M9 实施**，首步 Hook(owner) 三态见 M9 §6；本节为完整设计输入）

> 2026-08-15 用户拍板补入：M7 交付了第三方资源面（skill hooks.json / plugin hooks / plugin 启用 / MCP），缺统一的权限门控。本节为调研定稿的设计储备（四家对标一手源码），**不在 M8 实施范围**——启动时机由用户定（建议 M9 沙箱实施前回看，两者正交可合）。

### 11.1 双维模型（核心）

**资源行为三态 × 交互时机三档分离**（调研结论：两维必须分开建模，混在一维的"记住允许"表达不出"显式要求每次都问"）：

```
PermissionDecision（用户每次确认的回答）= { behavior: allow | deny, scope: once | session | persistent }
Rule（持久化状态）                      = { resource, behavior: allow | ask | deny, source }
```

- `ask` 是一等状态：显式要求每次弹窗，不能被低层 allow 意外覆盖（deny 任意层终局）。
- **与现有交互的映射**（四个现有机制全是该模型子集，可统一引擎分阶段迁入）：MCP 的 y/n/a = allow once / deny / allow session；`.mcp.json` 首用批准 = allow persistent（hash 维度）+ 隐式 deny persistent；plugin 启用 = `Plugin(id)` 的 allow/deny；skill hooks 首次执行确认 = `Hook(owner)` 规则——**这是 MVP 切入点**。

### 11.2 存储三层与求值

| 文件 | 内容 | git |
|---|---|---|
| `~/.ecode/settings.json`（用户级） | `permissions: { allow/ask/deny: [...] }` + 资源开关 | 否 |
| `<proj>/.ecode/settings.json`（项目级，团队共享） | 同 schema——维护者给团队推荐默认 | 是 |
| `<proj>/.ecode/settings.local.json`（项目个人） | 同 schema——**交互式"记住"的默认落点** | 否（自动 gitignore） |

求值：`local > project > user`，规则带 `source` 供 UI 展示来源；规则格式字符串式（可手编可 UI 列）：`"Skill(name)"` / `"Plugin(plugin@market)"` / `"Mcp(server)"` / `"Hook(owner:event)"`，支持 `prefix:*`。现有 `~/.ecode/config.json`（用户源 hooks）与扩展注册表**保持不动**——权限层只在其上做门（分层铁律不破）。

### 11.3 与 M9 沙箱的关系（正交）

M9 §4 的沙箱三档（default/read-only/workspace-write）是**模式**（codex Permission Profile 思路：会话级粗粒度开关），本节是**规则**（资源级细粒度三态 + 持久化）。正交可组合：模式定基调、规则打补丁；deny 规则优先于一切模式（对齐 claude-code 语义）。实施顺序建议：M9 沙箱先行（M9 已含），规则系统随后（或合并实施——求值器共享）。

### 11.4 分阶段接入

1. **第一步（建议 M9.5/M10）**：`Hook(owner)` 三态 + 三档 scope——扩展源 hook（skill/plugin）首次执行前查规则，用户源 hooks 不问（所有者侧非被管控对象）。
2. `Plugin(id)`：marketplace 启用状态迁入同 schema。
3. `Mcp(server)`：approved-mcp.json 的 hash 批准 + y/n/a 会话记忆统一到 decision 模型（底层存储可仍两文件，求值层统一）。
4. `Skill(name)` / `Bash(prefix)`（工具级确认统一，schema 预留）。
5. UI：`/permissions` 三栏列表（allow/ask/deny + 来源层 + 删除；加规则选 destination）。防御细节：交互产物默认落 local（不污染团队文件）；被遮蔽规则检测（低层 allow 被高层 deny 盖时提示）。
