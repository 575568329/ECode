# M14 TUI 超屏防护与输出查看器实施方案（v1.3 待启动）

## 0. 背景：问题与根因

### 0.1 现象与复现

动态区（活动区）内容超出终端高度时：视角被顶回顶部、scrollback 无法滚动、屏幕顶端永远停在输出开头。触发路径包括：轮末长回复全量渲染、Ctrl+O 展开大 diff/长输出、输入框粘贴大段文本、面板在矮终端下打开。

本项是 M10 §9"动态区高度预算系列"挂账的复活——2026-08-18 拍板暂不执行时登记的复活条件为"用户再次实际受困于超屏"，2026-08-24 用户报障，条件成立。

### 0.2 根因（ink 7.1.1 源码实证）

Ink 的正常渲染循环依赖"擦除旧帧"：每帧用 `eraseLines(N)` 自底向上逐行 `ESC[2K + ESC[1A` 擦掉上一帧。该序列的前提是光标上移（CUU）能爬回帧顶，而 **CUU 会被视口顶边钳住、永远进不了 scrollback**——所以帧高 > 终端行数时擦除必然残缺。

Ink 对此的兜底不是截断帧高（Yoga 布局只 clamp 宽度、不 clamp 高度），而是运行时检测溢出后**整帧降级**（`shouldClearTerminalForFrame`）：发 `clearTerminal = ESC[2J + ESC[3J + ESC[H` 清屏后全量重印。用户看到的三个症状全部来自这一条序列：

- `ESC[3J` 每帧清空整个 scrollback（30fps 节流下持续清）→ **滚轮无物可滚**；
- `ESC[H` 光标与视口被钉回 (0,0) → **视角跳顶**；
- 每帧重放 `fullStaticOutput + 当前帧` → 屏幕顶端永远是开头。

Windows 特例（ink #969）：帧高**恰好等于** rows 也触发全清（conhost 写右下角单元格立即滚动，与增量擦除失步留残影）——因此预算必须留余量，目标帧高 ≤ rows−2。

### 0.3 ECode 溢出源盘点（现状核查）

| 溢出源 | 现状 | 严重度 |
|---|---|---|
| 轮末全量 Markdown | 无上限；且实际机制是**延迟 commit**——`turn/completed` 只置 `streaming:false`，全量 Markdown 滞留动态区直到下一次 submit（`TuiApp.tsx:465-467` 才兑现上一轮） | 最大源 |
| Ctrl+O 展开的工具输出/diff | 全文渲染无上限（"临时增高，仅当前轮可展开"） | 高 |
| 输入中大段粘贴 | **已修**（3bb98f4+01a4a45：超 5 行头窗偏置折叠+caret 行亮出，用户拍板头窗；V2 仅需补物理行感知——现按逻辑行切） | 已降级 |
| 流式灰字 | `foldStreamText` 按逻辑行切不看 wrap 宽度——minified JSON/长 URL 单行可爆出几十物理行 | 中 |
| 面板窗口 | `PanelShell` 固定 `MAX_VISIBLE=12`，不感知 rows | 中 |
| 轮末 Markdown（宽度面） | `Markdown` 只有宽度 clamp（`min(columns, 80..100)`），无高度上限；wrap 后物理行数无界 | 高（与第一项同源） |

视口高度感知目前全项目仅两处（`ConfirmPrompt.previewMaxLines = max(5, rows−17)`、`Select = min(12, rows−14)`），公式重复两份未收敛；无 resize 监听（依赖 Ink 内部重渲）。

## 1. 目标与非目标

**目标**：

1. **超屏防护（硬指标）**：任意交互序列下，动态区帧高恒 < 终端行数，Ink 永不进入 fullscreen 兜底分支（`ESC[3J` 不再出现）；
2. **完整内容可看**：被折叠的工具执行内容/子进程输出有任意长滚动 + 搜索的查看载体；
3. **子进程实时可观察**：运行中后台任务的日志可 attach（tail -f 语义）+ 常驻状态行扫一眼。

**非目标（明确排除）**：

- **fork/魔改 Ink 渲染层**（帧允许超视口、就地展开全文不打断）——成本与理由见 §2 被否决备选，作为观察项挂账（§7）；
- **全屏 alt-screen 接管 + 组件内主滚动**（OpenTUI/ratatui 路线）——与"非 alt screen + 原生 scrollback"既有拍板冲突；
- **前台 bash 执行中实时流回显**——需 bash 工具加 onOutput 流回调（工具层改动），挂 P2（§7）；
- **流式 markdown 渐进渲染**——M8-D12 已弃，本方案不复活；
- 转义序列直写 scrollback（insert-history 式）——见 §2 否决理由。

## 2. 路线拍板

**选定路线：动态区高度预算（budget guard）**——保持 stock Ink + 最小 Static 架构，让"动态区帧高 ≥ rows"这个条件**永假**。长内容不进对话流，进 scrollback（历史）或查看器（轮中）。

三条被否决备选（按解析目录论证要求记录）：

| 备选 | 做法 | 否决理由 |
|---|---|---|
| fork 渲染器 | vendor 魔改 ink 输出层：帧允许超视口、新增行 LF 推进 scrollback、viewportY 跟踪不可达行 | ① vendor 整棵 fork 树（viewportY/diffEach/full-reset/DEC2026/frame 抽象）；② 魔改版删了 Static，ECode 全 TUI 建立在 Static 上（M2 架构）——迁移或回加都是大工程；③ 长期维护税（上游升级断供）；④ M8-D12 已评估同堵墙拍板"改造面与收益不匹配"。买到的唯一增量 = 就地展开全文不打断（少一次面板进出），不值 1.5-3 周 |
| 全屏接管 | 换 OpenTUI/自绘渲染器 + ScrollBox 主滚动 | 与非 alt screen 拍板冲突；框架级重写 |
| insert-history | 展开时把全文转义序列直写 scrollback | 打断 Static 顺序（轮末 commit 时同内容二次进入 scrollback 造成重复）；破坏"Static 是唯一历史固化通道"不变量 |

### 3.3 时序层：轮末 commit 查因与拍板（V4）

轮末 Markdown 滞留是最大溢出源，本质是"延迟 commit"偏离了 M2/M9 文档的"轮末 commit Static 自愈"设计。两个修法：

- **方案一（优先求证）**：恢复轮末即 commit——`turn/completed` 直接把本轮全量内容送进 Static/scrollback，动态区归零（空闲态只剩输入框+状态栏，永不超限），全文天然可滚轮回看。**前置**：查清当初改延迟的原因（疑与 afterTools 质量回喂/后台任务通知在 completed 之后追加消息有关）——若提前 commit 会导致追加消息漏入 Static 或次序错乱，则不可简单提前；
- **方案二（保底）**：保持延迟 commit，轮末 Markdown 走 head-tail 折叠。代价：中间内容在进 Static 前不可见（折叠了又不在 scrollback），UX 次优。

V4 批内先做 30 分钟查因（git log + 宿主事件时序核对），按结论二选一，回填本节。

**实施记录（2026-08-27，提交 9d95fd7）**：查因结论——延迟 commit 是 M2 最小 Static 重构的**交互决策**（「runLoop 结束不 commit 留动态区可 Ctrl+O 展开，下次 submit 才收进 Static」，git 史与记忆均有据），**不是** afterTools 时序的 bug 修复；且 `turn/completed` 发布时本轮 transcript 已终局（afterTools 是轮间回喂、跨 turn 后台任务通知是下轮 startTurn 注入），提前 commit 无漏消息/次序风险。M3 §7.5 早已决策 Static 工具组展开（事后看全文）——「展开回看」语义由 Static 承接优于动态区 Ctrl+O。**取方案一**：`turn/completed` 即 `setCommitted(messagesToCommitted(transcript))` + `setActive(createActive())`（同帧批处理无双份闪烁）；error 轮无 completed 帧，submit 开头的兜底 commit 保留。方案二（head-tail 折叠轮末 markdown）不再需要——CappedAssistantMessage 仅对 error 轮残留超预算降级提示。

**勘误（2026-08-27 审阅批4）**：上节提交信息中"24 行终端 toolCap=3/stream=5"数值失准——当时代码与测试实际为 toolCap=2/stream=6（对标分析师核验 P1-2）；批4 复审后又改：输入区按折叠态实占 8 行计、条件段（TasksBar/SubagentBar）显式扣减、退化线 21+条件行、展开态收 1 组——最终公式与数值以 `src/tui/viewport.ts` 与 `tests/tui/viewport.test.ts` 为准。

### 3.4 总守卫：ViewportGuard + 退化保护（V5）

各段独立截断不保证**总和** < rows（病态组合仍可能超）。Conversation 动态区顶层做一次预算分配：

```
budget(rows) 分配：
  输入区（实测行，本身被 §3.2 粘贴折叠钳制）
  + ActivityBar(1) + StatusBar(1) + SubagentBar(≤3) + 任务状态行(§3.5，≤3)
  + 确认弹窗/overlay 打开时的固定预留（ConfirmPrompt 已有公式，迁入收敛）
  + SAFETY_MARGIN(2)
  剩余 → markdown/stream 区拿大头；工具区每组恒 ≤4 × 可见组数上限
退化保护：rows < 12 时 markdown/stream 区直接显示 `[终端过小，本轮内容已折叠——/output 查看]`，
宁可不显示也不触发 3J。
```

实现形态：`sectionBudget()` 纯函数（可单测）+ Context 下发各段 cap，各段组件消费自己的 cap。

### 3.5 OutputViewer 输出查看器（V3）

**核心原理**：Ink 帧超视口会炸，但**帧高恒定、内容在 React state 里"滚"**完全安全——滚动 = state 改 offset → 重渲 `slice(offset, offset+H)`，内容 10 万行也只有 H 行上屏，永不触发兜底。

**组件结构**（复用 PanelShell 的 overlay 挂载/Esc 逐级回退/边框主题，内核换文本滚动窗）：

```tsx
// src/tui/OutputViewer.tsx
props: { title: string; source: LineSource; follow?: boolean }
state: { offset: number; followed: boolean }

渲染（所有行计入预算，总帧高恒定）：
  标题行（1）: "task#2: dev-server（运行中）"
  内容窗（H = budget − 固定行）: lines[offset .. offset+H-1]
  状态行（1）: "L412-L459 / 8921  [F]跟随 [/]搜索"（仿 less）

键位（面板态，InputStream 已让位——PanelShell 现成模式）:
  ↑/↓ 单行 · PgUp/PgDn 半页 · g/G 头/尾 · F 切跟随 · / 搜索（复用即时搜索） · Esc 逐级回退
新数据到达: followed=true → offset = max(0, total−H)；用户手动上滚 → followed 自动断开
```

**数据源接口与三个适配器**：

```ts
interface LineSource {
  lines(): string[]          // 全量（已 wrap 成物理行）
  isGrowing(): boolean       // 运行中任务 → follow 语义
  subscribe?(cb: () => void): () => void   // 增长通知（watch 日志 mtime）
}
// ① ToolResultSource   工具执行内容：transcript tool result 全文（含 LLM 侧截断前——边界：前台 bash 有
//                      工具层 30KB 天花板 truncateOutput 30_720 字节，超限部分 transcript 也不存在，
//                      全文只有 run_in_background 任务日志有）
// ② TaskFileSource     子进程内容：后台任务日志文件（TaskRegistry 落盘）；
//                      增量读复用 task_output 已有句柄定位实现，实时 tail；
//                      边界：TaskRegistry 私有需加公开访问器，dispose 会 unlink 日志——只能 attach 活任务
// ③ SubagentSource     子代理 transcript（~/.ecode/agents/<id>.jsonl，一行一条调用）
```

**入口（两级面板）**：

- 对话态 `/output`（斜杠命令，零新全局键）→ **输出列表页**：最近工具调用 + 后台任务（运行中标 activity，仿 SubagentBar 一行一条）→ Enter 进全文滚动页；
- `Ctrl+P`（p=peek）为可选快捷入口，当前空闲无绑定、与 Ctrl+O 轮级展开（保留原职 `TuiApp.tsx:849`）、Tab 沙箱、Ctrl+U 清队列、Alt+V 粘贴不冲突——V3 末尾再拍板要不要；

**任务状态行（常驻扫一眼）**：运行中后台任务在 ActivityBar 上方常驻 ≤3 行（照 SubagentBar 折叠模式），每行 = 任务名 + 输出最后一行截断 + `Ctrl+P 查看` 提示。零操作知道"还活着、在干什么"。

**交互分工**：Ctrl+O = 对话流内就地快速瞥（预算内 head-tail）；OutputViewer = 认真看（任意滚/搜索/实时跟随）。

### 3.6 与既有架构的关系

- Static 不变量不动：Static 仍是唯一历史固化通道（append-only、/clear remount 等既有机制原样）；
- 最小 Static 哲学补完："Static 承载全量、动态区最小化"从"靠折叠常量 approx"升级为"预算体系 guarantee"；
- OutputViewer 是 M10 §9 M12+ 档挂账"diff 浏览器面板"的直接底座（文本滚动窗 + LineSource 复用）。
