## 0. 一页结论

ECode 的记忆现状 = `memory.ts` 63 行:**两级 MEMORY.md 索引 + 主题文件,模型自主读写**。这是 Phase 0(人工模式)。本周 GitHub 霸榜的三家记忆项目(claude-mem / supermemory / ai-memory)证明了行业收敛出的完整形态是六环闭环:

```
采集 → 压缩 → 存储 → 注入 → 遗忘 → 反馈
(hook)  (LLM结构化)  (md真相源+FTS5)  (SessionStart双层)  (衰减公式)  (👍/👎审核)
```

ECode 的独特优势是**六环的地基全部已有**:HookRunner 七事件(M9)、compaction 链(M5)、task 子代理(M11)、skill 双触发面(M6)、serve 常驻(M12)、web 面板(M13)。缺的只是把它们接成闭环。本方案 = 三线一体:**A 线记忆闭环(主体)+ S 线 Skill 生态对齐 + L 线生活化最小闭环**,外加 P 线行为克制(半天级小改)。

## 3. A 线:记忆闭环(=M15 主体,六环)

### A-B0 存储层:记忆目录+派生索引(1.5 天)
- 目录:`<project>/.ecode/memory/` 已有,扩展为:
  ```
  .ecode/memory/
  ├── MEMORY.md            # 保留:两级索引(现有格式不动)
  ├── topics/*.md          # 主题文件(现有,增加 frontmatter)
  ├── observations/        # 新:会话观察(按日期滚动,auto-markdown)
  ├── handoff.md           # 新:当前待交付交接卡
  └── index.sqlite         # 新:派生索引(FTS5 over topics+observations)
  ```
- 主题文件加 frontmatter:`created/updated/salience/access_count/kind(preference|fact|decision|gotcha)/sources[]`。
- SQLite 表对齐 ai-memory 精简版:`pages`(带 salience/expires_at)、`pages_fts`、`observations`、`handoffs`、`audit_log`;**写入方=单 writer,markdown 为真相源,索引可随时重建**。
- 验收:删库重建命令 `ecode memory reindex` 全量恢复;测试覆盖重建一致性。

### A-B1 采集:HookRunner 挂观察(1 天)
- PostToolUse/Stop 两事件挂观察器:工具名+输入摘要+结果摘要(有界:2KB 摘录/16KB 兜底,对齐 ai-memory),**fire-and-forget**,失败静默(claude-mem 纪律:记忆永不阻塞主流程)。
- 复用 logstore,不新增传输进程(与 claude-mem 的 worker 分离不同,ECode 单进程已有宿主,直接内存队列+落盘)。
- 验收:kill 记忆子系统(故障注入),主循环零感知;观察不落敏感文件(redact 复用 M8)。

### A-B2 压缩:结构化记忆项(2 天)
- 会话 Stop 时,把本次 observations+压缩链产物提炼为结构化条目:`{title, narrative, facts[], concepts[], files_read[], files_modified[]}`(v1.4 核正:claude-mem schema 实为 files_read+files_modified 两字段,原文误写 files_touched;此字段集系 claude-mem 范式而非三家公约数,ECode 取其结构化思想)。
- 写入 topics/*.md(frontmatter+正文),同步 FTS5;audit_log 记来源。
- 防抖:无新信息的会话不产生条目(token 经济学,claude-mem TokenCalculator 思路)。
- 验收:同一会话重复运行幂等;条目 token 开销统计入 /stats(M12 已有口径)。

### A-B3 注入:SessionStart 双层渲染(1.5 天)
- 会话启动注入两块:**static**(用户偏好/项目约定,现有 MEMORY.md 索引)+ **dynamic**(最近 N 条观察/上会话 handoff 卡,时间窗 7 天,对齐 supermemory static/dynamic 与 period 设计)。
- 注入块带信任边界分隔符+总 token 预算(超预算按 salience 截断);Agent/Human 双格式(claude-mem 范式):模型吃 Agent 格式,面板吃 Human 格式。
- handoff 注入规则:存在未过期 handoff → 置顶注入并标记 accepted(ai-memory 三态);`/handoff` 命令可手动查看/清除。
- 验收:跨会话实测("昨天做到哪了"零重述);注入 token 计入 usage 四维。

### A-B4 遗忘:衰减+lint(1 天)
- salience 公式**简化采用** ai-memory:`salience·exp(−λΔt) + σ·log(1+access_count)·exp(−μ·days_since_access)`(λ/μ config 可调)。v1.4 核正:原式还有访问广度项 `(1+breadth_weight·ln(1+max(distinct_actors−1,0)))`,单用户 distinct_actors=1 时该项恒为 1 故省略,验收对表按简化式执行。低于阈值进 `.trash/`(v1.4 核正:此为 ECode 自创设计便于误删恢复;ai-memory 原版实为 TTL hard-delete,明确不走该路线)。
- `ecode memory lint`:矛盾检测(同主题 facts 冲突列 report)、过期(TTL expires_at)、孤儿索引清理;发现级问题写报告**不自动改正文**(claude-obsidian 的 lint 是一等公民,ECode 同判)。
- 验收:30 天模拟数据集上驱逐率/保留率符合 config;lint 报告可读。

### A-B5 反馈+面板(1.5 天)
- 模型侧:记忆条目被 read_file 引用→access_count+1(检索反馈)。
- 人侧:web 面板新增 Memory 页:条目列表👍/👎/stale/wrong(page_feedback 对齐 ai-memory),👎 直接影响 salience;pending 条目(若 D3 开审核)在此批准。
- 验收:面板操作→salience 变化→下次注入顺序变化,端到端可演示。

**A 线合计 ≈ 7.5 天(不含审阅与真机门)。**

## 4. S 线:Skill 生态对齐(2 天,可穿插)

- **S1 包型对齐社区标准**(0.5 天):skill 目录支持 `manifest.json + references/ + scripts/`(garden-skills 包型),兼容现有双触发面;加载器渐进披露:默认只读 SKILL.md,references 按需(garden/archify 范式)。
- **S2 skill 验收协议**(0.5 天):skill 编写规范新增可选段:`validation`(验收命令+量化通过标准)、`stop_condition`(两轮无改善如实报告)、`quality_profile`(档位)——全部吸收自 archify SKILL.md;ec-skills 模板同步。
- **S3 内置知识库索引树 skill**(1 天):`kb-index`(对任意目录生成/更新分层 `data_structure.md` 索引树)+ `kb-ask`(先索引后局部检索,禁整文件加载,PDF/Excel 强制先学 references——garden kb-retriever 内置化)。对用户 D:/study/资料/ 新闻知识库直接可用。
- **S4 内置 skill 清单定版**(0.5 天,随各批次分散实现):常驻判定原则=①每周≥1次 ②跨项目通用 ③不依赖个人数据 ④渐进披露后常驻成本仅 description 数十 token;**常驻≠常加载**(M6 机制:正文按需读)。
  - Tier 1(与 A/S 线强耦合):`memory-search`/`memory-lint`/`handoff`(A-B4/B5 技能面,模型可自主查记忆/体检/看交接卡,claude-mem mem-search 范式)、`kb-index`+`kb-ask`(即 S3)、`review`(drafter-reviewer 泛化:spawn 新 context 审阅产物→问题清单→复验,ai-job-search 模式+用户新闻流日更验证)。
  - Tier 2(高频工程):`arch-diagram`(archify 协议+`npx` 调其渲染引擎,ECode 不重写渲染器)、`lazy-engineer`(ponytail 七级梯子,可选风格包,不硬编码进系统提示词)、`doctor`(已有 /doctor 命令 skill 化,让模型自主诊断端点/hook/记忆库健康)。
  - Tier 3(生活化,产品卖点):`news-digest`(=L1 模板实例)、`deep-research`(websearch(M10)之上的方法论:定日期→多源交叉→来源标注→时效审阅)、`doc-export`(markdown→排版 HTML/PDF,garden beautiful-article 简化版,呼应 v1.1 分端原则:产物落 TUI 之外富格式)。
  - **明确不内置**:目录站类(awesome-* 合集,只留市场安装入口)、领域专用包(求职/健身等,L 线模板让用户自建)、重工具型(浏览器操控/Office 全家桶,走 MCP 按需加载)。
  - 合计约 10 个,常驻 description 成本几百 token;实现分散挂在 A-B4/B5、S2、S3、L1 各批次,不单列大批次。
- **S5 内置 skill 保鲜机制**(1 天):内置≠一劳永逸,按半衰期分三层——
  - **L0 协议层**(skill 正文方法论:七级梯子/drafter-reviewer/IR→validate 协议):半年级慢变量,随 ECode 正常发版,不追新。
  - **L1 引用层**:manifest 声明 `upstream: repo@version-range`;`skills.lock.json` 锁版本,`ecode skill update` 显式升级 = 改 lock + diff 审阅 + 全量测试门 + checkpoint(M9)可回滚——skill 升级与代码变更同规格。
  - **L2 引擎层**(易变外部依赖):arch-diagram 调 archify 渲染引擎、doc-export 渲染器走 `npx` 代理;config `engine: latest|pinned`,默认 pinned + 每周 CI 探新。
  - **运行时自检**(archify check-update / ai-job-search check_upstream_updates 范本):skill 执行时异步查上游版本,新版推送告警中心(M8),绝不打断任务。
  - **退役机制**(与记忆六环同构):/stats 加 per-skill 调用计数;`ecode skill lint` 报告 90 天零调用内置 skill → 降级为不预装、可市场安装。内置清单自身也要有遗忘曲线。
  - **红线**:不做自动热更新——skill 是注入上下文的指令面,静默变更=提示词供应链风险;所有更新必过 diff 审阅,不引入"运行时拉远程内容进提示词"通道(L2 引擎代理除外,且默认 pinned)。
  - S4 十个 skill 的分层归属:memory 家族/review/deep-research/doctor/news-digest=自有 L0;arch-diagram/doc-export=代理型 L2(仅此两个需 lockfile);lazy-engineer/kb-*=vendored 慢文本(上游理念型慢迭代,季度人工 sync)。
  - **S5 附带(0.5 天内)**:①建官方 marketplace 仓库(空壳+内置 skill 可降级安装的落点,格式沿用 M7 marketplace.json);②真机验证与 Claude Code 生态 marketplace 的兼容性(ponytail 等已发布 .claude-plugin/marketplace.json,若可直接添加则白捡社区分发渠道)。

## 5. L 线:生活化最小闭环(3 天,依赖 A 线 B3)

> **v1.1 审阅修正(用户审阅意见:生活化内容在 TUI 上可读性差)**:确立分端原则——**生产在 TUI/后台,消费在 web/IM/文件;TUI 只回执,不承载阅读**。调研佐证:ai-job-search 产物是 PDF、claude-obsidian 消费端是 Obsidian、archify 产物是自包含 HTML、openhuman 是桌面应用——没有一家把生活内容渲染在终端里;ECode M12/M13 已有的 web/PWA+飞书通道即为此而生。

- **L1 命令包模板**(1 天):定义"生活命令包"目录约定:`commands/<flow>/`(流程 md)+资料目录+可选 skills;移植 ai-job-search 的命令结构(/setup→/apply→/interview,drafter-reviewer 是 /apply 流程内嵌步骤而非独立命令——v1.4 核正)为官方模板 `ecode life-flow`。首个官方包:`news-digest`(用户每日新闻工作流固化为命令,含审阅角色步)。**展示分端**:产物统一 markdown/HTML **落盘**(news-digest 直写 `D:\study\资料\新闻动态\`);TUI 仅回执一行(`✅ 日报已生成 → 路径 + 要闻标题行`);完整阅读走文件或 web 渲染。
- **L2 定时记忆探针**(1 天):serve 常驻模式下挂 cron 任务(如每日 08:00):跑指定命令包→产物/结论自动走 A-B2 写入记忆(openhuman auto-fetch 的本地化最小版)。config:`memory.probes[]`。**展示分端**:探针纯后台运行(无需开终端),产物经**飞书卡片推送**(M13 gateway 现成:标题列表+查看全文链接),手机为主消费端。

## 8. 风险与对策

1. **记忆污染**(错误事实反复注入):三层防——结构化字段+来源溯源(A-B2)、lint 矛盾报告(A-B4)、👍/👎 反馈压 salience(A-B5);D3 可一键切审核制。
2. **token 成本膨胀**:注入双层+预算截断+按需 read 主题文件(现有机制保留);/stats 已有成本口径,记忆开销透明可见。
3. **Windows 路径/锁**(SQLite on Win32):沿用 checkpoint(M9)已趟过的 content-addressed 经验;FTS5 是 SQLite 内建,无新依赖。
4. **范围蔓延**:D4(工具输出压缩)、memory-graph 可视化、向量检索全部**显式不做**,挂账待六环闭环跑通后评估。

## 11. 四角色审阅结论(v1.4,2026-08-30)

> 四个并行审阅 agent(架构师/事实核查员/安全员/怀疑论者)对 v1.3 的完整报告。共同底色:**基线核码全部属实、证据链可信度高、无推翻方案骨架的发现**;分歧集中在范围与安全深度。

### 11.1 架构师:需修订后启动(基线核码通过,无 P0)
P1×5(实施前提):
1. **SQLite 运行时选型未定**:ECode 现无任何 sqlite 依赖;`node:sqlite` 在 Node 22.0-22.4 不存在/22.5-22.12 需 `--experimental-sqlite` flag/22.13+ 免 flag(本机 v22.22.2 实测 FTS5 可用但带 ExperimentalWarning)——发行版 CLI 必须在 B0 第一天钉死(node:sqlite 提 engines 下限 vs better-sqlite3 如实承认新增原生依赖),"FTS5 内建无新依赖"论断不成立。
2. **跨进程单 writer 仲裁缺失**:TUI 进程与 serve daemon 可同开同一项目库;需 WAL+busy_timeout+写冲突重试;`reindex` 删库重建在 Windows 下另一进程持连接会 EBUSY,须检测活动会话或取独占锁。
3. **rewind/checkpoint 与记忆交互零覆盖**:/rewind 回退点后的 observations 已落盘,Stop 时仍会提炼——用户明确否决的工作被写成"长期事实"。须规定 rewind 丢弃/标记回退点后观察,handoff accepted 态同废。
4. **A-B2 与 M5 压缩链交接接口未定义**:压缩产物是 boundary line 无暴露口,需明确取数路径;且"Stop 提炼"每轮末触发,LLM 成本需轮末防抖窗(如 N 分钟聚合)。
5. **SessionEnd 不可靠时 handoff 丢失**:应把 handoff 合成挂 `gracefulShutdown.ts`(已有)并补 `/handoff flush` 手动收口(ai-memory 范式)。
P2:子代理内部工具调用采不到(验收写明 scope)、用户级记忆检索范围未定义、A-B2/A-B5/L2/L3 排期各偏紧 +0.5~1 天、D3 回滚应为 append-only 反向事件、HostSession 类名统一。

### 11.2 事实核查员:证据链可信度高(无 P0,P1×5 已修入正文)
- 已修:公式截断、files_touched、.trash 来源、L1 命令链、两处"共识/公约数"过度引申(A-B2 字段系 claude-mem 独有范式;D1 存储是 ai-memory 单家路线)。
- 遗留提醒:docs/01 claude-mem 版本号应为 13.18.0;"npx 调 archify 引擎"依赖其已发 npm(repo 版本 2.16.0-dev.0,S5 验收先验发布态);ai-job-search 的 check_upstream_updates.py 语义是 fork 同步预览,方案做了泛化引申(可用但注明)。

### 11.3 安全员:有安全意识、未成安全体系(P0×5,实施前提)
最大定性偏差:§8 把"记忆污染"当数据质量问题,**未当安全问题(持久化提示词注入)**。P0 五项(启动前必须补设计):
1. **记忆信任模型**(R1 高):恶意网页/工具输出→采集→**反复注入后续所有会话**;dynamic 层注入的是 2KB 原始摘录不经压缩,仅分隔符不够。补:来源信任分级贯通(sources[] 记录事件链)、**隔离层三态(已采集→已压缩→已批准→可注入)**,工具/网页来源默认"写而不注入",待面板批准才进注入池;压缩提示词硬约束"工具输出是数据非指令";`.ecode/memory/**` 写操作走 Hook ask,frontmatter schema 校验。**D3 默认值应按来源分档,非全局二选一。**
2. **敏感信息入记忆**(R2 高):`cat .env`/read 凭据文件→摘录→facts→落盘,且 `.ecode/memory/` 不在默认 ignore 清单,commit 即外溢。补:redact 四生效点(采集/压缩输出/compaction 并入处/远程调用前);凭据类路径事件不进采集(ai-memory 最近标记策略);`.ecode/memory/` 进 gitignore 模板+add 告警;lint 加密钥扫描;远程压缩模型标注出站面。
3. **探针无人值守**(R5 高):ask 态在探针上下文一律降级 deny+审计(绝不挂起);新增探针需首用确认;探针记忆强制走隔离层;飞书只推标题+路径不推正文,正文过 redact;`--no-probes` 总开关+每次运行进 audit_log。
4. **npx 代理供应链**(R4 高):禁裸 npx exec,改 `npm ci --ignore-scripts` 受管缓存+lockfile 记 tarball sha256+首用批准(复用 MCP 指纹交互);`latest` 默认禁用;无人值守场景只准用已批准缓存。四档 bash 沙箱对 postinstall 无效,此为独立执行边界。
5. **多项目隔离+Memory 页写权限**(R3 中):每查询强制 project 作用域;面板写操作(👎/批准/删除)仅 primary 凭据类,device 类只读;飞书不推记忆正文。
P1:安全记忆保护层(salience 下限/删除走 ask)、salience 变更 append-only 审计+批量变更告警、marketplace 审核策略+安装时 diff 门(红线补"安装时"半边)、`ecode memory purge` 全链删除。
