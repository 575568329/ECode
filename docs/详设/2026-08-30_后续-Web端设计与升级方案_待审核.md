# ECode Web 端设计与升级方案

> 日期：2026-08-30 · 状态：待审核（六项目源码调研汇总，Q1-Q6 待拍板后分批实施）
> 本文基于六份对标分析（opencode app / deepseek-harness / OpenHands / LibreChat / lobe-chat / NextChat，源码已克隆至 `D:\study\`，路径证据见各分析文档）汇总而成。

## 1. 现状盘点

当前 web 端（M13/M14 交付）的资产与缺口：

**已有**：daemon 同源部署的单页端（Vite8 + React19 + Tailwind4 + Zustand5，~394KB）；项目→会话两级列表；会话流（react-markdown 全量渲染 + 工具卡 + 图片直渲）；审批/单选/问答 takeover；SSE mux 单流 + 断线重连 + 全量补拉（restore→read）；`/stats`、ModelChip 顶栏、移动两态 + KeyboardAware；PWA 可安装壳；bundle 内 git 23 测。

**缺口（本方案的靶子）**：

1. 流式渲染是 react-markdown **全文重渲**——长回复/长工具输出流式期间卡顿且高亮反复重跑。
2. 长会话无容量策略——数千条工具事件全量挂 DOM。
3. 会话列表只有「项目→会话」裸列表——无分组/搜索/置顶/重命名/删除，运行态只有布尔点。
4. 工具卡无 diff 展示（TUI 已有全量 diff 数据源，web 点开是原始文本）。
5. 插话在 web 端仅 queue 文本条，无用户消息留痕语义对齐（TUI 已补，web 需对齐核查）。
6. 重连靠全量 `session/read` 补拉——无游标续传。
7. 样式硬编码色值散落，无语义令牌层；暗色是唯一形态，无主题演进位。

## 3. 设计原则（不改的三条底盘）

1. **daemon 权威，前端纯视图**：协议不为本方案让路；唯一例外是 W9 的 since 游标（协议增强，向后兼容）。
2. **单层状态**：Zustand 分片 + 少量 SWR/React Query 语义的服务器数据钩子；禁止引入第二套状态体系。
3. **轻量端定位**：不引组件库、不引重运行时；每项设计标注「轻做法」，优先 NextChat 式解法。

## 4. 现有功能升级（W 线，按优先级）

### W-1 流式渲染管线（P0，体验收益最大）

现状 `Markdown` 组件全文重渲。升级为**分块投影 + 尾块 live**：

- `splitBlocks(text)`：marked.lexer 按顶层块切分，前 N-1 块为稳定块（按内容 hash 键控 memo 跳过重渲），尾块 live。
- 稳定块渲染完成后才做代码高亮（流式期间代码块纯文本 + 「高亮于完成后」策略，NextChat/harness 同款取舍）。
- SSE delta 进 **rAF 批处理缓冲**（OpenHands batcher 蓝本，76 行零依赖），每帧至多一次 store commit。
- 锚点：`D:\study\LibreChat\client\src\components\Chat\Messages\Content\splitMarkdown.ts`、`D:\study\OpenHands\src\utils\streaming-delta-batcher.ts`。
- 验收：10KB 回复流式期间主线程单帧解析量 = 尾块长度；工具卡/markdown 混排流式无闪烁。

### W-2 长会话容量（P0）

三档递进，先轻后重：

1. 第一档：**渐进挂载窗口**（只挂可视深度内的行，窗口只扩不缩；LibreChat `useProgressiveRowMount` 蓝本）+ `content-visibility:auto`。
2. 第二档：3 页窗口分页（NextChat，~40 行，无库）。
3. 第三档（会话规模证明需要时）：`virtua` 虚拟化 + keepMounted 规则（流式行/选区行不回收；lobe-chat 三规则）。
- 配套：会话流自动滚动改为「尾部签名」触发 + hitBottom 阈值 + 回到底部按钮（harness ChatView 蓝本）。

### W-3 会话列表升级（P1）

- **时间分组**：今日/昨日/过去 7 日/更早（`groupConversationsByDate` 同款固定组）。
- **搜索**：客户端子串（title+firstUser）起步，协议演进项见 W9。
- **会话操作**：重命名（pin 语义：手动命名即固化标题，harness 同款）、删除（**撤销 toast**，NextChat 内存 undo）、置顶（独立分组）。
- **状态点语义**：待交互（amber，审批/提问挂起）> 运行中（蓝，脉冲）> 完成提醒（绿，仅未打开过）> idle（harness 四态 + OpenHands 视觉词汇）；daemon 已有 running 帧与审批帧，`pendingInteraction` 由客户端从 mux 帧推导，零协议改动。

### W-4 工具卡 diff 展示（P1）

编辑类工具（edit_file/write_file）结果已含 unified diff（TUI 侧已全量化）。web 工具卡展开态渲染 **+/- 着色 diff**：无依赖 LCS DiffView（OpenHands ~150 行蓝本，含首尾裁剪/300 行截断/超大降级三护栏）。截断帧（>4KB）沿用 item/read 补全。

### W-5 消息操作集（P1）

消息级操作：复制（文本/代码块）、重发该问题（startTurn 同文本）、插话引用。用**操作注册表**组织（每操作一文件，icon/label/handler/hide 条件），后续操作零侵入扩展（lobe-chat defineAction 模式）。不做消息树/分支（ECode 会话模型是线性+checkpoint 回退，无 sibling 语义）。

### W-6 审批交互升级（P2）

- takeover 保留（sensitive 语义不变），非敏感审批从「整卡替换 composer」演进为 **dock 卡**：钉在 composer 上方、与输入并存、三键层级 Deny(ghost)/Once(primary)/Always(secondary)。
- auto-accept 作用域：会话级记忆（localStorage）——服务端 once/always 语义不变，纯客户端快捷层。
- 锚点：opencode `session-permission-dock.tsx`、harness `ApprovalPanel.tsx`（按钮行恒在滚动区外 + 一次性 latch + 失败 re-arm——ECode takeover 已有 latch，补 re-arm 核查）。

### W-7 移动端细节包（P2）

iOS 四件套（NextChat）：输入 16px 防缩放、body touch-action、viewport 禁双击缩放、iOS 侧栏 transition 修复；抽屉手势（LibreChat useDrawerSwipe 参数：10px/轴锁定 1.5/35%/0.3px/ms，直写 DOM transform）；`interactive-widget=resizes-content` + `viewport-fit=cover` meta（opencode，已部分有，补齐核查）。

### W-8 语义令牌层（P2）

现状硬编码 Tailwind 色值（neutral-800 等）散落。建立语义令牌 CSS 变量层（`--ec-bg-surface`/`--ec-text-primary`…）喂给 Tailwind4 `@theme`，组件只消费语义类；暗色为唯一形态不变，但留出亮色/主色切换的演进位（lobe-chat cssVar 思想的轻量版，不引 antd 栈）。

### W-9 重连游标（P2，协议增强）

`session/read` 全量补拉演进为「REST 拉尾页 + SSE `since <seq>` 续传 + 事件 id 去重」（OpenHands 模型）。mux 帧已带 seq 语义（harness subscribed lastSeq 同构），daemon 侧增量实现。**向后兼容**：老客户端不传 since 走全量。

### W-10 插话留痕对齐核查（P1，小）

TUI 已实现插话留痕（排队行 + 轮末转写）；web 端核查三点：queue 帧驱动的排队条视觉升级为用户消息行样式、注入后 appendUser 时序、轮末补拉包含注入消息。零协议改动。

## 6. 不做清单（反面集）

- 第二套状态体系（Recoil/Jotai/30 Context——LibreChat 教训）；ECode 保持 Zustand 单层。
- react-virtualized + CellMeasurer 手动缓存（停维护库 + 4 个失效 effect）。
- 多后端代理层/双认证/云本地双模（OpenHands 连接复杂度放大器）。
- 会话偏好矩阵（pinned/标签/分组文件夹/compact 双形态 8+ 开关——桌面重度产品形态）。
- 市场供给端 monorepo、Next+SPA 双构建、Electron 桥（ECode 无此产品面）。
- 消息树/分支（与 checkpoint 回退模型冲突，线性会话不做 sibling）。
