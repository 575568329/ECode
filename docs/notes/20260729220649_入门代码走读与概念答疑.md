## 二、问答记录

### Q1：`process.argv[2]` 是干啥的？

Node 内置的全局对象 `process.argv` 是个**数组**，存启动进程时的命令行参数：

| 下标 | 内容 |
|------|------|
| `[0]` | Node 可执行文件路径 |
| `[1]` | 被执行的脚本路径 |
| `[2]` | **第一个用户参数** ← 任务描述 |

用户传的参数从 `[2]` 开始（前两位被 Node 和脚本占掉）。[index.ts:18](../../src/index.ts#L18) 取它作为任务描述，[index.ts:20-24](../../src/index.ts#L20-L24) 卫语句兜底（没传则退出）。

**要记**：argv 是原始字符串数组，Node 内置，从 `[2]` 开始是用户参数。
**不用记**：argv[0]/[1] 具体长啥样（用时打印一下就知道）。

---

### Q2：`[2]` 后面还能加命令吗？

能加，`process.argv` 会全收下——但**能不能用由你的代码决定**。当前只读 `[2]`，后面全忽略。选项多了（`--model`、`--verbose`）就要上 `commander`/`yargs` 这类解析库（YAGNI，现在不引入）。

**要记**：argv 本身不懂"选项"，它只是收纳箱；解析靠代码或库。

---

### Q3：`messages` 每次都重新创建 → 只支持单次对话？

对。但要分清两个层面：

| 层面 | 是否累加 | 说明 |
|------|---------|------|
| **单次运行内**（loop 内部） | ✅ 累加 | 每轮 push，LLM 能看到完整历史 |
| **跨运行 / 多轮对话** | ❌ 不累加 | `messages` 是函数局部变量，进程退出就没了 |

[agent.ts:45-47](../../src/agent.ts#L45-L47) 每次调 `runAgent` 新建数组（只含本次任务）。不支持"追问"——没有持久化、没有交互式 REPL。

**要记**："loop 内累加" ≠ "跨对话累加"。当前缺持久化 + REPL，是刻意保持的最小实现（YAGNI）。
**后续**：`.ecode/session.json` 持久化（`.gitignore` 已预留 `*.session.json`），属于 M3 范畴。

---

### Q4：OpenAI 和 Anthropic 的 message 格式不一样？

不一样，而且差异是**全局性**的（不只 message）。最关键的 4 处：

| 维度 | Anthropic | OpenAI |
|------|-----------|--------|
| **system 位置** | 顶层 `system` 字段 | `messages` 里 `role:'system'` |
| **工具调用长在哪** | content 数组里的 `tool_use` block | message 的独立字段 `tool_calls` |
| **工具参数类型** | `input` = **对象** ✅ | `function.arguments` = **JSON 字符串** ❌（要 parse） |
| **工具结果回传** | user 消息里塞 `tool_result` block | 独立 `role:'tool'` 消息 |
| **ID 字段名** | `tool_use_id` | `tool_call_id` |
| **终止信号** | `stop_reason: 'tool_use'/'end_turn'` | `finish_reason: 'tool_calls'/'stop'` |

**要记**：差异是**全方位**的（system/调用/结果/ID/终止信号/工具定义），不只是 message；M2 要用 **Provider 抽象层**抹平——agent loop 只认统一内部格式，每家写翻译器。
**不用记**：具体字段名（查 [docs/04](../04-OpenAI-vs-Anthropic-API协议对比.md)）。

### Q5：`truncate(content, 50_000)` 什么意思？

把内容截断到最多 5 万字符，防撑爆 LLM 上下文窗口（[tools.ts:75-78](../../src/tools.ts#L75-L78)）。

- `50_000` 的 `_` 是 JS 数字分隔符（ES2021），给人看的，`50_000 === 50000`。
- `read_file` 用 50k，`bash` 用默认 30k（`MAX_OUTPUT_LENGTH`，[tools.ts:54](../../src/tools.ts#L54)）——命令输出噪音多，给更紧预算。

**要记**：这是**粗暴硬切**（只留头部），M3 会换成 token 计数 + 智能压缩。本质是"上下文保险丝"。
**不用记**：具体阈值数字。

---

### Q6：`executeBash` 是什么工具？

让 LLM 能在你电脑上执行 shell 命令——agent 从"聊天"变"干活"的关键，也是最大风险点（[tools.ts:92-107](../../src/tools.ts#L92-L107)）。

核心是 `execSync`（同步阻塞），带三个防御参数：`maxBuffer: 10MB`（防撑爆内存）、`timeout: 30s`（防 hang 死）、失败也回传（`isError: true`，让 LLM 自我修正）。

**要记**：3 个局限 = 后续里程碑的靶子——
1. 同步阻塞 → spawn 流式（工程优化）
2. 无权限拦截 → **M4 权限系统**（头号目标）
3. 单条命令无交互 → 每次新 shell，`cd` 不保留

---

### Q7：`execSync` 就是执行 shell 让 LLM 控制电脑？

对。`execSync` 是 **Node 内置 API**（`node:child_process` 模块），把字符串丢给系统 shell 跑、阻塞等输出。接上这个工具，LLM 就有了"伸进你电脑的手"。

**要记**：`execSync` = Node 内置、同步、阻塞。注释要写 **Why**（为什么 10MB/30s/同步）而非 What（"执行命令"）——呼应 CLAUDE.md §1.2。

---

### Q8：异步怎么写？（当前是同步）

两条路：

| 方案 | API | 特点 |
|------|-----|------|
| **A. 最小改动** | `exec`（execSync 的异步亲兄弟） | 不阻塞，但仍"憋大招"等全部输出 |
| **B. 流式（推荐）** | `spawn` | 事件驱动，边跑边吐，能实时回显/取消 |

**要记**：spawn 比 exec 强在——实时回显、流式喂 LLM（M3）、优雅超时 kill（M4 取消）。现在 M1 不急着换（YAGNI）；真换直接上 spawn，别走 exec 中间态。
**Windows 三个坑**：`shell:true` 必须开（不然复合命令 ENOENT）、跨平台命令差异、超时后进程可能没真死（要 taskkill 杀进程树）。

---

### Q9：subagent 本质是 shell 开窗口？

**不准确**。subagent 本质 = **进程内再起一个 agent loop 实例**（函数调用，不是 shell）：

- 独立的 `messages`、system prompt、工具子集
- 跑完只把**最终文本**交回主 agent（中间过程主 agent 看不到 → 隔离上下文消耗，这是核心价值）
- 落地 = 给主 agent 加个 `dispatch_subagent` 工具，内部 `await runAgent(subTask, {silent, tools})`

"shell 开窗口"对应的是**子进程模式**（`spawn('node', ['subagent.js'])`），隔离更强但通信开销大，**不是主流**。

**要记**：subagent = 上下文隔离的复用 loop，进程内函数调用。Claude Code 日常 subagent 是进程内的。
**后续**：M5，要把 [agent.ts:30](../../src/agent.ts#L30) 的 `runAgent` 从"直接 console.log + void"改造成"返回最终文本 + 可配 systemPrompt/tools/silent"。

---

### Q10：`spawn` 是插件还是内部命令？

**都不是**。`spawn` 是 **Node.js 内置 API**（`node:child_process` 模块的函数），和 `execSync`、`exec` 同模块同家。不用装、不是命令。

**要记的心智模型**（划清这条线，看 import 就知道东西哪来的）：

| 类别 | 例子 | 来源 |
|------|------|------|
| **Node 内置模块** | `child_process` / `fs` / `path` / `http` | 运行时自带，import 即用，零依赖 |
| **npm 包（第三方库）** | `@anthropic-ai/sdk` / `vitest` / `tsx` | 要 `npm install` |
| **shell 命令** | `ls` / `npm test` / `git` | 操作系统程序，用 spawn/execSync 去调 |

## 三、补充：对话里没展开但重要的点

### 3.1 Agent Loop 的三条硬约束（违反会 400 / 死循环）

1. **assistant 回复必须原样 push**（[agent.ts:100-103](../../src/agent.ts#L100-L103)）：不能只存文本，要存整个 `response.content`（含所有 text + tool_use block）。
2. **`tool_use_id` 必须配对**（[agent.ts:125-135](../../src/agent.ts#L125-L135)）：`tool_result.tool_use_id` == `tool_use.id`，不配对 API 400。
3. **messages 累加不重建**：每轮传完整历史——这就是为什么 M3 必须做上下文压缩。

### 3.2 Node 的同步 vs 异步 = 事件循环（Event Loop）

同步函数（`execSync`/`readFileSync`）会**阻塞整个事件循环**——命令跑多久，Node 啥都干不了（连日志都写不进去，直到它返回）。异步（`spawn`/`exec`/`fs.promises`）在 `await` 期间**让出事件循环**，Node 能继续处理别的（写日志、回显输出、响应别的请求）。

> 这是"为什么 async 好"的底层原因：不是更快，而是**不卡住别人**。

### 3.3 `child_process` 三件套对比

| 函数 | 同步? | 输出方式 | 典型场景 |
|------|-------|---------|---------|
| `execSync` | ✅ 阻塞 | 一次性返回 | 简单脚本，不在乎卡 |
| `exec` / `promisify(exec)` | ❌ | 一次性（带 maxBuffer） | 不阻塞但等全量结果 |
| `spawn` | ❌ | **流式事件** | 长命令、要实时回显/取消 |
| `fork` | ❌ | 流式 + IPC 通道 | 起一个 Node 子进程并双向通信（subagent 子进程模式可用） |

### 3.4 工具层的"两处同改"约定

新增工具必须同时改 [tools.ts](../../src/tools.ts) 两处：
1. `toolDefinitions`（[tools.ts:18-48](../../src/tools.ts#L18-L48)）—— 给 LLM 看的清单（Anthropic `input_schema` 格式）。
2. `executeTool` 的 `switch`（[tools.ts:61-73](../../src/tools.ts#L61-L73)）—— 实际执行分发。

漏一处：要么 LLM 不知道有这工具，要么 LLM 调了却没实现。

### 3.5 subagent vs 普通工具调用的本质区别

| 维度 | 普通工具（如 read_file） | subagent |
|------|------------------------|----------|
| 内部 | 一次函数调用 | 一个**完整的 agent loop**（多轮工具调用） |
| 返回 | 工具的直接输出 | 子 agent 跑完 loop 的**最终文本答案** |
| 上下文 | 输出进主 messages | 中间过程**不进**主 messages，只进最终答案 |
| 用途 | 原子操作 | 复杂子任务（需要多步探索） |
