# ECode M2 TUI 实施方案

> 日期：2026-08-12 · 状态：**草案待讨论**
> M1 已完成（readline REPL + 心脏闭环，真 LLM 跑通）。M2 把 readline 换成 Ink 7 全屏 TUI。
> 本文是 TUI 规范（"做什么"）到实施（"怎么做、什么顺序、验收什么"）的桥梁。
> 标 ★ 的决策点需要讨论拍板。

## 1. 目标 & 验收

**目标**：把 M1 的 readline REPL 换成 Ink 7 全屏 TUI，loop 的 callbacks 接到 TUI 组件。

**验收标准**（对应详设 §10 M2）：
- 流式期灰字占位 → 完成后 markdown 正确渲染（代码高亮 / 表格 / 列表）
- Ctrl+C 中断（一次中断 + 1.5s 内两次退出），中断后已生成内容保留
- ActivityBar loading 常驻（用户始终知道当前状态，§4.10）
- 工具调用 3 行摘要 + 折叠/展开 + 同轮聚合（§4.11）
- `<Static>` 几百条消息重绘 < 100ms

## 2. 范围

**M2 做**：
- Ink 7 接入（替换 readline）+ **自建 TextInput/Select/Spinner**（不用 @inkjs/ui，组件方式插入，参考 `D:\study\claude-code-main` 源码：`BaseTextInput.tsx` / `CustomSelect/` / ink components）
- **自建三件**：流式分阶段渲染 / 终端 Markdown / 折叠 ToolCallView
- 13 组件（见 TUI 规范 §7）
- Ctrl+C 中断 + **AbortSignal 透传**（loop→provider→SDK，补 M1 TODO）
- 适度色彩（暗色主题，`theme.ts`）
- 焦点导航（`useFocus` + Tab，输入框 ↔ 折叠区）
- 斜杠命令 `/help` `/clear`（**CommandRegistry 可扩展**：未来 skill / 管理命令注册，呼应 CC 把 commands 合并进 skills）
- **bash 确认 ConfirmPrompt → 挪 M3**（和写工具 diff + 危险命令拦截一起做）；M2 bash 延续 M1 默认全确认（ActivityBar 显示命令可见即可）

**M2 不做**（留后续）：
- 写工具 `write_file`/`edit_file`（M3）→ ConfirmPrompt 的 diff 预览随 M3
- `glob`/`grep`/`ls`（M3）
- 斜杠命令 `/model` `/history`（M4，需 Config 完整版 + HistoryStore）
- bash 全套安全（危险命令拦截/输出截断，M3）
- 首次运行向导（M2 只欢迎屏）
- 历史持久化（M4）

## 3. 前置烟测（第 0 步，决定方案）★

M2 开工前必做（技术栈解析决策 2 反驳点）：
1. 装 ink@7 + react + `@inkjs/ui` + marked + cli-highlight + string-width
2. 烟测 `@inkjs/ui` 是否跟上 Ink 7（ESM 导出 + 组件能用）
3. 烟测 `<Static>` 几百条消息重绘性能（< 100ms）
4. 烟测 Ink 下 Ctrl+C / AbortSignal 行为（中断 SDK 流式请求）
5. 烟测 string-width 中文宽度处理
6. **烟测滚动行为（⚠️ 阻断性）**：Ink 全屏 alt buffer 下，**鼠标滚轮是否触发 Ink mouse 事件**（还是被终端原生滚 scrollback）+ Shift+PgUp 看 `<Static>` 历史 + 流式重绘是否打断。**这是 follow 滚动锁定的前提**——若鼠标滚轮不触发 Ink 事件，follow 改用键触发（Shift+PgUp），方案要调。

> 烟测结果影响方案：若某依赖不兼容 Ink 7，调整（降级 Ink 5 / 换组件）；若滚动被打断或鼠标滚轮不触发 Ink 事件，follow 标志改键触发；若 Static 性能不达标，限制历史长度。

## 4. 实施拆解

### 第 1 步：基础设施
- 装依赖（第 0 步）
- `tui/theme.ts`（配色：青工具名 / 绿✓ / 红✗ / 黄⚠ / 灰次要）
- `tui/symbols.ts`（❯⏺✓✗▸▾⟳ + Unicode 退化）
- 全局状态 Context（会话 messages / provider / ActivityBar 状态 / abortController / 焦点）
- **改 loop**：透传 AbortSignal 给 provider.run（补 M1 TODO）→ AnthropicProvider 用 stream.abort()

### 第 2a 步：自建三件（核心）
- `Markdown.tsx`：marked 解析 + cli-highlight 代码高亮 + string-width 中文宽度换行
- `ToolCallView.tsx`：3 行摘要 + 折叠/展开 + **同轮同工具聚合**（§4.11）+ `useFocus` + Ctrl+O 全部展开
- `render.ts`（流式分阶段，**方案 A**）：commit 清灰字 + 一次性 markdown 渲染

### 第 2b 步：流式折叠 + 滚动锁定
- 流式灰字占位（**超 5 行折叠尾部 + 顶部提示行数**，追加进 scrollback 不重绘历史，§4.12）
- **滚动锁定 follow**：检测用户上滚（**鼠标事件可行性见第 0 步阻断性烟测**）→ 停止跟随 + StatusBar 提示「↓ N 行新」；End 恢复（§4.12）

### 第 3 步：布局组件
- `App.tsx`（根 + 全局状态 Provider）
- `StatusBar.tsx`（model / 轮数 / token / 成本）
- `ActivityBar.tsx`（loading 常驻，6 态状态机，§4.10）
- `MessageList.tsx`（`<Static>` 历史 + 动态当前）
- `UserMessage.tsx`（灰 ❯）/ `AssistantMessage.tsx`（流式灰字 / 提交 markdown）

### 第 4 步：输入 + 启动 + 命令
- `InputStream.tsx`（`@inkjs/ui` TextInput + ↑↓ 历史 + / 斜杠补全）
- `ShortcutHint.tsx`（随上下文变的快捷键提示）
- `WelcomeScreen.tsx`（纯文字启动屏，§4.1）
- 斜杠命令 `/help`（列命令）/`/clear`（清空当前会话 messages）——纯本地控制，不进 loop

### 第 5 步：中断 + 错误
- Ctrl+C 全局处理（`useInput`：一次中断 `abortController.abort()` + 1.5s 窗口两次退出）
- `ErrorBanner.tsx`（fatal 错误展示）
- 中断固化（loop 的 try/finally 已做，TUI 显示「已中断，内容已保留」）
- _（ConfirmPrompt 随 bash 确认 + 写工具 diff 留 M3；M2 bash 默认全确认）_

### 第 6 步：集成 + 端到端
- `cli/index.ts` 换 Ink render（替换 readline）
- loop callbacks 接 TUI：onText→streamText、onToolStart→ActivityBar、onToolResult→ToolCallView、onWarn→ErrorBanner/ActivityBar
- 端到端：真 LLM 跑通（GLM-5.2）+ 中断测试 + 性能压测

## 6. 风险 & 开放问题

- **Ink 7 兼容**：`@inkjs/ui` 等是否跟上（烟测）—— 不兼容则降级 Ink 5 或换组件
- **Static 性能**：几百条消息重绘（烟测）—— 不达标则增量渲染优化
- **流式 markdown**：M2 灰字占位（求稳），增量宽容解析留后续
- **中文宽度**：marked + cli-highlight + string-width 协同（代码块/表格中文对齐）
- **AbortSignal 链路**：Ink 下 Ctrl+C → abortController.abort() → SDK stream 中断（M1 TODO，M2 验证）

## 7. 自建组件设计理念（借鉴 Claude Code，ECode 简洁化）

> 原则：**学设计理念（why），不抄代码（how）**。Claude Code 是生产级（Cursor.ts 1530 行，含 Emacs kill-ring / image-chip / voice 等高级特性）；ECode 是 MVP——精简到够用，做出自己的特色（简洁 + 跨平台中文 + 流式友好）。
> 参考源码：`D:\study\claude-code-main/src/components`（BaseTextInput / CustomSelect / Spinner）。

### 可借鉴的设计理念（6 条）

1. **编辑逻辑与渲染分离（TextInput）**：光标编辑做成独立纯函数模型（Cursor），不散在 useInput 的 if-else。好处：可单测、渲染层薄。**ECode**：Cursor 精简（insert/backspace/left/right + 反色渲染 + 停泊），不做 Emacs kill-ring / image-chip。
2. **光标反色渲染（TextInput）**：用反色（`chalk.inverse`）当前字素，不塞 `▋` 字符。好处：跨字素不错位、多行定位准。**ECode**：直接采用（成本低效果好）。
3. **停泊原生终端光标（TextInput）**：把原生光标移到 caret 位置。好处：中文输入法 / IME / 读屏兼容。**ECode**：**必做**（支持中文输入的必要投入，@inkjs/ui 没做这点）。
4. **动画共享单时钟（Spinner）**：N 个动画订阅一个 Clock（单定时器 + 订阅 + keepAlive + 离屏暂停）。**ECode**：ActivityBar + 工具 spinner 共享一个 Clock（避免多 setInterval，帧同步）。
5. **导航状态机化（Select）**：选项导航用 reducer（可预测）+ 视口边缘滚动（焦点触底才滚一格）+ 首尾环绕。**ECode**：精简 reducer（固定 ↑↓Enter Esc，不做 keybinding 可配置）。
6. **乒乓帧 + reduced-motion（Spinner）**：`[...chars, ...chars.reverse()]` 来回弹；reduced-motion 退化静态。**ECode**：乒乓帧（零成本）；reduced-motion 留后续（MVP 可不做）。

### ECode 简化（不做的 Claude Code 高级特性）

- Emacs 快捷键（Ctrl+A/E/K kill-ring）
- 图片 chip（`[Image #N]` 整体跳过）
- voice 波形光标
- keybinding 可配置（`/keybindings`）
- 颜色插值（卡顿变红）
- SelectMulti（MVP 单选够用）

### ECode 特色

- **简洁**：Cursor ~150 行（CC 1530），只做核心编辑。
- **跨平台中文**：反色光标 + 停泊原生光标（IME 兼容）。
- **流式友好**：灰字占位→commit（方案 A，滚动友好，§4.12）。
- **适度色彩**：暗色主题，工具青/状态色/灰字次要（不做颜色插值）。

## 8. 多模态预留（前瞻性约束）

> MVP 不做多模态（图像输入，YAGNI），但**设计预留**避免将来破坏性改。详设 §2.1 已在规范模型层预留 ImageBlock 占位（M1 types.ts 有注释占位）。

M2 自建时同步预留的口子：

| 层 | 预留口子 | MVP 状态 |
|---|---|---|
| types.ts | ImageBlock 注释占位（ContentBlock 联合预留） | ✅ M1 已做 |
| **Cursor 模型** | 操作单元 = 「不可分割字素」模型（`Intl.Segmenter`），**不写死"只处理文字"**——将来 image chip（`[Image #N]`）作为特殊字素接入，不改架构 | M2 自建时遵循 |
| **InputStream** | 留 `onPasteImage` 钩子位（接口预留，MVP 不实现粘贴图片） | M2 接口预留 |
| **Provider toXxxMsgs** | content block 按 type 分发，留 `case 'image': TODO` 分支 | M2 占位 |
| **HistoryStore（M4）** | image 进 messages 后持久化要存 base64（体积大，JSONL 膨胀）—— M4 考虑存路径/引用而非内联 base64 | M4 预留 |
| **LogStore 脱敏（M3）** | image base64 不落 trace 日志（脱敏规则处理 image，不内联） | M3 预留 |

> Cursor 的字素模型天然兼容 image chip（chip 是「不可分割单元」的特例，和 emoji `👨‍👩‍👧` 同机制）。将来加图像输入 = 字素识别加一种单元类型，**不改 Cursor 架构**。
