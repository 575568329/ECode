# M12 服务化与多端调研（token 统计 / Web UI / 手机 / 远程与 IM）

> 日期：2026-08-18 · 来源：用户需求输入（token 多维统计、Web 对话页、手机、远程调服务器/家机 ECode、飞书微信调用）+ 三路并行源码调研（CC/opencode/deepseek-harness/codex/aider 本地源码 + 网络检索 IM 生态现状）。
> 定位一句话：M12 = ECode 从"单终端工具"走向"可观测（用量）+ 可触达（服务化多端）"的第一个里程碑。

---

## 0. 需求输入与块间依赖

用户原始需求五块：

| 块 | 内容 | 性质 |
|---|---|---|
| A. token 统计 | 按输入/输出、对话（会话）、时间等多维度统计消耗 | 纯本地功能，独立 |
| B. Web 对话页 | 浏览器里和 ECode 对话；要快、UI/交互要对标优秀项目 | 依赖 C（server 面） |
| C. 远程调用 | 部署服务器/自家电脑跑 ECode，别处通过网页操作（对话、内容查询） | B 的地基；E 的地基 |
| D. 手机端 | 单独手机页面 vs 手机适配 | B 的响应式延伸 |
| E. IM 接入 | 飞书/微信调用 ECode | 依赖 C；网关层独立 |

依赖链：**A 独立**；C → B → D；C → E。核心架构决策全在 C（服务化形态），B/D/E 都是 C 之上的消费者。

## 1. Token 用量统计（A）

### 1.1 三家事实

| 维度 | Claude Code | opencode | deepseek-harness |
|---|---|---|---|
| 采集点 | 流式 `message_delta/message_stop`（`services/api/claude.ts:2246`） | `step-finish`（`session/processor.ts:438`） | `assistant/chunk(usage)` 事件 |
| 会话内累计 | 内存全局 STATE（`cost-tracker.ts` addToTotalSessionCost） | SQLite session 行六字段（cost+五维 tokens）直接 UPDATE | 无持久化——事件流投影（projection）实时 fold |
| 跨会话存储 | 会话 JSONL 内嵌 `message.usage` + `~/.claude/stats-cache.json` 聚合缓存 | SQLite 表（session/message/part 三级带 tokens+cost） | 事件日志（无独立 usage 存储） |
| 时间聚合 | **按天缓存+今天实时扫**（statsCache：历史按天聚合缓存，原子写） | `stats` 命令全量扫描（大数据集提示 slow） | 无 |
| 统计维度 | 天/模型/时段/会话/连续天数（/stats：7/30/全时间三档 + 热力图） | 项目/天数/模型/工具（CLI `stats` 表格） | 会话内/每轮（TTFT、decode 速率、cache 命中率） |
| 定价源 | **硬编码**（modelCost.ts，仅自家模型） | models.opencode.ai 在线 + 5min 本地缓存；**支持 tiers 分级定价**（超上下文阈值加价） | 无成本计算 |
| cache 计价 | read/write 独立单价 | read/write 独立单价 + **input 含 cache 的去重**（AI SDK inputTokens 含 cached，须减） | 只计数 |

### 1.2 ECode 方案要点（借鉴结论）

- **存储走 CC 模式**（JSONL 生态不动）：会话内内存累计（SessionCostAccumulator，每轮累加）+ 会话结束/切换写一条 summary 条目进会话 JSONL；跨会话按天聚合用 CC 的 stats-cache 增量模式（历史天缓存文件 + 今天实时扫），**不引 SQLite**（opencode 模式与 JSONL 追加写冲突）。
- **维度**：按会话（现有 /cost 扩展为会话累计）/ 按天·周·月（/stats 新命令）/ 按模型 / 输入输出四维（已有）。项目维度：会话 JSONL 本就按项目目录组织（.ecode/），聚合天然带项目。
- **定价**：models.dev 已接入（M5），扩展 tiers 字段（opencode 的按上下文长度选 tier 逻辑为参考实现）。
- **须核对的坑**：双协议 usage 里 input 是否已含 cache（Anthropic 语义不含、OpenAI 语义含——翻译层统一时确认，避免重复计价）。
- **不做**：热力图/连续天数（CC 自己都算复杂度高价值低）、全量扫描式 stats（opencode 的教训）。

## 2. Web 对话 UI（B）

### 2.1 三家事实

| 维度 | opencode（app/desktop） | deepseek-harness | aider |
|---|---|---|---|
| 架构 | REST + **SSE 事件流**（`/api/event`，15s 心跳）；desktop=Electron 壳 sidecar 起 server（`utilityProcess.fork`，127.0.0.1 随机端口+Basic Auth） | HTTP RPC 上行 + **WebSocket 双下行流**（/ws/mux 会话事件 + /ws/host 主机事件，downlink-only）；单进程无桌面壳 | Streamlit 同进程（无 API 层，`st.write_stream`） |
| 前端栈 | **SolidJS** + 自建组件库（kobalte 原语）+ Tailwind v4 + tanstack query/virtual | **React 18** + use-sync-external-store + CSS Modules + 自建 20+ UI 包 | Streamlit（无前端栈） |
| 流式 Markdown | marked + shiki（**Web Worker 内高亮**）+ remend 修复未闭合块 + **增量投影**（只重解析最后一个未完成 block） | MarkdownText 组件 + rAF 节流（3 帧间隔） | st.write_stream |
| **快的秘诀** | 事件 **coalesce**（text.delta 字符串拼接合并）+ **16ms 帧级 flush** + 8ms yield；虚拟列表 + 测量缓存（切换会话复用，最多 16 个）+ 冷启动 overscan 6→20 两段 | keyed row flow layout（不虚拟化，消息数百内够用）+ ResizeObserver 跟随 + prepend 锚定 | 无 |
| 输入框 | contentEditable 多行 + @文件提及 + /命令 + 图片粘贴 + 模型/agent 选择器 | composer + 分页加载 | st.chat_input |
| 工具调用展示 | MessagePart 折叠/展开 + diff 视图（@pierre/diffs）+ 上下文工具组 | tool row 分组 + 可展开 | 只显示 commit+diff |
| 手机适配 | **无专门适配**（仅 PWA manifest + 触摸滚动处理） | 无 | Streamlit 自带基础响应式 |

### 2.2 ECode 最小架构结论

- **通信：REST（命令）+ SSE（事件）**——opencode 同款；WebSocket 是过度设计（harness 用 WS 因它有两条异构下行流）。
- **前端：React 19 + Vite + Tailwind**——ECode 已有 React/TS 全栈经验（Ink 即 React），不引第二框架；组件库先手写（opencode 也是自建）。
- **快的三板斧直接抄理念**：①前端事件 coalesce + 16ms 帧 flush；②Markdown 增量投影（只重解析尾块）+ 高亮 Worker 后置；③消息列表先 flow layout keyed rows，超长会话再上虚拟化。
- **不做**：桌面壳（Electron/Tauri）、i18n、双框架。

## 3. 服务化：ecode serve（C——本里程碑核心架构决策）

### 3.1 四家事实

| 维度 | opencode serve | Claude Code | deepseek-harness | codex app-server |
|---|---|---|---|---|
| 形态 | `opencode serve` headless server（`instance:false` 不绑项目；workspace 按请求头 `x-opencode-directory` 路由） | **云侧托管**（Remote Control 服务端在 Anthropic；开源码只有客户端：OAuth 建会话→bridge 换短命 JWT→SSE 读+POST 写→epoch 防重放） | 同进程 Cordis 插件（`dsh web`）+ **ACP 桥**（JSON-RPC over stdio 供 IDE 驱动，每会话同时仅一个 in-flight prompt） | Rust app-server（JSON-RPC 2.0；传输 stdio/unix-socket/WebSocket/off 四选） |
| HTTP 框架 | Effect HttpRouter（类型安全声明式路由）→ 可导出为标准 fetch handler | — | node:http 桥接 WHATWG fetch（http-bridge.ts 约 100 行，带背压） | — |
| 端口/发现 | `--port 0`（4096 优先+随机 fallback）、`--hostname 127.0.0.1`、`--mdns`（局域网发现 opencode.local） | — | — | `--listen` 默认 stdio |
| 鉴权 | **Basic Auth**（env 密码；无密码=无鉴权+警告；PWA 静态资源豁免；?auth_token= 兜底 SSE 场景） | OAuth+短命 JWT+epoch（最完善） | 无（可信内网设计；loopback 白名单+DNS rebinding 防护） | 多 AuthMode（ApiKey/PAT/Headers…） |
| TLS | **四家全部不内置 TLS**——公网暴露一律靠反代（caddy/nginx）终止 | 云侧 HTTPS | 无 | 无 |
| 多客户端同会话 | 每客户端独立 SSE 队列；SessionProcessor 串行化 prompt；promptAsync 202 立返 | 云侧 | ACP in-flight 单锁 | 连接级 mpsc(128) 路由，过载回 -32001 |
| 会话管理 | Session 全生命周期 API（list/create/fork/abort/share/prompt/messages/diff/todo…）+ PTY WebSocket（一次性 connect-token）+ 文件/配置/MCP/权限 API | — | Map<SessionId, SessionRecord> + dispose | startup lock 防多实例 |

### 3.2 ECode 路径结论

三条候选路径评估（调研结论 + ECode 现状约束）：

- **路径 a（采纳）：`ecode serve` 独立入口，同进程内嵌 node:http**——不与 TUI 同时跑（互斥：serve 模式完全不初始化 Ink，规避非 TTY raw mode 崩溃）。opencode 验证过的形态；零新增进程管理。框架用原生 node:http + 手写路由（harness http-bridge 仅百行的先例），不引 Express/Fastify/Effect。
- 路径 b（否决，观察）：独立 serve 常驻进程 + CLI 进程共享 `~/.ecode` 数据——JSONL append 无文件锁，双进程并发写 history 必丢数据；Windows 文件锁语义更严（rename 受限）。除非未来引入 SQLite+WAL，否则不开。
- 路径 c（IM 时再评估）：网关 bot 进程调 serve 的 HTTP API（不是调 headless stdio）——见 §5。
- **API 面分期**：M12 只做最小集（health/session list/create/prompt(异步 202)/messages/SSE event 流/interrupt + Static web 资源）；PTY WebSocket、文件 API、MCP 管理、多 workspace 路由全部后置。
- **鉴权**：Basic Auth（env `ECODE_SERVER_PASSWORD`，无密码=仅 127.0.0.1 可用+启动警告）——opencode 同款；公网部署文档引导 caddy/nginx 反代 TLS；短命 token/epoch 机制观察区。
- **Windows 三个坑**：首次监听端口防火墙弹窗（文档提示）；不用 unix socket；graceful shutdown 不能依赖 SIGUSR*。

## 4. 手机端（D）

- 各家现状：opencode = 响应式 web + PWA（无专门移动断点）+ 官方 iOS App（闭源，连自建 server）；CC = 闭源原生 App + Remote Control；harness/aider = 无。
- **结论：响应式 web 优先，PWA manifest 顺带，原生 App 不做**。依据：opencode 已验证"浏览器访问 serve 端口"的路线在手机上可用；原生 App 的增量价值（推送/后台连接）对 M12 场景（主动查看/插话）非必需。手机适配点：单列布局断点、侧栏抽屉化、输入框防缩放、长按替代右键。
- 局域网直连（手机与电脑同网段访问 `http://电脑IP:port`）是零成本首发形态；外网走 Tailscale/反代（opencode 社区同款玩法，文档引导即可，不做内置穿透）。

## 5. IM 接入（E）

### 5.1 渠道现状（2026-08 检索结论）

| 渠道 | 结论 | 依据 |
|---|---|---|
| **微信个人号** | **不做**（封号风险高） | wechaty 官方 issue 明示可能封号（梯度 1 天→7 天→30 天→永封）；iPad 协议/wxauto 等方案风控持续收紧；多封后永封 |
| **企业微信** | 可做（官方 API 模式机器人+**长连接**——无需公网回调） | 智能机器人 API 模式：Bot ID+Secret、WebSocket 长连接收消息 |
| **飞书** | **优先做**（官方支持最完整） | 事件订阅支持 HTTP 回调与 WebSocket 长连接两种；`im.message.receive_v1` 单聊/群聊；已有 OpenAPI MCP 生态 |
| 开源网关 | LangBot / chatgpt-on-wechat 可作 IM 适配层（自定义后端指向 ECode serve API） | 均支持自定义 API endpoint |

### 5.2 ECode 结论

- **IM 接入建议整体滑出 M12**（M13 候选）：它依赖 serve 稳定后的 API 面，且网关层是独立工程（消息格式转换、长任务先回"处理中"再持续更新——飞书回调 3 秒超时、权限确认怎么过 IM 等都要单独设计）。
- M12 只需保证一件事：**serve 的 API 设计对机器友好**（promptAsync 立返 202 + SSE 事件流可订阅），网关层（自建薄网关 or LangBot 对接）留干净接口。
- 若 M12 内做，只做飞书单渠道最小版（长连接收消息→promptAsync→SSE 聚合→回复文本，权限确认先映射为"拒绝并说明"）。

## 6. M12 内容框架（拆分建议）

```
M12 = A（token 统计）+ C（serve 最小面）+ B（Web 对话页）+ D（响应式适配）
M13 候选 = E（飞书/企微网关）+ serve 完整面（PTY/文件 API/多会话并发）+ 短命 token 鉴权
```

| 部分 | 内容 | 依赖 |
|---|---|---|
| **P0 用量统计** | SessionCostAccumulator（每轮累加+会话 summary 落 JSONL）+ /cost 升级（会话累计）+ /stats 新命令（按天/模型/会话/项目聚合，stats-cache 增量缓存）+ 定价 tiers 扩展 + 双协议 cache 口径核对 | 无（可先行） |
| **P1 serve 基座** | `ecode serve` 入口（跳过 Ink）+ node:http 路由 + Basic Auth + 最小 API（health/session CRUD/promptAsync/messages/interrupt）+ SSE /event（心跳+断线语义）+ 事件源接线（loop callbacks → 事件总线） | 无 |
| **P2 Web UI** | React 19 + Vite + Tailwind 单页（会话列表/对话流/输入框）+ SSE 订阅（coalesce+16ms 帧 flush）+ Markdown 增量投影渲染 + Static 资产由 serve 托管 | P1 |
| **P3 手机适配** | 响应式断点 + 侧栏抽屉 + 输入框细节 + PWA manifest | P2 |
| **P4 IM（建议滑出）** | 飞书长连接网关最小版（若拍板留在 M12） | P1 |

### 6.1 ECode 现状的关键约束（实施前须知）

1. **headless 与 Ink**：serve 入口必须完全不初始化 Ink（非 TTY 下 raw mode 直接崩）；cli/index.ts 分流。
2. **单进程单写者**：serve 运行期间 CLI 不得同时写同一会话 JSONL——M12 用"serve 与 TUI 互斥 + 会话级进行中标记"约定（.ecode/ 下锁文件或 running 标记），不引入文件锁库。
3. **事件总线**：TuiApp 现在直接消费 loop callbacks；serve 需要同一回调面 fan-out 到 SSE——加一层轻量 EventEmitter（TUI 与 SSE 都是订阅者），TuiApp 改造成本要在方案阶段评估（或 serve 复用 TuiApp 的装配逻辑但替换 UI 面——方案阶段定）。
4. **多会话**：TUI 是单会话模型；serve 天然多会话（每 HTTP 会话一个 loop 实例）。M5 压缩/orchestrator 实例化路径要按会话隔离（M11 子代理已验证独立实例模式，同源）。
