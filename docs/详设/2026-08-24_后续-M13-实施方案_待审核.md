## 1. 目标与非目标

**目标**：

1. 手机/Web 打开 → 本机所有有历史的项目（registered ∪ active ∪ 历史聚合）→ 新建/恢复对话 → 答审批；可输新项目路径（428 栅栏已有）
2. 同项目多对话**并行**（A 跑长任务 B 同时聊）
3. 多端同帧；审批谁先答谁得
4. 飞书远程交流：单聊驱动会话/轮末回复/**卡片按钮答审批**（长连接免公网）
5. 成本：缓存命中率/无效轮次止损/重复注入与重复读去重/压缩摘要走便宜模型/子代理超时自总结

**非目标（防翻烧饼）**：活流回填/SSE 补帧；TUI 跨进程连 serve；手机原生 App；个人微信 web 协议/wechaty（已死）；模型难度自动路由（判不准+丢缓存+弱模型瞎转三头不讨好，便宜模型靠 roles 静态指派）；双人协同编辑；**配对+中继+E2EE+per-device token 本批不做（M14）但 M13 三处预留**；会话删除/重命名（留口）；群聊 IM。

   ▼                                                   ▼
serveMulti ── mux 汇流层（HostEvent 生命周期帧 + baseline + 审批重放 + per-client 过滤钩子[预留]）

## 3. 架构批设计（W1-W4）

### 3.1 两层宿主（W1）

| | ProjectHost（registry 持有，常驻） | ConversationHost（会话级，sweep 收） |
|---|---|---|
| 生命周期 | acquire 创建不回收（两家实证） | prompt 隐式/restore ensure；闲置 sweep |
| 持有 | providerRegistry、tools（Hooked）、MCP manager、checkpoint、quality、hookRunner、logger、config getter、skills/plugin 装配 | messages 权威、runLoop 运行态、channel、ApprovalBroker、插话队列、usage（含 mcpCallCount）、editedFiles、sandbox 档、FileHistoryStore（构造定 sessionId）、rewind 线 |

- `makeDeps` 拆 `makeProjectDeps(cwd)` + `makeConversationDeps(projectDeps, sessionId)`；TuiApp/argv 保持等价形态（单 ProjectHost+单 ConversationHost），**旧用例零改动通过 = 等价性门**。
- 宿主事件翻译/afterTools/hooks 分发随 ConversationHost；mountBridges 桥挂 ProjectHost + 会话窄端口指当前 ConversationHost（D5 延续）；子代理吃 projectDeps getter 闭包，confirm/askUser 经窄端口回所属会话。

**W1 显式改造项——三个进程级全局单例收敛**（审阅 P0 串台三连）：

1. **skillRegistry/globalExtensionHooks**（`skill.ts:520`/`hooks/global.ts:12` 全局单例）——多项目 /clear 触发 `unregisterAllSkillHooks` 清掉别家。实例化进 ProjectHost，模块级降 argv 兜底。
2. **mountBridges 三桥模块级全局 setter**（`session.ts:136-153`：setSubagentBridge/setPermissionAsker/setAskUserHandler）——多会话后挂覆盖前挂。改每 ConversationHost 实例级挂桥（闭包捕获本实例；M12 四桥实例化收口）。
3. **HookRunner.getSessionId 闭包**绑死创建时 id（`runner.ts:69`）——改经会话上下文动态取，否则非首会话 hook 事件 session_id 全错。

### 3.2 协议信封与命令路由（W2）

- **MuxFrame 信封**（内层 27 事件枚举零改动）：`{project, sessionId?, ev} | HostEvent`；类型落 `src/protocol/mux.ts`。
- **HostEvent 独立联合**（与 ProtocolEvent 不交，mux 专属）：`project/added`、`project/removed`、`session/created`、`session/removed`、`session/baseline`。
- **命令信封**：`POST /api/p/<path>/cmd` body `{sessionId?, op}`，sessionId 三态：①显式→路由指定会话（TUI 等价显式）②缺省+有默认会话→默认会话 ③缺省+无默认→prompt 隐式创建并标记默认（回执带 id）。`session/create` 列保留项。过渡兼容：body 含顶层 `op` 按信封解，否则裸命令（W5 后移除）。
- `session/restore` 接线（宿主 default 现返回 NOT_IMPLEMENTED）：**ensure 语义**——活复用/死载入（restoreFrom）/并发幂等单飞（deferred 模式，M12 实测坑⑤）。
- `approval/respond` 路由靠信封 sessionId 找 ConversationHost 的 broker（requestId 只需会话内唯一，UUID 天然满足）。

### 3.3 mux 端点（W3）

- `GET /api/events.mux`：wrapper handler 把 ProtocolEvent 包装为 MuxFrame 写流（channel/handler 签名零改动）；ProjectHost 会话 Map 增删动态补订/退订；响应头带 `X-Accel-Buffering: no`；复用 M12 SSE 工程包（drain 背压/15s 心跳/token/loopback）。
- 连接三连：①`session/baseline`（活会话+项目清单）②重放各会话 pending 审批帧（按会话分组展示，与实时帧共用审批组件）③持续广播。
- 单项目 `/api/p/<path>/events` 保留为调试端点（裸帧）。

### 3.4 会话生命周期与回收（W2/W4）

- 默认会话生命周期：ProjectHost 创建不建会话；首个缺省 prompt 隐式建并标默认；被 sweep 收后标记不持久，下次缺省 prompt 重建；restore 冷会话载入后转正为默认。
- 回收：**项目基座常驻不收**；会话级 sweep——无订阅者 && brokerPending=0 && loop 空闲 && 超 `sessionIdleMinutes`（默认 120）→ dispose（内存释放，**历史/checkpoint 不动**）；运行态永不收；收后广播 `session/removed`。

### 3.5 历史与项目发现（W4）

1. MetaLine 增 `cwd`（FileHistoryStore 构造收 cwd，makeConversationDeps 传入；启动校验绝对路径）；存量无 cwd 归"未归类"，不回填。
2. `/api/projects`：registered ∪ active ∪ 历史聚合（扫 sessions 首行 meta.cwd 去重，loadAll 2048B 读法现成）。
3. `session/list` 冷热合并（活 running 态 ∪ 历史 meta），updatedAt 降序。

### 3.6 冲突防护（对齐两家务实水平）

checkpoint objects 按会话分目录物理隔离（无需 gitdir 锁；同会话内 content-addressed 去重；跨会话磁盘冗余低危挂账）；edit per-file 信号量与 git autoCommit 交织挂账观察；write 无锁 last-write-wins 社会约束（文档提示）。

## 5. 成本优化六项（B 线）

### #1 cache_control 显式打标（B5，条件：B0 探针通过）

- **堵什么**：同会话每轮全价重发历史前缀——缓存命中率是省钱最大头。
- **规则**：①每轮从投影后 messages 尾部往前找第一条有文字消息，其最后 text block 打 `cache_control:{type:'ephemeral'}` ②累计 ≥4096 字符才标 ③每轮重标 ④落点在投影合并后（`anthropic.ts:205` 合并产物上，防字节序炸缓存）⑤**仅对话请求打标**——压缩摘要/自总结等单次请求跳过（cache write 25% 溢价纯亏）；实现=请求参数 `skipCacheControl` 标志（callSummary 传 true；"构造入口分流"不可行——与主循环同走 `provider.run`）。
- **开关** `ProviderCfg.explicitCache`，B0 探针（打标/不打标各 3 轮对比 `cache_read_input_tokens` 与 400 行为）拍板默认值。
- **落点**：`src/providers/anthropic.ts` 构造请求处（协议能力封 Provider 内，OpenAI 侧天然不实现，心脏零改动）。

### #2 无效轮次检测（B2）

- **堵什么**：复读机（DeepSeek flash 曾复读 685 次）、同参工具死循环、连续空错——每轮都是真金白银。
- **loopGuard 三检测器**（宿主层，loop 零改动；阈值常量不入 config）：

| 检测 | 判定 | 动作 |
|---|---|---|
| 跨轮复读 | 本轮 assistant 前 500 字 sha256 与近 3 轮精确相同 | 工具轮 afterTools feedback ×2 → 第 3 次 abort；纯文本轮 onWarn |
| 同参工具 | PostToolUse hook（带 tool_input）name+args 连续相同 | 连 8 轮提醒 → 不改 abort |
| 连续空错 | round.tools 全 isError 非空 | 连 5 轮提醒 → 连 8 轮 abort |

- 公共约束：指纹/计数变化即清零；触发记日志（category=loop-guard）观测误伤率；abort 前 systemMsg 可读原因；feedback 带 `[loop-guard]` 前缀。
- **附带**：审批 15 分钟超时自动 reject（`approvalTimeoutMs` 默认 900000，0=不限；落点 approval.ts）——多端/IM 延迟答审批交互已互标（§9 R10）。

### #3 Skill 重复注入去重（B1）

execute 前 `ctx.session.isSkillActive?(name)`——扫**投影后** messages 找 `<skill_content name="x"` 标记；活着回一行 notice。扫投影=rewind/压缩一致性免费（消息即状态同构）。手动 `/skill` 同 execute 自动获益。无宿主缺省不去重。

### #4 重复 read 去重（B1）

execute 前 `ctx.session.readFileGuard.check(path)`——stat mtimeMs 与 Map 比对；未变回"文件自上次读取后未变化…可用 bash cat"。写后 mtime 变自然放行；**不加 force 参数**（bash cat 即逃生口）；无宿主不去重。

### #5 压缩摘要模型分流（B3，排 W1 后——装配点在拆分中移动）

- **配置**：`roles.summary: {provider, model}`（不配=会话模型，零行为变化）；启动校验 provider 名存在。
- **B3 三项变更**：①`CompactionContext.effectiveWindow` 拆 `triggerWindow`（主模型，触发阈值）/`summaryWindow`（摘要模型，批预算+归并判定）——否则按主模型 200k 切批喂 128k flash 直接超限 ②**provider/providerReq 替换**——装配链 `hook.ts:67-78` 现透传主会话笔，漏此分流完全失效 ③启动校验摘要模型窗口下限从批预算常量反算（20000+4096+8000+1500=**33,596**，取 2 倍余量 ≥64k）。
- 摘要调用天然不带 thinking（已核）；map-reduce 对小窗口免疫（批变多变小）；ECode 分支无前缀对齐机会成本（分批本重构消息），roles.summary 纯赚——量化：flash 全价（≈0.1 美元/M 量级）< 旗舰缓存读价（≈全价 10% ≈0.3 美元/M 量级）；/config 文案带此说明。

### #6 子代理超时自总结（B4）

### #7 MCP deferred——仅登记复评触发器（不实施）
