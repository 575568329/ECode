## 0. 需求还原与方案定位

### 0.1 用户诉求拆解

1. **统一时间线**：一轮内 LLM 全部产出（文本段 / 思考 / 工具调用）进**同一条按时间序的活动流**，不再按类别分槽位固定摆放；
2. **折叠语义 = 最新优先**：放得下就全按序显示；放不下时**最老的先折叠**，最新的（正在发生的）完整可见；
3. **轮末整体固化**：整条流按原序一次性进 Static 历史，顺序不跳变；
4. **两态交互**（ZCode 实证）：每个工具/思考条目有**收起（单行摘要）与展开（详情）两种形态**，TUI/Web/移动端三端同构；
5. **loading 行动态化**（用户点名）：思考中 / 执行工具时，底部活动行（loading 处）**动态显示正在思考什么、正在执行什么命令**——一行、动态、让用户知道程序还在走。

### 0.2 参照物：CC 截图 + ZCode 实测，两者布局共识

CC 截图与 ZCode 桌面端实测（§2）在消息流结构上高度一致，构成布局共识：
**文本段落（全宽 Markdown）与单行工具卡按时间序交替；每卡可展开收起；运行中条目行内带状态词；底部一行动态 loading。** 本方案以此为唯一视觉权威。

### 0.3 现状一句话

动态区是**固定槽位制**（①用户输入 → ②所有工具合并一组 → ③流式文本），工具与文本的相对位置失真；思考内容**四层全断**；轮末 commit 反而是按序的——**问题集中在动态区模型与 thinking 链路，历史区结构基本不动**。

## 1. 现状盘点（代码锚点）

### 1.1 动态区固定槽位模型（要改的主体）

- 状态：`ActiveState`（`src/tui/types.ts:26`）——`userInput` / `tools: ActiveTool[]` / `streamingText` / `streaming` 三个平行槽，无时序关系。
- 渲染：`Conversation.tsx` 动态区顺序写死——`FoldedUserInput` → `ToolGroupView`（全部工具合并一组）→ `ConfirmPrompt | GrayStreaming/AssistantMessage`。
- **时序损伤两处**：
  - **文本跨工具黏连**：`delta` 帧无条件 `streamingText += text`（`TuiApp.tsx:575`，v1.5 行号校准）。text→tool→text 三段黏成一段灰字，轮末 `pullTranscript()` 重建后才拆开——轮末瞬间视觉跳变。
  - **工具与文本相对位置失真**：工具组恒在文本上方，实际时序「说一段→查一次→再说一段」显示成「所有工具→所有文本」。

## 2. ZCode 布局学习实录（v1.1，computer-use 实测）

> 实测方法：ZCode 桌面端（Electron）AX 树全量元素 + 截帧两轮（本会话运行实况，恰好覆盖「收起态全集 + 运行态 + 底部 loading」）。展开态因控制通道对目标窗口的 raw input 不可用（元素 AX 动作列表为空、坐标帧绑定失败）未实点，其结构以入口命名与收起态推断 + ECode 既有展开体系映射，已在 §5.3 标注。

### 2.1 消息流结构（收起态全集）

文本段落与工具卡按时间序交替。工具卡**每类一种行形态**，全部单行收起：

| 类型 | 实测行形态（ZCode） | 备注 |
|---|---|---|
| 文本段 | 顶格全宽 Markdown | 与 CC 截图一致 |
| 终端 | `▢ 终端  grep -n "PromptResult" src/protocol/types.ts \| head -3; sed …` | 类型名 + 命令摘要（超宽截断） |
| 编辑 | `✎ 编辑  ⭐ TuiApp.tsx  src/tui/  +1 -1` | 文件名 + 目录 + **增删行数** |
| 写入 | `✎ 写入  …/memory/user-runs-global-dist-ecode.md  +12` | 路径 + 新增行数 |
| 查阅 | `⌕ 查阅 · 2 文件` / `⌕ 查阅 · 1 搜索, 1 文件` | **同批搜索/读取聚合计数行**（CC「查询 · 2 搜索」同款） |
| 思考 | `⊕ 思考 · 持续了几秒` | 可点击展开（button） |
| 任务输出 | `▢ 任务输出  exec_b860a42e…  取行失败` | 后台任务卡 |
| 错误态 | `▢ 终端  tail -8 …` + `执行失败` | 状态词着色 |

### 2.2 运行态与 loading 行（用户点名对应物）

- **行内运行态**：`⌕ 查阅 · 正在执行  npx vitest run 2>&1 \| grep -E "FAIL " …` —— 状态词「正在执行」+ **命令全文**（dim），跑什么一目了然；
- **底部 loading 行**：spinner + `正在运行 <命令全文>` —— 用户要的「loading 处看到在执行什么」ZCode 的实现位置；
- 轮级：`工作中 2 分 31 秒`（button，轮级耗时，点击展开该轮聚合）。

### 2.3 两态交互（展开/收起）

- **收起 = 上表单行**，是默认与历史态；
- **展开入口三处**：每工具行「展开工具详情」按钮（实测 AX 树大量 `button 展开工具详情`）；轮级「工作中 N 秒」按钮（整轮聚合展开）；变更卡「展开已更改文件」；
- 展开态内容（推断 + ECode 映射）：完整命令/参数 + 输出全文（终端）/diff（编辑）——与 ECode 的 Ctrl+T 全屏查看器（执行时间线 + 来源列表）**语义同构**（v1.4 修正：ECode 展开基建=面板不是内联，F-50 已废），TUI 侧缺的是「行形态统一 + 时间线化」，不是展开机制。

### 2.4 其他可借鉴形态

- **变更汇总卡**：`7 个文件已更改 +107 -34` + `撤销` + 展开文件列表——轮末变更聚合卡（ECode 现状无，P2 挂账）；
- 用户消息右侧气泡、右栏 Git 工具面板——超出本方案范围，不采。

## 3. 数据模型：TurnTimeline（轮内时间线）

### 3.1 ActiveState 改造（`src/tui/types.ts`）

```ts
/** 轮内时间线条目：按事件到达序 append，永不重排 */
export type TimelineEntry =
  | { kind: 'text'; id: string; text: string; live: boolean }        // live=流式中（灰字）；false=封口（Markdown）
  | { kind: 'thinking'; id: string; startedAt: number; endedAt?: number; text: string }
  | { kind: 'tool'; id: string; tool: ActiveTool }                    // ActiveTool 复用；+digest（D9）

export interface ActiveState {
  userInput: string
  timeline: TimelineEntry[]          // ← 替代 tools + streamingText；类型归属（v1.7 管线审阅 P1-2）：TimelineEntry/归约所需 ActiveTool 投影随 timelineReducer 落 src/protocol/（web 可 import 不拖 Ink），tui/types.ts re-export
  confirm: ConfirmState | null
  streaming: boolean
  // 注：expandedTools 不保留——F-50 已废内联展开（时间线恒收起，全文走 Ctrl+T 面板 §5.4），
  // 新模型无展开态字段
}
```

一次切换不留过渡字段（消费方全在仓内）。

### 3.2 事件 → 时间线归约（纯函数，重点单测）

`timelineReducer(state, event)` 收口全部分段逻辑（**实现锚 v1.7 渲染审阅 P1-2：append-only + 按 id 原位换新对象、未动条目对象恒等**——这是条目级 React.memo 生效的前提；src/tui 现状零 memo，时间线 60+ 条目每 delta 全量重渲 + D15 又引入每帧全量 diff wrap【现状动态区 diff 恒收起只在 Static 渲一次】——四件套随 B4 实做：①reducer 恒等 ②条目级 memo ③foldLines 结果缓存【cachedWrap 同款键：内容长+width+cap，`OutputViewer.tsx:49-60` 先例】④**16ms 合帧从 §9 挂账提为实做**（与 web W-T4 rAF 合帧对等，TUI 侧不能只挂账一边））：

| 到达事件 | 归约 |
|---|---|
| `delta`(text) | 末项是 live text 段 → 追加；否则 **append 新 text 段**（live=true） |
| `thinking` 帧 | 按 `blockIndex` 匹配未闭合 thinking 段 → 追加；无匹配 append 新段（startedAt=now；末项匹配仅作 blockIndex 缺失的兜底分支——审阅 TUI P1-2） |
| `item/started`（真实 id，§4） | 所有 live 段封口（**text 分段唯一封口信号**）；append tool 条目（running，真实 id） |
| `item/executing`（§4 新帧） | 按 itemId 回填 tool.digest——工具行转入「正在执行 <digest>」态 |
| `item/completed` | 按 id 回填 tool.use/result/status（itemId 同源修复后闭环；旧宿主回退按 name+running——A/B 同名并行 B 先完成仍可能配错，现状既有降级，接受并注明） |
| `thinking/ended` 帧 | 按 blockIndex 匹配补 endedAt（durMs 随帧） |
| `turn/completed` / `error` | 全部 live 段封口（error 轮无 completed 帧的兜底同现状语义） |

**分段正确性**：动态区分段靠「非 text 事件间插」，transcript 分段靠 content blocks——两者同源，轮末重建结果天然一致，跳变根治。

### 3.3 生命周期

- `turn/started`：timeline 清空——**双清空点权威**（审阅 TUI P1-1）：TuiApp 新增 turn/started case 用**函数式 setState 只重置 timeline**（不动 userInput/confirm/streaming——doSubmit `TuiApp.tsx:860` 的整对象重置保留为发送失败回执窗口兜底，两处幂等；prompt 发送失败路径无 turn/started，doSubmit 是该路径唯一清空点）。
- 轮内永不重排：条目只 append 与原位回填（按 id）。
- 轮末：`turn/completed` → `pullTranscript()` → `messagesToCommitted()` 全量重建 committed（权威源不变，V4 拍板与 rewind/多端一致性都依赖 transcript 重建）→ 动态区清零。

#### 5.5.4 单调性论证（防抖动，v1.5 按审阅 TUI P1-4 改写准确口径）

抖动的定义：**同一稳态输入下折叠线反复移动**。三个变化均不构成抖动：
- 新条目到达/条目 done（1→2 行）：实占单调增（计价统一在 timelineBudget 内、宽度基准统一 **`WIDTH.body(columns)`**——MessageRow 栅格内容列宽；v1.7 管线审阅 P1-5：现状 CappedAssistantMessage（`Conversation.tsx:237` 用 columns 计价而渲染宽是 body，判断系统性低估）与 FoldedUserInput（:46 columns 全宽）两处偏差随 B4 顺手修正）→ 折叠线只下移；
- 封口（live→终态）：单向一次性事件；
- resize（变大/变小）：用户主动行为，折叠线双向移动可接受（变小则更多条目进折叠区是正确行为，与 §5.5.1 转换行口径对齐）。

#### 5.5.5 展开交互不复存在（v1.4：原缺口 A/B 随 F-50 基线修正消失）

v1.2 的缺口 A（展开块被折叠线吞）/B（展开预算降级链）建立在「Ctrl+E 内联展开」上——v1.4 核码发现 F-50 已废除该交互（`TuiApp.tsx:1227`），时间线内恒收起后两个问题不存在；展开需求统一由 Ctrl+T 面板承载（§5.4.2），面板自身虚拟窗口无超限。原 D12（钉住三级链）/D13（Ctrl+E 作用域）作废。

#### 5.5.6 live thinking 的折叠计价（v1.1 缺口 C 补）

live thinking 段**存在于 timeline**（loading 行取 tail 摘要的数据源）但**渲染层跳过、不占行**；`thinking/ended` 后转终态行（1 行）才参与折叠计价。对齐 ZCode 实测：进行中思考只见底部 loading，结束才在时间线出现「思考 · 持续了 N 秒」。好处：折叠单价表恒定（thinking 恒 1 行），无「进行中占位行→终态行」的中间态。

## 6. 固化与历史一致性

### 6.1 文本/工具：零改动

### 6.2 思考固化（D4，推荐 B-lite）

| 案 | 内容 | 后果 |
|---|---|---|
