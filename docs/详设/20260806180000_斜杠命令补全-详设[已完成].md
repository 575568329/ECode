picker 与 InputBar **并存**（InputBar 还在打字），若 picker 用独立 `useInput` 会和 InputBar 抢键（ink 按挂载序分发，行为不确定）。

## 三、接口设计

### 3.1 InputBar 内部状态扩展
```ts
// 新增：当前选中候选索引。null = 输入态（未选中或无候选）；数字 = 选择态
const [pickerIndex, setPickerIndex] = useState<number | null>(null);
```
候选计算（派生，不存状态）：
```ts
const query = text.startsWith('/') && !text.includes(' ') ? text.slice(1).toLowerCase() : null;
const candidates = query === null ? [] : SLASH_COMMANDS.filter(c => c.name.startsWith(query));
const pickerVisible = candidates.length > 0;
```
- `/` 开头 + **无空格** → 过滤候选；有空格（带参数）→ 不显示（对齐 CC `hasCommandArgs`）。
- 无匹配（如 `/foo`）→ 候选空 → 不显示 picker，text 保留，可继续当普通文本送出（对齐 CC「未匹配仍可送出」）。

### 3.2 useInput 分支（单一 useInput，按 `pickerVisible`/`pickerIndex` 分流）
> 与 CC 的差异（用户决策）：CC 是「suggestions 显示时 Enter 不提交，先 Tab 补全」（`PromptInput.tsx` `onSubmit` early return 防误）。
> 用户要**更短路径**：既然能 ↑↓ 选，选中即 Enter 执行，去掉 Tab 中间补全步——对齐 CLAUDE.md §4.6「操作路径最短化」。
> 配套取消键 = **Esc**（对齐 CC，见决策点①；Esc 与「中断流」状态互斥，不冲突）。

**picker 显示时**（`pickerVisible`）：
- ↑/↓ → 移动 `pickerIndex`（循环；长列表触发滚动窗口，见 3.3）——历史 ↑↓ 让位
- Enter → **直接执行选中命令**（`onSubmit('/' + candidates[pickerIndex].name)`），picker 关闭。默认选中第一项，省去 Tab 补全
- Esc → **关闭 picker**（text 保留，回纯输入态，不执行命令）——对齐 CC「关 picker 归 Esc」
- 普通字符 → append 到 text（边输边过滤，继续打可输带参命令如 `/model xxx`；输入空格 picker 自动消失）

**picker 未显示时**（无 `/` 前缀 / 已带参 / 无匹配）：
- 现有逻辑：↑/↓ 历史、Enter 提交、backspace、字符

> **决策点①（已定稿）**：**去 Tab——↑↓ 选中即 Enter 直接执行选中命令；取消键=Esc（对齐 CC）**。
> 与 CC（Tab 补全 + Enter 不提交）相反，走「最短路径」（CLAUDE.md §4.6）。
> 流程：`/he` → picker 选中 help → Enter → 执行。
> 带参命令：输到 `/model `（空格）picker 自动消失 → 续输参数 → Enter 提交（走未显示分支，不误触执行）。
>
> **取消/关闭键 = Esc（已定稿，对齐 CC）**：
> - CC 研究结论（task #9）：CC 的 Ctrl+C **从不关弹窗**——关 picker 永远归 Esc，Ctrl+C 只管「中断运行 + 双击退出」。故 picker 取消键 = **Esc**（与 CC 一致），不用 Ctrl+C（避免 Ctrl+C 既关 picker 又双击退出的语义冲突）。
> - **Esc 不冲突的解释**：ECode picker 只在「输入栏可输入」(=idle) 时出现；running 时 InputBar `disabled`、打不了字 → picker 不会出现。故「Esc 关 picker」(idle) 与「Esc 中断运行中流」(running) **状态互斥**，不冲突——等价 CC 的 overlay 让位，只是 ECode 状态机天然互斥。
> - **实施前置（已查证）**：ECode「Esc 中断流」handler 在 `app.tsx:66`（`key.escape && isRunning && !pendingPermission`）——**只在 running 时触发**。picker 只在 idle（`!isRunning`）出现，此时 app 层 Esc 短路为 no-op → InputBar 在 picker 显示分支加 Esc 关 picker，**与 app 层零冲突，A 完全独立于方向 E**。InputBar 现不处理 escape（grep 确认无命中），A 新增即可。
> - 横向分工（方向 E，后续）：Esc=关面板(picker/展开视图)+中断流(互斥)；Ctrl+C=中断流(running)+双击退出(补 800ms 提示 / gracefulShutdown / 中断保留输出 + `[Request interrupted by user]` 标记)。A 只做「picker 显示时 Esc 关 picker」子集，不被方向 E 阻塞。

### 3.3 UI 设计（参考 CC `PromptInputFooterSuggestions.tsx`，落到 ECode token）

**位置**：InputBar **上方**浮层（ECode 布局里 InputBar 上方有空间，下方紧接 StatusBar）。CC 因自身布局放 prompt 下方 footer——位置不照搬，照搬视觉与对齐。

**单行多列对齐**（每条候选一行，`wrap="truncate"` 不换行）：

| 列 | 内容 | 宽度 |
|----|------|------|
| 选中指示 | `❯`（SYMBOLS.user）/ 空格 | 2（固定，对齐 PermissionDialog） |
| 命令名 | `/name` | pad 到固定宽，最多 `floor(columns×0.4)`（借 CC，保 description 空间） |
| 描述 | description | 剩余宽度，truncate |

**配色**（ECode token）：
- 选中行：命令名 `T.accent`（#89B4FA 蓝，醒目）；描述 `T.suggestion`
- 未选中行：整体 dim（`<Text dimColor>`）——借 CC「未选中 dim」
- 底部提示行：`T.muted`

**容量与滚动**（借 CC `OVERLAY_MAX_ITEMS`）：
- 最多显示 **5** 条；ECode 8 条命令，输 `/` 全显超 5 → 滚动窗口
- 滚动：`startIndex = clamp(pickerIndex - floor(5/2), 0, len-5)`，选中项保持视窗中部

**wireframe**（输 `/`，8 条显前 5，help 选中）：
```
❯ /help       显示可用命令          ← accent 蓝
  /clear      清空当前对话          ← dim 灰
  /cost       显示 token 用量
  /model      切换模型
  /compact    手动压缩上下文
  ↑↓ 选择 · enter 执行 · esc 取消       ← muted
❯ /_
```
↓ 两次（选中 cost，窗口下滚）：
```
  /clear      清空当前对话
❯ /cost       显示 token 用量          ← accent 蓝
  /model      切换模型
  /compact    手动压缩上下文
  /resume     恢复历史会话
  ↑↓ 选择 · tab 补全 · esc 取消
❯ /_
```
- **自画**（map + 选中高亮），**不用 ink `<SelectInput>`**（它自带 `useInput` 会抢键，见 §二核心约束）。
- 渲染层抽 `<PickerList>` 展示组件（A/C 共用，见 §四）。

## 四、组件复用（与 C 共用）

A（命令 picker，内嵌 InputBar）与 C（会话 picker，独立 Modal）**交互模式不同**：
- A：overlay，边输边过滤，↑↓ 选，补全到输入栏
- C：Modal 替换 InputBar，↑↓ 选，Enter 载入会话

→ 抽 **`<PickerList items selectedIndex hint/>` 纯展示组件**（渲染候选行 + 选中高亮 + 提示行）；A 和 C 各自的交互逻辑（useInput 分支）独立。复用渲染、不强行统一交互。

| 用例 | 操作 | 断言 |
|------|------|------|
| 输 `/` 显示候选 | type `/` | frame 含 `/help` `/clear` `/cost` … |
| 前缀过滤 | type `/c` | 只剩 `/clear` `/cost` `/compact` |
| 无匹配不显示 | type `/foo` | 无候选列表（text 保留） |

## 八、风险

- **双 useInput 抢键**：已规避（picker 不用独立 useInput，靠 InputBar 单 useInput 分支）。L2「↓ 移动选中」用例守住。
- **↑↓ 语义冲突**：`/` 前缀时 ↑↓ 给 picker、历史 ↑↓ 让位。用户预期可能不一致 → L2 用例 + 冒烟验证。
- **Esc 分工（已查证，无冲突）**：取消键=Esc。「Esc 中断流」在 `app.tsx:66`（仅 `isRunning && !pendingPermission` 触发）；picker 只在 idle(`!isRunning`) 出现 → app 层 Esc 短路 no-op，InputBar 加 Esc 关 picker 零冲突。**A 完全独立于方向 E**。
- **Enter 误执行**：picker 显示时 Enter 直接执行选中项，手滑可能误触发（如 `/clear`）；Esc 是后悔药（关 picker 不执行）→ 冒烟验证手感。
- **Static 无关**：picker 在动态区（InputBar），不碰 `<Static>`，无 B 方向的约束。
