### 2.2 数据流：三支点如何接入 agent loop

```
                        ┌─ Skills: catalog（name+desc）→ system prompt（LLM 知道有哪些菜谱）
                        │   触发（/skill 手动 或 LLM 自动匹配）→ 读正文按需注入 → 照菜谱干
                        │   【阶段2】干完 → Stop hook → LLM 归纳 → proposal 队列 → /accept 转正
                        │
用户 prompt ──→ runAgentStream ──→ 每轮迭代前：路由层决定 provider+model（注入 opts）
                        │              │  └ 路由触发点：子代理model字段 / 压缩摘要cheap / Skill model / 全局
                        │              ▼
                        │      消费 LLM 流 → yield AgentEvent
                        │
                        │   ┌─ 多渠道：AgentEvent 流 → WS 推送 → 渠道前端（TUI/Web/IM）渲染
                        │   │   每渠道连接 ↔ 独立 sessionId（复用 session.ts）
                        │   ▼
                   核心循环轻改（仅压缩触发点侵入 compressOpts；全局/Skill/子代理三触发点循环外注入）
```

## 三、核心设计决策（源自功能架构，已拍板）

> 这些决策在 [`功能架构设计`](../功能方案/功能架构设计[进行中].md) 支点 13/22/23 已定，本节列结论，理由见 [技术选型](./M6-技术选型与理由[待实现].md)。

### Skills（支点 13）

1. **SKILL.md + frontmatter 三家标准**：格式抄 CC/openclaw/opencode，零成本跨工具兼容。
2. **懒加载注入**：catalog（name+description）进 system prompt，触发才读正文，防 prompt 爆炸。
3. **两种来源**：手写先行（阶段1），自动生成后置（阶段2，依赖 M5 Hooks）。
4. **手动 + 自动匹配双触发**：`/skill` 命令 + LLM 据 description 自动用。
5. **自动生成 = LLM 归纳 + proposal 审批**：不直接落盘，`/accept` 才转正（OpenClaw 正则假自动是反面教训）。

### 模型路由（支点 22）

6. **规则映射，非 LLM 决策**：路由本身要轻，不能花掉省下的钱。
7. **四触发点，三处调用前注入 + 压缩轻微侵入**：全局 / Skill `model` / 子代理 `model` 三处在构造 opts 时填入，**循环内部零改动**；压缩触发点需**轻微侵入 `compressOpts` 构造**（`agent.ts:298-310`，把 `model = resolvedModel` 换成 `resolveModelForScenario('compress')`），侵入级别同 M5 阶段0 改 `tools` 注入。详见 [方案解析 §2.2](./M6-方案解析[待实现].md)。
8. **复用 Provider 层**：路由 = alias → 模型 ID 映射，不新建抽象。

### 多渠道接入（支点 23）

9. **前后端分离**：终端 REPL 只是「对话前端」之一，分离后前端可任意。
10. **服务化是公共前提（D2 推荐 A 先行）**：本地 HTTP+WS + 会话路由 + 鉴权；Web/IM 是渠道适配器。
11. **复用 runAgentStream + AgentEvent**：渠道侧消费事件流，核心不改。
12. **安全硬网**：默认 `127.0.0.1` + token 鉴权 + 凭证独立（呼应 §9.2）。

### 阶段 1：Skills 手写 —— SKILL.md + 懒加载 + /skill + 自动匹配（支点13 阶段1）

**🔴 前置依赖（支点14）**：`/skill`、`/accept`、`/reject`、`/proposals`、`/channels` 等斜杠命令的**注册**依赖**支点14 注册式重构**——`slash-commands.ts` 当前 `SlashCommandDef` 只有 name+description、无 execute、硬编码 8 条，无法挂回调。「注册式重构」是 M5 阶段3 前置（见 [`M5-实施方案`](./M5-实施方案[待实现].md) 阶段3）。**决策点 D6**：该重构归 M5 还是 M6 自带，待用户定（本期默认 M5 阶段3 前置，M6 依赖）。

**目标**：用户能写 SKILL.md，agent 启动看到 catalog，手动 `/skill` 或 LLM 自动匹配触发，按菜谱干。

**接口设计**：

```ts
// src/skills/types.ts
export interface SkillDefinition {
  name: string;              // 文件名 stem / frontmatter name
  description: string;       // frontmatter：何时用这个菜谱（LLM 匹配依据 + catalog 展示）
  allowedTools?: string[];   // frontmatter：收紧工具子集（呼应子代理 tools:）
  model?: ModelAlias;        // frontmatter：指定模型（路由细粒度入口，22-T2）
  body: string;              // SKILL.md 正文（人设/步骤，懒加载：触发才读）
  source: 'user' | 'project' | 'system';
  filePath: string;
}

// src/skills/loader.ts —— glob {skills}/**/SKILL.md 三层作用域
export function loadSkills(): SkillDefinition[];  // 走 resolveDataDir；零 manifest（opencode glob）

// src/skills/catalog.ts —— 拼 catalog 进 system prompt（懒加载：只 name+description）
export function buildSkillsCatalog(skills: SkillDefinition[]): string;
// 输出形如：
// ## 可用技能（用 /skill <name> 调用，或我会自动匹配）
// - **deploy**：标准化部署流程。工具：bash+read。
// - **code-review**：代码审查 checklist。工具：只读。

// src/skills/matcher.ts —— 自动匹配（LLM 决策，走 system prompt catalog）+ 手动路由
export function getSkillBody(name: string, skills: SkillDefinition[]): string | null;  // 手动 /skill 触发读正文
// 自动匹配 = LLM 看到 catalog 后主动调（无需专门工具，LLM 在回复中说明用了哪个 skill）
```

**前端 UI 交互（TUI）**：

| 交互 | 实现 | 复用 |
|------|------|------|
| `/skill` 选择器 | 输入 `/skill ` 触发 picker，列出所有 skill（name+description） | 复用 `picker-list.tsx` + 斜杠补全（支点14） |
| catalog 注入 | 无 UI（进 system prompt，LLM 可见） | — |
| Skill 触发标记 | status-bar 显示当前激活的 skill 名（如 `🎯 deploy`） | 复用 `status-bar.tsx` 加字段 |
| 自动匹配提示 | LLM 回复中说明「使用了 xxx skill」（prompt 引导，非专门 UI） | — |

**接线**：
- `loadSkills()` 启动调一次（走 resolveDataDir，三层作用域合并）。
- `buildSkillsCatalog()` 拼进 `buildSystemPrompt()`（`src/system-prompt.ts`，与 CLAUDE.md / agents catalog 并列）。
- `/skill <name>` 命令注册进斜杠命令中心（支点14），执行 = 读 body 注入对话（交 LLM 跑）。

**TDD 步骤**：

- [ ] `catalog.test.ts`：catalog 拼装（只 name+description，不含正文 → 防 prompt 爆炸）
- [ ] `matcher.test.ts`：手动 getSkillBody 命中/未命中；自动匹配（mock LLM 据 catalog 决策）
- [ ] 集成：无 `.ecode/skills/` 时降级（catalog 为空，不崩）

**验收**：
- ✅ 放一个 SKILL.md → catalog 出现 → `/skill` 能选 → 正文注入 → LLM 照菜谱干

### 阶段 2：Skills 自动生成 —— Stop hook 归纳 + proposal 审批（支点13 阶段2，依赖 M5 Hooks）

**目标**：agent 干完活，Stop hook 触发 LLM 归纳「这次怎么干的」→ 生成 SKILL.md 提案 → 进审批队列 → 用户 `/accept` 转正。

**🔴 硬依赖**：本阶段依赖 M5 Hooks 的 **Stop 事件**（[`M5-实施方案`](./M5-实施方案[待实现].md) 阶段2）。M5 未实施则本阶段阻塞。

**接口设计**：

```ts
// src/skills/generator.ts —— Stop hook 回调：LLM 归纳 → 提案
export async function onStopGenerateSkill(payload: StopHookPayload): Promise<HookResult>;
//  - LLM 归纳本次对话的成功流程（非正则，13-T5）
//  - 产出 SKILL.md 提案（frontmatter + body 草稿）
//  - 写入 proposal 队列（resolveDataDir/skills/proposals/）

// src/skills/security-scan.ts —— 安全扫描（功能架构 §支点13 既定环节，13-T5，不可删）
export interface ScanReport { passed: boolean; risks: string[]; }  // risks: 危险模式命中清单
export function scanProposal(proposal: SkillProposal): ScanReport;
//  - 自动扫危险模式（rm -rf / / 密钥 / 外发 URL 等，本期默认，决策点 D7）
//  - 命中 → 标记，accept 时拦截强制人工二次确认；正文质量仍需人工 review（自动扫兜底，人工把关）

// src/skills/proposal.ts —— proposal 队列 + /accept /reject
export function listProposals(): SkillProposal[];
export function acceptProposal(id: string): void;   // 转正：移到 skills/ 目录，下次 loadSkills 可见（accept 前跑 scanProposal，命中危险模式则拦截强制人工 review）
```

**接线**：

### 阶段 3：模型路由 —— 规则映射 + 三触发点 + 可观测（支点22，依赖 M5 子代理）

**目标**：不同场景派不同模型，省钱省力；status-bar 可见当前模型与路由来源。

**🔴 硬依赖**：子代理 `model` 字段触发点依赖 M5 子代理（[`M5-实施方案`](./M5-实施方案[待实现].md) 阶段1）。M5 未实施则子代理触发点阻塞，但压缩/全局触发点可独立先做。

**接口设计**：

```ts
// src/router/rules.ts —— 场景规则映射
export function resolveModelForScenario(
  scenario: 'subagent' | 'compress' | 'skill' | 'global',
  context?: { agentModel?: string; skillModel?: ModelAlias },
): { provider: string; model: string };
//  - 优先级：显式（agent/skill model 字段）> 场景规则 > global defaultModel
//  - 读 config.json routing.rules + routing.aliases

// 接线点（基于 src/agent.ts:127/135 现状 provider/model 注入，无需 M5 阶段0）：
// ① 全局：index.ts 选模型时调 resolveModelForScenario('global') → opts.provider/model（循环外）
// ② 压缩：轻微侵入 agent.ts:298-310 的 compressOpts 构造，model 从 resolvedModel 改为 resolveModelForScenario('compress')（同 M5 阶段0 改 tools 级别）
// ③ 子代理：M5 createTaskTool 用 agent.model（frontmatter）→ resolveAlias（依赖 M5 子代理，此触发点阻塞于 M5）
// ④ Skill：阶段1 skill.model → resolveAlias（循环外注入）
```

**config.json 扩展**：


### 阶段 4：多渠道服务化 —— 本地 HTTP+WS + 会话路由 + 鉴权（支点23，D2 推荐 A）

**目标**：ECode 起本地 HTTP+WS 服务，把对话能力暴露成 API；外部（脚本/Web/IM 适配器）能连上来对话。**不建 Web UI**（Web 留阶段5 条件性）。

**接口设计**：

```ts
// src/channels/server.ts —— 本地 HTTP+WS 服务
export function startChannelServer(opts: {
  port: number;
  host?: '127.0.0.1';       // 默认仅本地，硬安全网（23-T7）
  authToken: string;         // 连接鉴权 token
}): { close(): Promise<void> };
//  - 框架：hono 或 原生 http（23-T2，待 D 决策）
//  - WS 端点 /ws（对话流）+ HTTP 端点（会话管理：list/resume）

// src/channels/ws-stream.ts —— AgentEvent → WS 推送
//  - 客户端发 { sessionId?, prompt, authToken } → 服务端 runAgentStream → for await event → ws.send(event)
//  - 透传 AgentEvent（text_delta/tool_call_start/tool_result/usage/completed），客户端按类型渲染（与 agent-events.ts 实际类型一致，无 tool_call）

// src/channels/session-router.ts —— 连接 ↔ sessionId 映射（自建运行时映射 + 锁，session.ts 无状态）
export function getOrCreateSession(connectionId: string): string;  // 维护 connectionId→sessionId Map
//  - 持久化复用 session.ts saveSession/loadSession/listSessions（纯函数，无 resume）；续接靠 agent.ts ResumeContext
//  - 每渠道连接独立 session（23-T4），多渠道不串话
//  - 🔴 并发锁：session.ts 无运行时 session 表/锁，session-router 须自建「同 session 串行排队」锁（绝不两个 runAgentStream 同 session 并发）

// src/channels/auth.ts —— token 鉴权
export function verifyToken(token: string): boolean;
//  - 连接时校验 authToken；失败拒连
```

**协议（WS 消息）**：

```jsonc
// 客户端 → 服务端
{ "type": "message", "sessionId": "abc", "prompt": "帮我看看 src/", "authToken": "xxx" }

// 服务端 → 客户端（透传 AgentEvent）
{ "type": "text_delta", "text": "..." }
{ "type": "tool_call_start", "id": "...", "name": "read_file", "input": {...} }
{ "type": "usage", "input": 123, "output": 456 }
{ "type": "completed", "sessionId": "abc" }
```

**前端 UI 交互（TUI）**：
- **阶段4 TUI 不变**：终端 REPL 仍是主入口，服务化是「额外开一个口子」给外部用。
- status-bar 可选显示「🌐 渠道服务 :3107（1 连接）」让用户知道服务在跑。
- 新增 `/channels` 命令：查看当前连接的渠道 + session（只读，复用 picker-list）。

**安全接线**：
- 默认 `host: '127.0.0.1'`（不暴露公网，23-T7）。
- `authToken` 启动生成 + 写入 `resolveDataDir/channels/token`（用户可改，gitignore）。
- 服务开关：config `channels.enabled`（默认关，opt-in）。

**TDD 步骤**：
- [ ] `server.test.ts`：起服务 + WS 连接 + 鉴权（token 错拒连）+ 127.0.0.1 绑定
- [ ] `ws-stream.test.ts`：发 prompt → runAgentStream（mock）→ AgentEvent 透传
- [ ] `session-router.test.ts`：多连接独立 session；复用 session.ts saveSession/loadSession；同 session 并发请求排队（锁）；续接走 ResumeContext
- [ ] 集成：两个 WS 连接并发对话不串话

**验收**：
- ✅ 起服务 → WS 连接（带 token）→ 发 prompt → 收 AgentEvent 流
- ✅ token 错拒连；非本机连不上（127.0.0.1）
- ✅ 多连接独立 session 不串话
- ✅ **同 session 并发请求排队**（绝不两个 runAgentStream 同 session 并发，session-router 锁验证）
- ✅ 服务默认关（config opt-in）

## 五、前端 UI 交互设计汇总（贯穿三支点）

> 用户特别强调「除了后端架构还要考虑前端 UI 交互」。本节汇总三支点的 TUI 交互 + 条件性 Web。

### 5.1 TUI（Ink，所有支点必做）—— 复用优先，不新建

| 支点 | 交互 | 组件 | 新建/复用 |
|------|------|------|----------|
| Skills | `/skill` 选择器 | skill-picker | 复用 `picker-list` |
| Skills | proposal 审批弹窗 | proposal-dialog | 复用 `permission-dialog` 模式（D4） |
| Skills | `/accept` `/reject` `/proposals` | 斜杠命令 | 支点14 命令中心 |
| Skills | 当前 skill 标记 | status-bar | 复用，加字段 |
| 路由 | 当前模型 + 路由来源 | status-bar | 复用，加来源标签 |
| 路由 | `/model` 手动切换 | model-picker | 复用（支点5 缺口） |
| 多渠道 | `/channels` 查看连接 | picker-list | 复用 |
| 多渠道 | 服务状态 | status-bar | 复用，加「🌐 渠道」 |

**原则**：TUI 侧**零新增重型组件**，能用 picker-list / permission-dialog / status-bar 复用的全部复用（§1.7）。

### 5.2 Web（仅当 D2 = B）—— 独立前端工程

若做 Web，`src/web/` 独立工程，CLAUDE.md §4.2 栈：
- **对话窗口**：消费 `text_delta` 流式渲染（markdown，移植 TUI `markdown.tsx` 逻辑到 Web）。
- **输入栏**：发 prompt 到 WS；多行 / 斜杠命令 / @file 与 TUI 对齐。
- **工具折叠**：消费 `tool_call_start`/`tool_result`，折叠展示（移植 TUI FOLD_STRATEGIES）。
- **审批弹窗**：权限 / proposal 审批（Web 版 permission-dialog）。
- **状态栏**：模型 / 成本 / Ctx% / 渠道连接数。
- **Zustand store**：chatStore（消息流）/ uiStore（弹窗/picker），与 TUI reducer 同源 AgentEvent。

**关键**：Web 与 TUI **共享 `AgentEvent` 类型 + runAgentStream**，前端只是渲染渠道（F-T3）。TUI 的渲染逻辑（markdown 解析、折叠策略）尽量抽成纯函数供 Web 复用。

### 5.3 IM（仅当 D2 = C）—— 适配器

IM 无富 UI：AgentEvent 折叠成纯文本回复（流式 → completed 一次性 / 分段）。审批类交互 IM 难承载（建议 IM 渠道走 bypass 或预批准模式）。
