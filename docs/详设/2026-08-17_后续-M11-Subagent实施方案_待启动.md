# ECode 后续 M11 实施方案：Subagent（并发子代理）

> 日期：2026-08-17 · 状态：**设计稿 v1（待启动；调研定型八项 + 本文定稿剩余六项）**
> 主题一句话：LLM 能把独立子任务**并发**委派给隔离的子代理跑完拿结论——task 是普通工具，心脏零改动。
> 来源：观察区 subagent 项（M7 §H2）经三轮用户拍板（并发直上/日志隔离/禁 ask_user）+ 两手源码调研（CC/opencode/deepseek-harness）。

---

## 0. 目标与验收

**目标**：主 LLM 可在单轮里发起多个并发子代理（各自独立上下文跑完返回结论）；子代理改文件有快照、有确认门、进 git 提交集；日志可按 agentId 切轨迹；运行时可见进度且不破活动区高度预算。

**验收**：
- **task 工具**：`task(description, prompt)` 注册进 ToolRegistry；**readonly:true（并行池）**——单消息多 task_use 即并发，无硬上限
- **隔离**：子代理全新 messages（prompt 为首条 user）；**禁配两张：task（递归一层封顶）+ ask_user**（交互权归主循环——疑问写进返回结果，由主 agent 决定是否代问用户）；write/edit/bash/MCP/web_fetch/skill 全给
- **history**：子代理消息**不进主会话 JSONL**（NoopHistoryStore + transcript 独立 `~/.ecode/agents/<id>.jsonl`，Static 回看数据源）
- **并发安全**：子代理内副作用工具仍走 ConfirmPrompt（单槽排队）；checkpoint/onBeforeWrite 照挂（改前必拍）；工具 prompt 教学"并行任务不碰相同文件"
- **日志**：LogEntry 加可选 `agentId`，子代理包装 logger 注入（同文件混流，grep 切轨迹）；iterNum=各自循环轮数
- **UI**：动态区每运行中子代理恒 1 行（description + 最近工具活动）；超高度预算压缩为合计行；结束后随本轮 commit 进 Static（全量 transcript 展开键位 Ctrl+O 体系内）
- **顺带修**：stop 谎报防御（'end' 但有 tool_use 也继续喂结果——opencode 实证 provider 会谎报）

**不做**（后置）：子代理运行中插话/wake（harness inbox 形态——"跑完即返"已定）、外部 CLI 子代理（kind:'external' 接口位预留不做）、后台 run_in_background（M10 P3 之后再合）、用户自定义 agent 定义文件（.ecode/agents/——先内置两种）、plugin `agents` 组件与 SubagentStart/Stop hook（观察区原位）。

## 1. 核心形态：task 工具内嵌 runLoop 新调用

```
父：TuiApp.submit ──► runLoop(messagesRef.current, input, optsA)      ← 主循环
                            │ LLM 单消息发 N 个 task_use
                            ▼ readonly 并行池 Promise.all
子×N：task.execute ──► runLoop([], prompt, optsBᵢ) ──► 取最后 assistant 文本
                            │                        作 tool_result 回父循环
                            ▼
                     父循环下轮看到 N 个结果继续
```

**optsB 构造**（子代理的全部特化，工厂函数 `makeSubagentOpts(parentOpts, agentId)`）：

| 项 | 来源 | 说明 |
|---|---|---|
| messages | `[]` | prompt 作首条 user（loop 的 userInput 参数即 prompt） |
| provider/providerReq | 传引用 | 同模型同配置 |
| tools | **裁剪版 Registry** | 新建 ToolRegistryImpl，register 排除 task + ask_user |
| history | NoopHistoryStore | 不碰主会话；transcript 由 callbacks 写 `~/.ecode/agents/<agentId>.jsonl` |
| system | 子代理骨架 system | 见 §2 |
| callbacks.onText/onToolStart/onToolResult | 喂进度缓冲 | 尾部滚动窗数据源 + transcript 落盘；**绝不 setActive** |
| callbacks.onUsage | 转发主 onUsage | 成本归并 StatusBar/`/cost` 零改动 |
| confirm | **同一 confirm 通道** | 父 optsA 的 confirm 引用直接传（单槽排队，用户逐个放行） |
| signal | 父 signal | Ctrl+C 连子代理一起停 |
| toolCtx | 新构造 | cwd/signal 同父；onBeforeWrite 照挂（checkpoint 快照 + editedFilesRef 归主——**注意：子代理改的文件要进主循环 autoCommit 集**，onBeforeWrite 回调直接用父的） |
| afterTools | 照挂 | quality 回喂进子代理自己的 messages（EDIT_TOOLS 按工具名判定，与循环无关） |
| logger | 包装 logger | emit 注入 agentId |
| maxIterations | 钳 min(父值, 25) | 防跑飞（CC 无默认的风险；25=父默认 50 的一半，够调研型任务） |

**递归封顶**在裁剪 Registry 实现（不注入 task 即物理不可能递归——CC `filterToolsForAgent` 同款，比深度计数硬）。

**返回契约**：最后一条 assistant 文本（无文本时兜底"（子代理无文本输出，查 transcript: <路径>）"）；截断 16k 字符（防失控输出撑爆父上下文）；超时（单子代理 10 分钟）与 abort 转可读 is_error。

## 2. 两层提示词模板（调研定稿）

**task 工具 description**（教主 LLM 调用纪律——防滥用的主手段，业界共识"防错用不防多用"）：

```
把独立的子任务委派给并发子代理。子代理看不到当前对话，prompt 必须自包含。

何时用：大范围搜索/多文件调研归纳/互相独立的并行子任务/不需要过程细节只要结论的工作。
何时不用（直接自己做更快更准）：读指定文件、找特定定义、2-3 个文件内的小改动、
  需要当前对话上下文的任务。

写 prompt 像给刚进门的同事 briefing：目标与原因、涉及文件/目录、验收标准、期望返回格式。
禁止"根据你的发现修 bug"这类委派理解的写法——写清文件路径与具体要改什么。
明确告知是写代码还是只调研。并行任务给不同子代理时，让它们碰不同的文件。
```

**子代理 system 骨架**（两种内置类型，S1 定稿）：

- **general（全能型）**：`你是独立子任务代理，prompt 是你的全部背景，缺信息用工具自查不要猜。只做 prompt 说的事。完成后只输出结论：结果/关键发现/产物路径三段——调用者只拿这段文字，过程细节不会被看到。你不能向用户提问；有疑问就把不确定点写进结论。你不能派子任务。` + 通用行为准则（广搜窄读/不建文档文件——CC SHARED_GUIDELINES 同款）
- **explore（调研型）**：general 骨架 + **只读宣言**（无写类工具，尝试会失败——CC Explore 同款）+ 返回绝对路径 + 彻底度跟随 prompt 指定（quick/medium/very thorough）

task 参数：`{ description: 3-5 词, prompt: 任务书, kind?: 'general' | 'explore'（默认 general） }`。

## 3. UI 展示（S4 定稿）

- **折叠态（动态区）**：每运行中子代理恒 1 行 `⏺ 「重构成因」 · grep src/loop.ts…`（description + 最近工具名与目标，进度缓冲尾部）；**多行进高度预算**：行数超预算（防超屏体系同约束）压缩为 `⏺ 3 个子代理运行中（重构成因 · 依赖盘点 · 测试梳理）` 合计行
- **展开（Ctrl+O 体系内）**：当前轮展开时显示进度缓冲**尾部滚动窗**（最近 ~10 行 + `⋯ 共 N 行`——高度感知封顶，ConfirmPrompt 截断同款 clamp）
- **结束**：随本轮 commit 进 Static——ToolGroupView 里 task 是一个工具条目，展开显示返回结论全文；完整 transcript 按 `~/.ecode/agents/<agentId>.jsonl` 路径提示（工具结果尾部带路径，用户要看过程自己 cat——CC "output_file 但别偷看" 的 ECode 版：**允许看，但 LLM 不主动读**，写进 description 一句）
- **告警中心**：子代理启动/结束/超时/失败各一行 info/warn（成本可感知）

## 4. 日志与观测（S9 定稿）

- LogEntry 加可选 `agentId?: string`（logstore schema 一处 + emit 透传；主循环不带）
- 子代理 logger 包装：`makeAgentLogger(base, agentId)`——debug/info/warn/error 全通道注入
- agentId 形态：`a-<use.id 前 4>`（如 `a-t19f`），与 task_use id 天然关联
- iterNum 保持各自循环轮数（grep agentId 后 iterNum 即该代理轮次，零侵入）

## 7. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 并发子代理同改一文件 | 中 | ConfirmPrompt 单槽排队（用户逐个放行可见）+ checkpoint 每改必拍 + prompt 教学 |
| 子代理返回结论质量差（prompt 写烂） | 中 | description 元规则（反委派理解）+ 返回契约三段式 + 主 agent 可再派/自己做 |
| 成本失控（并发多代理烧 token） | 中 | 无硬上限但对齐"防错用不防多用"；usage 归并 StatusBar 可感知；告警中心启动/结束各行 |
| 子代理跑飞（迭代不终止） | 低 | maxIterations 钳 25 + 10 分钟硬超时 + abort 连坐 |
| transcript 磁盘膨胀 | 低 | `~/.ecode/agents/` 挂 cleanup-service 同款 retention（M10 后台任务的清理一并做，此处留接口） |
| 进度缓冲内存 | 低 | 环形数组封顶（尾部 200 行），全量走 transcript 磁盘 |
