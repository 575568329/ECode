## 1. 三库 Web/远程客户端实证

### 1.1 deepseek-harness（最完整的参考实现）

**形态**：React 18 + Vite 6 + TypeScript + CSS Modules（无 Tailwind）+ Zustand vanilla + **WebSocket 双流**（mux `/api/events.mux` + host `/api/events.host`，`packages/client/connection/src/client/connection.ts:61-202`）。

| 维度 | 它的做法 | 锚点 |
|---|---|---|
| 状态分层 | 服务端状态（SessionManager 不可变 snapshot + Notifier 批量通知）/ 本地 UI（zustand defineStore + rAF 批量刷新 + localStorage 持久化），React 桥接用 useSyncExternalStore | `client/runtime/src/client/contract/store.ts:12-241` |
| 断线重连 | 指数退避 500ms×2 封顶 10s + 抖动；每代重连=abort 旧流→新 AbortController→双流打开→readiness handshake；3s open timeout 防代理不回 onOpen | `connection.ts:16-169` |
| 流式 markdown | **自研增量渲染器**：冻结已完成前 N 个 block 为缓存元素、仅重解析尾部增量（micromark 管线）；流式期间高亮/数学降级纯文本，finalize 后切换 | `ui-primitives/src/markdown/MarkdownText.tsx:59-138` |
| 代码高亮 | Shiki **JS regex engine**（无 WASM）：3 语法启动静态加载、22 语法懒加载、CSS variables 主题 | `ui-primitives/src/markdown/highlight.ts:1-312` |
| 审批 UI | **composer-takeover 模式**：pending 时占据输入框位置（琥珀条+命令预览+允许/拒绝一 shot，resolved 帧到达即消失） | `ui-conversation/src/client/skeleton/ApprovalPanel.tsx:1-88` |
| 提问 UI | 同 takeover 模式，多题分页导航/单选多选自由文本/可折叠草稿保留/IME 兼容 | `ui-user-questions/src/client/QuestionComposer.tsx:1-365` |
| 两级列表 | Workspace→Session 两级树+拖拽排序+搜索（本地+远程 RPC 250ms debounce）；running 态由 host 帧驱动+边沿检测弹完成通知 | `ui-workspace/src/client/WorkspaceBrowser.tsx` |
| 鉴权 | **same-origin 零鉴权**（`dsh web` 同源启动设计）；无 token 注入逻辑 | `connection/src/api-path.ts:8` |
| PWA | 仅 manifest（fullscreen），无 service worker，无 touch 专项 | `apps/web/public/manifest.webmanifest` |

### 1.2 orca（远程/移动方向）

三客户端形态：Electron 桌面（Vite+React+Tailwind）/ **React Native 移动端（Expo 55 + RN 0.83 + React 19 + zustand 5）** / Web 端（Electron 渲染器的 Web 构建复用，pairing URL 连远程 runtime）。通信=WebSocket + NaCl E2EE + JSON-RPC。Web 客户端工程亮点（`src/renderer/src/web/web-runtime-client.ts:78-855`）：重连退避表 [500,1000,2000,4000,8000,15000]ms、**心跳 10s + 25s 无帧 liveness probe + 20s 未答关闭**、重连后 `replayInterruptedSubscriptions()` 订阅重放、**冻结 tab 检测**（tick 间隔 ≥2×心跳间隔判定被挂起）、pairing URL + scope 权限（mobile vs full web）。

### 1.3 opencode

**没有 Web 交互客户端**——`packages/web` 是 Astro 文档站；`packages/ui`/`session-ui` 是 SolidJS 组件库（供 Electron 桌面端消费，含 `markdown-stream`/`@shikijs/stream`/morphdom 等流式渲染件）。无 WS/SSE 消费代码。参考价值有限（不选型）。

## 2. 2026-08 生态选型（在线调研，来源全标注）

| 项 | 结论 | 要点 |
|---|---|---|
| Vite | **v8.2.2**（2026-08-20） | Rolldown+Oxc 替代 esbuild+Rollup（快 10-30×）；@vitejs/plugin-react v6；Node ≥20.19；纯 ESM |
| Tailwind | **v4 + @tailwindcss/vite 插件** | CSS-first 配置（@theme 入 CSS），删 tailwind.config 与 PostCSS；入口一行 `@import "tailwindcss"` |
| **SSE 消费** | **fetch + ReadableStream + eventsource-parser（v3.1.0）** | EventSource 不能带 Authorization header/不能 POST/同域限 6 连接；**token 入 URL query 是 OWASP 认定风险**（日志/历史/Referer 泄露）；@microsoft/fetch-event-source 停维护 ~5 年弃用 |
| 重连语义 | Last-Event-ID 浏览器自动带，但**服务端必须处理**否则重放从头；LLM 生成不可重放——断点续传无意义，重连=重发/补拉 | 与多端方案 Q10（session/read 全量补拉）一致 |
| 流式 markdown | **Streamdown（Vercel 官方）**：react-markdown 的流式特化替代——不完整语法自动补全 + 块级 memo（仅活跃块重渲染）+ 内置高亮/数学/Mermaid | 备选 react-markdown v10 + 手动 block memo（其全量重解析是已知性能问题 issue#684） |
| 代码高亮 | Prism.js 最轻最快（core ~2KB）客户端 CSR 首选；Shiki 准确性最佳但重（WASM 语法）；**选 Streamdown 则自带** | harness 用 Shiki JS engine + 懒加载是自研路线的配套 |
| 状态管理 | **Zustand v5**（1KB 无 Provider）——单流+按会话过滤+表单态一 store 搞定；TanStack Query 不适合管 SSE 流（可选用于 REST 分页） | 与 harness 实证（zustand vanilla+Immer）相互印证 |
| PWA | vite-plugin-pwa **v1.3.0**（2026-05，已支持 Vite 8，Workbox 7.3） | 最小离线壳零配置；`registerType:'autoUpdate'`+API NetworkFirst |
| 代理坑 | Nginx 默认 `proxy_buffering on` 会攒批——SSE 端点须 `X-Accel-Buffering: no` 响应头（服务端加，ECode daemon 直连场景不经过但公网反代必撞） | W3 mux 端点顺手带上此头 |
| 移动端坑 | iOS Safari 切后台**主动杀流**（回前台 visibilitychange 重连）；Android Chrome 后台可能 OS 级挂起；iOS PWA 不支持 Background Sync/Push（壳可用，高级特性不依赖） | 印证方案 §5"仅前台连 mux"与 R6 |

## 3. ECode 落定选型（W5 开箱即用）

| 层 | 选型 | 说明 |
|---|---|---|
| 框架/构建 | React 19 + Vite（v8）+ @vitejs/plugin-react v6 | 方案 Q3 拍板 React19+Vite 维持，版本落 v8 |
| 样式 | Tailwind v4 + @tailwindcss/vite | Q3 拍板维持，集成方式=插件非 PostCSS |
| 流连接 | **fetch + ReadableStream + eventsource-parser**（不用 EventSource——token 走 Authorization header 不落 URL） | 重连工程对齐两家：指数退避 500ms×2 封顶 10s + 抖动 + 3s open timeout + visibilitychange 前台重连 + 冻结 tab 检测 |
| 流式渲染 | Streamdown（备选 react-markdown v10 + 手动块 memo） | 自研增量渲染器（harness 路线）**不做**——Streamdown 已解决同一问题，YAGNI |
| 状态 | Zustand v5 单 store（sessions/currentId/流缓冲/UI 态） | 方案 §4"选型 W5 批定"就此落定 |
| PWA | vite-plugin-pwa v1.3.0 最小离线壳 | iOS 只当壳用 |
| 不引入 | TanStack Query（SSE 非请求-缓存模式；REST 分页可选后再说）、AI SDK（服务端绑定 Next.js，只需借鉴其组件思想）、自研 markdown 引擎 | |

**与方案 Q4（REST+SSE）的关系**：两家实证用的是 WebSocket，但 ECode 坚持 SSE——daemon 已按 SSE 建好 mux/背压/心跳工程（M12），且 SSE 的单向事件流+回执式 POST 完全覆盖需求；WS 的双向能力用不上。吸收的是**客户端连接工程**（退避/心跳/冻结检测/订阅重放语义→重连后 baseline+read 补拉，与 Q10 一致）。

## 4. 借鉴模式清单（按学习价值）

1. **composer-takeover 审批/提问交互**（harness ApprovalPanel/QuestionComposer）——pending 占输入框位、一 shot 按钮、resolved 即散；ECode 审批 UI 直接采此模式
2. **重连工程全套**（harness connection.ts + orca web-runtime-client.ts）——退避表/抖动/open timeout/心跳 liveness/冻结 tab 检测
3. **两级列表实时化**（harness WorkspaceBrowser）——host 帧驱动增删 + running 边沿检测完成通知；ECode mux 的 project/session 帧同构
4. **Vendor chunk 拆分**（harness vite.config）——markdown/高亮/math 独立 chunk 惰性加载
5. 流式期间高亮降级（streaming=纯文本，finalize 切高亮）——Streamdown 下仍可借鉴其降级思路
6. IME 兼容检测（isComposing）——中文输入必踩，ECode 用户中文为主必须有
7. pairing URL + scope（orca）——远期公网访问形态参考（M13 不做，per-device token 升级位）

## 5. 对多端方案的修订输入（已同步 §4）

- §4"全局单 EventSource"表述改为"全局单流连接（fetch+ReadableStream+eventsource-parser）"——EventSource 不能带鉴权 header
- 状态管理落定 Zustand v5（原"W5 批定"提前关）
- 流式渲染落定 Streamdown；审批 UI 采 composer-takeover 模式
- W3 mux 端点响应头补 `X-Accel-Buffering: no`（公网反代场景）
- W5 批补"连接工程"子项（退避/抖动/open timeout/visibilitychange）
