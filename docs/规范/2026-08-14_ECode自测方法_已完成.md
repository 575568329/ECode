# ECode 自测方法

> 让 Agent 能完全自测 ECode，覆盖纯逻辑 → 真模块 → 真 TUI 全链路，不必等用户手动。
> 关键突破：管道 stdin 跑不了 Ink TUI（raw mode 要 TTY），但 node-pty 提供 pseudo-terminal 解决。

## 5 层测试方法（真机接近度递增）

| 层 | 工具 | 测什么 | 限制 |
|---|---|---|---|
| **1 单测** | vitest | 纯逻辑（errors/summarize/orchestrator/context/tokenizer/pricing/contextWindow/history/loop）| 不跑进程 |
| **2 ink-testing** | ink-testing-library | TUI 组件渲染 + 命令交互（`render(<TuiApp>) + stdin.write + lastFrame()`）| 不跑真进程；不测真 LLM 流式（要 mock provider）|
| **3 node 脚本** | `.mts` + `npx tsx` | 核心逻辑端到端 + **真 LLM**（import 真模块，内存构造数据）| 要手动构造 deps/messages |
| **4 argv 真机** | `npm run dev -- "问题"` | 单次真进程 + **真 LLM** | 命令行长度 ~32k 限制；单次不交互 |
| **5 node-pty 真 TUI** | node-pty + stripAnsi | **完整真进程 TUI**（raw mode + 真输入 + 真渲染 + 命令）| native 模块；ANSI 解析 |

## 何时用哪层

- 改**纯逻辑**（非 TUI）：1 单测 + 3 node 脚本（真 LLM 验证）
- 改 **TUI 渲染/命令**：2 ink-testing（快，迭代）+ 5 node-pty（真机确认手感）
- 改**端到端**（cli/loop/provider）：3 node 脚本 + 4 argv
- **完整真机确认**：5 node-pty（最接近真机，含 raw mode 交互）

## 第 5 层：node-pty 真 TUI（最全，重点）

管道跑 `npm run dev` 会报 "Raw mode is not supported"（Ink 要 TTY stdin，管道不是）。node-pty 提供 pseudo-terminal（pty = 假终端），Ink raw mode 在 pty 下正常工作。

### 安装
```bash
npm i -D node-pty   # native，Windows 有预编译（~2s 装好）
```

### 用法（spawn dev + 喂输入 + 捕获渲染）
```js
const pty = require('node-pty')
const proc = pty.spawn('cmd.exe', ['/c', 'npm', 'run', 'dev'], {
  cwd: process.cwd(), env: process.env, cols: 100, rows: 30,
})
let out = ''
proc.onData((d) => { out += d })
// 去 ANSI 转义（CSI 颜色/光标/清屏 + OSC 终端标题），看纯文本。
// 注：ECode src/tui/ansi.ts 是 parseAnsi（解析成 Span 供 markdown 渲染），不是 strip——strip 用此正则或 strip-ansi 包
const stripAnsi = (s) => s.replace(/\x1b\[[0-9;?]*[a-zA-Z]/g, '').replace(/\x1b\][^\x07\x1b]*(?:\x07|\x1b\\)/g, '').replace(/\x1b[()][0AB]/g, '')

setTimeout(() => { proc.write('/cost') }, 4000)       // ① 输入命令（等 TUI 启动）
setTimeout(() => { proc.write('\r') }, 5500)           // ② ★ 单独写回车
setTimeout(() => {
  console.log(stripAnsi(out).split('\n').map(l=>l.replace(/\r/g,'').trimEnd()).filter(Boolean).slice(-15).join('\n'))
  proc.kill(); process.exit(0)
}, 8000)                                               // ③ 等 1.5s 渲染后看帧
```

> 上面是简版（固定 setTimeout）。**健壮版**（`onData` 轮询检测启动标志再 write + `onExit` 错误处理 + spawn `try/catch` 捕 native 加载失败）见 skill `test-terminal-app` 第 5 层——避免慢机器启动超时丢命令、子进程早退静默卡空帧。

### ★ 三个关键技巧

1. **分开写「输入」和「回车」**：`proc.write('/cost')` 等 ~1s 再 `proc.write('\r')`。一次写 `'/cost\r'` 会被 TextInput 当一串字符流，`\r` 不触发 `onSubmit`（React state 更新 vs submit 的时序）。**这是最大的坑**。
2. **stripAnsi**：pty 输出含 ANSI 转义（\x1b[...m 颜色 / \x1b[?25l 光标 / 清屏），正则去除看纯文本。
3. **cols/rows + 时序**：设窗口大小（Ink 按尺寸渲染）；TUI 启动 ~4s（config + Ink 初始化），命令后等 ~1.5s（渲染 flush）。

### 限制
- **多帧叠加**：TUI 全屏重绘，`out` 累积所有帧。取最后 N 行近似最新帧（精确取单帧要终端模拟器如 xterm.js 解析缓冲）。
- **真 LLM 消耗**：TUI 输入真问题会调 LLM（花 token + 等响应）。测命令/UI 用 `/cost` `/help` `/model`（不调 LLM 或不 submit）。
- **native**：node-pty 是 C++，Windows 预编译 OK；Linux/Mac 一般也有预编译，偶尔要 build tools。

## 第 2 层 ECode 实战（ink-testing-library）

测 TuiApp 渲染/命令（不跑真进程，快，迭代 UI）。**注意**：根组件是 `TuiApp({ deps, banner? })`（不是 `App`），且必须构造 `deps: TuiAppDeps`（含 orchestrator/lastUsage）。

```ts
// test.mts → npx tsx test.mts
import { render } from 'ink-testing-library'
import React from 'react'
import { TuiApp } from './src/tui/TuiApp.js'
import { CompactionOrchestrator } from './src/services/compaction/orchestrator.js'
import { SummarizeStrategy } from './src/services/compaction/summarize.js'
const orchestrator = new CompactionOrchestrator(); orchestrator.register(new SummarizeStrategy())
const deps = {
  providerRegistry: { getByType: () => ({ type: 'mock', async *run() {} }) } as any,
  tools: { specs: () => [], get: () => undefined, validate: () => ({ ok: true }) } as any,
  logger: { info() {}, warn() {}, error() {}, debug() {} },
  history: { append() {}, appendCompactBoundary() {}, loadAll: () => [], restore: () => [], restoreFull: () => [], setSessionId() {} },
  config: { providers: { x: { type: 'anthropic' as const, baseURL: '', apiKey: '', models: ['m'] } }, current: { name: 'x', model: 'm' }, maxIterations: 50, bashMaxOutputBytes: 30720, logLevel: 'info' as const },
  orchestrator, lastUsage: { input: 0, output: 0, cacheRead: 0, cacheCreation: 0 },
} as any
const { stdin, lastFrame } = render(React.createElement(TuiApp, { deps }))
await new Promise((r) => setTimeout(r, 30))
stdin.write('/cost'); await new Promise((r) => setTimeout(r, 30))
stdin.write('\r'); await new Promise((r) => setTimeout(r, 50))
console.log(lastFrame())  // 含「本轮 token...」= /cost 执行成功
```
完整可跑示例见 `tests/tui/TuiApp.test.tsx`（`makeDeps` 构造 deps）。ECode 内第 2 层优先（比第 5 层 pty 快、无 native）；要真进程真机确认才上第 5 层。

## 已验证能跑的（2026-08-14）

- **/cost 命令**（node-pty）：补全建议 + 执行 + systemMsgs 在输入框上方 ✓
- **真 LLM 压缩**（node 脚本调 hook + 超 messages）：summary 结构化 + boundary 落盘 + 投影缩小 ✓
- **argv 单次**（npm run dev -- "..."）：真 LLM 回复 ✓

## 不能自测的（仍需用户）

- 真 LLM 流式响应的**视觉手感**（流式灰字滚动、卡顿）—— node-pty 能看最终帧，但流式过程要肉眼。
- 真机交互的**直觉问题**（布局对齐、ambiguous 字符宽度错位）—— 要真实终端渲染。
