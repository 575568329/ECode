# ECode 后续 M8 实施方案：交互与上下文智能（懂你 · 会问你 · 能查证）

> 日期：2026-08-15 · 状态：**设计稿 v1（待启动）**
> 主题一句话：让 Agent **记得住**（AGENTS.md/memory）、**问得准**（ask_user 选项框）、**查得到**（WebFetch）、**看得爽**（流式 markdown）。
> 来源：用户提出 memory 系统 + 提问选项框；经四家调研（提问机制 + 功能差距盘点）补齐选型后成稿。参考实现集中附录 B，正文只写 ECode 自己的设计。

---

## 0. 目标与验收

**目标**：补齐「Agent 与用户之间的信息通道」——指令进得来（AGENTS.md）、偏好记得住（memory）、歧义问得清（选项框）、外部信息查得到（WebFetch）；顺带清偿 M5 遗留小额债。

**验收**：
- **AGENTS.md 注入**：工作区有 AGENTS.md 时 system prompt 含其内容（findUp 首个匹配）；超限截断有提示；无文件零开销
- **ask_user**：LLM 遇模糊需求调 `ask_user` → overlay 选项面板（数字键直选/Other 自由输入/多选/Esc 取消）；argv 单次模式不挂死（非交互守卫）；回传格式 `User has answered...`
- **auto-memory**：`~/.ecode/memory/MEMORY.md`（用户级）与 `.ecode/memory/MEMORY.md`（项目级）索引注入 system prompt；模型用现有读写工具维护，零新工具
- **WebFetch**：LLM 可抓公开网页转文本（30KB 截断）；私网/回环地址拦截（SSRF 防护）；重定向 ≤3、超时 15s
- **流式 markdown**：流式期已完成的顶层 block 实时渲染格式，末尾未完块保持灰字；commit 后全量 markdown（现有路径不变）
- **OSC8**：终端支持时链接可点击，不支持降级 `text (href)`
- **分段化**：system prompt = 静态前缀 + 动态后缀，动态内容变化不击穿前缀（cache 友好）
- **债**：pricing 从 models.dev 同步 + config 覆盖定价；preserveToolPairs O(n²) 收敛

**不做**（后置）：WebSearch（需外部搜索 API/key）、memory 管理命令（/memory 等，文件即真相）、ask_user preview 分栏、跨进程事件总线（单进程用不上）。

## 1. AGENTS.md runtime 注入（P0，~1 天）

**问题**：ECode 的 AGENTS.md 写得极完整（通用原则 + TS/Node 规范），却从未喂给 LLM——用户在每个项目里的工作区指令全部失效。

**设计（两级，审阅后从单级补全）**：
- **用户级 `~/.ecode/AGENTS.md`**：跨项目个人偏好（语言/风格/背景），先注入
- **项目级**：findUp 找 AGENTS.md（**首个命中即止**；边界同 skill 的 findUpDir——home 停、非 home 树收在最近 git 根，避免两套边界漂移），后注入（更具体的项目约定居后，语义上覆盖个人偏好）
- `buildSystemPrompt` 动态段分块追加：`--- 用户指令（~/.ecode/AGENTS.md）---` + `--- 工作区指令（AGENTS.md）---`
- **大小守卫**：两级各 32KB 上限（超限截断 + 末尾提示「已截断，原文 <path>」），并计入 `estimateContextTokens`（压缩估算已含 system，天然生效）
- 注入位置选 system（而非 user-context 消息）：ECode 的 Provider 接口 system 是单字符串，拼接追加成本最低；分段化（§6）后归动态段，缓存语义不损

## 2. ask_user 提问选项框（P0，~2-3 天）

**问题**：模糊需求只能纯文本追问（用户要重新读一段话再打字）；ConfirmPrompt 只有二元 y/n，且语义是「授权」不是「收集」。

**工具定义**（`src/tools/builtin/ask_user.ts`，`readonly: true`——信息收集免确认、可与只读工具并行）：

```jsonc
{
  "questions": { "type": "array", "minItems": 1, "maxItems": 4, "items": {
    "question":    "完整问句，清晰具体，以？结尾；multiSelect 时措辞相应调整（选哪些 vs 选哪个）",
    "header":      "短标签，≤12 字符（多问题时 tab 导航 chip 用）",
    "options":   { "type": "array", "minItems": 2, "maxItems": 4, "items": {
      "label":       "1-5 词显示文本；推荐项放第一个并加 (Recommended) 后缀",
      "description": "选项含义 / trade-off 说明" } },
    "multiSelect": "boolean，默认 false"
  }}
}
```

- **AJV 追加两条校验**：问题文本全局唯一、每题内 label 唯一（防模型生成重复项）；`header` 加 `maxLength: 12` 硬约束
- **Other 不由模型生成**：description 明令「用户始终可选 Other 自由输入，不要生成兜底选项」，UI 端自动追加
- **并发独占**（审阅补）：ask_user 是 `readonly: true` 会被 executeTools 与其它只读工具 `Promise.all` 并行——同轮多个 ask_user 会抢 overlay。修法：工具内**会话级排队锁**（先到先弹，后到 await 排队；~5 行）+ description 约束「一轮最多问一组问题」

**TUI**（`QuestionPanel.tsx`，PanelShell + Promise resolve 桥——ConfirmPrompt 同款机制，心脏零感知）：
- 单问题单选：**选中即提交**（数字键 1-9 一步完成，无确认页）
- 多问题/多选：header chips 导航（已答/未答变色）+ 末尾 Review 页列 `问题 → 答案`；多选 `[✓] label`（space toggle）
- Other 恒居末位，选中展开内联 TextInput；**聚焦输入框时数字键为打字**（已知坑）
- `Esc` = 取消提问 → tool_result「用户取消了提问」（明确信号，不挂死）

**非交互守卫**：argv 单次模式 / 非 TTY → execute 检测后直接返回「非交互环境无法弹出选项，请基于上下文选择合理默认并说明」——模型自行决策，不阻塞。

**回传格式**（两家独立实现共识，对模型最友好）：`User has answered your questions: "q"="a, b". You can now continue with the user's answers in mind.`（多选逗号连接）。

**防滥用三支柱**（写进工具 description）：能推断就别问（合理默认直接采用并说明）/ 先调查再问（读代码 grep 之后真卡住才问）/ 不重复问。**职责分界**：ConfirmPrompt = 副作用授权（框架拦截发起）；ask_user = 模型主动信息收集（不进审批语义）。

## 3. auto-memory（P1，~2-3 天）

**问题**：跨会话零记忆——上个会话定下的偏好（「这个项目用 vitest 别用 jest」）每次重新教。

**设计**（零新基建，约定 + 注入）：
- 两级目录：`~/.ecode/memory/MEMORY.md`（用户级偏好）+ `.ecode/memory/MEMORY.md`（项目级，可进 git 团队共享）——**只注入索引文件全文**，topic 文件（同目录 `*.md`）由模型按需 read_file
- 索引格式：每条一行 `- [主题](文件名.md) — 一句话钩子`（与 Claude Code MEMORY.md 惯例同构，用户可直接手写）
- 维护：模型用现有 write_file/edit_file 操作（无新工具、无新权限面）；AGENTS.md 里已要求「重要偏好写入 memory」——注入后模型自然遵循
- 注入点：system prompt 动态段（`--- 记忆索引 ---`），受 32KB 级守卫；memory 在 system 不进 messages → **不受压缩影响、不进 HistoryStore**（边界清晰）

## 4. 流式 markdown + OSC8 链接（P1，~2 天）

**问题**：流式期是灰字纯文本，整段结束才「闪变」成格式——终端 markdown 调研定位的最大体验差距。

**设计**（调研已定选型：顶层 block 边界 stable/unstable 切分）：
- 流式期把 `streamingText` 分两段：**稳定前缀**（已确认完整的顶层 block——用 marked.lexer 的 token 边界判定，boundary 单调前进）渲染成 markdown；**可变尾部**（最后一个未完 block）保持灰字
- 每 delta 只对 unstable 后缀跑 lexer（O(unstable)），稳定前缀 memo 不重渲
- 架构适配：ECode 现行 = Static（已 commit）+ 动态区（当前轮）——本节改造发生在**动态区内**的 GrayStreaming 组件；commit 进 Static 的路径零改动
- **OSC8**：启动探测一次 `supports-hyperlinks`（缓存），支持时 `inlineToAnsi` 的 link 分支发 `ESC]8;;URL BEL text ESC]8;;BEL`，不支持降级现有 `text (href)`；link token 内文本不再二次 linkify（防嵌套）

## 5. WebFetch 工具（P1，~2 天）

**问题**：模型对「最新的库 API / 端点行为」只能凭训练记忆猜——四家成熟 CLI 全有 web 工具，ECode 唯一没有的硬缺口之一。

**设计**（基础版，无头浏览器后置）：
- `src/tools/builtin/web_fetch.ts`（`readonly: true`）：Node 原生 fetch GET → HTML→文本（去 script/style/nav，保留标题/正文/代码块）→ 30KB 头尾中截（复用截断惯例）→ 带 URL/标题/截断标记返回
- **SSRF 防护**（必须）：DNS 解析后校验目标 IP——私有段（10/172.16-31/192.168）/ 回环 / 链路本地 / .local 一律拒绝（is_error 提示「内网地址禁止抓取」）；重定向逐跳复检，≤3 跳；超时 15s；仅 GET
- 免确认（只读公开网页，与 bash curl 同级但更受限）；M9 沙箱统一收口
- prompt 教学：优先读本地代码/文档，线上信息不确定时才 fetch

## 6. system prompt 分段化（P2，~1-2 天）

**设计**：`buildSystemPrompt` 内部结构化为**静态前缀**（身份/平台/工具指引）+ **动态后缀**（AGENTS.md / memory 索引 / skills 清单 / 路由行）以 `\n\n` join——对外仍返回单字符串（Provider 协议不动，四个调用点零改动）。收益：动态内容变化（skills 增删、memory 更新）不击穿静态前缀的 prompt cache。

## 7. 小额债清账（P2，~1 天）

- **#6 pricing**：models.dev 刷新 cache 时同步 cost 字段进本地表；实现 config 覆盖定价（`providers.<name>.pricing`，方案风险表早提过）
- **#2 preserveToolPairs O(n²)**：单遍先算 tailUseIds 集合再逐步删除（~10 行）

## 10. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| AGENTS.md/memory 过大吃窗口 | 中 | 32KB 上限 + 计入压缩估算（system 已在估算内）|
| ask_user 被滥用（每轮都问）| 中 | prompt 三支柱 + 1-4×2-4 硬上限 + Esc 明确信号 |
| WebFetch SSRF/隐私 | 中 | 私网拦截 + GET only + 重定向复检 + 截断；M9 沙箱收口 |
| 流式 markdown 性能（每 delta 全量 lexer）| 低 | 只 lexer unstable 后缀 + 稳定前缀 memo；实测长回复 |
| memory 与压缩边界混淆 | 低 | memory 只在 system（不进 messages），文档明示 |
| 分段化击穿既有 prompt 断言 | 低 | 纯构造层重构，系统测试锁全文 |

## 11. 决策表

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| M8-D1 | AGENTS.md 注入位置 | system 动态段（拼接），非 user 消息 | Provider system 单字符串改造成本最低；分段化后缓存不损 |
| M8-D2 | AGENTS.md 层级 | **两级**：用户级 `~/.ecode/AGENTS.md`（个人偏好，先注入）+ 项目级 findUp 首个命中（后注入，语义覆盖前者）| codex/opencode 均有用户级；两级分工清晰（跨项目偏好 vs 项目约定）|
| M8-D3 | ask_user 架构 | 普通 Tool + PanelShell + Promise 桥（**不进审批语义**） | 信息收集 ≠ 授权；ConfirmPrompt 分界清晰 |
| M8-D4 | ask_user 约束 | 1-4 问 × 2-4 选 + Other UI 追加 + 唯一性校验 + **并发排队锁** | 两家共识防问卷轰炸；readonly 并行会抢 overlay（审阅补）|
| M8-D5 | ask_user 非交互 | execute 检测返回提示文本（不 is_error 挂死） | argv 模式无 UI，模型需自行决策 |
| M8-D6 | memory 形态 | MEMORY.md 索引 + topic 文件 + 现有工具维护 | 零新基建；注入索引不注入全文 |
| M8-D7 | 流式 md 路线 | 顶层 block stable/unstable（claude-code 同构） | marked token 边界天然安全；O(unstable) |
| M8-D8 | OSC8 | 启动探测一次 + 降级 `text (href)` | 运行时自探测、失败优雅降级（项目哲学）|
| M8-D9 | WebFetch 安全基线 | SSRF 私网拦截 + GET + ≤3 跳 + 15s + 30KB | 无沙箱前的最小防线；M9 收口 |
| M8-D10 | WebSearch | 后置 | 需外部搜索 API/key，非零依赖 |
