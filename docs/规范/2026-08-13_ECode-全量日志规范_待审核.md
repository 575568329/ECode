# ECode 全量日志规范

> 日期：2026-08-13 · 状态：待审核
> 实现：`src/services/{redact,logstore,logger}.ts` + `src/core/loop.ts` emit + `src/cli/index.ts`
> 测试：`tests/services/{redact,logstore}.test.ts`（258/258 全量）
> 依据：AGENTS §2.7/§5.2 + 详设 §4.4 + 角色审阅（2026-08-13）

## 1. 目标

- **排查**：重建一次会话的完整运行过程（iter / provider / tool / error / abort / stop）。
- **不进 context**：LogStore 是运行 trace（调试用），**≠ HistoryStore**（对话 messages，喂 LLM、/history 恢复）。靠 `sessionId` 关联。
- **不阻塞主流程**：落盘失败降级（只丢日志，stderr 提示一次）。
- **崩溃不丢关键日志**：exit / uncaughtException / unhandledRejection 同步 flush。

## 2. 架构

```
loop / 工具 / cli
   └─→ Logger.debug|info|warn|error(category, event, payload?, iterNum?)
         └─→ LogStore.emit
               └─→ buffer（经 redact 脱敏）
                     ├─ 批量 flush（100 条 或 500ms）→ WriteStream 异步写
                     ├─ error 立即 flush
                     └─ close() 同步 flush（writeFileSync，exit 兜底）
                           └─→ JSONL 落盘 ~/.ecode/logs/<sessionId>.jsonl
```

**唯一写入入口**：`LogStore.emit`（AGENTS §2.7：禁止散落 `console.log`）。

## 3. JSONL schema

每行一个 JSON 对象：

```jsonl
{"ts":"2026-08-13T01:20:16.677Z","level":"info","category":"loop","event":"iter_start","sessionId":"2026-08-13T01-20-16-676Z","iterNum":1,"payload":{"iter":1,"max":50,"model":"glm-5.2"}}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `ts` | string | ISO 时间戳 |
| `level` | enum | `debug` \| `info` \| `warn` \| `error` |
| `category` | enum | `loop` \| `provider` \| `tool` \| `config` \| `tui` \| `system` |
| `event` | string | 事件名（见 §4 清单） |
| `sessionId` | string | 会话 ID（文件名同名） |
| `iterNum?` | number | 心脏迭代轮（loop 相关事件） |
| `payload?` | object | 脱敏后数据（见 §5） |

## 4. 事件清单

### system（系统生命周期）
| event | level | payload | 说明 |
|---|---|---|---|
| `startup` | info | model, cwd, logPath, node, platform, providerType | 启动 |
| `shutdown` | info | exitCode | 正常退出（exit handler） |
| `uncaught` | error | message, stack | 未捕获异常（兜底） |
| `unhandled_rejection` | error | message, stack | 未处理 Promise 拒绝（兜底） |

### loop（心脏）
| event | level | payload | 说明 |
|---|---|---|---|
| `iter_start` | info | iter, max, model | 每轮开始 |
| `stop` | info | stopReason, iter | 正常停止（end/aborted） |
| `aborted` | info | iter | 中断（Ctrl+C） |
| `stream_error` | error | code, message, recoverable, isAborted | 流内错误（网络/认证/限流） |
| `max_tokens_truncated` | warn | iter | 输出截断（length） |
| `content_filter` | warn | iter | 内容被安全过滤 |
| `empty_tool_use` | warn | iter | LLM 要求工具但未给（防护跳过） |
| `fatal_stop` | error | stopReason | stop_reason='error' fatal（throw 前） |

### provider（LLM）
| event | level | payload | 说明 |
|---|---|---|---|
| `request` | debug | messageCount | 发起请求 |
| `usage` | debug | input, output | token 消耗（成本追踪） |
| `retry` | warn | attempt, code, backoff_ms | 指数退避重试 |

### tool（工具）
| event | level | payload | 说明 |
|---|---|---|---|
| `invoke` | debug | id, name, input(脱敏), readonly | 调用（含 LLM 入参，排查工具为何如此调用） |
| `result` | info | id, name, is_error, bytes | 结果（输出侧 + 字节数） |

> 对照详设 §4.4.3（16 事件基线）：本规范已覆盖核心排查路径；剩余 `trace` 级、`duration_ms`、ToolContext 注入 logger 留 M3/M4。

## 5. 脱敏规则（redact）

payload 在 `LogStore.emit` 内经 `redact()` 递归脱敏，**调用方不需手动脱**。

**字符串模式**（扫描替换为 `[REDACTED]`）：
- `sk-[A-Za-z0-9_-]{20,}`（Anthropic）
- `AKIA[A-Z0-9]{16}`（AWS）
- `[a-f0-9]{64}`（通用 64 位 hex：GLM/DeepSeek 等；**会误杀合法 SHA-256，安全偏向可接受**）
- `[a-f0-9]{8,}\.[A-Za-z0-9_-]{20,}`（GLM `{id}.{secret}` 格式）
- env 赋值：`XXX_API_KEY=...` / `XXX_TOKEN=...` / `XXX_SECRET=...`（保留键名，值替换）

**字段**（子串匹配，整体替换）：
`apiKey` / `api_key` / `authorization` / `token` / `secret` / `password` / `bearer`

**递归保护**：
- 环引用 → `[CIRCULAR]`（WeakSet seen-guard）
- 深度上限 10 → `[MAX_DEPTH]`（防栈溢出）

## 6. flush 机制（落盘策略）

| 触发 | 方式 | 说明 |
|---|---|---|
| 批量 | WriteStream 异步写 | 100 条 或 500ms（默认） |
| error | 立即 flush | error 级事件不进 buffer 等批量 |
| close | **writeFileSync 同步写** | exit handler 同步，WriteStream async write 不保证落盘；**这是设计铁律，不是优化** |
| 落盘失败 | stderr 通知一次 + 降级 | 不阻塞主流程（AGENTS §2.7：失败可优雅降级） |

## 7. 崩溃兜底（cli main 注册）

```ts
process.on('exit', () => { logger.info('shutdown', ...); logStore.close() })
process.on('uncaughtException', (e) => { logger.error('uncaught', ...); logStore.close(); process.exit(1) })
process.on('unhandledRejection', (r) => { logger.error('unhandled_rejection', ...); logStore.close(); process.exit(1) })
```

> SIGKILL / OOM 无法兜（OS 强杀，只能靠已 flush 的）。

## 8. 使用（排查）

```bash
# 看最新会话日志
cat ~/.ecode/logs/$(ls -t ~/.ecode/logs/ | head -1)

# 按事件过滤
jq 'select(.event=="stream_error")' ~/.ecode/logs/<sessionId>.jsonl

# 重建流程（按时间）
jq -r '"\(.ts) [\(.level)] \(.category)/\(.event)"' ~/.ecode/logs/<sessionId>.jsonl
```

- `sessionId` = 文件名 = `new Date().toISOString()`（时间戳；M4 改 UUID + 关联 HistoryStore）
- `startup` 事件含 `logPath`（首次启动可从日志确认路径）
- `iterNum` 关联心脏轮次，与 HistoryStore 的 messages 对应

## 9. 与 HistoryStore 的区别

| | LogStore | HistoryStore（M4） |
|---|---|---|
| 内容 | 运行 trace（调试） | 对话 messages |
| 进 context | **否** | 是（喂 LLM） |
| 用途 | 排查 | /history 恢复 |
| 脱敏 | 是（密钥） | 是（密钥） |
| 关联 | sessionId | sessionId（M4 共享同一 ID） |

| 项 | 现状 | 计划 |
|---|---|---|

| `trace` 级 | 无（4 级） | M3：补 trace（细粒度） |

| stdout/stderr 捕获 | 工具结果含，中间过程无 | M3：bash 流式输出 |
| `error` category | 用 system/loop 替代 | 对齐详设（当前 category 无 'error'） |

## 11. 设计原则（呼应 AGENTS §2.7）

1. **唯一写入入口**（LogStore.emit），禁止散落 `console.log`。
2. **JSONL 结构化**，统一字段 schema（便于 jq/工具解析）。
3. **异步批量 flush**，`fatal` 抛出前 / exit 前同步 flush。
4. **脱敏集中**（redact.ts），Logger 与 HistoryStore 共用同一规则。
5. **LogStore ≠ HistoryStore**：trace ≠ messages，靠 sessionId 关联。
