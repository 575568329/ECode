## 0. 背景与定位

外部文章《Harness 成本篇》（提取见 [姊妹篇一](../解析/2026-08-21_Agent成本优化实战文章精华提取_已完成.md)）给出"少发 × 发得便宜 × 少想 × 隔离 × 拦截 × 分流"的成本框架；[姊妹篇二（ECode 对照）](../解析/2026-08-21_Agent成本优化ECode对照与差距清单_已完成.md)经三路源码核查 + 三角色审阅 + 主对话逐条复核，确认 ECode 已同款资产五项（system 分段化/每轮重建、CC 式工具标准化、thinking 四档控制、Subagent 结论回传、QualityGate 指纹熔断先例），剩余差距七项并给出排序。

本文把其中**六项可落地差距**转为实施方案（第七项 MCP deferred 只登记复评触发器，不实施）。**核心立场继承对照文档 §5**：这是机会清单不是缺陷清单——ECode 轮次密度低于文章的生产诊断场景，各项收益以落地后度量为准，不做没有数据背书的激进改造。

## 1. 目标与非目标

**目标**（编号沿用对照文档差距清单）：

| # | 项 | 一句话 |
|---|---|---|
| 1 | cache_control 显式打标 | AnthropicProvider 出口尾部断点，把隐式缓存抽奖换成合约 |
| 2 | 无效轮次检测 | 宿主层复读/同参/空错三类检测 + 熔断，拦截 GLM 退化空转 |
| 3 | Skill 重复注入去重 | 同 skill 全文只进历史一次，重复调用回一行回执 |

| 5 | 压缩摘要模型分流 | roles.summary 角色指针，摘要调用可用便宜模型 |
| 6 | 子代理超时自总结 | 超时分支注入一轮总结，把已烧的探索 token 变成可回传结论 |

**非目标（明确排除，防范围蠕变）**：

- **"空回答不进历史"**：需要丢弃语义、messages 归 loop 持有，动心脏（M12 §11.4 硬门同款约束），收益存疑（ECode 有 empty_tool_use 防护兜底）——不做；
- **复读相似度模糊匹配**（文章 80% 相似度）：实现重、误伤险高，先做精确指纹（D3）；
- **MCP schema 延迟加载（#7）**：YAGNI 缓做，仅登记复评触发器（§4.7）；
- **ModelRegistry 四角色全套**：ECode 当前辅助 LLM 调用只有压缩摘要一个消费点（无标题生成/意图分类），只做单角色指针（D9）；
- **子代理按角色分流**（文章 explore 走 Flash）：子代理是完整 agent 非辅助调用，P2 观察，不进本期；
- **thinking 细化**：四档已有 + 摘要调用天然不带 thinking，无缺口（对照文档 §3.3 已核）。

## 3. 公共设计：ctx.session 窄端口扩展

#3/#4 的会话级状态全部经 `ctx.session` 扩展（结构类型窄接口，HostSession 实现；缺省 undefined = argv/旧测试路径走"不去重"兜底，语义与 B4/B8.2 现有一致）：

```ts
// src/tools/interface.ts —— ctx.session 追加两个窄方法
session?: {
  // ... 现有 tasks/updateSubagent/confirmTool/askUser 不动 ...
  /** M13-#3：该 skill 全文是否已在当前上下文（宿主按投影后 messages 扫描） */
  isSkillActive?(name: string): boolean
  /** M13-#4：read 去重守卫（mtime 比对；宿主持 Map<path, mtimeMs>） */
  readFileGuard?: {
    check(path: string): Promise<{ skip: boolean }>
    record(path: string, mtimeMs: number): void
  }
}
```

设计原则：**状态挂在宿主，工具只消费窄端口**——不放模块级单例（B4 正在拆除该形态），不给工具暴露全量 messages（权限面最小化）。

## 4. 分项设计

### 4.1 #1 cache_control 显式打标（Provider 层）

**落点**：`src/providers/anthropic.ts` 构造请求处（`toAnthropicMsgs` 之后、发送之前）——协议能力封在 Provider 内部，OpenAI 侧无此概念天然不实现，心脏与规范模型零改动。

**规则**（文章 §4.2 尾部断点纪律）：

1. 每轮请求，从投影后的 messages 末尾往前找**第一条有文字 content 的消息**，在其最后一个 text block 上标 `cache_control: { type: 'ephemeral' }`；
2. 打标门槛：从请求头部累计到该 block 的文本 **≥ 4096 字符**（Anthropic 下限 1024 token × 4 余量）才标，不足跳过本轮（短会话不占标记语义）；
3. 每轮重标（标记范围 = 整个前缀，含 system+tools+全部历史；端点对已缓存旧前缀不重复收费）；
4. 落点必须**在投影合并之后**（`anthropic.ts:205` 相邻同 role 合并的产物上打标，避免合并改变字节序炸缓存）；
5. **仅对话请求打标**（2026-08-24 调研补充）——压缩摘要（`callSummary`）、超时自总结等一次性辅助请求显式跳过：单次请求永远等不回 cache read，cache write 的 25% 溢价纯亏（opencode V2 auto 策略对压缩调用也机械打标——前车之鉴，其源码注释自认"对压缩调用意义不大"）。**实现（v1.1 核码修正：「按构造入口分流」不可行——callSummary 与主循环同走 `provider.run()` 同一入口）：请求参数加 `skipCacheControl` 布尔标志**，callSummary/自总结构造请求时传 true、主循环缺省不传——Provider 接口零业务语义分支（仅一个通用选项），原则=无后续轮次的请求不打标。

**开关**：`ProviderCfg.explicitCache?: boolean`，默认值由 B0 探针拍板（支持 → true；行为异常 → false 留配置逃生口）。

**验证**：B0 探针 = 打标/不打标各跑 3 轮同 prompt 会话（临时脚本或 argv 模式），对比响应 `cache_read_input_tokens` 与 400 行为；结论写回本文档 §7。

### 4.2 #2 无效轮次检测（宿主层，loop 零改动）

**状态**：`HostSession` 增 `loopGuard` 字段（最近 3 轮文本指纹环、复读计数、跨轮工具签名比对窗、连续空错计数）。

**三类检测器与动作**（阈值对齐文章，常量不入 config——D5）：

| 检测 | 数据源 | 动作 |
|---|---|---|
| 跨 Turn 复读 | 宿主事件翻译层轮末取本轮 assistant 纯文本前 500 字符 sha256，与最近 3 轮比对（精确相同） | 有工具轮：afterTools 返回 feedback（"[loop-guard] 最近 N 轮输出高度重复，请更换方法或工具"）×2 次；纯文本轮：onWarn 用户可见；第 3 次 → 宿主 abort + systemMsg 说明终止原因 |
| 同参工具 | **PostToolUse hook**（带 tool_input）收集 name+args 摘要，跨轮比对连续相同 | 连续 8 轮 → afterTools feedback 提醒重新判断；提醒后仍不变 → abort |
| 连续空错 | afterTools 的 `round.tools`（全 isError 且非空） | 连续 5 轮 → feedback"连续失败，请更换思路或基于已有信息回答"；连续 8 轮 → abort |

**公共约束**：指纹/计数变化即清零重计（文章同款）；每次触发写 LogStore（category=loop-guard，可观测）；abort 前 systemMsg 给用户可读原因；feedback 文本带 `[loop-guard]` 前缀便于 transcript 识别。

**附带小项——审批超时**（文章 §7.3"用户 3 次未响应就停"的多端版）：ApprovalBroker pending 请求加默认 **15 分钟超时自动 reject**（事件轨迹记 timeout 原因，非零订阅者静默），`config.approvalTimeoutMs?: number`（0 = 不限，默认 15000×60）。落点 `src/host/approval.ts`，与 loop 无关。**多端交互标注（v1.1 补，M13 多端方案 §9 R10 同步）**：手机延迟答审批可能已被超时 reject、任务终止——approvalTimeoutMs 可配 0 关闭；M13 Web 审批帧可带倒计时（W6b 可选）。

### 4.3 #3 Skill 重复注入去重

**判定**：`Skill` 工具 execute 时调 `ctx.session.isSkillActive?.(name)`；返回 true → 不返回全文，改回一行：

```
<skill_notice name="x">该 skill 指令已在上文生效，无需重复加载。</skill_notice>
```

**宿主实现**：HostSession 的 `isSkillActive` 扫**投影后** messages（`buildContextMessages` 结果）的 tool_result 内容是否含 `<skill_content name="x"` 标记——O(n) 一次、skill 调用低频可接受；按投影而非全量扫描，/rewind、/clear、压缩后的一致性免费（标记行被投影掉 = 自动回到未激活态，与"消息即状态"同构）。无宿主（argv/测试/子代理）缺省不去重（现状）。

**手动面**：`/skill args` 与 LLM 面最终经同一 Skill 工具 execute，自动获益；实施时验证手动分流路径确实过 execute。

### 4.4 #4 重复 read 去重

**流程**：read_file execute 前 `ctx.session.readFileGuard` 存在则 `check(path)`（宿主 stat 拿 mtimeMs 与 Map 比对）；skip=true → 返回 `文件自上次读取后未变化（本会话已读，见上文 tool_result）。如需强制查看可用 bash cat。`；false → 正常读取 + `record(path, mtimeMs)`。

**边界**：write_file/edit_file 改文件后 mtime 变，下次 read 自然放行；同批次并行读同文件，先完成者 record、后者 skip（本来就是重复读）；**不加 force 参数**——bash cat 是逃生口（D6）。无宿主缺省不去重。

### 4.5 #5 压缩摘要模型分流

**配置**（模板与 /config 面板同步）：

```jsonc
"roles": {
  "summary": { "provider": "zhipu-flash", "model": "glm-4.6-flash" }  // 压缩摘要专用；不配 = 会话模型（现状）
}
```

**消费点**：宿主装配压缩链构造 `CompactionContext` 时（`src/services/compaction/strategy.ts` 装配处），按 `roles.summary` 从 ProviderRegistry 解析出独立 provider + providerReq；未配置回退会话 providerReq。config 加载时校验 provider 名存在于 providers map，缺失报配置错误（启动期校验，不拖到压缩时才炸）。摘要调用已天然不带 thinking（对照文档 §3.3 已核），无需额外动作。

**窗口随角色分流（2026-08-24 审阅补充——effectiveWindow 拆双字段）**：现状 `CompactionContext.effectiveWindow` 一个数三处消费（strategy.ts:25）：①触发阈值（对话逼近窗口该压了）②批预算 `batchBudgetTokens(window)`（summarize.ts:73）③归并轮判定（summarize.ts:155 摘要+近期+预留超窗再压一轮）。分流后摘要模型 ≠ 会话模型，窗口可能更小——①必须盯**主模型**窗口、②③必须盯**摘要模型**窗口，否则批按主模型 200k 切、喂给 128k 的 flash 直接超限，压缩失败（有熔断与手动兜底不伤主流程，但分流功能失效）。实施：

- `CompactionContext` 拆 `triggerWindow`（主模型）+ `summaryWindow`（`resolveContextWindow(roles.summary.model)`——models.dev 预热机制现成，未配 roles 时两值同源现状不变）
- `batchBudgetTokens`/归并判定消费 `summaryWindow`；orchestrator/shouldRun 消费 `triggerWindow`
- 启动期校验追加：`roles.summary` 模型窗口下限**从批预算常量反算**（`MIN_BATCH_TOKENS(20000) + SUMMARY_OUTPUT_RESERVE(4096) + BATCH_BUFFER_TOKENS(8000) + SCOPE_SYSTEM_RESERVE_TOKENS(1500) = 33,596`——v1.1 核码修正，v1.0 写 ~36k 有误；校验取 2 倍余量即 **≥64k**），公式变则校验自动跟
- map-reduce 对小窗口天然免疫——窗口小只意味着批次变多变小（并行 map 不变），不意味着失败；该校验防的是极端小窗（如 32k 以下）而非普通 flash（128k 级均安全）

**provider/providerReq 替换（v1.1 补——核码 P0：漏此分流完全失效）**：装配链 `hook.ts:67-78`（makeOnBeforeRequest）直接把**主会话**的 provider/providerReq 透传给 orchestrator.run（session.ts:428 与 subagent.ts:220 两处调用源）——roles.summary 配置时若只换窗口不换笔，摘要仍发给主模型。实施：装配点解析 roles.summary 出独立 provider + providerReq 传入（未配置回退透传现状）。**B3 批变更由此为三项**：①effectiveWindow 拆双字段 ②provider/providerReq 替换 ③启动期校验（窗口下限+provider 名存在性）。

**分流与前缀缓存不可兼得的权衡（2026-08-24 调研备注）**：harness 的摘要调用复用主对话 system/tools/消息前缀（构造为主请求的真前缀），免费蹭 provider 的 KV cache——但配置独立摘要模型后该对齐失效（不同模型不共享缓存）。ECode 分流**没有这笔机会成本**：map-reduce 分批本就将消息重构为"指令+块"，不保留原前缀，前缀对齐在 ECode 形态下本不成立。算账兜底：flash 全价（≈0.1 美元/M 量级）仍低于旗舰缓存读价（≈全价 10%，0.3 美元/M 量级），roles.summary 是纯赚配置；/config 面板说明文案带一句此权衡。

### 4.6 #6 子代理超时自总结

**落点**：`src/services/subagent.ts` 超时/中断 catch 分支（现 :325 `AbortSignal.timeout`、:341-344 直接取 lastAssistantText 或报错）。

**流程**：超时/中断时若 `lastAssistantText` 为空或过短 → 用**子代理自己的 provider** 发一次性总结调用（`tools: []`、`max_tokens: 2048`、自身限时 60s，`AbortSignal.timeout` 独立信号），prompt 固定格式：

> 任务被中断/超时。请严格按以下格式总结已完成的调查，没查到的明确说没查：状态 / 结论 / 证据位置 / 未确认项 / 下一步。

**产出**：总结文本直接作为 task 工具返回 content（不追加进 messages——D8，与 lastAssistantText 语义不重叠）；transcript 照旧落原始过程，并在尾部附一行自总结标记（供人工复核）。总结调用自身失败 → 回落现状报错路径（报错 + transcript 路径），不无限重试。正常完成路径零改动。

### 4.7 #7 MCP deferred——仅登记复评触发器（不实施）

按对照文档 §4：① M12 token 统计批把"固定前缀 token 量（system + tools.specs()）"纳入 /stats（让"收益不显"可证伪）；② 复评条件——单会话 MCP schema 固定开销占比过高，或 plugin 经 `.ecode-plugin/` 携带大量 MCP 工具进场。触发后另开方案。

### 4.8 观察项：溢出恢复的残余缺口（2026-08-24 登记；v1.1 核码修正原表述）

v1.0 写"ECode 压缩现为阈值预判单触发"**不准确**——核码实证 ECode 已是双触发：阈值预判（`hook.ts:65` pressure）+ loop 内溢出兜底（`loop.ts:262-275` 收到 CONTEXT_TOO_LONG 经 `core/errors.ts:160` 正则识别后 `onBeforeRequest('overflow')` 压缩重试）——与 harness 差异仅在形态（ECode 同轮重试 vs harness 外部再压）。**残余缺口**：压缩未生效（messages 长度未变）时仅 break + warn，本轮报废。观察项改登记此缺口：日志/stats 观测到 overflow 触发后压缩未生效的频率，出现即升格（候选：强制 compactManual + 降批重试）。

## 8. 风险与回退

| 风险 | 缓解 |
|---|---|
| GLM 端点对 cache_control 静默忽略或行为异常 | B0 探针先行；explicitCache 配置逃生口；打标是纯增量字段，回退=开关关 |

| read 去重跳过导致模型读到过期内容 | mtime 语义保证（文件变了必放行）；bash cat 逃生口；无宿主路径不去重 |
