# ECode 双协议出入参规范（Anthropic / OpenAI）

> 整理日期：2026-08-15 · 状态：待审核
> 覆盖 ECode Provider 层实际收发的两协议完整出入参。标注约定：
> **★必填**——缺失即 400；**⚠格式**——有结构性要求，写错即 400 或行为异常；**（ECode）**——本项目的处理方式。
> 代码锚点：`src/providers/anthropic.ts`、`src/providers/openai.ts`、`src/providers/interface.ts`（规范入参 `LLMProviderRunRequest`）。
> 密钥说明：两协议 apiKey 均走 HTTP header（`x-api-key`+`anthropic-version` / `Authorization: Bearer`），由 SDK 注入，**不在请求体内**，无敏感字段落 body。

## 一、Anthropic Messages API（`POST /v1/messages`）

### 1.1 请求体字段

| 字段 | 必填 | 类型/格式 | 作用 | ECode 处理 |
|---|---|---|---|---|
| `model` | ★必填 | string | 模型名（如 `glm-5.2`）| `providerReq.model`（config `models[]`）|
| `messages` | ★必填 | `Message[]`（见 1.2）| 对话本体 | 规范 `Message[]` 透传（`toAnthropicMsgs`）|
| `max_tokens` | **★必填**（协议特有，多数 API 可选此处不是）| number ≥1 | **输出** token 上限 | `resolveMaxTokens`：默认 8192；⚠ thinking 时必须 `> budget_tokens`（clamp 到 budget+1）|
| `system` | 可选 | string | 系统提示词，**独立参数不进 messages** | `buildSystemPrompt()`（M6 注入 skill 清单）|
| `tools` | 可选 | `ToolSpec[]`（见 1.3）| 工具声明 | ⚠ **空数组 `[]` 报 400**——有工具才传（`req.tools.length > 0`）|
| `thinking` | 可选 | ⚠ `{ type:'enabled', budget_tokens:number }` | 扩展思考 | 枚举 off/low/medium/high → budget 2048/8192/16384（`thinkingToAnthropic`）|
| `temperature` / `top_p` | 可选 | number 0-1 | 采样控制 | ⚠ **thinking enabled 时禁传**（否则 400）——条件展开不传 |
| `stream` | 可选 | bool | 流式开关 | SDK `.stream()` 隐含 true（ECode 恒流式）|
| 未用 | — | `tool_choice` / `stop_sequences` / `top_k` / `metadata` | 强制工具/自定义停止等 | YAGNI 未接 |

### 1.2 `messages` 结构（★核心，三条格式铁律）

role 只有 `user | assistant` 两种 ⚠。content 是 **block 数组**（不是纯字符串）⚠，三种形态：

```jsonc
[
  { "role": "user", "content": [
      { "type": "text", "text": "读 package.json" } ]},          // ① TextBlock：type★ text★
  { "role": "assistant", "content": [
      { "type": "text", "text": "好的我来读" },                    // ② TextBlock
      { "type": "tool_use",                                       // ③ ToolUseBlock：
        "id": "call_A",                                           //    id★（唯一，回填配对用）
        "name": "read_file",                                      //    name★
        "input": { "path": "package.json" } } ]},                 //    input★ ⚠是对象（不是 JSON 字符串）
  { "role": "user", "content": [
      { "type": "tool_result",                                    // ④ ToolResultBlock：
        "tool_use_id": "call_A",                                  //    tool_use_id★（必须回填上面的 id）
        "content": "文件内容...",                                  //    content★ ⚠是纯字符串
        "is_error": false } ]}                                    //    is_error 可选（LLM 自纠标志）
]
```

**三条铁律（违反 = 400）**：
1. ⚠ **首条 message 必须 `role:'user'`**（assistant 开头被拒）
2. ⚠ **`tool_result` 必须与配对的 `tool_use` 相邻出现，中间不可切断**（M5 压缩 `preserveToolPairs` 的存在原因）
3. ⚠ **`tool_result` 放在 `user` role 的 content 里**（不是独立 role）

### 1.3 `tools` 结构（扁平三字段）

```jsonc
[{ "name": "read_file",            // ★必填，^[a-zA-Z0-9_-]{1,64}$
   "description": "读取文件内容",   // ★必填（模型靠它决定何时调）
   "input_schema": {               // ★必填，JSON Schema；⚠ECode 约束扁平化（避开 oneOf/$ref，GLM 支持度）
     "type": "object", "properties": { "path": {"type":"string"} }, "required": ["path"] } }]
```

### 1.4 流式出参（SSE 事件序列）

每帧格式 ⚠：`event: <类型>\n` + `data: <JSON>\n` + 空行。事件**按序到达**：

| 事件 | 作用 | ⚠格式要点 | ECode 翻译（→规范 Delta）|
|---|---|---|---|
| `message_start` | 开帧 | 带 `message.usage` 种子；**Astron 等兼容端点此处报 0/0**，真值在 `message_delta` | 攒 usage（守卫覆盖兜兼容端点）|
| `ping` | 心跳保活 | — | 丢弃 |
| `content_block_start` | 开内容块 | **tool_use 块的 `id`/`name` 全流只在此出现一次**；`index` 为块地址 | → `tool_use_start`；建 index→id 映射表 |
| `content_block_delta` | 增量 | 三种子类型：`text_delta`（文字）/ `input_json_delta`（**JSON 碎片，只有 index 无 id** ⚠——id 靠映射表查回）/ `thinking_delta` | text→`text`；json→查表补 id→`tool_use_delta` |
| `content_block_stop` | 块结束 | — | tool_use 块 → `tool_use_end` + 删映射 |
| `message_delta` | 收帧 | **`stop_reason` + 最终 usage**；usage 是**累积语义**（覆盖前值，非增量，禁止相加 ⚠）| mapStopReason 攒着；usage 四维守卫覆盖 |
| `message_stop` | 彻底结束 | — | 无 Delta |
| `error` | 流内错误 | — | → `error` Delta |

**`stop_reason` 取值** ⚠：`end_turn`（答完）/ `tool_use`（要调工具）/ `max_tokens`（截断）/ `stop_sequence` / `content_filter`。loop 据此判退出（`tool_use` → 执行工具继续循环）。

**usage 字段**（message_start 与 message_delta 同构）：`input_tokens` / `output_tokens` / `cache_read_input_tokens`（读缓存，单价 ~0.1×）/ `cache_creation_input_tokens`（写缓存，~1.25×）。

## 二、OpenAI Chat Completions API（`POST /v1/chat/completions`）

### 2.1 请求体字段

| 字段 | 必填 | 类型/格式 | 作用 | ECode 处理 |
|---|---|---|---|---|
| `model` | ★必填 | string | 模型名 | 同上 |
| `messages` | ★必填 | `OpenaiMsg[]`（见 2.2，**与 Anthropic 结构不同** ⚠）| 对话本体 | `toOpenaiMsgs` **真翻译**（非透传）|
| `stream` | — | bool | 流式 | ECode 恒 `true` |
| `stream_options` | 格式要求 | ⚠ `{ include_usage: true }`——**不传则流式拿不到 usage** | usage 开关 | 恒传（P1-6 修复项）|
| `tools` | 可选 | ⚠**包一层 function**（见 2.3）| 工具声明 | `toOpenaiTools` 包装；空数组部分端点 400（有才传）|
| `max_tokens` | **可选**（对比 Anthropic 必填）| number | 输出上限 | config 有才传 |
| `temperature` / `top_p` | 可选 | number | 采样控制 | 直接透传（无 thinking 互斥约束）|
| `reasoning_effort` | 可选 | ⚠ `'low'\|'medium'\|'high'` | 推理力度 | thinking 枚举映射（`thinkingToOpenai`）；⚠ 第三方端点对未知参数可能 400（DeepSeek 通常忽略，OpenAI 非推理模型可能报错）|
| `signal` | — | AbortSignal | 中断 | 直接传给 SDK（对比 Anthropic 需监听 abort 调 `stream.abort()`）|

### 2.2 `messages` 结构（与 Anthropic 四处不同 ⚠）

role 有 **`system | user | assistant | tool` 四种**。content 是**纯字符串**（不是 block 数组）：

```jsonc
[
  { "role": "system",    "content": "你是 ECode..." },            // ① system 是消息，不是独立参数 ⚠
  { "role": "user",      "content": "读 package.json" },          // ② content 纯字符串 ⚠（多块需 join）
  { "role": "assistant", "content": "好的我来读",                  // ③ 工具调用不在 content 里，
    "tool_calls": [                                               //    在并列的 tool_calls 数组 ⚠
      { "id": "call_A", "type": "function",                       //    type★'function'
        "function": { "name": "read_file",                        //    再包一层 function ⚠
          "arguments": "{\"path\":\"package.json\"}" } }]},       //    ⚠ arguments 是 JSON 字符串（非对象！）
  { "role": "tool",                                                // ④ tool_result 是独立 role:'tool' 消息 ⚠
    "tool_call_id": "call_A",                                      //    ★必填（对应 tool_calls[].id）
    "content": "文件内容..." } ]                                   //    每条 result 一条消息（不合并）
]
```

**铁律**：⚠ `role:'tool'` 消息必须紧跟在带 `tool_calls` 的 assistant 消息之后（配对不可断，同 Anthropic 语义但结构不同）。

### 2.3 `tools` 结构（包裹式）

```jsonc
[{ "type": "function",                          // ★必填，恒 'function'
   "function": {
     "name": "read_file",                       // ★必填
     "description": "读取文件内容",
     "parameters": { "type":"object", ... } } }] // ★schema 字段名叫 parameters（非 input_schema）⚠
```

### 2.4 流式出参（chunk 序列）

**没有 `event:` 行**——所有帧都是 `data: {chunk}`，⚠**靠「delta 里出现什么字段」区分类型**（形状区分）：

```jsonc
// ① 文字：delta.content 出现
{"choices":[{"delta":{"content":"好的"}}]}
// ② 工具首块：tool_calls[i] 带 index + id + name（id/name 全流只在此出现一次）
{"choices":[{"delta":{"tool_calls":[{"index":0,"id":"call_A","function":{"name":"read_file"}}]}}]}
// ③ 工具入参碎片：只有 arguments（⚠JSON 字符串碎片，靠 index 归属）
{"choices":[{"delta":{"tool_calls":[{"index":0,"function":{"arguments":"{\"pa"}}]}}]}
// ④ 收尾：finish_reason 出现
{"choices":[{"delta":{},"finish_reason":"tool_calls"}]}
// ⑤ usage-only 末块：choices 为空数组 ⚠
{"choices":[],"usage":{"prompt_tokens":170,"completion_tokens":23,"prompt_tokens_details":{"cached_tokens":0}}}
```

**⚠ 四个格式要点**：
1. **并行工具靠 `tool_calls[].index` 归属**（碎片无 id，翻译层须建 index→id 表——与 Anthropic 的 content block index 同理）
2. **无显式「块结束」事件**——`finish_reason='tool_calls'` 时统一收尾；若 `length` 截断在工具中途，须在流结束 flush **补发未 end 的工具**（ECode `OpenaiTranslator.flush` 的 ended 集合，P2-9）
3. **usage 在最后一个 chunk** 且 `choices:[]`——须开 `stream_options.include_usage`，且解析要容忍无 choices 的帧
4. **finish_reason 取值**：`stop`（≈end_turn）/ `length`（≈max_tokens）/ `tool_calls` / `content_filter`

## 三、详细对比

### 3.1 入参对比

| 维度 | Anthropic Messages | OpenAI Chat Completions |
|---|---|---|
| 端点 | `POST /v1/messages` | `POST /v1/chat/completions` |
| **必填差异** | `model` + `messages` + **`max_tokens`（★特有必填）** | `model` + `messages`（max_tokens 可选）|
| system 位置 | **独立参数**（不进 messages）| **messages[0] 的 `role:'system'`** |
| content 形态 | **block 数组**（text/tool_use/tool_result 混排）| **纯字符串**（工具走别的字段）|
| 模型要调工具 | content 里嵌 `{type:'tool_use', input:对象}` | 并列字段 `tool_calls[{function:{arguments:JSON字符串}}]` |
| 工具结果回喂 | `user` 消息 content 里的 `tool_result` block | **独立 `role:'tool'` 消息**（`tool_call_id` 配对）|
| role 枚举 | `user`/`assistant` 两种 | `system`/`user`/`assistant`/`tool` 四种 |
| tools 声明 | 扁平 `{name, description, input_schema}` | **包裹** `{type:'function', function:{name, description, parameters}}` |
| schema 字段名 | `input_schema` | `parameters` |
| 工具入参类型 | `input` 是**对象** | `arguments` 是 **JSON 字符串** |
| 思考控制 | `thinking:{type:'enabled', budget_tokens:N}`；⚠ 与 temperature 互斥 | `reasoning_effort:'low|medium|high'`；无互斥 |
| 空工具数组 | ⚠ `tools:[]` 报 400 | 部分端点报 400（ECode 统一：有才传）|

### 3.2 出参对比

| 维度 | Anthropic | OpenAI |
|---|---|---|
| 流式风格 | **事件名区分**（`event:` 行：message_start/content_block_*/message_delta）| **字段形状区分**（无 event 行，看 delta 出现什么字段）|
| 内容块寻址 | `content_block_*` 的 `index` | `tool_calls[].index`（文字无 index）|
| 工具 id/name 何时出现 | `content_block_start` 一次 | 首个 tool_calls chunk 一次 |
| 工具入参增量 | `input_json_delta.partial_json` | `function.arguments` 碎片 |
| 块结束信号 | **显式** `content_block_stop` | **无**（finish_reason='tool_calls' 统一收尾 + flush 兜底）|
| 停止原因 | `message_delta.stop_reason`：`end_turn`/`tool_use`/`max_tokens`/`stop_sequence`/`content_filter` | `finish_reason`：`stop`/`tool_calls`/`length`/`content_filter` |
| usage 位置 | message_start 种子 + message_delta 终值（**累积覆盖**语义）| **最后一个 chunk**（choices:[]，需 `stream_options.include_usage`）|
| cache 计数 | `cache_read_input_tokens` / `cache_creation_input_tokens`（两个字段）| `prompt_tokens_details.cached_tokens`（嵌套一个字段）|
| 心跳 | `ping` 事件 | 无 |

### 3.3 ECode 翻译层对照（两协议 → 同一套规范 Delta）

| 规范 Delta | anthropic.ts 触发 | openai.ts 触发 |
|---|---|---|
| `text` | `text_delta` 事件 | `delta.content` 字段出现 |
| `tool_use_start` | `content_block_start(tool_use)` | tool_calls 首块（id+name 齐）|
| `tool_use_delta` | `input_json_delta` | `function.arguments` 碎片 |
| `tool_use_end` | `content_block_stop` | finish_reason='tool_calls' 或 flush 补发 |
| `usage` | start+delta 守卫覆盖聚合 | usage-only 末块 |
| `done` | `message_delta.stop_reason` | `finish_reason` |
| `error` | `error` 事件 | —（SDK 抛异常走 errors.ts）|

**出方向（请求翻译）成本不对称**：规范模型贴近 Anthropic 设计 → `toAnthropicMsgs` 是**透传**（3 行）；`toOpenaiMsgs` 是**真翻译**（system 注入首条 / 多 text join / tool_use→tool_calls+JSON.stringify / tool_result→独立 role:tool 消息）。入方向两家都要有状态翻译器（index→id 映射 + usage 聚合 + stopReason 映射），各自封在 Translator 类内，loop 只消费规范 Delta——协议差异零渗漏（详设 §2.4 铁律）。

### 3.4 两协议共同的坑清单（ECode 已防御）

1. 空 tools 数组 400 → 有才传（两家统一策略）
2. 工具配对不可切断 → M5 压缩 `preserveToolPairs` 在规范层保护（协议无关）
3. 中断：Anthropic 需监听 abort 调 `stream.abort()`（finally 摘监听防泄漏）；OpenAI signal 直传 SDK
4. 兼容端点 usage 偏差（Astron start 报 0/0）→ 守卫覆盖聚合（M5 修复，对齐官方 SDK 0.115+ 写法）
5. OpenAI 非推理模型对 `reasoning_effort` 可能 400 → config `thinking:off` 规避（文档化）
