# Esc/Ctrl+C 键位分工 — 详设

> 任务 #10。本文档经两次决策：
> ① 2026-08-07 初版方案 A（Esc 专职中断 / Ctrl+C 专职退出）已实施于 `b972f13`；
> ② **同日用户反馈反转** → **Ctrl+C 中断+退出 / Esc 退出弹窗+双击清空**（本版，已实施）。

---

## 一、当前键位分工（二次修订，已实施）

| 键 | 行为 |
|----|------|
| **Ctrl+C 单击** | 中断对话（streaming 时 abort agent） |
| **Ctrl+C 双击**（2s 内） | 关闭对话（`process.exit` 退出程序） |
| **Esc（弹窗内）** | 退出该弹窗：picker→关闭 / 权限→deny / 会话→取消 |
| **Esc（主输入区）双击**（500ms 内） | 清空输入框 |
| **Esc 单击（主区）** | 无操作 |
| Ctrl+O | 转录 pager（不变） |

> 设计：**Ctrl+C 包揽中断+退出**（对齐 Claude Code 经典交互：一次中断、两次退出）；
> **Esc 只做两件事——退出弹窗 + 双击清空**，不中断、不退出程序。
> 弹窗内 Esc 由各 modal 组件自身 `useInput` 接（App 全局不抢）；主区 Esc 双击清空由 InputBar 接。

---

## 二、完整行为矩阵

| 场景 | Ctrl+C 单击 | Ctrl+C 双击 | Esc |
|------|------------|------------|-----|
| streaming | **中断 agent** | 退出程序 | 无操作（不中断） |
| idle·输入框有内容 | 进退出窗口 | 退出程序 | 双击→清空；单击无操作 |
| idle·输入框空 | 进退出窗口 | 退出程序 | 无操作 |
| picker 打开 | 进退出窗口 | 退出程序 | 单击→关 picker |
| 权限弹窗 | （modal 各自处理） | （modal） | 单击→deny |
| 会话选择 | （modal） | （modal） | 单击→取消 |
| pager | 让位 less | 让位 less | 让位 less |

> modal 打开时 InputBar 不挂载（App 三元 `resumeOpen ? SessionPicker : pendingPermission ? PermissionDialog : InputBar`），
> 故 modal 的 Esc 由各自组件 `useInput` 处理，与 App 全局 / InputBar 无冲突。

## 三、改动清单

### `src/ui/app.tsx`（全局 useInput）
- **删 Esc 分支**（中断归 Ctrl+C；Esc 退出弹窗归各 modal、清空归 InputBar）。
- **Ctrl+C 分支**：双击(2s)→`process.exit`；单击→`setLastCtrlC`（进退出窗口）+ `if(isRunning) api.abort()`（中断）。
- `lastCtrlC` state / `lastCtrlCRef` / phase（permission > exit-window > streaming > idle）保留。

### `src/ui/input-bar.tsx`（主输入区 Esc 双击清空）
- 非 picker 分支新增 Esc 双击：`DOUBLE_ESC_MS`(500ms) 内第二次 Esc → `setText('')` + `dispatch({type:'reset'})`；单击仅记 `lastEscRef`、无操作。
- picker 分支 Esc 关 picker（不变；picker 态 Esc 不参与双击计数，避免关 picker 误触清空）。
- reducer 加 `reset` action（清空回草稿态 index=-1，保留已提交历史）。
- disabled 文案 `esc to interrupt` → `ctrl+c to interrupt`。

### `src/ui/status-bar.tsx`
- streaming 动态段 `esc to interrupt` → `ctrl+c to interrupt`。

## 四、TDD（`tests/ui/repl-human.test.tsx`）

- `Ctrl+C 中断运行中流`（streaming → ctrlC → abort → 输入栏恢复）
- `Esc 不中断流`（streaming → esc → 仍 running；中断专职 Ctrl+C）
- `Ctrl+C 双击 → process.exit`（关闭对话）
- `双击 Esc 清空输入框`（idle 有内容 → esc esc → 清空）
- `picker 打开时 Esc 关 picker`（不退出不清空，输入保留）
- 联动：`status-bar.test.tsx` / `input-bar.test.tsx` 文案断言同步 `ctrl+c`。

全量 402 测试绿，tsc clean。

> 踩坑：初版（b972f13）的 Esc 中断在 fake-timer 下靠 `sim.esc()` 的 20ms escape flush 触发，abort 链路渲染 flush 时序不稳；
> 本版 Ctrl+C 走 `'\x03'` 立即 emit，abort 链路稳定生效（`Ctrl+C 中断` 用例真绿，非假绿）。

## 六、方案演进（历史）

1. **`b972f13` 初版（方案 A）**：Esc 专职中断 / Ctrl+C 专职退出（单击不中断、只进退出窗口）。
   - breaking：streaming 时 Ctrl+C 单击不再中断，改 Esc。
2. **2026-08-07 用户反馈反转**：用户要 **Ctrl+C 一次中断、两次关闭**（对齐 CC 经典）+ **Esc 只退出弹窗 + 双击清空输入框**。
   - 即恢复 `b972f13` 之前的 Ctrl+C 单击中断（加回一行 `abort`），双击退出保留；
   - Esc 撤销中断职责，改为退出弹窗（modal 内，原本就有）+ 主区双击清空（新增）。
   - 回退到方案 A 只需在 app.tsx Ctrl+C 分支删 `if(isRunning) abort()` + 加回 Esc 分支。
