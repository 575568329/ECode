## 一、范围界定（本里程碑做什么 / 不做什么）

### 1.1 M5 = 三个 L4 扩展层挂载点

总纲 [`00-开发规划`](../总纲/00-开发规划[进行中].md) §4.1 明示：L4 扩展层（子代理 / MCP / Hooks / Skills）当前**无代码**，是 M5+ 要「长」出来的挂载点，复用核心 loop、不动核心。本里程碑落地前三者（Skills 推 M6，依赖 Hooks 的 Stop 事件触发归纳）。

| 支点 | 一句话 | 本里程碑范围 |
|------|--------|-------------|
| **支点 9 子代理** | 主代理派「侦察兵」分身独立跑，只回结论 | ✅ Task 工具 + agents 定义 + 递归 runAgentStream + 权限⊆ + 结果回收 |
| **支点 10 MCP** | 装「第三方 App」的应用商店协议，工具自动调 + Prompt 手动触发 | ✅ 阶段 1 stdio + Tools + Prompts 原语 + 独立注册 + /mcp；⏸ 阶段 2 Streamable HTTP+OAuth 远期 |
| **支点 12 Hooks** | agent 生命周期关键事件挂自定义脚本 | ✅ 6 核心事件 + 系统 hooks 强制叠加 + 用户 hooks 分层 + Pre/Post 注入 |

### 1.2 三支点的共同红利：复用主干道，不造新循环

| 复用资产 | 位置 | 子代理怎么用 | MCP 怎么用 | Hooks 怎么用 |
|---------|------|------------|-----------|-------------|
| `runAgentStream` | `agent.ts:255` | **递归调一次**（换 system+tools+空 messages） | 不直接用（MCP 工具是 execute 闭包） | 不动（只挂回调） |
| `check()` 权限流水线 | `permission/rule-engine.ts` | 继承（allow 副本 + 模式 + denyRules） | MCP 工具 dangerous=true 走 check | hook 在 check 前后注入 |
| `permissionGate` 注入 | `agent.ts:461` | 子代理共享主对话 gate（ask 归主对话） | MCP 工具 ask 弹窗 | PreToolUse hook = 同款 Promise-await 模型 |
| 事件流 `AgentEvent` | `agent-events.ts` | 子代理**不对外** yield（黑盒） | 不用 | Stop 走事件流 |
| 声明式 `ToolDefinition` | `tools/types.ts` | Task 工具加一条；子代理 tools 是它的子集 | MCP 工具适配成此形状 | 不用 |

**唯一对核心的侵入**：`runAgentStream` 当前**硬编码** `toolDefinitions`（`agent.ts:272`），不支持外部注入工具集。子代理（限定工具子集）和 MCP（动态加第三方工具）都需要 `RunAgentStreamOptions` 新增 `tools?: ToolDefinition[]` 选项。这是本里程碑的**地基改动**（阶段 0），改动极小（一行默认值 + 透传），不破坏现有 683 测试。

### 2.2 数据流：三支点如何接入 agent loop

```
                        ┌─ agents/*.md catalog ─→ system prompt（主 LLM 知道可派谁）
                        │
用户 prompt ──→ runAgentStream ──→ LLM 返回 tool_use(name='Task', input={description,prompt})
                        │              │
                        │              ▼ （Task 工具 execute）
                        │      递归 runAgentStream(子) ── 独立 messages + tools子集 + 权限⊆
                        │              │  ↑ 不对外 yield 中间过程（黑盒）
                        │              ▼ 只回最终 assistant text（侦察兵模式）
                        │      tool_result(子代理结论) ──→ 主 LLM 综合后回用户
                        │
                        │   ┌─ MCP: listTools() → ToolDefinition[] 合并进 opts.tools（透明，LLM 自动调）
                        │   │   MCP 工具 dangerous=true → check() → ask 弹窗（不可信代码）
                        │   ▼
   每个工具执行 ──→ ① PreToolUse hook（Promise-await，可 deny/block/改输入）
                        ↓
                   ② check() 权限流水线（deny→ask→allow→mode）
                        ↓
                   ③ executeTool
                        ↓
                   ④ PostToolUse hook（可改输出）
                        ↓
                   tool_result 回喂
                        ↓
   会话终止 ──→ Stop hook（走事件流，可打回继续干）
```

## 三、核心设计决策（源自支点讨论记录，已拍板）

> 这些决策在 [`支点讨论记录`](../功能方案/支点讨论记录[已完成].md) 支点 9/10/12 已逐条确认，本节只列结论，理由见方案解析。

### 子代理（支点 9）

1. **侦察兵模式**：子代理只回**最终结论**（assistant 末尾文本），不回中间过程（防主上下文污染 + 主代理退化成传话筒）。
2. **复用主干道**：子代理 = 递归调一次 `runAgentStream`（换 system + tools 子集 + 空 messages），不造新循环。
3. **权限⊆红线**：子代理权限**只能更严不能更宽**——默认继承主代理模式 + denyRules + 已批准 allow；可被人设 `tools:` 字段**收紧**（限定工具子集）。防「权限代持绕过审批」。
4. **ask 归主对话**：子代理的 `permissionGate` 共享主对话（不让子代理自己弹窗），弹窗在主 REPL。
5. **不独立沉淀/不存 session**：跑完即弃；结论回主代理，由主代理决定记不记。

### MCP（支点 10）

6. **App Store 协议**：MCP server = 第三方 App，接上协议白嫖生态（GitHub/Slack/DB…）。
7. **独立注册，不进 config.json**：MCP 安装态在 `~/.ecode/mcp/registry.json`，防用户替换 config 不知情连坐删 MCP（VS Code 扩展模式）。
8. **传输分阶段**：阶段 1 **stdio**（本地起步，隐私+凭证不出机器）→ 阶段 2 **Streamable HTTP + OAuth**（远程，跟上趋势；旧 HTTP+SSE 已废弃）。
9. **做 Tools + Prompts 原语**：Tools 透明加入工具列表 LLM 自动调（不用 / 命令）；Prompts 斜杠 `/mcp__server__prompt` 手动触发（位置参数模板，实现极简，2026-08-09 砍→做反转，见技术选型 10-T3a）；Resources 后置（Tools 暂能替代）。
10. **不可信代码红线**：MCP server 是第三方不可信代码 → MCP 工具必须走权限审批 + 用户显式登记 + 防 stdio RCE（最小权限）。
11. **`/mcp` 只读可观测**：server 清单 + 连接状态 + 暴露工具（不执行，呼应支点 17）。

### Hooks（支点 12）

12. **6 核心事件先做**：`SessionStart` / `SessionEnd` / `UserPromptSubmit` / `PreToolUse` / `PostToolUse` / `Stop`。其他（SubagentStop/PreCompact/Notification/FileChanged 等）记录，看情况加。
13. **系统 hooks 强制叠加**：代码注册（hardcoded registry），用户 config **无法删除/覆盖**，只能追加自己的。系统级一切跟 config.json 零依赖。
14. **用户 hooks 进 config 分层**：user（`~/.ecode/`）/ project（`.ecode/`，git 跟踪）/ project-local（`.ecode/`，gitignore）。
15. **Pre/Post 必须 Promise-await，Stop 可走事件流**：Pre/Post 要「等决策」（可 deny/block/改输入输出），单向事件流承载不了；Stop 只通知，复用事件流。
16. **hook 只能收紧不能放宽**：权限 `deny` 是硬边界，hook 不能覆盖。执行顺序 `PreToolUse hook → check() → 执行 → PostToolUse hook`。
17. **handler 先做 command**（shell），http/prompt/agent 后置。hook 命令跨平台走 bash 工具同款 shell 分流（呼应 §9.3）。

**接口设计**：

```ts
// 输出形如：

// - **code-reviewer**：审查代码质量与风险。工具：只读。
```

```ts
// src/tools/subagent.ts —— Task 工具
// 注册进 registry.ts（一条），dangerous=true（子代理会调 read/write/bash，须审批）
export const taskTool: ToolDefinition = {
  name: 'Task',
  description: '派遣子代理独立完成子任务（独立上下文），只回最终结论。适合读/分析大量文件、并行处理多模块。',
  dangerous: true,
  parameters: {
    type: 'object',
    properties: {
      description: { type: 'string', description: '子任务一句话描述（给用户看进度）' },
      prompt: { type: 'string', description: '给子代理的完整指令' },
      agent: { type: 'string', description: '可选：派专项人设（.ecode/agents/*.md 的 name）' },
    },
    required: ['description', 'prompt'],
  },
  execute: (input) => runSubagent(input),
};

// execute 核心：递归 runAgentStream，侦察兵模式（只回最终文本）
async function runSubagent(input: {
  description: string; prompt: string; agent?: string;
}): Promise<ToolResult> {
  // 0. 嵌套深度硬限制（仿 opencode task.ts:104-117 + subagent_depth，默认 1）：
  //    子代理默认不能再派子代理（防递归爆炸）。可经 settings 的 subagentDepth 调。
  if (currentDepth >= (settings.subagentDepth ?? 1)) {
    return { content: `子代理嵌套深度超限（${settings.subagentDepth ?? 1}），拒绝派发`, isError: true };
  }
  // 1. 选人设：agent 命中 loadAgents() 则用其 systemPrompt + tools 子集；否则用默认（继承主 system）
  const persona = agents.find(a => a.name === input.agent);
  const subSystem = persona?.systemPrompt ?? buildSystemPrompt();  // 默认读项目 CLAUDE.md（支点 9 决策）
  const subTools = persona?.tools
    ? toolDefinitions.filter(t => persona.tools!.includes(t.name))  // 人设收紧工具子集
    : toolDefinitions;

  // 2. 权限⊆：继承主代理 allow（副本）+ permissionMode + denyRules；gate 共享主对话（ask 归主）
  //    （allow/denyRules/mode/gate 由闭包捕获主 runAgentStream 的 opts，见接线 §五）

  // 3. 递归：空 messages（独立上下文），drain 事件只取最终 assistant text（黑盒，不 yield 中间）
  let conclusion = '';
  for await (const event of runAgentStream(input.prompt, {
    system: subSystem,
    tools: subTools,
    allow: inheritedAllow,            // 副本：子代理能用主代理已批准的，但不能新增放宽
    permissionMode: inheritedMode,
    denyRules: inheritedDenyRules,
    permissionGate: mainGate,         // 共享：子代理 ask 弹窗归主对话
    provider,                         // 复用主 provider
  })) {
    if (event.type === 'completed') conclusion = extractFinalText(event.messages);
    if (event.type === 'error') return { content: `子代理执行失败: ${event.message}`, isError: true };
  }
  return { content: conclusion || '（子代理未产出文本结论）', isError: false };
}
```

**接线（agent.ts）**：Task 工具的 execute 需要拿到主 `runAgentStream` 当前 opts（allow/mode/denyRules/gate/provider）以实现权限⊆。方案：Task 工具不静态注册，而是在 `runAgentStream` 内**动态构造** taskTool 闭包（捕获当前 opts）后并入 `tools`。这样权限继承天然成立，无需全局态。

```ts
// agent.ts runAgentStream 内（阶段 0 的 tools 之后）：
const tools = useTools ? (opts.tools ?? toolDefinitions) : [];
// 阶段 1：动态注入 Task 工具（闭包捕获本 runAgentStream 的 allow/mode/denyRules/gate/provider）
const taskTool = createTaskTool({ allow, permissionMode, denyRules: opts.denyRules, gate: opts.permissionGate, provider, model: resolvedModel });
const toolsWithTask = [...tools.filter(t => t.name !== 'Task'), taskTool];
```

```ts
  | 'SessionStart' | 'SessionEnd' | 'UserPromptSubmit'
  | 'PreToolUse' | 'PostToolUse' | 'Stop';

export interface HookDef {
  event: HookEvent;
  /** command handler：shell 命令（跨平台走 bash 工具同款 shell 分流）。http/prompt/agent 后置 */
  command: string;
  /** PreToolUse/PostToolUse 的工具名 matcher（glob，如 'Bash' / 'Edit' / '*'） */
  matcher?: string;
  source: 'system' | 'user' | 'project' | 'project-local';
}

/** hook 返回：可阻断（deny）、改输入输出、或纯通过 */
export interface HookResult {

  reason?: string;                          // deny/block 的原因（回喂 LLM）

  modifiedOutput?: string;                  // PostToolUse 改输出
  stopHookContinue?: boolean;              // Stop hook 打回继续干（true=不让停）
}
```

**接线（agent.ts，挂点已定位）**：

| Hook | 挂点（agent.ts） | 注入方式 |
|------|-----------------|---------|
| **PreToolUse** | `for (const tc of toolCalls)` 入口（`:417`），`check()`（`:421`）**之前** | `await opts.hooks?.preToolUse(tc.name, tc.input)` → 若 deny/block → 同权限 deny 分支回喂；若 modifiedInput → 替换 tc.input |

| **SessionEnd** | `runAgentStream` 收尾（finally） | 走事件流 |
| **UserPromptSubmit** | `submit` 入口（use-agent-stream / drain 点） | 走事件流 |

```ts
// src/mcp/adapter.ts —— MCP prompt → 斜杠命令（Prompts 原语，2026-08-09 砍→做，见技术选型 10-T3a）
// 复用现有斜杠命令系统：每个 prompt 注册成一条命令，位置参数 → arguments map（双源共识，非 TUI 表单）
export function adaptMcpPrompt(
  serverName: string,
  mcpPrompt: McpPromptDescriptor,
  client: McpConnection,
): SlashCommandDef {
  const argNames = mcpPrompt.arguments?.map((a) => a.name) ?? [];
  return {
    name: `mcp__${serverName}__${mcpPrompt.name}`,   // 命名同 tool
    description: mcpPrompt.description ?? '',
    argNames,                                          // 给 typeahead 生成 [arg] hint
    execute: async (args) => {
      const argv = shellQuoteSplit(args);             // shell-quote 切参（比 CC split(' ') 强，支持带空格值）
      const argMap = Object.fromEntries(argNames.map((n, i) => [n, argv[i] ?? '']));  // 位置→具名，缺参空串
      const { messages } = await client.getPrompt({ name: mcpPrompt.name, arguments: argMap });
      injectAsUserMessage(messages);                  // 作为 user message 注入对话（双源一致）
    },
  };
}
```
