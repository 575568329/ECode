# ECode M2 TUI 实施方案

> 日期：2026-08-12 · 状态：**草案待讨论**
> M1 已完成（readline REPL + 心脏闭环，真 LLM 跑通）。M2 把 readline 换成 Ink 7 全屏 TUI。
> 本文是 TUI 规范（"做什么"）到实施（"怎么做、什么顺序、验收什么"）的桥梁。
> 标 ★ 的决策点需要讨论拍板。

## 1. 目标 & 验收

**目标**：把 M1 的 readline REPL 换成 Ink 7 全屏 TUI，loop 的 callbacks 接到 TUI 组件。

**验收标准**（对应详设 §10 M2）：
- 流式期灰字占位 → 完成后 markdown 正确渲染（代码高亮 / 表格 / 列表）
- Ctrl+C 中断（一次中断 + 1.5s 内两次退出），中断后已生成内容保留
- ActivityBar loading 常驻（用户始终知道当前状态，§4.10）
- 工具调用 3 行摘要 + 折叠/展开 + 同轮聚合（§4.11）
- `<Static>` 几百条消息重绘 < 100ms

## 2. 范围

**M2 做**：
- Ink 7 接入（替换 readline）+ **自建 TextInput/Select/Spinner**（不用 @inkjs/ui，组件方式插入，参考 `D:\study\claude-code-main` 源码：`BaseTextInput.tsx` / `CustomSelect/` / ink components）
- **自建三件**：流式分阶段渲染 / 终端 Markdown / 折叠 ToolCallView
- 13 组件（见 TUI 规范 §7）
- Ctrl+C 中断 + **AbortSignal 透传**（loop→provider→SDK，补 M1 TODO）
- 适度色彩（暗色主题，`theme.ts`）
- 焦点导航（`useFocus` + Tab，输入框 ↔ 折叠区）
- 斜杠命令 `/help` `/clear`（**CommandRegistry 可扩展**：未来 skill / 管理命令注册，呼应 CC 把 commands 合并进 skills）
- **bash 确认 ConfirmPrompt → 挪 M3**（和写工具 diff + 危险命令拦截一起做）；M2 bash 延续 M1 默认全确认（ActivityBar 显示命令可见即可）

**M2 不做**（留后续）：
- 写工具 `write_file`/`edit_file`（M3）→ ConfirmPrompt 的 diff 预览随 M3
- `glob`/`grep`/`ls`（M3）
- 斜杠命令 `/model` `/history`（M4，需 Config 完整版 + HistoryStore）
- bash 全套安全（危险命令拦截/输出截断，M3）
- 首次运行向导（M2 只欢迎屏）
- 历史持久化（M4）

## 3. 前置烟测（第 0 步，决定方案）★

M2 开工前必做（技术栈解析决策 2 反驳点）：
1. 装依赖（见附录 A）：ink@7 + react + marked + cli-highlight + string-width + wrap-ansi + cli-table3（**自建 TextInput/Select/Spinner，不用 @inkjs/ui**）
2. ~~烟测 `@inkjs/ui`~~（**已定自建 TextInput/Select/Spinner，不用 @inkjs/ui**，见附录 A）
3. 烟测 `<Static>` 几百条消息重绘性能（< 100ms）
4. 烟测 Ink 下 Ctrl+C / AbortSignal 行为（中断 SDK 流式请求）
5. 烟测 string-width 中文宽度处理
6. **滚动行为（结论已定，仅剩真终端验证）**：经源码核实 **Ink 7 无任何鼠标 API**（[Issue #765](https://github.com/vadimdemedes/ink/issues/765) 列为 non-goal，见附录 B.1），follow 滚动锁定**不走鼠标**。**不开 alternateScreen**（保终端原生 scrollback，用户用滚轮/Shift+PgUp 滚历史）；Static 走单独 buffer，动态区刷新不擦历史（滚动友好的根因）。**剩余验证**：真实终端（Windows Terminal）下流式重绘是否打断用户滚历史。

> 烟测结果影响方案：① 依赖兼容（已升级到全 ESM 纯净版，见附录 A）；② 滚动（已确认 Ink 7 无鼠标 API，follow 改依赖终端原生 scrollback + 键盘，见上）；③ Static 性能（M2 烟测实测 1000 条 224ms、增量 O(1)，非阻断）。

## 6. 风险 & 开放问题

- **Ink 7 兼容**：`@inkjs/ui` 等是否跟上（烟测）—— 不兼容则降级 Ink 5 或换组件
- **Static 性能**：几百条消息重绘（烟测）—— 不达标则增量渲染优化
- **流式 markdown**：M2 灰字占位（求稳），增量宽容解析留后续

## 7. 自建组件设计理念（借鉴 Claude Code，ECode 简洁化）

> 原则：**学设计理念（why），不抄代码（how）**。Claude Code 是生产级（Cursor.ts 1530 行，含 Emacs kill-ring / image-chip / voice 等高级特性）；ECode 是 MVP——精简到够用，做出自己的特色（简洁 + 跨平台中文 + 流式友好）。
> 参考源码：`D:\study\claude-code-main/src/components`（BaseTextInput / CustomSelect / Spinner）。

### 可借鉴的设计理念（6 条）

1. **编辑逻辑与渲染分离（TextInput）**：光标编辑做成独立纯函数模型（Cursor），不散在 useInput 的 if-else。好处：可单测、渲染层薄。**ECode**：Cursor 精简（insert/backspace/left/right + 反色渲染 + 停泊），不做 Emacs kill-ring / image-chip。
2. **光标反色渲染（TextInput）**：用反色（`chalk.inverse`）当前字素，不塞 `▋` 字符。好处：跨字素不错位、多行定位准。**ECode**：直接采用（成本低效果好）。
3. **停泊原生终端光标（TextInput）**：把原生光标移到 caret 位置。好处：中文输入法 / IME / 读屏兼容。**ECode**：**必做**（支持中文输入的必要投入，@inkjs/ui 没做这点）。
4. **动画共享单时钟（Spinner）**：N 个动画订阅一个 Clock（单定时器 + 订阅 + keepAlive + 离屏暂停）。**ECode**：ActivityBar + 工具 spinner 共享一个 Clock（避免多 setInterval，帧同步）。
5. **导航状态机化（Select）**：选项导航用 reducer（可预测）+ 视口边缘滚动（焦点触底才滚一格）+ 首尾环绕。**ECode**：精简 reducer（固定 ↑↓Enter Esc，不做 keybinding 可配置）。
6. **乒乓帧 + reduced-motion（Spinner）**：`[...chars, ...chars.reverse()]` 来回弹；reduced-motion 退化静态。**ECode**：乒乓帧（零成本）；reduced-motion 留后续（MVP 可不做）。

### ECode 简化（不做的 Claude Code 高级特性）

- Emacs 快捷键（Ctrl+A/E/K kill-ring）
- 图片 chip（`[Image #N]` 整体跳过）
- voice 波形光标
- keybinding 可配置（`/keybindings`）
- 颜色插值（卡顿变红）
- SelectMulti（MVP 单选够用）

### ECode 特色

- **简洁**：Cursor ~150 行（CC 1530），只做核心编辑。
- **跨平台中文**：反色光标 + 停泊原生光标（IME 兼容）。
- **流式友好**：灰字占位→commit（方案 A，滚动友好，§4.12）。
- **适度色彩**：暗色主题，工具青/状态色/灰字次要（不做颜色插值）。

## 附录 B：核心组件调研与设计（2026-08-12）

> **调研对象**：自建三件（Markdown / ToolCallView / render.ts）的实现方案。
> **方法**：① 查现成库（marked-terminal / cli-markdown / ink-markdown）维护状态与兼容性；② 读本地 claude-code-main / opencode / aider 源码；③ 读 Ink 7.1.1 源码（useFocus / Static / 鼠标支持现状）。
> **核心结论**：**三家主流终端 Agent（Claude Code / Aider / opencode）的 markdown 渲染全部自建，无一家用现成库。**

### B.1 关键发现（影响方案的事实）

1. **marked-terminal 不可用**（三重墙）：
   - **Ink 布局冲突**：它输出整段预格式化 ANSI 字符串，喂给 Ink `<Text>` 后 Ink 会再次换行，与它内部的换行/表格布局打架（表格错位、长行重复折行）。也丧失 Ink 组件组合能力（无法在代码块上加可交互的折叠/复制）。
   - **CJK 换行 bug**：源码 `reflowText` 用 `.length`（字符数）而非显示宽度，中文长行按宽度折行算错（默认 `reflowText:false` 不暴露，一开自动折行即翻车）。
   - **marked v18 不兼容**：peerDep 锁 `marked >=1 <16`，marked 已到 v18，强行用须锁 v15。
2. **ink-markdown 已死**：2023-10 后停更（≈3 年），本质是 marked+marked-terminal 的壳，无独立价值。
3. **Ink 7 无内置 Collapsible**：组件只有 Box/Text/Static/Newline/Spacer/Transform，折叠须自建（`useFocus`+`useInput`+`useState`）。
4. **Ink 7 无鼠标 API**：全仓库零鼠标实现，[Issue #765](https://github.com/vadimdemedes/ink/issues/765) 明确列为 non-goal。要滚轮须自己往 stdin 写 `\x1b[?1006h` + 解析 SGR 序列（可参考 claude-code-main 的 parse-keypress.ts）。
5. **Static 机制**：走单独 buffer，主树重渲染时 `skipStaticElements` 跳过 static 节点——已提交消息冻结，动态区刷新不擦历史（滚动友好的根因）。

### B.2 Markdown.tsx 设计

**决策：自建渲染层（marked 只做 lexer，不用 marked-terminal）。** ★

**理由**：① 三家都自建（Claude Code = marked.lexer + 自建 formatToken + Ansi 桥；opencode = marked.lexer + remend + shiki；aider = rich.markdown + Live 窗口）；② marked-terminal 与 Ink 三重冲突（B.1）；③ 只有自建才能完全掌控 CJK 宽度（换行用 `wrap-ansi` 按显示宽度）。

**架构（两阶段）**：

**阶段一（M2 交付）：静态 markdown** —— 给已 commit 的助手消息用。

`marked.lexer(text)` → token[] → 按 `token.type` 映射 Ink 原语：

| token.type | 渲染 | 说明 |
|---|---|---|
| `heading` | `<Text bold color={按级别}>` | h1 青 / h2 绿 / h3+ 默认 |
| `paragraph` / `text` | `<Text>` + `wrap-ansi` 按列宽折行 | 列宽取 `process.stdout.columns` |
| `code` | `<Box borderStyle="round"><Text>{高亮后}</Text></Box>` | cli-highlight 高亮 + 圆角边框 |
| `list_item` | `<Box flexDirection="column">` + 缩进 + 列表标记 | 有序（十进制/字母）/ 无序 |
| `blockquote` | `<Box borderStyle="left"><Text dimColor>` | 左竖线 + 暗色（dim 在深色终端不可见，用 italic+正常亮度） |
| `table` | `cli-table3.toString()` → `<Text>` | 整块文本，不参与 Ink 折行（CJK 对齐靠 cli-table3 内置 string-width） |
| `link` | M2 纯文本 `text (url)`（**OSC 8 超链接留后续**：stock Ink 无 Link 组件，且终端支持参差，MVP 收益低） | `{owner}/{repo}#123` 自动 linkify |
| `hr` | `<Text dimColor>{'─'.repeat(cols)}</Text>` | 分隔线 |

**Ansi 桥（关键枢纽，M2 必须实现）**：cli-highlight 输出的是 ANSI 字符串（`\x1b[...m`），而 Ink `<Text>` 接受 `color/bold/...` props，不直接吃 ANSI 串。**注意：claude-code 的 `Ansi.tsx` 依赖它自己 fork 的 Ink 的 `termio` 解析器（9 文件全集），ECode 用 stock Ink 没有这个模块——不要照抄。** M2 自写一个**最小 SGR-only 解析器**（~100-150 行状态机）：cli-highlight 只发 SGR 码（`\x1b[...m`），不需要 CSI/OSC/DEC 全集，把 SGR 转成 `{text, color, bold}` span 数组喂 `<Text>` 即可。**无现成 Ink 向 ANSI 解析库**（`ansi-to-react` 是 DOM 向，需改造）。cli-highlight 是 CJS，ESM 下须**动态 `import()`** + 全局共享单 Promise（首次 fallback 纯文本，加载完再重渲染，参考 claude-code `utils/cliHighlight.ts`）。

**阶段二（后续升级）：流式 markdown** —— 借鉴 opencode 三板斧（M2 不做，接口预留）：
- `remend` 治愈残缺 markdown（流式中半截代码块/未闭合链接自动补全）。
- stablePrefix（冻结，`useMemo` 缓存）+ unstableSuffix（每次只重解析尾部）切分——`marked.lexer` 把未闭合围栏当单 token，块边界是安全切分点。
- `StreamingMarkdown` 与 `Markdown` 两个独立组件，用 `null` 切换（避免状态机复杂度，组件卸载天然重置 ref）。

> M2 流式期仍走**灰字占位**（方案 A，已定，§5 决策 7），commit 后才用 Markdown 重渲染。阶段二的流式 markdown 是明确的后续升级路径。

**性能要点（借鉴 Claude Code）**：
- `hasMarkdownSyntax` 快速路径：正则采样前 500 字符，无 markdown 标记则跳过 lexer 直接单段 `<Text>`。
- 模块级 LRU token 缓存（按内容 hash，~500 条）：`useMemo` 抗不住虚拟滚动卸载重挂载。
- 代码高亮器懒加载 + 全局共享单 Promise（首次 fallback 纯文本，加载完再重渲染，成本只付一次）。

### B.3 ToolCallView.tsx 设计

**纯逻辑层已就绪**：`tui/toolview.ts`（13/13 测试）提供 `summarize` / `groupByName` / `previewLine` / `inputDigest`。渲染层套 Ink。

**布局（借鉴 Claude Code 的"通用 shell + 内容委托"）**：

```
[⏺ 闪烁 minWidth=2] [工具名 bold 青] [inputDigest] [状态 ✓/✗/⟳]   ← 单行摘要（summarize）
   ▸ 输出 (折叠, 1.2KB)                                               ← 折叠态
   ┌ 展开内容 ───────────────────────────────────────────────────┐    ← 展开态（previewLine）
```

- **执行中用闪烁 `⏺`（与规范 §2.2 符号统一，不是 `●`）**：工具执行中 `⏺` 闪烁（多个工具共享一个动画时钟同步闪烁，store 已有 activity 机制可复用，借鉴 Claude Code `useBlink` → 单 `useAnimationFrame`）；完成/失败后定型为静态 `⏺` + 状态色（绿✓/红✗）。不是 spinner 字形旋转。
- **折叠交互**：`useFocus({id: toolUseId})`（**必须传稳定 id**，不传随机生成导致重渲染焦点抖动）+ `useInput` 监听 Enter toggle。Ink 7 的 `useFocusManager.focus(id)` 支持精准跳转。
- **聚合**：`groupByName` 把同轮同工具合并（"read_file × 3"）。Claude Code 聚合是 per-tool opt-in，M2 简化为全部聚合。
- **Ctrl+O 全部展开**：全局 flag 翻转所有折叠项 collapsed（§5 决策 8）。
- **MIN_HINT_DISPLAY_MS**：快速完成的工具至少显示 ~700ms（借鉴 Claude Code `useMinDisplayTime`），避免一帧闪过读不清。

**焦点流转（呼应 TUI 规范 §5.2）**：默认焦点输入框；Tab：输入框 → 当前轮折叠项 → 输入框（循环）；↑/↓ 在折叠项间精准跳转（`focus(id)`，不只靠 Tab 线性环）；**只对当前轮可折叠**，commit 进 Static 后定型不可折叠（呼应 §8 Static 不可变约定）。

### B.4 render.ts 流式协调

**核心机制：`streamingText` 是独立状态，不是半成品消息。**

借鉴 Claude Code `Messages.tsx`：`streamingText` 非空时，在已提交消息列表**下方**渲染独立流式块；一轮结束时 `streamingText` 置 null，最终 assistant 文本进消息列表用 Markdown 重渲染。**用 null 切换两个不同组件，而非让一个组件切模式**——避免状态机复杂度。

**布局**：

```tsx
<Static items={已完成消息}>               {/* 静态历史区（冻结，走单独 buffer） */}
  {(msg) => <CommittedMessage {...msg} />}
</Static>
<Box flexDirection="column">              {/* 动态当前区（每帧重渲染，只这一块） */}
  {streamingText && <GrayStreaming text={streamingText} />}     {/* 流式期灰字占位 */}
  {currentToolCalls.map((tc) => <ToolCallView {...tc} />)}      {/* 当前轮工具 */}
  <ActivityBar state={activity} />                             {/* 状态指示 */}
  <InputStream onSubmit={...} />                               {/* 输入框 */}
  <ShortcutHint />                                             {/* 快捷键提示 */}
</Box>
```

**关键约定**：
- **流结束 = 从动态区移入 Static 的时机**。流式消息完成 → 推入 Static items（冻结），动态区清空。
- **★ 推入 Static 的充要条件：本轮所有 tool_use 已拿到 tool_result（或被中断固化）**。Static 渲染后永不重渲染（`items.slice(index)` + 游标推进），**执行中（⟳）的工具必须留在动态区**，否则状态永远卡在 ⟳。中断场景（try/finally）要确保固化后的中间态是终态（如「已中断，保留 N 行」）才推。
- **灰字块是动态区内的 React 组件，每帧重渲染显示尾部 N 行**（全量文本存 React state，commit 时进 Static）——**不要用 `console.log` 直接写 stdout**，会破坏 Ink 输出排他性。
- **不开 alternateScreen**：会杀终端 scrollback（用户滚不动历史，Ink readme 明确说明）。MVP 依赖终端原生 scrollback。
- **不做鼠标滚轮**：Ink 7 无 API（B.1）。follow 滚动锁定改用键盘（Shift+PgUp 看 Static 历史，第 0 步阻断性烟测验证）。
- **Static 性能**：stock Ink 的 Static 对 MVP 够用（流式消息完成即推入冻结，动态区只放当前那条）。消息量破百 + 60fps 流式 + 复杂 markdown 同时出现才撞墙，届时再考虑虚拟化 / OffscreenFreeze（Claude Code 的做法）。M2 烟测已实测 1000 条全量 224ms、增量 O(1)，非阻断。

### B.5 Ink 7 关键技术点（实现时盯）

| 点 | 结论 |
|---|---|
| `useFocus({id})` | **必须传稳定 id**（不传随机生成，重渲染导致焦点抖动） |
| `useFocusManager` | Ink 7.0 新增 `activeId` + `focus(id)`，支持精准跳转（不只 next/previous 盲走） |
| `useInput` | Ink 7 用 `useEffectEvent` 包 handler——**永远最新闭包，不重注册监听**（输入热路径性能修复） |
| key 判断坑 | `key.backspace` 与 `key.delete` 在 7.x **分离**；**裸 Escape 用 `key.escape`**（Meta/Alt 组合仍看 `key.meta`，二者不冲突） |
| 多 `useInput` 共存 | 同时 active 都收事件——用 `options.isActive=false` 或 `isFocused` 守卫，只焦点组件响应 |
| Static 机制 | 走单独 buffer，主树重渲染 `skipStaticElements` 跳过 static 节点（冻结） |
| alternateScreen | **别开**（杀 scrollback）；MVP 依赖终端原生 scrollback |
| 鼠标 | 无 API（#765 non-goal）；要滚轮自己解析 SGR（参考 claude-code-main parse-keypress.ts） |
