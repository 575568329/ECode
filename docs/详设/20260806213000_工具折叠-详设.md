## 一、背景与目标

**现状缺口**：M3.5 Phase 2 已实现**静态折叠**（`tool-panel.tsx` 的 `foldContent`）：工具结果按 per-tool 策略裁剪（read_file 只报行数 / bash 前 3 行错 5 行 / grep 前 3 行 / edit/write 完整），`decideToolMode` ≤1 行 Inline、≥2 行 Block，末尾 `… N more lines` 提示。

**问题**：折叠后**长输出看不全**——bash 几百行日志、grep 上百条匹配、read_file 内容完全不显示。用户无法核实工具到底返回了什么，只能去翻 `.ecode/` 落盘或重跑。

**目标**：让用户能**查看工具结果的完整内容**（可滚动、可搜索），同时保持默认视图简洁（折叠态不变）。

## 二、CC 怎么做（调研结论，出处 `D:\Study\claude-code-main`）

CC **不是**"单条工具结果就地展开"，而是**全局转录屏（transcript screen）**：

| 机制 | 出处 | 要点 |
|------|------|------|
| 双屏切换 | `keybindings/defaultBindings.ts:44`；`hooks/useGlobalKeybindings.tsx:95-132` | `Ctrl+O` → `app:toggleTranscript`，在 `prompt`（折叠态）↔ `transcript`（全屏展开）两屏间切 |
| 次级展开 | `keybindings/defaultBindings.ts:163`；`useGlobalKeybindings.tsx:135-141` | transcript 屏内 `Ctrl+E` → `transcript:toggleShowAll` 再切"显示全部" |

| 渲染层 | `screens/REPL.tsx:4238-4336` | CC **自绘终端渲染**（diff + 虚拟滚动），这是它能切屏/滚动的根基 |
| per-tool 渲染器 | `Tool.ts`；各工具 `UI.tsx` | 每个工具自注册 `renderToolResultMessage(result, { verbose })`（59 个工具各自实现），无共享渲染器 |

| 折叠组 | `utils/collapseReadSearch.ts:762-950`；`CollapsedReadSearchContent.tsx` | 连续 read/grep/glob/mcp/搜索-bash 合并成一行 "Searched N patterns, read N files"；edit/write/助手文本**打破组** |
| 截断提示 | `components/CtrlOToExpand.tsx:47` | `… +N lines (ctrl+o to expand)` dim |
| 就地展开唯一例外 | `components/shell/ExpandShellOutputContext.tsx:12-35` | 最近 `!`-command 被 `ExpandShellOutputProvider` 自动展开 |

**关键结论**：CC 的"展开看历史"本质是**进一个全屏可滚动的转录视图**，依赖它**自绘的渲染层**。CC **没有**"就地展开某一条已冻结工具结果"的 UI。

## 三、ECode 约束分析（为何不能照搬 CC）

| 维度 | CC | ECode |
|------|----|----|
| 渲染层 | 自绘（diff + 虚拟滚动） | **ink**（React for CLI） |
| 历史区 | 可重渲染、可滚动 | `<Static>` **append-only**（[#009](memory/debugging.md)）：写 stdout 后冻结，单条结果事后就地展开**做不到** |
| 整体重灌 | 支持（diff，无闪屏） | `staticKey` 重 mount 可重灌但**整会话级、闪屏**（[#009](memory/debugging.md)），不适合频繁展开 |
| 虚拟滚动 | 自带 | ink **无原生虚拟滚动** |

**ink 的可用能力**：非 `<Static>` 区（普通 `Box`/`Text`，如 InputBar）**支持 diff 重渲染**——但要做"可滚动看完整历史"仍需自绘滚动逻辑（offset + 窗口），工作量大。

**结论**：ECode 仿不了 CC 的自绘转录屏。要给用户"可滚动可搜索看完整工具输出"，**借终端原生 pager** 是 ink 约束下成本最低、体验最好的路径——pager 在独立 screen buffer 跑，不碰 ink 渲染，滚动/搜索/退出全由终端/pager 原生提供。

## 四、方案选型（三对比，已定 pager）

| 方案 | 思路 | 代价 | 体验 | 决策 |
|------|------|------|------|------|
| 全局 verbose + staticKey 重 mount | 仿 CC 思想，verbose 变→全量重灌 | 闪屏、滚动条乱跳 | 差 | 否决 |
| **pager（less + alternate screen）** | 按键→切 alternate buffer→spawn less 看完整转录→q 回主屏 | ink↔less stdio 协调（PoC 验证）；依赖 less | **最好**（可滚/可搜/原生） | ✅ **已选** |
| 纯静态优化（放弃交互展开） | 对齐 CC 阈值/提示/折叠组，长结果仍看不全 | 零风险 | 够用但不完整 | 作为 P0 打底（与 pager 正交，必做） |

**选 pager 的理由**：ink 约束下唯一能给"可滚动可搜索看完整长输出"的方案；对齐 CC"看历史进专门视图"的思路——ECode 用终端 pager 代替 CC 的自绘转录屏，获得等价核心价值（全屏看完整 + 可滚 + 可搜 + 干净退出）而无需自绘渲染层。

## 五、pager 技术栈详述（重点）

### 5.1 alternate screen buffer（隔离基石）

**原理**：终端有两个 screen buffer——主 buffer（正常输出）与 alternate buffer（全屏覆盖）。进 alternate 后在其中渲染，退出时**主 buffer 原样恢复**（光标位置、历史内容都在）。

**ANSI 序列**：
- `\x1b[?1049h`：切入 alternate（保存光标 + 切 buffer + 清屏）
- `\x1b[?1049l`：切回主（恢复光标 + 主 buffer 原样）

**作用**：less/pager 在 alternate buffer 满屏渲染，**不污染主 buffer**——退出后 ECode 主界面（ink 渲染的历史 + 输入栏 + 状态栏）原样还在，无残留行需清理。这是 `git log` / `vim` / `man` / `htop` 等 CLI 全屏工具的标准做法。

**兼容性**：Windows Terminal / Win10+ cmd（ConPTY）/ WSL / macOS Terminal / Linux 终端均支持 `1049`。极老 cmd（无 ConPTY，如 Win7 默认 cmd）不支持——见 5.6 fallback。

### 5.2 内容生成（转录纯函数）

进入 pager 前，把当前 `completedMessages` 渲染成**带 ANSI 颜色的纯文本转录**（工具结果用**完整 content，不 foldContent 裁剪**）：

```
❯ 你
  帮我读 package.json
● ECode
  我来读取...
⏺ read_file (package.json)
  ⎿ {完整文件内容，不裁剪}
⏺ bash (npm test)
  ⎿ {完整 stdout/stderr}
```

- **纯函数** `sessionMessagesToTranscript(messages: DisplayMessage[], opts?): string`，可单测（与 `messagesToDisplayMessages` 同级，放 `src/ui/`）。
- 复用 `renderCompleted` 的角色/符号约定，但输出文本而非 React 节点；工具结果直接取完整 `content`。
- ANSI 着色复用 `theme.ts` 的 `T.*` token（转 ANSI 转义）。

### 5.3 less 调用

```ts
const child = spawn('less', ['-R', '--no-init', '-P', '转录视图 · /搜索 · q退出'], {
  stdio: ['pipe', 'inherit', 'inherit'],
});
child.stdin.write(transcript);   // 5.2 生成的转录文本
child.stdin.end();
await new Promise((r) => child.on('exit', r));
```

- `-R`：解析 ANSI 颜色（保留转录着色，关键——否则颜色转义乱码）。
- `--no-init`：不发 termcap 初始化，避免某些终端进/出时清屏闪烁。
- `-P`：自定义底部提示符。
- 内容经 stdin pipe 喂入；less 退出（用户 `q`）后 await resolve。

### 5.4 ink 协调与输入让位（核心难点）

**冲突**：ink 的 `useInput` 依赖 stdin raw mode 持续读键；less `inherit` stdio 也需独占 stdin raw 读取。两者抢 stdin + raw mode。

**方案**（进入 pager 时）：
1. 生成转录文本（5.2）。
2. `setState({ inPager: true })` → App 所有 `useInput` 回调在 `inPager` 时**早 return**（不响应键）。
3. `stdout.write('\x1b[?1049h')` 切 alternate buffer。
4. spawn less（5.3），less inherit stdin 物理独占读取。
5. `await less exit`（用户 `q`）。
6. `stdout.write('\x1b[?1049l')` 切回主 buffer。
7. `setState({ inPager: false })` → ink `useInput` 恢复。

> **待 PoC 验证**（见 §八 清单）：ink 是否需要显式 `unmount`/重 `render` 才能干净让出 stdin，还是 `useInput` flag 让位 + less inherit 足够；raw mode 切换是否平滑无残留。这是本方案不确定性最高处，**实施前先做最小 PoC**（一个能 `Ctrl+O` 进 less 看固定文本再 `q` 退出的玩具），跑通了再铺功能。

### 5.5 进出生命周期

```
用户按 Ctrl+O
  ├─ 生成转录文本 sessionMessagesToTranscript(messages)
  ├─ setState inPager=true      （useInput 让位）
  ├─ stdout \x1b[?1049h          （切 alternate）
  ├─ spawn less ← 转录文本       （用户浏览：↑↓/PgUp/PgDn/搜索/q）
  ├─ await less exit
  ├─ stdout \x1b[?1049l          （切回主）
  └─ setState inPager=false      （ink 恢复，主界面原样）
```

### 5.6 Windows 兼容

**less 存在性检测**：`command -v less`（\*nix/WSL）/ `where less`（Win）。无 less 时 fallback：

| 选项 | 做法 | 取舍 |
|------|------|------|
| A（推荐 P2） | Node 自绘极简 pager：alternate screen + 读 `↑↓/PgUp/PgDn/q` + 维护 offset 渲染窗口 | 零外部依赖、Windows 无忧；功能少（无搜索），需自实现滚动 |
| B | 提示用户装 less（git-for-windows / scoop 自带） | 零开发；但增使用门槛 |

**决策**：MVP **要求 less**（\*nix/WSL/mac 原生有；Win 装一次 git 即带）；自绘 fallback（选项 A）列为 **P2**，覆盖纯 Windows 无 less 场景。

### 5.7 边界场景

- **空历史**（无 completedMessages）：提示"暂无内容可查看"，不进 pager。
- **超长内容**（十万行级）：less 本身能处理；转录生成是 O(n) 字符串拼接，注意内存——必要时改**流式 pipe**（分块 `stdin.write`，不一次性 `write` 全串）。
- **ANSI 颜色**：bash 彩色输出、markdown 渲染着色保留（`-R`）；注意 `--no-init` 下颜色转义不被吞。
- **less 异常退出**（被信号杀 / 不存在抛错）：try/catch 兜底，确保 `\x1b[?1049l` 切回主屏 + `inPager=false`（finally），**绝不让 ECode 卡在 alternate buffer**。

| 项 | 设计 | 理由 |
|----|------|------|
| **入口键** | `Ctrl+O` | 对齐 CC，迁移用户零学习成本 |

| 工具 | ECode 现状 | CC | 动作 |

| 截断提示 | `… N more lines` | `… +N lines (ctrl+o to expand)` dim | **统一格式 + ctrl+o 提示** |

## 十、风险与决策记录

| # | 决策 | 理由 / 代价 |
|---|------|------------|
| ① | 选 pager，不选 CC 式自绘转录屏 | ink 无虚拟滚动，自绘成本高；pager 借终端原生零成本获等价价值。代价：pager 是**进入时刻的快照**，不像 CC transcript 实时同步——但"查看历史"场景足够（查看时不再增长） |
| ② | 入口键 `Ctrl+O` | 对齐 CC，迁移成本低 |
| ③ | MVP 要求 less，自绘 fallback 列 P2 | \*nix/mac 原生有；Win 装 git 即带；先把核心跑通，兼容性后置 |
| ④ | ink↔less 协调用 `useInput` flag 让位，**待 PoC** | 不确定性最高；先玩具验证，跑通再铺功能，避免凭假设写一大堆返工 |
| ⑤ | 整段转录 pager（非单条展开）作为 MVP | 单条需"选中模式"（进转录 + ↑↓ + enter），复杂；MVP 先满足"能看完整" |

### 待 PoC 验证清单（实施 P1 前必做）
- [ ] ink `useInput` flag 让位 + less `inherit` stdio，是否足够让 less 独占按键（还是要 ink `unmount`/重 `render`）
