# ECode MVP 详设 评审报告

> 评审对象：[ECode MVP 详设 v1](../详设/2026-08-11_ECode-MVP详设_待审核.md)
> 评审日期：2026-08-11
> 评审角色：资深架构评审者 + Agent CLI 领域专家（熟悉 Claude Code / Aider / opencode）

## 总体评价

文档成熟度明显高于一般 MVP 详设：架构哲学自洽、伪代码可落地、关键难点（流式 JSON 拼接、工具并行/串行、错误二分）都被点名了，附录 A 的决策也都能对上正文。可以据此开工 M1。但有三处系统性盲区：
1. 运行环境是 Windows（win32），文档对跨平台零提及；
2. 流式契约（Delta）缺 error/usage、abort 与 messages 持久化的交互没对上；
3. 错误分类里"网络/超时/上下文超限一律 fatal"会让 MVP 在真实使用中频繁崩溃。

> **修订状态**：本报告提出的 5 条阻塞级 + 9 条重要级问题，已在 MVP 详设 v2 中全部修订（见被评文档附录 A 新增决策 ADR-008 起）。下文保留原始评审内容作为决策依据。

## 优点

1. **铁律可验证、可守住**——"心脏不出现 `if provider === 'xxx'`"配合 `LLMProvider.run(): AsyncIterable<Delta>` 的统一流，协议差异封死在 Provider 内部，比很多同类设计的抽象都干净。
2. **规范模型贴近 Anthropic 但留翻译面**——首版零适配、OpenAIProvider 承担翻译，是务实的"先跑通再泛化"路线。
3. **工具 readonly 并行 / 副作用串行**——二元划分清晰，可直接映射到 `Promise.all` + for-await，提速与安全兼得。
4. **AJV 直接吃 JSON Schema 零转换**——避免"定义层 Zod → 校验层 AJV"的双写，MVP 不引 Zod 是正确克制。
5. **错误契约 recoverable/fatal 二分理念正确**——"能让 LLM 处理的尽量交给 LLM"是对的方向。
6. **构建顺序由内向外**（M1-M4），每步可验证——契合"心脏先跑通"的架构观。

## 问题（按严重程度）

### [阻塞] Delta 流缺少 error 与 usage 类型
- **位置**：2.1 节 Delta 定义
- **问题**：Delta 只有 text / tool_use_* / done。Provider 流中途出错（网络断、畸形事件、parse 失败）无法表达；token 用量无载体。
- **建议**：加 `{type:'error'; error: AppError}` 和 `{type:'usage'; input/output_tokens}`。
- **修订**：✅ 已在 v2 补入。

### [阻塞] abort 流程描述与伪代码矛盾
- **位置**：3.1 主循环、3.4 中断
- **问题**：3.4 说"保留已生成内容"，但 3.1 的 for await 外层无 try/catch，AbortError 一抛，textBuf/newToolUses 随栈展开丢弃。
- **建议**：for await 包进 try/finally，catch 到 AbortError 时执行固化逻辑；StopReason 加 `aborted`。
- **修订**：✅ 已在 v2 用 try/finally 重写主循环。

### [阻塞] system 在 Message.role 与 run 参数重复定义
- **位置**：2.1 Message、2.2 run
- **问题**：同一份系统提示词既可能在 messages 里又是 run 的独立参数，契约级歧义。
- **建议**：删 Message.role 的 'system'，system 只走 run({system})。
- **修订**：✅ 已在 v2 改。

### [阻塞] Windows 跨平台零提及
- **位置**：全局，尤其 bash 工具、glob/grep、Config 路径
- **问题**：`~/.ecode/` 在 Windows 的展开、bash 跑哪个 shell、glob 反斜杠全没说。
- **建议**：单开"跨平台约定"节，路径用 os.homedir()/node:path，bash 显式依赖 Git Bash。
- **修订**：✅ 已在 v2 加 4.6 节。

### [阻塞] 空 tool_use 死循环
- **位置**：3.1 停止判定
- **问题**：LLM 返回 stop_reason='tool_use' 但无工具块时，空转到 50 轮上限。
- **建议**：stop_reason='tool_use' && newToolUses.length===0 时 continue 并提示，不执行空工具。
- **修订**：✅ 已在 v2 加防护。

### [重要] 错误分类把网络/超时/限流/上下文超限全标 fatal
- **位置**：6.2 分类表
- **问题**：一次网络抖动就丢整轮对话；401 和 429 混在一起；上下文超限直接挂。
- **建议**：网络/超时/429 → recoverable + 指数退避；上下文超限 → recoverable + 提示 /clear；401/模型不存在 → fatal。
- **修订**：✅ 已在 v2 重做 6.2，新增 6.3 重试策略、6.4 副作用工具自纠风险。

### [重要] length 当 fatal 抛出太激进
- **位置**：3.1 停止判定
- **问题**：length 表示"回答没说完"，直接 throw 等于扔半截回答。
- **建议**：改 recoverable，保留 textBuf，提示用户输入"继续"。
- **修订**：✅ 已在 v2 改。

### [重要] 流式 JSON.parse 无 try/catch
- **位置**：3.1 tool_use_end 分支
- **问题**：buf 残缺时 parse 抛 SyntaxError 逃出 Loop。
- **建议**：包 try/catch，失败时产出 is_error 的 ToolResult 交 LLM 自纠。
- **修订**：✅ 已在 v2 改。

### [重要] bash 工具元数据不足以承载沙箱/超时
- **位置**：2.3 Tool 接口、4.5 Permissions
- **问题**：bash 能 rm -rf、外发数据、卡死 Loop，readonly:false + y/n 完全不够。
- **建议**：Tool 加 timeout_ms；bash 强制 timeout/输出截断/危险命令模式拦截/cwd 约束。
- **修订**：✅ 已在 v2 加 timeout_ms 字段和 bash 安全约束段。

### [重要] 危险工具 recoverable 错误交 LLM 自纠可能放大伤害
- **位置**：3.2 工具执行、3.3 难点
- **问题**：rm 失败后 LLM 可能改 sudo rm 重试。
- **建议**：副作用工具 recoverable 错误连续同类失败 2 次后强制人工确认。
- **修订**：✅ 已在 v2 加 6.4 节。

### [重要] 写工具确认只显示 path，无 diff 预览
- **位置**：5.4 UI 样式
- **问题**：盲签，Aider/Claude Code 的核心 UX 缺失。
- **建议**：write_file/edit_file 确认带 unified diff，cli-highlight 着色。
- **修订**：✅ 已在 v2 改 ConfirmPrompt 样式。

### [重要] ConfirmPrompt 期间 Ctrl+C 语义不明 + 历史落盘时机
- **位置**：5.3 中断控制、4.2 HistoryStore
- **问题**：confirm 时 Ctrl+C 是中断 confirm 还是退出？被中断的 Loop 不走"结束"，已生成内容不入历史。
- **建议**：confirm 的 Ctrl+C = 取消该工具；落盘改每轮增量 append。
- **修订**：✅ 已在 v2 改（5.3 + 4.2 增量落盘）。

### [重要] CommandRegistry 命名带 Registry 却归分层服务
- **位置**：1 章图、4.3、7 章目录
- **问题**：结构与 Tool/Provider Registry 同构却画在"分层服务"框，概念自相矛盾。
- **建议**：MVP 标封闭（不开放注册），归分层服务；未来开放再升扩展面。
- **修订**：✅ 已在 v2 的 4.3 写明身份。

### [重要] M1 隐含依赖 Config 最小版，但 Config 放 M4
- **位置**：10 节里程碑、4.1 Config
- **问题**：M1 跑通必须有 apiKey/baseURL，但 Config 完整版在 M4，依赖遗漏。
- **建议**：M1 显式加 Config 最小切片（读 env+.env），M4 做完整版。
- **修订**：✅ 已在 v2 改里程碑表。

### [建议] Ctrl+C"两次退出"未定义判定窗口
- **建议**：明确 1.5 秒窗口，第一次后 StatusBar 显示"再按一次退出"。
- **修订**：✅ 已在 v2 改。

### [建议] MAX_ITERATIONS=50 偏高，预警缺交互出口
- **建议**：到达上限弹"是否继续"交互，而非硬终止。
- **修订**：✅ 已在 v2 加 confirmReachedLimit 交互。

### [建议] 规范模型缺 image block、StopReason 缺 content_filter，"零转换"说法不严谨
- **建议**：补 ImageBlock 占位、StopReason 补 content_filter；"零转换"改为"翻译最薄"。
- **修订**：✅ 已在 v2 改（ImageBlock 注释占位、StopReason 补值、措辞修正）。

### [建议] 流式期灰字占位实时性损失
- **建议**：MVP 可接受，M2 后改增量宽容 markdown 解析。
- **修订**：⚠️ MVP 维持现状（取舍已记），M2 后再评估。

### [建议] 依赖清单无版本锁定，未评估 Astron 兼容度风险
- **建议**：锁主版本；M1 加 Astron 端点烟测。
- **修订**：✅ 已在 v2 改（依赖加主版本列、M1 加烟测）。
