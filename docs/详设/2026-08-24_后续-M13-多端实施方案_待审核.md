## 1. 目标与非目标

**目标**（验收场景 G3 展开，M12 §15 已定）：

1. 手机/Web 打开 → 看到本机所有有历史记录的项目（registered ∪ active ∪ 历史聚合）
2. 点项目 → 会话列表（冷热合并）→ 新建对话 / 恢复历史对话，恢复后继续聊、能答审批
3. 同项目多个对话**并行进行**（A 跑长任务 B 同时聊天，互不换台）
4. 可输入新项目路径开聊（428 confirm 栅栏已有）
5. 多端同帧共享；审批谁先答谁得

**非目标（明确不做，防翻烧饼）**：

- 活流回填 / SSE 补帧 / 断线增量重放——恢复走 session/read 全量或尾页（两家同款全量重放路线；mux 是汇流不是回放）
- TUI 跨进程连 serve（用户核心入口是 Web/移动端，不挂账）
- 手机原生 App；个人微信接入（封号风险）
- 模型难度自动路由（2026-08-24 讨论定论：代码任务难度不可先验判定 + 逐轮换模型丢缓存前缀 + 弱模型工具循环烧轮次，三头不讨好；便宜模型靠 roles 静态指派，见成本方案 §4.5）
- 双人协作语义（同时编辑/光标同步等）——多端是"共享会话"不是"协同编辑"
- **daemon 开机自启/后台服务化（M12 决策延续）**——手机访问需提前在电脑前手动 `ecode serve`（首次还需设 ECODE_SERVE_HOST 与密码）；"人在外远程连家里电脑"场景不在 M13 范围，显式声明防交付后体验落差（审阅 P0）
- 会话删除/重命名（用户拍板只提新建/恢复；协议已有 session/clear 清消息，session/delete 按需后加枚举，留口不做）

## 2. 总体架构

```
浏览器 / 手机 PWA（React 19 + Vite + Tailwind）
   │  GET /            静态资源（daemon 托管 dist）
   │  GET /api/events.mux      ← 唯一 EventSource：mux 信封帧 + host 级生命周期帧
   │  POST /api/p/<path>/cmd   ← 命令信封 {sessionId, op}（协议命令零改动）
   ▼
serveMulti（M12 交付 + 本方案扩展）
   ├─ ProjectRegistry：path → ProjectHost（锁语义不变=项目唯一）
   │     ├─ ProjectHost（项目级共享，常驻）
   │     │    config/provider/tools 装配/MCP/checkpoint/quality/hooks/skills
   │     ├─ ConversationHost A（会话级私有）
   │     │    messages/loop/channel/broker/插话队列/usage/sandbox 档/rewind
   │     ├─ ConversationHost B ←── 同项目并行对话
   │     └─ Map<sessionId, ConversationHost>（幂等单飞）
   └─ mux 汇流层：所有 ConversationHost 的 channel 订阅 → 信封包装 → 单流广播
```

分层依据（源码实证见调研文档 §1 对照表、§4 改造清单）：opencode 的 Instance/Session 两层同构；harness 的 Session+Agent 1:1 与 mux 单流同形。

## 3. 架构批设计（W1-W4）

### 3.1 两层宿主（W1）

`HostSession`（M12 单体）拆为：

| | ProjectHost（项目级，registry 持有） | ConversationHost（会话级） |
|---|---|---|
| 生命周期 | acquire 创建，**常驻不回收**（两家实证，见调研 §3.5） | prompt 隐式创建 / restore ensure；闲置 sweep |
| 持有 | makeDeps 的项目级件：providerRegistry、tools（HookedToolRegistry）、MCP manager、checkpoint、quality、hookRunner、logger、config getter、skills/plugin 装配 | messages 权威、runLoop 运行态、InMemoryChannel、ApprovalBroker、插话队列、usage 累计器（含 mcpCallCount）、editedFiles、sandbox 当前档、FileHistoryStore（按 sessionId，构造时定 id）、rewind 线 |
| 复用 | 同项目全部对话共享一份 | 一对话一份，互不串台 |

- `makeDeps` 拆两段：`makeProjectDeps(config, logger, cwd)`（现 makeDeps 去会话件）+ `makeConversationDeps(projectDeps, sessionId)`（history/usage/broker/channel）。
- **TuiApp 与 argv 保持等价形态**：REPL = makeProjectDeps + 单 ConversationHost（行为与 M12 完全一致，现有 386 条 TUI 用例是等价性安全网）；argv = runOnce 内联同构。
- 宿主事件翻译/afterTools/hooks 分发逻辑随 ConversationHost 走（这些是轮次语义）；mountBridges 的桥挂 ProjectHost（skill/MCP 项目级）+ 会话窄端口指到当前 ConversationHost（D5 模式延续）。
- 子代理（makeTaskTool）继续吃 projectDeps 的 getter 闭包，confirm/askUser 经 session 窄端口到所属 ConversationHost——多会话下子代理审批不串台。

**W1 显式改造项——三个进程级全局单例收敛（v1.1 补，审阅 P0-1/P0-2/P1-1）**：

1. **skillRegistry 与 globalExtensionHooks**现为进程级全局单例（`skill.ts:520` / `hooks/global.ts:12`）——多项目下 A 项目 `/clear` 或 restoreFrom 触发 `unregisterAllSkillHooks()` 会清掉 B 项目的 skill hooks（数据面串台）。W1 实例化进 ProjectHost（对齐 opencode Instance 级注册表），模块级降为 argv 单会话兜底。
2. **mountBridges 三桥现为模块级全局 setter**（`setSubagentBridge`/`setPermissionAsker`/`setAskUserHandler`，session.ts:136-153）——多会话下后挂覆盖前挂，子代理/权限/askUser 全串台。W1 改实例级注入：每个 ConversationHost 创建时各自挂桥，闭包只捕获本实例（M12"四桥实例化"未尽事宜在此收口，模块级同降兜底）。
3. **HookRunner.getSessionId 闭包**绑死 makeDeps 创建时的单个 sessionId（`runner.ts:69`、`cli/index.ts:117`）——ProjectHost 常驻后新会话的 hook 事件 `session_id` 全错。W1 改经会话上下文动态取（构造从 makeConversationDeps 注入当前 id）。

### 3.2 协议信封与命令路由（W2）

- **MuxFrame 信封**（内层 27 事件枚举零改动）：`{ project: string, sessionId?: string, ev: ProtocolEvent } | HostEvent`——汇流层包装，不改内层帧结构；单项目端点 `/api/p/<path>/events` 保持现状裸帧（调试端点）。
- **HostEvent 新增 5 枚举**：`project/added`、`project/removed`、`session/created`（含 cwd/sessionId/firstUser）、`session/removed`、`session/baseline`（连接时全量活会话清单）。
- **命令信封**：`POST /api/p/<path>/cmd` body 从裸 ProtocolCommand 改为 `{ sessionId?: string, op: ProtocolCommand }`。sessionId **三态语义**（v1.1 修——v1.0 两句表述矛盾）：
  1. 显式携带 → 路由到指定会话（TUI 固定持有自己的会话 id，等价显式）；
  2. 缺省且项目已有默认会话 → 路由到默认会话；
  3. 缺省且无默认会话（新项目 / 默认会话已被 sweep 收）→ prompt 隐式创建新会话并标记为默认，回执与后续帧全带 sessionId。
  `session/create` 显式命令列**保留项**（Web 若需"先建容器再发内容"的交互流时加枚举，Q3 复议口径，不预建）。
- 信封**过渡兼容**（v1.1 补）：cmd 路由解 body 时含顶层 `op` 字段即按信封解包，否则当裸 ProtocolCommand——旧客户端窗口，W5 后移除。
- `session/restore`（枚举已有，宿主 default 分支现返回 NOT_IMPLEMENTED——session.ts:361）接线：**ensure 语义**——ConversationHost 已活复用；不存在则 history 读全量行 restoreFrom 载入新建；并发同 id 幂等单飞（harness `sessionCreations` 同款，deferred 模式——M12 实测坑⑤）。
- **HostEvent 为独立联合类型**（与 ProtocolEvent 不交——后者经信封包装广播；前者 mux 专属，所需字段自带帧体内，不占信封 sessionId 字段）；MuxFrame 类型定义落 `src/protocol/mux.ts`（types.ts 零改动，v1.1 补）。
- 审批可答帧经信封带 sessionId；`approval/respond` 命令本身无 sessionId 字段（types.ts:93）——**路由靠信封外层**：serveMulti 解信封找 ConversationHost 后内层 op 直送其 broker，requestId 只需在该会话 broker 的 pending Map 内唯一（UUID 天然满足）。

### 3.3 mux 端点与汇流（W3）

- `GET /api/events.mux`：每连接遍历所有 ProjectHost 的全部 ConversationHost subscribe（复用 M12 SSE 工程包：drain 背压/15s 心跳/token/loopback/断连退订）+ ProjectRegistry 的项目增删订阅。**实现形态**（v1.1 补）：mux 端点用 wrapper handler 把 ProtocolEvent 包装为 MuxFrame 再写流——channel 与 handler 签名零改动；ProjectHost 会话 Map 增删时 mux 连接动态补订/退订新会话。
- 连接三连（对齐 harness mux，调研 §2.4）：①`session/baseline`（当前所有活会话+项目清单）；②重放各会话 pending 审批帧（broker 订阅即重放已有，汇流层接上；**批量重放按会话分组展示，与实时帧共用同一审批 UI 组件**——v1.1 补前端约定）；③连接后持续广播信封帧。
- 单项目 events 端点保留；两个端点可并存订阅（互不干扰——channel 本就多订阅 fan-out）。

### 3.4 会话生命周期与回收（W2/W4）

- 创建：prompt 隐式（见 3.2）；显式 restore ensure；冷会话（历史文件存在、宿主无实例）restore 时载入。
- 回收（对齐调研 §3.5 结论）：**项目基座常驻**（sweepIdle 的项目维度退役；daemon 退出 disposeAll 不变）；**会话级 sweep**——无订阅者 && brokerPending=0 && loop 空闲 && 超过 `sessionIdleMinutes`（默认 120，0=不收）→ ConversationHost.dispose（messages 内存释放/channel dispose；**历史文件/checkpoint 不动**，restore 即续）。会话被收后 mux 广播 `session/removed`。
- 运行态会话（loop 在跑/审批挂起/有订阅者）永不收。
- **项目默认会话生命周期**（v1.1 补）：ProjectHost 创建时不自动建会话（冷启动语义延续）；首个缺省 prompt 隐式创建并标记默认；默认会话被 sweep 收后标记不持久化，下次缺省 prompt 重新隐式创建；restore 载入冷会话后将其转正为新默认（最近操作意图所在）。

### 3.5 历史与项目发现（W4，原三小块）

1. **meta 补 cwd**：`FileHistoryStore` 构造收 cwd，MetaLine 增 `cwd` 字段（启动期校验绝对路径）；`makeConversationDeps` 传入。存量文件首行无 cwd 不可归档（不回填）——Web 列表归入"未归类"。
2. **`/api/projects` 增强**：registered ∪ active ∪ 历史聚合（扫 `~/.ecode/sessions/` 首行 meta.cwd 去重；loadAll 首行 2048B 读法现成）。
3. **`session/list` 冷热合并**：活 ConversationHost（含 running 态）∪ 历史文件 meta（含 cwd/firstUser/createdAt），按 updatedAt 降序。

### 3.6 冲突防护（对齐调研 §3.4/§3.5，不建大机制）

- checkpoint：objects **按会话分目录物理隔离**（`checkpoint.ts:81` sessionDir(sessionId)）——跨会话不共享对象目录，无并发写同一 objects 路径，故**无需 gitdir 锁**；同会话内多轮快照 content-addressed 去重（v1.1 改写——"跨会话天然去重"原表述不实）。跨会话磁盘冗余（两对话同文件各存一份）低危挂账观察。
- edit per-file 信号量：**挂账观察**（真出现两对话编辑同文件再上，进程级全局锁 10 行内）。
- git autoCommit 多会话交织：git 原子不坏仓库，提交历史交织低危——挂账观察。
- write 无锁 last-write-wins：与两家同为社会约束（"别同时让两个对话改同一个文件"），文档提示即可。

### 3.7 网络与鉴权（W3/W5）

- 绑定放开：`ECODE_SERVE_HOST`（默认 `127.0.0.1`）。设为非 loopback 地址时**强制要求 `ECODE_SERVER_PASSWORD`**，否则拒绝启动（手机局域网访问的前提；防"忘了密码裸奔局域网"）。**启动体验**（v1.1 补，审阅 P1）：非 loopback 绑定时 stdout 打印一行完整可点击访问 URL（`Mobile: http://192.168.x.x:port`）——半行代码消除"我该在手机输什么"的摩擦；同时提示建议配置静态 IP（DHCP 变动风险见 §9 R8）。
- Web 鉴权双通道（M12 Q5 首发）：server.json token（本机浏览器：首次访问输入一次存 localStorage）或 Basic 密码（局域网手机）；两者校验逻辑已并存（Bearer/Basic 均可，M12 已做）。
- 审批代答防线不变：所有端点（除 health）鉴权 + 非 loopback 强制密码。

## 4. Web 客户端（W5-W7；选型已落定，依据 [Web 客户端技术栈调研](../解析/2026-08-24_M13-Web客户端技术栈调研_已完成.md)）

- **形态**：React 19 + Vite（v8）+ @vitejs/plugin-react v6 + Tailwind v4（`@tailwindcss/vite` 插件集成，CSS-first 配置）手写组件（Q3 维持）；构建产物 dist 由 daemon 直接托管（`GET /`→index.html，SPA 路由 fallback），不另起服务器。
- **数据层**：全局单流连接（mux）+ 按 `project/sessionId` 过滤分发；命令走 fetch POST（回执式）。**流连接用 fetch + ReadableStream + eventsource-parser（v3.1）——不用 EventSource**（不能带 Authorization header；token 落 URL query 属 OWASP 风险），token 经 header + localStorage。**状态管理落定 Zustand v5** 单 store（服务端权威、前端仅渲染态）。
- **流式渲染**：**Streamdown**（Vercel，react-markdown 流式特化——不完整语法补全+块级 memo+内置高亮）；备选 react-markdown v10+手动块 memo。自研增量渲染器（harness 路线）不做。
- **连接工程**（W5 子项，对齐 harness/orca 实证）：指数退避 500ms×2 封顶 10s+抖动、3s open timeout、visibilitychange 回前台重连、冻结 tab 检测；iOS 后台杀流为已知限制（回前台 baseline+补拉恢复）。
- **页面结构**：
  - 左栏两级树：项目列表（含"未归类"+ 输入新项目路径入口）→ 会话列表（running 标记/新建按钮；running 边沿检测弹完成提示——harness 同款）
  - 右侧对话区：流式 delta 渲染、工具卡（item started/completed 折叠详情）、usage/cost 角标
  - 审批可答帧 UI：**composer-takeover 模式**（pending 占据输入框位、一 shot 按钮、resolved 即散——harness ApprovalPanel 同款）；按 ApprovalKind 分策略提示（sensitive 标红强调不可"始终允许"）；askSelect/askUser 面板；插话输入框（StartOrSteer）；**IME 兼容检测**（isComposing——中文输入必踩）
- **断线策略**：重连后对当前打开会话 `session/read` 补拉全量（不做增量补帧——非目标）；mux baseline 帧刷新列表（与 Q10 一致）。
- **B5 缩水命令最小子集**：`model/set`（顶栏切模型，W6b 带）；`/stats` 数据已就绪（stats-cache 落盘 + 命令已 host 化），Web 端渲染为简单列表属低成本——列 **W6b 可选附带项**（非承诺）；rewind/panel/command/exec 维持挂账（Web 无对应 UI 前不做）。

## 5. 手机 PWA（W7）

- 响应式布局（列表页/对话页两态自适应窄屏）；manifest + service worker 离线壳（仅壳缓存，对话需在线）。
- 移动端交互适配：审批大按钮、工具卡默认折叠、软键盘弹起视口处理。
- 弱网：SSE 断线重连已有；PWA 仅前台连 mux（后台自动断，回前台 baseline 重建）。**daemon 不可达 fallback 页**（v1.1 补）：service worker 拦截连接失败显示"请确认电脑端 ecode serve 正在运行"——15 分钟项，消除"无法连接"的无诊断空白。
- G3 真机验收（DevTools 移动模拟 + 用户真机各一轮）。

| 协议 HostEvent | `project/added` `project/removed` `session/created` `session/removed` `session/baseline` | mux 专属；单项目端点不发 |
| 协议信封 | `MuxFrame = {project, sessionId?, ev} \| HostEvent` | 汇流层包装，内层枚举零改动 |
| 协议命令 | `session/restore` 接线（ensure 语义）；prompt 隐式建会话 | 枚举已有/零新增 |
| HTTP | `GET /api/events.mux`；`GET /`（静态托管）；`/api/projects` 三源并集；`ECODE_SERVE_HOST` + 密码强制联动 | |
| 配置 | `sessionIdleMinutes`（默认 120）；MetaLine.cwd | |

## 7. 决策台账

| # | 问题 | 决策 | 依据 / 被否决备选 |
|---|---|---|---|
| Q1 | 会话并发粒度 | 会话级宿主（ConversationHost 轻对象） | 两家同构（opencode Session/Runner、harness Agent）；被否决：维持项目级换台（Web 同项目多开是明确需求） |
| Q2 | mux 帧维度实现 | 信封包装，内层 27 枚举零改动 | 改动最小、单项目端点兼容；被否决：帧结构内嵌 project/sessionId（全枚举动一遍，协议不稳定） |

| Q4 | restore 语义 | ensure（活复用/死载入/并发单飞） | 幂等天然；被否决：每次 restore 重建（丢运行态，A 端正在跑会被拆） |
| Q5 | 项目基座回收 | 常驻不收 | 两家实证（调研 §3.5）；被否决：沿用 30 分钟 sweep（冷启动卡顿，Web 体验差） |
| Q6 | 会话回收阈值 | 120 分钟 + 三闸（订阅/审批/运行态） | 会话内存态重（完整 messages）确需回收，但比 M12 项目级 30 分钟放宽；W4 观测实际内存为调参留数据 |
| Q7 | Web 托管 | daemon 直接托管 dist | 零新进程零新端口；被否决：独立 Web 服务器（部署面翻倍） |
| Q8 | 手机访问 | ECODE_SERVE_HOST 放开 + 强制密码 | loopback 默认安全不动；密码与绑定联动防裸奔 |
| Q9 | IM（企微/飞书） | 可选批，用户确认需求后排期 | 本方案不展开设计 |
| Q10 | 断线恢复 | 重连后 session/read 全量补拉 | 非目标已定不做补帧；全量拉取实现最简且冷热同源 |
| Q11 | skillRegistry/globalExtensionHooks 归属 | 实例化进 ProjectHost，模块级降 argv 兜底 | 审阅 P0：全局单例在多项目 /clear 时串台清 hooks；opencode Instance 级注册表同款 |
| Q12 | mountBridges 全局 setter | 每 ConversationHost 实例级挂桥（闭包捕获本实例） | 审阅 P0：后挂覆盖前挂致子代理/权限/askUser 串台；M12 四桥实例化收口 |
