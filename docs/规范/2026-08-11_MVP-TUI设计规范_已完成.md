# ECode MVP TUI 设计规范

> 日期：2026-08-11 · 状态：待审核
> 方向（已定）：**全屏框架式（Claude Code 风）** + **品牌启动屏** + **适度色彩（暗色主题）**。
> 技术栈：标准 Ink 7 + **自建组件（TextInput/Select/Spinner，不用 @inkjs/ui）** + 自建三件（终端 Markdown / 折叠 ToolCallView / 流式分阶段渲染）。本文是详设第 5 节的细化，可被独立实现。

## 1. 设计原则

1. **键盘优先**：所有操作有快捷键，鼠标辅助。
2. **焦点明确**：当前焦点区域高亮（`useFocus`），用户始终知道「按键影响谁」。
3. **状态可见**：StatusBar 常驻元信息（model/轮数/token/成本）；**ActivityBar 常驻当前动作**（loading，输入框上方）——用户任何时刻既知"在什么环境"又知"系统在干嘛"。
4. **信息密度可控**：默认折叠冗长内容（工具输出），展开按需。
5. **中断可恢复**：Ctrl+C 不丢内容，视觉明确「已中断，内容已保留」。
6. **分阶段渲染无闪烁**：流式期灰字占位 → 提交期 markdown 重渲染，切换无跳变。

## 2. 视觉规范

### 2.1 配色（适度色彩，暗色主题）

终端默认暗色底，关键状态用色，其余默认色。

| 元素 | 颜色 | ANSI | 说明 |
|---|---|---|---|
| 用户输入/消息 | 灰（dim） | `\x1b[2m` | 区分用户与助手 |
| 助手文本 | 默认（白） | — | 主体内容 |
| 工具名 | 青（cyan） | `\x1b[36m` | ⏺ read_file 的工具名 |
| 成功 ✓ | 绿（green） | `\x1b[32m` | 工具成功、加载完成 |
| 警告 ⚠ | 黄（yellow） | `\x1b[33m` | 确认、轮数预警 |
| 错误 ✗ | 红（red） | `\x1b[31m` | fatal、is_error |
| 状态栏 | 蓝（blue）/反色 | `\x1b[34m` | 顶栏边框/标题 |
| 代码块 | cli-highlight 高亮 | — | marked + cli-highlight |
| 焦点高亮 | 反色 | `\x1b[7m` | 当前焦点区 |
| 折叠标记 ▸ | 灰 | `\x1b[2m` | 折叠提示 |
| 截断 … | 灰 | `\x1b[2m` | 输出截断 |

> 配色集中在 `tui/theme.ts`，便于后续主题切换（亮/暗）。MVP 只做暗色。

### 2.2 符号系统

| 符号 | 含义 |
|---|---|
| `❯` | 输入提示符（用户消息 + 输入框光标） |
| `⏺` | 工具调用标记 |
| `✓` | 成功（工具完成、config 加载、就绪） |
| `⚠` | 警告 / 需确认 |
| `✗` | 失败 / 错误 |
| `▸` | 折叠指示（未展开） |
| `▾` | 折叠指示（已展开） |
| `…` | 截断 |
| `⟳` | spinner 占位（实际用 ink-spinner 动画） |
| `❮❯` | 状态栏边框（可选） |

> 符号用 Unicode（终端普遍支持）；退化方案是 ASCII（`>` `*` `+` `!` `x` `>` `...`）——M1 烟测终端 Unicode 支持。

### 2.3 间距与缩进

- **消息间距**：消息块之间空 1 行。
- **缩进**：工具输出、diff 缩进 2 空格；嵌套再 +2。
- **边距**：内容左右各留 1 空格（不贴边）。
- **分隔线**：`─` 单行横线分隔区域（StatusBar 下、输入区上）。

## 3. 布局规范

### 3.1 区域划分（全屏框架式）

```
┌─ StatusBar（1 行，常驻顶）──────────────────────┐
├─ MessageList（中间，占满）──────────────────────┤
│  <Static>：已完成的不可变历史                    │
│  动态区：当前流式/工具/确认                      │
├─ ActivityBar（1 行，状态指示/loading）──────────┤  ← 常驻，输入框上方
├─ InputStream（底，固定）────────────────────────┤
├─ 快捷键提示栏（1 行，最底）─────────────────────┤
└────────────────────────────────────────────────┘
```

### 3.2 尺寸与边界

| 区域 | 高度 | 说明 |
|---|---|---|
| StatusBar | 1 行 | 固定顶栏，常驻（元信息：model/轮数/token/成本） |
| MessageList | 剩余空间 | `<Static>` 历史 + 动态当前 |
| **ActivityBar** | **1 行** | **状态指示/loading，常驻输入框上方**（见 4.10） |
| InputStream | 1-3 行（随输入增长，上限 3） | 固定底部 |
| 快捷键提示栏 | 1 行 | 最底 |
| 终端最小尺寸 | 80×24 | 小于此提示「终端太小」 |

> 非 alternate buffer 模式（**Ink 默认 `alternateScreen=false`**——开 alt screen 会杀终端 scrollback，用户滚不动历史，禁用；依赖终端原生 scrollback，见 §4.12 / M2 方案 B.4）；`<Static>` 保证历史只渲染一次，动态区重绘不卡顿。

### 4.1 欢迎屏（品牌启动屏）

启动 / 加载 config / 会话恢复时显示，任意键或加载完成进入主交互。

│   ECode v0.1.0 · 终端 Agent CLI                              │
│   GLM-5.2 · astron                                           │
│                                                              │
│   ✓ config 已加载      工作区: D:\study\ECode                │
│   ✓ 7 工具就绪         会话: 新建 (或 恢复 #abc123)          │
│   ✓ 日志: ~/.ecode/logs                                      │
│                                                              │
│   输入问题开始，或 /help 查看命令                             │

**状态分支**：
- config 不存在 → 欢迎屏显示 `✗ 未配置，请编辑 ~/.ecode/config.json`（首次运行向导留后续版本，MVP 只告知）。

│                                                              │

```

   +++ src/loop.ts
   @@ -45,3 +45,3 @@
   -const x = oldFunc()
   +const x = newFunc()

### 4.7 错误与中断

**recoverable 错误**（网络/超时/429，重试中）：
```
⚠ 网络超时，重试中 (2/3)...    ← 黄色，底部独立第二行（M7 R6）
```

**告警行规则（M7 R6 定稿）**：运行时告警（onWarn 通道）渲染为底部独立第二行——状态行/快捷键提示行之下，**不与 StatusBar 同行**（长消息曾把状态行挤碎）；消息单行化（换行/制表折叠为空格）+ 按终端宽度截断（宽度未知兜底 100 列）。源头（core/errors.ts fromHttpStatus）已把 HTTP 错误提炼为人话一行（SDK 嵌套 error.message + code），原始全文进 `context.raw` 保日志——UI 层截断是第二道防线。

**fatal 错误**（无 API Key / 模型不存在）：
```
✗ [NO_API_KEY] 缺少 API Key
  请配置 ~/.ecode/config.json 的 providers[].apiKey
  或设置环境变量 ANTHROPIC_API_KEY
  已保留当前对话，/history 可恢复。
```

**中断（Ctrl+C 第 1 次）**：
```
⚠ 已中断（已生成内容已保留）    ← 灰色，回到待输入
```
StatusBar 短暂显示「再按一次 Ctrl+C 退出」（1.5s 窗口）。

### 4.10 状态指示器（ActivityBar / loading）★

**核心需求**：只要对话在进行（未 done / 未中断），loading 一直常驻在输入框上方，交代当前动作，避免用户不知状态。所有 loading 统一格式、统一组件。

**位置**：MessageList 与 InputStream 之间，1 行，常驻。

**格式**：`⟳ <当前动作说明>`（spinner + 文字）。spinner 用 `@inkjs/ui` Spinner，状态由 Loop 消费 Delta 时映射（`tui.setActivity(state)`）。

**状态机**：

| Loop 阶段 | ActivityBar 显示 | 颜色 |
|---|---|---|
| 收到 `text` delta（LLM 生成中） | `⟳ 正在思考...` | 青 |
| `tool_use_start`（工具开始） | `⟳ 调用 read_file(src/loop.ts)...` | 青 |
| 工具执行中 | `⟳ read_file 执行中...`（副作用工具确认时由 ConfirmPrompt 接管显示） | 青 |
| recoverable 重试（退避中） | `⟳ 网络超时，重试中 (2/3)...` | 黄 |
| `done`（end/length/content_filter） | 清空（回到待输入，或淡显「就绪」） | — |
| `aborted`（Ctrl+C） | `✗ 已中断（内容已保留）` 渐隐 ~1.5s 后消失 | 灰 |

**原型**（在主交互界面中的位置）：
```
│  ⏺ edit_file  src/loop.ts  ⚠ 待确认              │
│     --- const x = oldFunc()                       │
│     +++ const x = newFunc()                       │
│     ⚠ 确认执行? [y]是 [n]否 [v]看完整             │
├──────────────────────────────────────────────────┤
│  ⟳ read_file 执行中...        ← ActivityBar       │  ← 常驻，输入框上方
├──────────────────────────────────────────────────┤
│  ❯ _                                              │
│  [⏎ 发送]  [Ctrl+C 中断]  [/ 命令]               │
└──────────────────────────────────────────────────┘
```

**规则**：
- **一直在**：Loop 进行中（流式生成 / 工具执行 / 重试）ActivityBar 必显；空闲（待输入）清空。用户任何时刻都知道系统在干嘛。
- **统一**：所有 loading（思考/工具/重试）走同一组件、同一 `⟳ <说明>` 格式，只换说明文字和颜色。
- **上下文**：说明文字带具体动作（工具名+入参摘要、重试次数），不是干转圈。
- **不抢占焦点**：ActivityBar 是只读指示，不接键盘焦点；输入框始终可输入（用户可在等待时打下一句）。

### 4.11 工具调用显示规范（折叠 + 聚合 + 样式）★

借鉴 Zed 的「展开/折叠回合」([zed-industries/zed#58314](https://github.com/zed-industries/zed/discussions/58314))与业界「最小输出（≤3 行）」原则。

**核心规则**：
1. **LLM 文本回答永不折叠**（markdown 全展开）——用户主要看的内容。
2. **工具块固定 3 行摘要**，超出折叠，展开看完整。
3. **同轮同工具聚合**：同一 assistant 回合里多次调用同一工具（如连读多个文件），合并为一个工具组显示，组内按调用序列各次——避免 `read → bash → read → bash` 穿插混乱。
4. **历史定型**：commit 进 `<Static>` 后，工具块保持 commit 时的折叠状态，不可再折叠（呼应 §8）。

**3 行摘要样式**（单次调用）：
```
⏺ read_file  src/foo.ts  ✓ 1.2KB          ← 行1：⏺ 工具名(青·明显) + 入参摘要 + 状态(✓绿/✗红) + 字节数
  import * as fs from 'node:fs'            ← 行2：输出首行预览(灰·次要)
  ▸ 还有 38 行 — 展开                       ← 行3：折叠提示(灰)
```

**同工具聚合样式**（同轮多次调用同一工具）：
```
⏺ read_file  (2 次)                        ← 工具名(青) + 次数
  src/a.ts ✓  import * as fs...            ← 各次：入参 + 状态 + 首行预览(灰)
  src/b.ts ✓  export function...
  ▸ 展开
```

**视觉**（呼应 §2.1）：

| 元素 | 颜色 | 说明 |
|---|---|---|
| `⏺` + 工具名 | **青（cyan）** | 明显，一眼定位 |
| 状态 `✓`/`✗`/`⟳` | 绿 / 红 / 青 | 成功 / 失败 / 执行中 |
| 入参摘要（path / command） | 默认色 | 关键信息 |
| 输出预览 / 折叠提示 / 字节数 | **灰（dim）** | 次要，不抢眼 |

**折叠阈值**：输出 > 200 字节（约 3 行）默认折叠；≤ 200 字节直接显示（无"展开"提示）。

**展开态**：展开看完整输出；超长（> `bashMaxOutputBytes` 默认 30KB）头尾中截（呼应 bash 截断 + 防编造提示）。展开/折叠切换：Tab 聚焦工具块 + Enter 切换（焦点在输入框时 Enter=发送，靠 `useFocus` 区分）。

**执行中**：行 1 状态位置显 `⟳`（Spinner 动画），ActivityBar 同步显 `调用 {工具名}...`。

### 4.12 流式渲染 + 滚动锁定 ★

**流式 markdown 方案：A（灰字占位 → commit，滚动友好）**

调研 md2term + 滚动问题权衡，M2 用方案 A（非实时 markdown 重渲染）：

- **流式期**：`streamText` 把增量写进灰色缓冲（纯文本，不做 markdown），追加进终端 scrollback（不重绘历史）→ 用户往上看历史不被流式重绘打断。
- **灰字折叠（最多 5 行）**：流式灰字超过 **5 行**时，只显**尾部 5 行** + 顶部提示「↑ N 行流式中」（灰），避免长输出刷屏遮挡历史。
  ```
  ↑ 12 行流式中（灰）
  ...（尾部 5 行灰字，最新在底）...
  ```
- **提交期**：`commitAssistantMessage` 清灰色缓冲 + 一次性 markdown 渲染（完整，代码高亮/表格/列表）。LLM 文本 commit 后不折叠（§4.11 规则 1）。
- **A+（实时 markdown）留后续**：流式期实时 markdown 重渲染（md2term 式全量重渲染），等滚动锁定成熟 + 性能验证后升级（§9）。

**滚动锁定（follow 标志，M2 必做）**

终端 agent 流式时用户往上看历史的痛点（业界叫 "scroll-to-bottom with detach" / "auto-follow with pause"）：

- 维护 `follow = true`（默认跟随底部）。
- 用户上滚（鼠标滚轮 / Shift+PgUp）→ `follow = false`，视图不动，新内容继续到底部 + StatusBar 提示「↓ N 行新输出」。
- 按 `End` / 下滚到底 → `follow = true`，恢复跟随。
- Ink 7 鼠标事件检测滚动；alt buffer 滚动行为 M2 烟测（Windows Terminal / iTerm / VSCode 终端各测）。

## 5. 键盘交互规范

### 5.1 快捷键表

| 键 | 上下文 | 行为 |
|---|---|---|
| `⏎ Enter` | 输入框 | 发送消息（空行不发送） |
| `Ctrl+C` | 全局 | 第 1 次：中断当前请求；1.5s 内第 2 次：退出程序 |
| `Ctrl+C` | 确认弹窗 | 取消该工具（返回 is_error「用户取消」），**不**退出、**不**中断 Loop |
| `↑` `↓` | 输入框（空） | 浏览输入历史 |
| `Tab` | 全局 | 切换焦点（输入框 ↔ 折叠区 ↔ 面板） |
| `⏎` | 折叠区 | 展开/折叠当前工具输出 |
| `Ctrl+O` | 全局（不管焦点） | 展开/折叠**当前轮全部**工具输出（toggle，和 Claude Code 一致；与 Enter 的「焦点项单个展开」区分） |
| `End` | 全局 | 滚动锁定 follow 恢复（回底部跟随新输出，见 §4.12） |
| `y` `n` `v` | 确认弹窗 | 是 / 否 / 看完整 |
| `/` | 输入框首字符 | 触发斜杠命令（补全） |
| `Esc` | 面板/确认 | 取消面板/确认（**不**用于主中断） |
| `←` `→` | 带页签的面板（PanelShell tabs，M7） | 切页签：**优先于一切面板分支**（空页签必须能切走——空列表守卫曾吞键困住用户）；搜索态同样切换并清搜索词；环绕（首页 ← 到末页） |
| `↑` `↓` | 面板（PanelShell） | 列表选择（环绕）；搜索即时过滤（可打印字符进入，backspace 删词） |
| `Ctrl+R` | /mcp 面板 | 光标 server 快捷重连（与面板键位广播叠加，不相交） |

> 仅 Ctrl+C 做中断/退出（详设 5.3），Esc 只取消局部弹窗。面板键位基线（M6 T4：↑↓/Enter/Esc 逐级先清搜索词/PageUp·PageDown/即时搜索/Ctrl+C 退面板）之上，M7 增加 ←→ 页签切换（仅传入 tabs 的面板生效，/plugin 三页签）。

### 5.2 焦点流转

```
默认焦点：输入框（InputStream）
折叠交互：**只对当前轮的工具输出可折叠/展开**（Enter 切换）；历史（commit 进 Static 后）定型，不可折叠（呼应 8 节 Static 不可变）。
Tab：输入框 → 当前轮折叠项（若有）→ 输入框（循环）。
面板打开时（/model /history）：焦点锁定面板，关闭后回输入框。
确认弹窗时：焦点锁定弹窗，y/n/v/Esc 响应。
```

### 5.3 Ctrl+C 双击退出（1.5s 窗口）

```
第 1 次 Ctrl+C（有请求进行中）→ abortController.abort() → 固化已生成内容 → StatusBar 显「再按一次退出」
1.5s 内第 2 次 → 退出程序
超过 1.5s → 提示消失，恢复单次中断语义
无请求进行时第 1 次 → 直接显「再按一次退出」
```

## 8. 实现约定（呼应详设 5 节 + 技术栈解析决策 2）

- **基础件自建**（不用 `@inkjs/ui`，组件方式插入）：TextInput（InputStream）/ Select（SlashCommandPanel）/ Spinner（ActivityBar / 工具执行），参考 `D:\study\claude-code-main/src/components`（BaseTextInput.tsx / CustomSelect/ / ink components）。
- **自建三件**：`Markdown`、`ToolCallView`（含折叠）、流式分阶段渲染（render.ts）——M2/M3 交付。
- **状态管理**：用 **React Context**（内置、轻量）做全局状态（会话 messages / provider / model / ActivityBar 状态 / abortController / 焦点），不引 Redux/Zustand（MVP 用不上）。组件树深、prop drilling 痛了再升级。
- **`<Static>` 不可变约定**（[Ink 3 官方](https://vadimdemedes.com/posts/ink-3)）：Static 是只追加/不可变的，item 渲染后冻结。**已 commit 的 assistant 消息 + 工具结果进 Static（定型，含折叠状态）；当前流式/工具/折叠在动态区**（可重绘）。→ 折叠只对当前轮，commit 后定型（见 5.2）。
- **中文字符宽度**：marked/cli-highlight 渲染换行必须按**显示宽度**（全角中文占 2 列，半角占 1 列），不能按字符数，否则中文行换行错位、边框对不齐。用 `string-width` 之类库计算。
- **配色集中** `tui/theme.ts`（Ink `<Text color>` prop，ANSI 码仅参考）；符号常量 `tui/symbols.ts`。
- **Unicode 退化**：M1 烟测终端 Unicode 支持，不支持则降级 ASCII 符号集（`>` `*` `+` `!` `x`）。

## 9. 开放问题

- **鼠标支持**：Ink 7 支持鼠标事件，MVP 不做（键盘优先），后续可加滚动/点击展开。
- **主题切换（亮/暗）**：MVP 只暗色，后续加 Config 项 + theme 切换。
- **A+ 流式期实时 markdown**：M2 用方案 A（灰字占位→commit，滚动友好）；后续升级 A+（流式期实时 markdown 重渲染，md2term 式全量重渲染），等滚动锁定 + 性能验证成熟。
- **终端宽度自适应**：markdown 渲染按 `process.stdout.columns` 换行，窗口 resize 重渲染。
