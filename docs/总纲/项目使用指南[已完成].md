# ECode — 项目使用指南

> ECode 是一个用 TypeScript + Node.js 从零手写的 AI coding agent（开源产品，对标 Claude Code）。
> 单包 CLI，核心是手写的 agent loop（不用 LangGraph 等框架），通过 LLM 工具调用在终端中完成编程任务。

---

## 快速开始

### 环境要求

- Node.js ≥ 18.0.0
- npm（禁用 pnpm / cnpm / yarn，见 CLAUDE.md §9.1）

### 安装

```bash
git clone <repo-url> ecode
cd ecode
npm install
```

### 配置 API Key

1. 复制 `.env.example` 为 `.env`：
   ```bash
   cp .env.example .env
   ```

2. 在 `.env` 中填入你使用的模型提供商的 API Key：
   ```env
   # 三选一（或多个都配，运行时切换）
   ZHIPUAI_API_KEY=sk-your-glm-key          # 智谱 GLM（默认）
   DEEPSEEK_API_KEY=sk-your-deepseek-key     # DeepSeek
   ANTHROPIC_API_KEY=sk-ant-api03-...        # Anthropic Claude
   ```

**不配 Key 也能启动**——ECode 有内置默认配置，但 LLM 调用会因认证失败报错。

### 开发运行

```bash
# 自动加载 .env，进入 REPL 沉浸式交互
npm run dev

# 或直接给任务（one-shot 模式）
npm run dev -- "帮我写一个快速排序"
```

### 构建

```bash
npm run build    # tsc strict 编译 → dist/
npm start        # 运行编译产物（等价于 node dist/index.js）
```

### 测试

```bash
npm test                           # 全套测试
npx vitest run tests/tools.test.ts # 单文件
npx vitest run -t "用例名"         # 按名称筛选
```

## 使用方式

ECode 有两种入口模式：

### 1. REPL 沉浸式模式（推荐）

在交互终端中无参启动，自动进入 REPL：

```bash
ecode                    # 或 npm run dev
```

REPL 特性：
- 多轮对话：连续输入任务，agent 自动保持上下文
- 流式输出：实时显示 LLM 回复（逐字流式）
- 工具可视化：工具调用显示运行状态（spinner）和完成结果
- 斜杠命令：`/help`、`/clear`、`/model`、`/exit` 等
- 会话持久化：对话自动保存，可续接

### 2. One-shot 单次模式

```bash
ecode "任务描述"                           # 新会话
ecode --model deepseek "任务描述"          # 指定模型
```

运行完自动退出，适合脚本/自动化场景。

## CLI 命令一览

| 命令 | 说明 |
|------|------|
| `ecode` | 进入 REPL 沉浸式交互 |
| `ecode --repl` | 强制进入 REPL（即便非交互终端） |
| `ecode "任务"` | 单次执行任务 |
| `ecode --model <name> "任务"` | 指定模型执行任务 |
| `ecode --list-models` | 列出所有可用模型 |
| `ecode --continue` | 恢复最近会话（打印摘要，不调 LLM） |
| `ecode -c "新指令"` | 续接最近会话（简写） |
| `ecode --resume <id>` | 恢复指定会话 |
| `ecode --resume <id> "新指令"` | 续接指定会话 |
| `ecode --sessions` | 列出本项目全部会话 |
| `ecode --permission-mode <mode>` | 权限档：`default` \| `acceptEdits` \| `bypass` |
| `ecode --dangerously-skip-permissions` | 跳过全部审批（= `bypass`，仅可信环境） |

## 配置系统

配置分三层（优先级从高到低）：

### 1. 环境变量（`.env` 文件）

```env
# API Key（必须配你要用的提供商）
ZHIPUAI_API_KEY=sk-...
DEEPSEEK_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-...

# 自定义端点（可选，留空用内置默认）
GLM_BASE_URL=https://open.bigmodel.cn/api/coding/paas/v4
DEEPSEEK_BASE_URL=https://api.deepseek.com
ANTHROPIC_BASE_URL=https://api.anthropic.com
```

- `npm run dev` 自动加载项目根目录的 `.env`
- 端点变量（`*_BASE_URL`）可覆盖 config.json 和 SDK 默认值

### 2. 用户级配置（`~/.ecode/config.json`）

> **首次启动自动生成**：运行 `npm run dev` 或 `ecode` 时，如果 `~/.ecode/config.json` 不存在，会自动创建带注释的配置模板。直接编辑即可，修改后重启生效。

```jsonc
{
  "defaultModel": "glm-5.2",
  "providers": {
    "glm": {
      "protocol": "openai",
      "baseURL": "https://open.bigmodel.cn/api/coding/paas/v4",
      "apiKeyEnv": "ZHIPUAI_API_KEY",
      "baseURLEnv": "GLM_BASE_URL"
    },
    "deepseek": {
      "protocol": "openai",
      "baseURL": "https://api.deepseek.com",
      "apiKeyEnv": "DEEPSEEK_API_KEY",
      "baseURLEnv": "DEEPSEEK_BASE_URL"
    },
    "claude": {
      "protocol": "anthropic",
      "baseURL": "https://api.anthropic.com",
      "apiKeyEnv": "ANTHROPIC_API_KEY",
      "baseURLEnv": "ANTHROPIC_BASE_URL"
    }
  },
  "models": {
    "glm-5.2": { "provider": "glm", "capabilities": ["tools"], "contextWindow": 1000000 },
    "deepseek-chat": { "provider": "deepseek", "capabilities": ["tools"], "contextWindow": 128000 }
  }
}
```

- 不存在 config.json 时用内置默认（开箱可用）
- 可添加自定义模型/提供商，零代码改动

### 3. 项目记忆（`CLAUDE.md` / `ECODE.md`）

ECode 启动时自动读取项目记忆文件（4 层回退，ECODE.md 优先）：

| 层级 | 路径 | 用途 |
|------|------|------|
| 1 | `~/ECODE.md` 或 `~/CLAUDE.md` | 全局用户偏好 |
| 2 | `<项目根>/ECODE.md` 或 `<项目根>/CLAUDE.md` | 项目级指令 |
| 3 | `<项目根>/.ecode/ECODE.md` | 本地配置（gitignore） |
| 4 | `<cwd>/ECODE.md` 或 `<cwd>/CLAUDE.md` | 工作目录级 |

这些内容会注入 system prompt，指导 LLM 的行为。已有 CLAUDE.md 的项目可直接复用（兼容 Claude Code 格式）。

## 内置工具

Agent 通过以下 5 个工具与本地环境交互：

| 工具 | 功能 | 默认审批 |
|------|------|----------|
| `read_file` | 读取文件内容 | 放行（工作区内） |
| `grep` / `glob` / `ls` | 搜索内容 / 查找文件 / 列目录（只读） | 放行 |
| `edit_file` | 精确替换文件片段 | **询问**（修改文件） |
| `write_file` | 整文件写入 | 询问 |
| `move` | 移动 / 重命名 | 询问 |
| `delete_file` | 删除文件 / 目录 | **拒绝**（始终危险，需显式 `allow` 放行） |
| `bash` | 执行 shell 命令 | 按规则分级（见[权限系统](#权限系统)） |
| `todo_write` | 更新任务清单 | 放行 |

> 工作区外路径、敏感文件（`.env`/`.git` 等）即使只读工具也会升级为询问。完整规则见下方[权限系统](#权限系统)章节。

**输出截断**：
- bash：输出超过 30,000 字符会被截断
- read_file：超过 2,000 行 / 单行超过 2,000 字符会被截断

## 权限系统

ECode 对所有「有副作用」的操作（写/删/移动文件、执行 bash）执行权限审批，防止误删、越界写、危险命令。

### 三档模式

| 模式 | 行为 | 适用 |
|------|------|------|
| `default` | 危险操作弹窗询问（**默认**） | 日常开发，推荐 |
| `acceptEdits` | 自动放行文件编辑（edit/write/move）；`bash` 仍按规则审批 | 批量重构、信任 agent 改文件 |
| `bypass` | 跳过全部审批 | 仅可信/沙箱环境 |

切换方式：

- **CLI**：`ecode --permission-mode acceptEdits`（启动即生效）
- **REPL 内**：`Shift+Tab` 循环 `default → acceptEdits → bypass → default`
- **配置文件**：`settings.json` 的 `"defaultMode"`

优先级：`--dangerously-skip-permissions` > `--permission-mode` > `settings.json.defaultMode` > `default`。

### 配置文件 settings.json

首次启动自动生成两层带注释模板（已存在不覆盖，便于直接编辑）：

| 层 | 路径 | 作用 |
|----|------|------|
| 用户级 | `~/.ecode/settings.json` | 个人全局默认 + 安全网 |
| 项目级 | `<项目>/.ecode/settings.json` | 覆盖用户级，写本项目特有规则 |

两层规则扁平合并；`defaultMode` 取后加载层（**项目级胜**）。

> **入库由你决定**：`.ecode/` 默认被 `.gitignore` 忽略（含会话数据）。想团队共享权限规则，自行 `git add -f .ecode/settings.json` 或改自己的 `.gitignore`。

示例（自动生成的模板，可直接编辑）：

```jsonc
{
  // defaultMode 可选：default | acceptEdits | bypass（省略 = 默认 default）
  "allow": ["Bash(npm run *)", "Bash(git status)", "Bash(ls)"],
  "deny": ["Bash(rm -rf *)", "Bash(git push --force *)", "Edit(.env)", "Edit(.env.*)"],
  "ask": ["Bash(git push *)"]
}
```

### 规则语法 `Tool(pattern)`

- **工具名**（首字母大写）：`Bash` / `Edit` / `Write` / `Read` / `Glob` / `Grep`
- **pattern**：精确 `npm run test`，或通配 `npm run *`
- **三组**：`allow`（放行）/ `deny`（拒绝回喂错误）/ `ask`（强制询问），优先级 **deny > ask > allow**
- **bash 复合命令**（`&&`/`||`/`;`/`|`）逐段校验，命中任一 `deny` 段则整条拒绝
- **bash 归约**：`git checkout main` 按 arity 字典归约成 `git checkout`，配 `Bash(git checkout *)` 一次放行同类

### 硬安全网（底层兜底）

即使在 `acceptEdits` 下也强制询问：

- **敏感文件**：`.env`/`.env.*`、`.gitconfig`、`.bashrc`/`.zshrc` 等 shell 配置、`.mcp.json`/`.claude.json`
- **敏感目录**：`.git/`、`.vscode/`、`.idea/`、`.claude/`、`.ecode/`
- **路径越界**：读写工作区之外的目录

### 审批交互

危险操作弹窗三选项（带 **425ms 防误触** grace）：

- **允许一次**：本次执行，下次仍询问
- **始终允许**：本次执行 + 本会话记住规则（仅内存，不写盘，防误点永久放行）
- **拒绝**：拒绝并回喂错误给 LLM（可附反馈文字）

> 连续 3 次相同工具 + 相同输入 → 触发 **doom_loop** 提示，避免死循环消耗。

## 会话管理

### 自动持久化

每次 agent 完成一轮回复，对话自动保存到 `.ecode/sessions/` 目录（已 gitignore）。

文件格式：`<UUID>_<任务摘要>.json`，包含完整的 messages 历史。

### 恢复会话

```bash
# 查看最近会话的摘要（不调 LLM）
ecode --continue

# 续接最近会话，继续对话
ecode -c "新的问题"

# 恢复指定会话
ecode --resume <session-id>

# 列出所有会话
ecode --sessions
```

续接时复用原会话的 ID 和首句任务，LLM 能看到之前的完整对话历史。

## 上下文管理

长对话会自动触发上下文压缩，防止超出模型的上下文窗口限制。

### 压缩策略（级联）

| 级别 | 策略 | LLM 成本 |
|------|------|---------|
| L2 | 旧 tool_result 内容清空为占位符（保留最近 3 个） | 零 |
| L3 | LLM 摘要压缩早期对话（保留最近 6 个工具往返） | 一次摘要调用 |
| L4 | 响应式强制压缩（API 报超限后触发，更激进） | 可能一次摘要 |

### 关键约束

- **压缩边界**落在完整的工具往返之间（不劈开 tool_call + tool_result 配对）
- **压缩后数据结构不变**：输出仍是标准 message 数组，agent loop 无感知
- 压缩失败自动降级（不阻塞 agent 运行）
- 压缩阈值：contextWindow × 80%（留 20% 给本轮回复）

## 运行时日志

每次运行 agent 会生成结构化日志，方便调试：

```
docs/logs/runtime/<session-id>/
├── <session-id>.md          # 主日志（人类可读摘要）
└── raw/                      # 完整 API 报文
    ├── round-1.req.json      # 第 1 轮请求
    ├── round-1.resp.json     # 第 1 轮响应
    ├── round-2.req.json
    └── ...
```

- 主日志用 `appendFileSync` 实时写入，进程崩溃不丢
- raw 目录存完整报文（截断处有指针标注）
- API 请求/响应/工具执行/错误都有记录

## TUI 界面

REPL 模式使用 Ink（React for CLI）构建的 TUI 界面。

### 界面组成

```
┌────────────────────────────────────────┐
│  ECode Logo / 欢迎屏（首次启动）        │
├────────────────────────────────────────┤
│  对话区域（<Static> + 动态区）          │
│                                        │
│  │ ❯ 你                               │  ← 用户消息（左边框 + 背景色）
│  │ 帮我写一个快排                      │
│  │                                    │
│  ◆ ECode                             │  ← 助手消息
│      好的，我来帮你...                  │
│                                        │
│  ✓ read_file · src/index.ts · Read 42 │  ← 工具 Inline 模式（单行）
│                                        │
│  │ ✓ bash (npm test)                  │  ← 工具 Block 模式（多行面板）
│  │ ↳ PASS                             │
│  │   ... 2 more lines                 │
│                                        │
├────────────────────────────────────────┤
│  输入栏                                │
│  > _                                  │
├────────────────────────────────────────┤
│  状态栏：模型 / token / 上下文 / 费用   │
└────────────────────────────────────────┘
```

### 视觉区分

- **用户消息**：`❯ 你` 前缀 + 左边框 + 深色背景
- **助手消息**：`◆ ECode` 前缀 + Markdown 渲染
- **工具 Inline**：单行摘要（`✓ read_file · 路径 · Read N lines`），适用于 read_file 等少量输出
- **工具 Block**：左边框面板 + 深色背景，适用于 bash 多行输出、grep 多匹配等
- **系统消息**：`▲`（警告）/ `✗`（错误）左边框

## 错误恢复

| 场景 | 处理方式 |
|------|---------|
| API 429/5xx | 指数退避 + jitter 重试（最多 3 次） |
| API 400 | 立即抛出（不可重试） |
| 工具执行失败 | 回喂 `isError=true` 的 tool_result，让 LLM 自行处理 |
| 上下文超限 | 自动压缩（L2→L3→L4 级联） |
| 死循环 | 最多 25 轮迭代后终止 |
| Agent 被中断 | Ctrl+C（AbortController），保持 tool 配对不断裂 |
| Session 写盘失败 | 首次 warn 提示，之后静默降级（不杀 agent） |
