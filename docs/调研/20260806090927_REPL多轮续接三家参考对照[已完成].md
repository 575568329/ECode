## 0. 一句话结论

**三个项目在同一件事上高度共识:「消息历史的真相源」必须单点化、跨多轮持久存在,且 sessionId 只生成一次。ECode 这两条都违反了**——所以才会「每轮新会话 + 失忆」。这不是 ECode 独有的坑,是行业里踩过无数遍的,有现成抄法。

最小修复路径已经清楚(见 §5):**补全 `completed` 事件 + UI 加一个 `sessionRef`**,改动 ~40 行、3 个文件,不动 one-shot、不动 session.ts。

## 1. 三家怎么解决的(对照表)

| 维度 | CCode(同栈) | Claude Code(本尊) | opencode(SST) |
|------|------|------|------|
| **历史真相源在哪** | 模块级单例 `ContextManager.#history`(`Message[]`) | React state + ref 镜像(`messagesRef.current`) | 后端 SQLite(前端只持 `sessionID`) |
| **agent loop 拿历史的方式** | `run(historyRef)` 接**引用**,内部 `HistoryWriter` 原地 push | `query({messages})` 接完整数组(无状态 generator) | runner 每 turn 从 db **重载**历史 |
| **回合结束事件带不带历史** | ❌ 不带(`done` 只带 reason) | ❌ 不带(根本没 completed 概念) | ✅ 带(`Step.Ended` 带 snapshot/tokens) |
| **sessionId 怎么生成** | `ensureSession()` 幂等,已有就返回 | bootstrap 生成一次,组件 ref 持守 | 首次 `session.create`,后续复用 |
| **持久化** | JSONL append-only + `parentUuid` 树 | JSONL append-only + cursor 只写新 tail | 事件 append + projector 物化 |
| **压缩触发** | `inputTokens/window >= 0.85`(百分比) | `window − max(20K output) − 13K buffer`(**绝对余量**) | `limit − max(output, 20K)` + keep 尾部 8K |
| **压缩断路器** | 无 | 连续失败 3 次停 | 无 |
| **可抄性** | ★★★★★ 同栈,代码可直接搬 | ★★★★★ 思想、★★★ 代码(规模太大) | ★★★★ 思想,外壳不能抄 |

## 2. 七条共识(行业标准,不是某家拍脑袋)

1. **历史真相源单点化、跨多轮持久**——绝不能每次用户发消息都从空数组开始。
2. **sessionId 幂等**——一个会话只生成一次 id,后续轮次复用。
3. **agent loop 不持有历史**——它要么接收外部引用(CCode),要么接收完整数组(Claude Code),要么从持久层重载(opencode)。agent 函数内部「自己 new 一个 messages」是反模式。
4. **持久化倾向 append**(JSONL/事件),不要整对象覆盖重写——append 天然抗「同秒重写、越聊越多文件」。
5. **压缩阈值用绝对 token 余量,不是百分比**——百分比会让小窗口过早压、大窗口过晚压(Claude Code / opencode 都这么干)。
6. **压缩保留尾部原文**——避免压完丢了最近一轮的精确 tool result(opencode keep 8K)。
7. **压缩要有断路器**——连续失败 N 次就停,否则 irrecoverable context 会无限重试烧钱(Claude Code:3 次)。

> ECode 违反了 **#1 #2 #3**(这是 bug 根因),#4 是覆盖写(有 slug 隐患但暂能跑),#5 #6 #7 是压缩优化项(可后置)。

## 3. ECode 现状对照(违反点 ↔ bug)

实读核对(`src/` 下):

| 共识 | ECode 现状 | 位置 | 后果 |
|------|-----------|------|------|
| #1 真相源单点 | `let messages = ...` 每次 submit 在函数栈上从空 new | `agent.ts:223-225` | agent 失忆 |
| #2 sessionId 幂等 | `opts.resumed?.id ?? generateSessionId()`,REPL 每次走右边 | `agent.ts:231` | 文件增殖 |
| #3 agent 不持历史 | runAgentStream 内部 new + push | `agent.ts:223, 327` | 同 #1 |
| — completed 带历史 | 只带 `{rounds, toolCalls, reason}` | `agent-events.ts:28` | UI 拿不到历史,无法续接(接口断点) |
| — REPL 传 resumed | `streamOpts` 从不带 resumed | `use-agent-stream.ts:70-81` | 病根入口 |

**诊断文档里的两个 bug(文件增殖 + 失忆)其实是同一个断点**:`completed` 事件不带历史 → UI 没法存 → 下一轮没法传 `resumed` → agent 当新会话跑。

## 4. 两条修复路线

三家分两种哲学:**真相源放 UI 层**(CCode / Claude Code) vs **真相源放 agent/后端层、UI 只持 id**(opencode / ECode 的 `resumed` 设计本意)。

| | **路线 A:UI 持有真相源(删 resumed)** | **路线 B:补全 resumed 闭环** |
|---|---|---|
| 出处 | CCode 单例 / Claude Code ref | opencode(completed 带历史回传) |
| 改动核心 | runAgentStream 改签名(接 messages 引用 + sessionId),删 `resumed` | completed 补 `sessionId+messages`,UI 加 `sessionRef` |
| completed 事件 | **不动** | 要加字段 |
| runAgentStream 签名 | **大改**(one-shot 也要跟着改) | **不动** |
| one-shot / --continue | 要跟着改签名 | **完全不动**(本就走 resumed) |
| 改动量 | ~100 行,4-5 文件 | **~40 行,3 文件** |
| 测试影响 | agent.ts 签名变,一批测试要改 | 小(completed 断言补字段) |
| 风险 | 全局可变状态(单例)或大范围签名改 | 低,局部 |
| 「正确性」 | 最干净(零拷贝、真相源纯 UI) | 同样满足共识 #1(sessionRef 即真相源) |

---

## 5. ⭐ 推荐:路线 B(最小、最稳、契合现有契约)

**理由**:ECode 的 `resumed` 设计本意就是路线 B,只是实现没闭环(completed 没带数据)。补全闭环即可,**one-shot / --continue 一行不用改**(它们本就走 resumed),改动面最小、风险最低。sessionRef 本质就是「UI 持有真相源」,只是同步方式是 completed 事件回传(对单进程零差异),同样满足七条共识。

路线 A 更「纯粹」(真相源彻底上移),但代价是改 runAgentStream 签名、波及 one-shot 和一批测试——**记为未来可选重构,这次不做**。

### 5.1 具体改动(3 文件,~40 行)

**(1) `src/agent-events.ts:28` —— completed 补字段**

```ts
| {
    type: 'completed';
    rounds: number;
    toolCalls: number;
    reason: AgentCompletionReason;
    sessionId: string;          // ← 新增
    messages: ECodeMessage[];   // ← 新增(本轮结束时累积的全量历史)
    task: string;               // ← 新增(会话首句,resumed 续接用)
    createdAt: string;          // ← 新增(会话创建时间,续接复用)
  }
```
(需 `import type { ECodeMessage } from './providers/types.js'`)

**(2) `src/agent.ts` —— 所有 completed 出口补字段**

`agent.ts:317-322`(done 路径)改成:
```ts
yield {
  type: 'completed',
  rounds: iteration + 1,
  toolCalls: stats.toolCalls,
  reason: 'done',
  sessionId,            // ← 都是函数内已有变量
  messages,             // ← 同上
  task: sessionTask,
  createdAt,
};
```
> ⚠️ **必须找到全部 completed 出口**(done / max-iterations / repeated / aborted 四条终止路径),逐个补齐,否则漏一条就续接失败。grep `type: 'completed'` 定位。

**(3) `src/ui/use-agent-stream.ts` —— 加 sessionRef + 续接**

顶部加 ref(和现有 `stateRef`/`generationRef` 同款):
```ts
// 跨轮会话续接的真相源:首次为 null(新会话),completed 后存 {id,messages,...};
// 之后 submit 经 resumed 传回 → agent 复用同一会话(修"每轮新会话+失忆")。
const sessionRef = useRef<ResumeContext | null>(null);
```

submit 里(`use-agent-stream.ts:70-81`)streamOpts 加 resumed:
```ts
const streamOpts: RunAgentStreamOptions = {
  model: opts.model,
  system: opts.system,
  signal: controller.signal,
  allow: allowRef.current,
  permissionGate: { ... },  // 原样
  resumed: sessionRef.current ?? undefined,   // ← 新增:首次 null→新会话,之后续接
};
```

async IIFE 的 for await 里(`use-agent-stream.ts:86-88`)捕获 completed:
```ts
for await (const event of runAgentStream(text, streamOpts)) {
  apply(event);
  if (event.type === 'completed') {
    sessionRef.current = {
      id: event.sessionId,
      messages: event.messages,
      task: event.task,
      createdAt: event.createdAt,
    };
  }
}
```

clear(`use-agent-stream.ts:121-123`)重置会话(开新文件):
```ts
const clear = useCallback(() => {
  sessionRef.current = null;                    // ← 新增:下轮走新会话
  setState((prev) => ({ ...prev, completedMessages: [] }));
}, []);
```

> `session.ts` **不动**——同 id 覆盖语义本来就对(现在 resumed 带对了 id,每轮覆盖同一个文件)。`app.tsx` **不动**——`/clear` 已调 `api.clear()`。

### 5.2 闭环验证(修完该满足)

- REPL 连发 3 句 → `.ecode/sessions/` 只有 **1 个**文件(每轮覆盖)。
- 第 2 句能引用第 1 句的内容(agent 有记忆)。
- `/clear` 后再发 → 新文件、新 id、不记得清空前的内容。
- `ecode "任务"`(one-shot)/ `ecode --continue` 行为不变。

## 7. 明确不要抄(过度设计)

| 项 | 出处 | 为什么不抄 |
|----|------|-----------|
| 客户端-服务端分离 / HTTP API / SSE | opencode | ECode 单进程 CLI,引入这层复杂度爆炸 |
| 事件溯源 + projector + durable event log | opencode | 一个 prompt 发 5-10 个事件,ECode 杀鸡用牛刀 |
| Effect-TS / Layer / Stream | opencode | ECode 是 vanilla TS + AsyncGenerator |
| SQLite + drizzle | opencode | JSON 文件存 session 对单进程足够 |
| 5 层压缩栈(micro/snip/collapse/sessionMemory/auto) | Claude Code | ECode 一个 maybeCompress 够用 |
| reactiveCompact | Claude Code | 开源版根本没有(`feature()` 门控 + DCE) |
| 自研 Ink fork / REPL.tsx 5005 行规模 | Claude Code | 学思想不学规模 |
| partialCompact(messageSelector) | Claude Code | 依赖 ECode 没有的 UI |
| JSONL parentUuid 树(/fork 分支) | CCode | ECode 单线会话,不需要树 |
| SessionLogger / HistoryWriter 抽象类 | CCode | ECode 持久化逻辑可直接写,短期不必抽 |
| 多 CompactStrategy 策略模式 | CCode | ECode 单条压缩路径够用 |

## 8. 落地步骤 + 决策点

### 决策(看完拍板)

1. **走路线 B 吗?**(推荐)—— 若否,走路线 A(改动大但更纯粹)或先不动。
2. **P2 压缩优化(§6)这次一起做,还是只修 bug?**(推荐:只修 bug,P2 另起)
3. **contextWindow 修复 + 本次续接修复,commit 怎么拆?**
   - 推荐:`fix(ui): contextWindow 改用真实窗口`(已改,独立)+ `fix(repl): 多轮续接,resumed 闭环`(本次)。两个原子提交。

### 若确认路线 B,实施顺序(TDD)

1. `agent-events.ts`:completed 加 4 字段(改类型 + 类型守卫不用动)。
2. `agent.ts`:4 个 completed 出口补字段(grep 全覆盖)。
3. `use-agent-stream.ts`:sessionRef + resumed + completed 捕获 + clear 重置。
4. 单测:`agent-events` 补 completed 字段断言;`use-agent-stream` 补「连发两句复用同 sessionRef」用例;`agent` 续接路径回归。
5. 手测:REPL 连发 3 句验「1 文件 + 有记忆」;`/clear` 验新会话;one-shot 回归。
6. 跑 `npx vitest run` 全绿(`vitest` 脚本是 watch 模式,见诊断文档 §6.3)。
