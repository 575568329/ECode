## 0. 概述

### 0.1 定位
ECode 是一个**终端 Agent CLI**,以 **AgentLoop 为心脏**,其他能力(工具、模型接入、TUI、斜杠命令、历史、配置)作为**分支**接入心脏。形态对标 Claude Code / Aider。

### 0.2 技术栈
- **语言/运行时**:TypeScript(严格模式) / Node.js
- **模块格式**:**ESM**(`package.json:"type":"module"`、`tsconfig:"module":"NodeNext"`)。4 坑:① import 路径须带 `.js` 扩展名(即使源是 .ts,tsx 容忍但规范写 `.js`);② 纯 CJS 包用默认导入(named import 可能拿不到,M1 烟测核实 `ink-text-input`/`ink-spinner`/`marked`/`cli-highlight` 的 ESM 导出);③ `__dirname`/`__filename` 不存在,改 `fileURLToPath(new URL('.', import.meta.url))`;④ JSON 用 `fs` 读,不走 import assertion。
- **TUI**:**标准 Ink 7 + `@inkjs/ui`**(基础件:TextInput/Select/Spinner/ConfirmInput 等)+ **自建三件**(终端 Markdown 渲染 / 折叠 ToolCallView / 流式分阶段渲染)。**不走** Claude Code 式自建 React reconciler 路线(生产级投入,MVP 不需要;详见 5 节 + 解析文档决策 2)。
- **首版模型接入**:`@anthropic-ai/sdk` 接 **Astron 的 Anthropic 兼容端点**(跑 GLM)

### 0.3 架构哲学:融合架构
- **两个"扩展面"走统一接口 + 注册中心**(可插拔):`Tool` 与 `LLMProvider`。加新工具/新模型 = 写实现 + `register()`,心脏零改动。
- **内部基础服务走分层直接接入**(YAGNI,不套接口):TUI、Config、History、Command、Logger、Permissions。

**唯一铁律:心脏(AgentLoop)永远不出现 `if provider === 'xxx'` 这类判断**——所有协议差异封在 Provider 实现内部。一旦这类判断钻进心脏,抽象就泄漏了。

### 0.4 MVP 范围(B 档:标准 MVP)
- AgentLoop 心脏(多轮 + 工具调用 + 流式)
- **多 Provider 切换**(实现 anthropic + openai **两协议**;`/model` 跨 provider 一键切 GLM/DeepSeek/OpenAI 等。详见解析决策 4)
- 内置工具(**7 个**):`read_file` / `write_file` / `edit_file` / **`ls`** / `glob` / `grep` / `bash`
  - **只读通道**(免确认、可并行):`read_file` / `ls` / `glob` / `grep`
  - **副作用通道**(确认、串行):`write_file` / `edit_file` / `bash`
- TUI(流式渲染 + 中断控制 + 折叠 + 终端 Markdown)
- 斜杠命令(`/help` `/clear` `/model` `/history`)
- 对话历史持久化(跨会话恢复)
- 配置系统(**用户级 `~/.ecode/config.json`**(JSONC,多 provider 多模型)+ `.env`(dev 专用);首次运行向导。详见 4.1)

**非目标(留后续版本)**:MCP 客户端、子 agent / 多 agent 编排、上下文自动压缩、**多 provider 路由(按任务自动选模型)**。

## 1. 整体架构

```
                      ┌────────────────────────────────────┐
                      │        ECode CLI 入口 (bin)        │
                      └─────────────────┬──────────────────┘
                                        │ 启动 / 接管终端
                      ┌─────────────────▼──────────────────┐
                      │        TUI 分支 (Ink, 类 React)     │
                      │  对话流渲染 · 工具调用展示 · 输入框  │
                      └─────────────────┬──────────────────┘
                                        │ 用户消息 / 渲染事件
              ╔═════════════════════════▼═══════════════════════╗
              ║             AgentLoop  (心脏)                    ║
              ║   while not done:                                ║
              ║     resp  = llm.run(messages, tools)            ║
              ║     for call in resp.tool_calls:                ║
              ║       result = tools.invoke(call)  ◄── 回流      ║
              ║       messages.append(result)                   ║
              ║     if no tool_calls: done = true               ║
              ╚══════════════╤══════════════════╤═══════════════╝
                             │                  │
          ┌──────────────────▼────┐    ┌────────▼─────────────────┐
          │  LLMProvider Registry │    │      Tool Registry       │
          │  (分支·模型接入)      │    │   (分支·工具能力)        │
          │                       │    │                          │
          │  • AnthropicProvider  │    │  read/write/edit/glob/   │
          │    → 接 GLM/Astron    │    │  grep/bash (内置)        │
          │  • (预留 OpenAI 等)   │    │  • (预留 MCP 动态注册)   │
          └───────────────────────┘    └──────────────────────────┘

   ┌──────────── 内置分层服务(直接接入心脏,不走 Registry)────────────┐
   │ Config(.env/模型/密钥) · HistoryStore(对话持久化)              │
   │ CommandRegistry(/help /clear /model …) · Logger · Permissions │
   └───────────────────────────────────────────────────────────────┘
```

**三句话解读:**
1. AgentLoop 只做一件事:反复调 LLM → 有工具调用就执行并把结果塞回 messages → 再调 LLM,直到 LLM 不再要求工具。它**不认识任何具体的工具或模型**,只认 Registry 给它的接口。
2. 两个 Registry 是"可插拔分支面",满足"模块统一格式、可插拔、改格式不痛"。
3. 基础服务走分层,不套接口(YAGNI)。

**构建顺序(由内向外):**
1. **心脏最小闭环** —— loop + 1 Provider + 2 个工具(read_file/bash),终端能跑通一轮对话
2. **接 TUI** —— 流式渲染、中断控制
3. **补全工具 / 斜杠命令**
4. **加历史持久化 / 配置系统**

每接一个分支都能立刻在 TUI 看到效果,契合"UI 同步实现"。

## 2. 核心接口契约

### 2.1 规范模型(全系统唯一通用格式)

心脏、工具、历史、TUI **只认这套模型**;各 Provider 负责与各家协议双向翻译。

```ts
// —— 内容块:盖住 text / 工具调用 / 工具结果三种形态 ——
interface TextBlock       { type: 'text';        text: string }
interface ToolUseBlock    { type: 'tool_use';    id: string; name: string; input: unknown }
interface ToolResultBlock { type: 'tool_result'; tool_use_id: string; content: string; is_error?: boolean }
// ImageBlock 留位(MVP 不实现图像输入,占类型位避免后续破坏性变更):
// interface ImageBlock    { type: 'image'; source: { type: 'base64'; media_type: string; data: string } }
type ContentBlock = TextBlock | ToolUseBlock | ToolResultBlock

// system 不进 messages,只走 LLMProvider.run({ system }) 参数(见 2.2)。
// 与 Anthropic 一致;OpenAIProvider 内部把 system 翻译成 messages[0]。
interface Message { role: 'user' | 'assistant'; content: ContentBlock[] }

interface ToolSpec { name: string; description: string; input_schema: object }   // JSON Schema(MVP 扁平化,见 2.3)

type StopReason = 'end' | 'tool_use' | 'length' | 'error' | 'aborted' | 'content_filter'

// —— 统一流式增量:心脏与 TUI 只消费这个 ——
// error: 流中途失败(网络断、畸形事件、parse 失败),发出后不再有 done。
// usage: token 用量,Provider 在 done 前或流末尾发出,承载计费可见性。
type Delta =
  | { type: 'text';           text: string }
  | { type: 'tool_use_start'; id: string; name: string }
  | { type: 'tool_use_delta'; id: string; partial_json: string }
  | { type: 'tool_use_end';   id: string }
  | { type: 'usage';          input_tokens: number; output_tokens: number; cache_read_tokens?: number }
  | { type: 'error';          error: AppError }
  | { type: 'done';           stop_reason: StopReason }
```

> 规范模型故意贴近 Anthropic(首版接 Anthropic 兼容端点,翻译最薄)。注意"翻译最薄"只对 messages/content 成立——**tools 数组跨 Provider 仍需翻译**(OpenAI 的 function wrapper、required 位置、additionalProperties 处理都不同),由各 Provider 内部承担。

### 2.2 LLMProvider 接口(模型接入分支面)

**两层架构(解析决策 3):** Provider **实现**(按 `type`,无状态) + Provider **配置实例**(按 `name`,从 config 读)。同一实现服务多个实例(如 OpenaiProvider 同时服务 deepseek 和 openai)。

```ts
interface LLMProvider {
  readonly type: string                                   // 协议类型:'anthropic' | 'openai' | ...(决定实现层)
  run(req: {
    name: string                                          // 配置实例名(astron/deepseek/...),用于 client 缓存
    baseURL: string
    apiKey: string
    model: string
    system: string
    messages: Message[]
    tools: ToolSpec[]
    signal?: AbortSignal                                  // 支持中断
  }): AsyncIterable<Delta>                                // 统一 Delta 流(实现按 name 缓存 SDK client,不在构造时绑定配置)
}

interface LLMProviderRegistry {
  register(p: LLMProvider): void
  getByType(type: string): LLMProvider                    // 按 type 取实现(anthropic/openai)
}
```

**AnthropicProvider(MVP 实现,内部借 SDK):**
```ts
class AnthropicProvider implements LLMProvider {
  readonly type = 'anthropic'
  private clients = new Map<string, Anthropic>()          // name → client 缓存(同实例复用,避免每轮 new)
  async *run({ name, baseURL, apiKey, model, system, messages, tools, signal }) {
    const client = this.clients.get(name) ?? new Anthropic({ baseURL, apiKey })
    if (!this.clients.has(name)) this.clients.set(name, client)
    const s = client.messages.stream({ model, system, messages: toAnthropicMsgs(messages), tools, signal })
    for await (const e of s) yield mapAnthropicEvent(e)   // 协议事件 → 统一 Delta
  }
}
```

**OpenaiProvider(MVP 实现,展示翻译职责):** system 塞进 messages 数组、`tool_use`→`tool_calls`(包一层 `function`)、`tool_result`→独立 `role:'tool'` 消息、`tools` 包 `function` wrapper、流式 chunk 映射成同一套 `Delta`。覆盖 OpenAI / DeepSeek / Moonshot / 智谱 OpenAI 兼容端等(各家的 `baseURL`/`apiKey`/`models` 不同,协议实现共用)。

**AgentLoop 每轮取 provider:** `current`(`/model` 选中的 `name`+`model`) → `config.providers[name]` → `registry.getByType(providerCfg.type)` → 注入 `baseURL`/`apiKey`/`model` → `run()`。**心脏只认 `type` 找实现,不认识具体厂商名**——铁律不变(解析决策 3)。

### 2.3 Tool 接口(工具能力分支面)

```ts
interface Tool {
  name: string
  description: string
  input_schema: object            // JSON Schema,直接传给 LLM 的协议格式
  readonly: boolean               // true=只读(可并行) / false=有副作用(串行+需确认)
  timeout_ms?: number             // 执行超时(默认 30s),超时转 recoverable 错误
  execute(args: unknown, ctx: ToolContext): Promise<ToolResult>
}

interface ToolResult { content: string; is_error?: boolean }

interface ToolContext {            // 注入,工具无全局状态
  cwd: string                     // current working directory
  config: Config
  logger: Logger
  signal: AbortSignal
}

interface ToolRegistry {
  register(t: Tool): void
  get(name: string): Tool | undefined
  specs(): ToolSpec[]             // 导出给 LLMProvider 的 tools 参数
}
```

**入参校验:** Registry 在 `invoke` 前用 **AJV** 按 `input_schema` 校验(协议原生格式,零转换),不通过直接返回 `is_error` 的 ToolResult,根本不进 Tool。

**工具定义层:** MVP 直接写 JSON Schema。未来若 DX 痛了,再加 Zod 做"定义层"(`zod → json-schema`),但**校验层始终是 AJV**。

**JSON Schema 扁平化(MVP 约束):** 工具 `input_schema` 只用 `type` + `properties` + `required` + 基础约束(`minimum`/`maximum`/`default`),**避开** `oneOf`/`anyOf`/`$ref`/`enum` 嵌套等高级特性——GLM(经 Astron 兼容端点)对复杂 schema 的支持度未知,扁平结构最稳(解析决策 7)。GLM 对高级特性的支持度列为 M1 烟测项(见 10 节)。

**bash 工具的安全约束(MVP 必须落地):** bash 是 7 个内置工具(及 3 个副作用工具)里破坏力最大的(能 `rm -rf`、外发数据、卡死 Loop),仅靠 `readonly:false + y/n` 不够。MVP 锁定:
- **超时**:强制 `timeout_ms: 30000`,超时杀进程、转 recoverable 错误。
- **输出截断**:stdout/stderr 合计超 `bashMaxOutputBytes`(默认 **30720/30KB**,可配)时**头尾各半中间截断**——头/尾各 ~15KB,中间标记「…(中间 N 字节已截断,需要完整用 read_file/grep,不要编造)」。对标 Codex(10KiB)/Claude(30KB);头尾中截是业界最佳实践(错误在尾、摘要在头,两头都留),防编造提示避免 LLM 编造截断内容。
- **危险命令模式拦截**:正则匹配 `rm -rf /`、`sudo`、`> /dev/sd`、`:(){:|:&};:`(fork bomb)、`curl ... | sh` 等模式,命中直接拒绝(不进 y/n,产出 is_error 的 ToolResult),不让 LLM 重试绕过。
- **cwd 约束**:命令在 `ctx.cwd` 执行,禁止通过 `cd /` 跳出工作区(配合跨平台约定 4.6)。
- **退出码非 0**:不抛异常,作为正常 ToolResult 返回(内容含 stderr),交 LLM 判断——这属于 debug 类 recoverable。

**内置工具实现约定(MVP):**
- **`ls`(新增,只读)**:列指定目录内容 + 元信息(type/size/mtime)。纯 JS(`fs.readdir`+`fs.stat`),`readonly:true` 免确认、可与其它只读工具并行。入参:`path`(必填) / `depth`(1-3,默认 1) / `all`(默认 false,是否含隐藏文件)。MVP **不显示权限字段**(Windows chmod 语义不同)。对标 Claude Code 的 LS。
  - **四工具职责区分**(写进 system prompt,避免 LLM 在 ls/glob 间选错):`ls`=列目录详情 / `glob`=模式匹配找路径 / `grep`=搜文件内容 / `read_file`=读单文件。
- **`glob`**:`fast-glob`,**显式 `caseSensitiveMatch: true`**——否则 Windows 默认不敏感、Linux 敏感,同一模式跨 OS 结果不一致(解析决策 5)。
- **`grep`**:**纯 JS**(`fast-glob` 取文件 + `RegExp` 匹配),零外部依赖、跨平台完全一致(解析决策 3)。性能不足时后续版本切内置 ripgrep。
- **`bash`**:跨 OS coreutils 差异(GNU↔BSD 的 `sed -i`/`date`/`find` flag 等)**由 LLM 负责**,MVP 工具层只保证 Git Bash,不保证命令跨 OS 语义一致(解析决策 6)。system prompt 注入 `process.platform` 供 LLM 给平台适配命令。
- **`.ecodeignore`(`ls`/`glob`/`grep` 共用)**:默认忽略 `node_modules`/`.git`/`.env*`/`dist`/`build`,避免扫巨量文件/密钥进 context。三工具共用同一忽略加载逻辑(`services/ignore.ts`),M3 落地。

## 3. AgentLoop 数据流(心脏)

### 3.1 主循环

```ts
const MAX_ITERATIONS = 50

async function loop(userInput: string) {
  messages.push({ role: 'user', content: [{ type: 'text', text: userInput }] })

  for (let iter = 1; iter <= MAX_ITERATIONS; iter++) {
    // 接近上限预警,并提供"是否继续"出口(避免硬终止)
    if (iter === MAX_ITERATIONS) {
      const cont = await tui.confirmReachedLimit()
      logger.emit({ category: 'loop', event: 'limit_reached', level: 'warn', iterNum: iter, payload: { cont } })
      if (!cont) { tui.warn('已达轮数上限,停止'); break }
    } else if (iter >= MAX_ITERATIONS - 5) {
      logger.emit({ category: 'loop', event: 'limit_warning', level: 'warn', iterNum: iter, payload: { remaining: MAX_ITERATIONS - iter } })
      tui.warnApproachingLimit(MAX_ITERATIONS - iter)
    }

    logger.emit({ category: 'loop', event: 'iter_start', level: 'debug', iterNum: iter, payload: { msgCount: messages.length, toolCount: registry.specs().length } })

    // —— 消费 Provider 的 Delta 流 ——
    const jsonBuf = new Map<string, { name: string; buf: string }>()  // tool_use id → 拼接缓冲
    let textBuf = ''                                                   // 本轮 text 累积
    const newToolUses: ToolUseBlock[] = []
    let stopReason: StopReason = 'end'
    const t0 = Date.now()

    // ★ try/finally 兜底:无论正常结束、Provider error delta、还是 abort,
    //   都要走固化逻辑保留已生成内容(兑现 3.4 的"保留已生成内容到历史")。
    let streamError: AppError | null = null
    try {
      logger.emit({ category: 'provider', event: 'request', level: 'debug', iterNum: iter, payload: { model, msgCount: messages.length, toolCount: registry.specs().length } })
      for await (const d of provider.run({ model, system, messages, tools: registry.specs(), signal })) {
        // trace 级:每个 delta 都记(复现流式 bug 用,默认关)
        logger.emit({ category: 'provider', event: 'delta', level: 'trace', iterNum: iter, payload: { type: d.type } })
        switch (d.type) {
          case 'text':           textBuf += d.text; tui.streamText(d.text); break
          case 'tool_use_start': jsonBuf.set(d.id, { name: d.name, buf: '' }); tui.toolStarted(d.name); break
          case 'tool_use_delta': jsonBuf.get(d.id)!.buf += d.partial_json; break
          case 'tool_use_end': {
            const { name, buf } = jsonBuf.get(d.id)!
            // ★ 流式 JSON 拼接:parse 失败转 is_error 的 ToolUse,交 LLM 自纠,不崩 Loop
            let input: unknown
            try { input = JSON.parse(buf) }
            catch {
              input = { __parse_error: '工具输入 JSON 解析失败' }
              logger.emit({ category: 'tool', event: 'json_parse_failed', level: 'warn', iterNum: iter, payload: { id: d.id, name } })
            }
            newToolUses.push({ type: 'tool_use', id: d.id, name, input })
            break
          }
          case 'usage': tui.reportUsage(d.input_tokens, d.output_tokens, d.cache_read_tokens); break
          case 'error':
            streamError = d.error                              // 流内错误,记录后不再有 done
            logger.emit({ category: 'provider', event: 'stream_error', level: 'error', iterNum: iter, payload: { code: d.error.code, message: d.error.message, recoverable: d.error.recoverable } })
            break
          case 'done':  stopReason = d.stop_reason; break
        }
      }
      logger.emit({ category: 'provider', event: 'response_done', level: 'debug', iterNum: iter, duration_ms: Date.now() - t0, payload: { stopReason } })
    } catch (e) {
      // AbortError 或 SDK 抛出的网络异常:同样走 finally 固化
      if (streamError === null) streamError = toAppError(e)
      if (e instanceof AbortError) {
        stopReason = 'aborted'
        logger.emit({ category: 'tui', event: 'abort', level: 'info', iterNum: iter, payload: { source: 'user_ctrl_c' } })
      }
      if (streamError.recoverable === false && !(e instanceof AbortError)) throw streamError
    } finally {
      // ★ 固化已生成内容(无论正常/错误/中断,只要本轮产出了东西就保留)
      const assistantBlocks: ContentBlock[] = []
      if (textBuf) assistantBlocks.push({ type: 'text', text: textBuf })
      assistantBlocks.push(...newToolUses)
      if (assistantBlocks.length > 0) {
        messages.push({ role: 'assistant', content: assistantBlocks })
        tui.commitAssistantMessage(textBuf)              // ★ 收完整段后一次性 markdown 渲染
        history.append(messages.tail())                  // ★ 增量落盘(见 4.2),不等 Loop 结束
      }
      logger.emit({ category: 'loop', event: 'iter_end', level: 'debug', iterNum: iter, payload: { stopReason, textLen: textBuf.length, toolUses: newToolUses.length } })
    }

    // —— 流内错误处理 ——
    if (streamError) {
      if (streamError.recoverable) { tui.warn(streamError.message); continue }
      logger.emit({ category: 'error', event: 'app_error', level: 'error', iterNum: iter, payload: { code: streamError.code, recoverable: false } })
      throw streamError                                     // fatal 才抛顶层
    }

    // —— 停止判定 ——
    if (stopReason === 'end' || stopReason === 'aborted') break
    if (stopReason === 'length') {
      // ★ length 改 recoverable:输出被截断,提示用户输入"继续"可续写,不丢半截回答
      tui.warn('输出被截断(达到 max_tokens),输入"继续"可续写')
      break
    }
    if (stopReason === 'content_filter') { tui.warn('内容被安全过滤'); break }
    if (stopReason === 'error') throw toFatal(stopReason)
    // stopReason === 'tool_use' → 执行工具后继续循环

    // ★ 空 tool_use 防护:LLM 畸形返回 stop_reason='tool_use' 但无工具块时,
    //   不执行空工具、不 push 空 user 消息,避免空转到上限
    if (newToolUses.length === 0) {
      tui.warn('LLM 要求工具调用但未给出工具,跳过本轮')
      continue
    }

    // —— 工具执行:只读并行 / 副作用串行 ——
    const results = await executeTools(newToolUses)
    messages.push({ role: 'user', content: results })   // 协议要求:所有 result 凑齐成一条 user 消息
    history.append(messages.tail())                      // ★ 增量落盘
  }
}
```

### 3.2 工具执行(并行/串行 + 校验 + 确认 + 错误兜底)

```ts
async function executeTools(uses: ToolUseBlock[]): Promise<ToolResultBlock[]> {
  const results: ToolResultBlock[] = []

  // 1) 只读工具:Promise.all 并行
  const readonlys = uses.filter(u => registry.get(u.name)?.readonly)
  results.push(...await Promise.all(readonlys.map(runOne)))

  // 2) 副作用工具:串行(每个前需用户确认)
  for (const u of uses.filter(x => !registry.get(x.name)?.readonly)) {
    results.push(await runOne(u))
  }
  return results

  async function runOne(use: ToolUseBlock): Promise<ToolResultBlock> {
    const tool = registry.get(use.name)
    if (!tool) {
      logger.emit({ category: 'tool', event: 'invoke', level: 'debug', payload: { name: use.name, found: false } })
      return toolResult(use.id, `工具 ${use.name} 不存在`, true)
    }

    const t0 = Date.now()
    logger.emit({ category: 'tool', event: 'invoke', level: 'debug', payload: { name: use.name, input: redact(use.input), readonly: tool.readonly } })

    // AJV 校验
    if (!ajv.validate(tool.input_schema, use.input)) {
      logger.emit({ category: 'tool', event: 'validation_failed', level: 'warn', payload: { name: use.name, errors: ajv.errorsText() } })
      return toolResult(use.id, `参数校验失败: ${ajv.errorsText()}`, true)
    }

    // 副作用工具:人在回路确认
    if (!tool.readonly) {
      const confirmed = await tui.confirm(`执行 ${use.name}?`)
      logger.emit({ category: 'tool', event: 'confirm', level: 'debug', payload: { name: use.name, result: confirmed ? 'yes' : 'no' } })
      if (!confirmed) return toolResult(use.id, '用户已取消', true)
    }

    try {
      const r = await tool.execute(use.input, ctx)
      logger.emit({ category: 'tool', event: 'invoke_result', level: 'debug', duration_ms: Date.now() - t0, payload: { name: use.name, is_error: r.is_error, outputLen: r.content.length } })
      return toolResult(use.id, r.content, r.is_error)
    } catch (e) {
      const err = toAppError(e)
      logger.emit({ category: 'tool', event: 'invoke_result', level: 'error', duration_ms: Date.now() - t0, payload: { name: use.name, is_error: true, code: err.code, recoverable: err.recoverable } })
      if (!err.recoverable) throw err        // fatal → 抛顶层中断 Loop
      return toolResult(use.id, err.message, true)   // recoverable → 转 is_error 交 LLM 自处理
    }
  }
}
```

### 3.3 关键难点(写代码时盯这四处)
1. **流式 JSON 拼接** —— `tool_use_delta` 的 `partial_json` 必须按 `id` 累积到 buffer,收齐 `tool_use_end` 才能 `JSON.parse`。期间用户不可见。**parse 失败不崩**:转成带 `__parse_error` 的 input,后续 executeTools 会因 AJV 校验失败产出 is_error 的 ToolResult 交 LLM 自纠。
2. **错误转 is_error 不中断 Loop** —— 工具异常一律捕获,recoverable 的转成 `tool_result(is_error:true)` 让 LLM 自纠;只有 fatal 才抛出中断。
3. **流内 error delta** —— Provider 通过 `{type:'error'}` 表达流中途失败(网络断、畸形事件),发出后不再有 `done`。Loop 记录 streamError,recoverable 的 continue,fatal 的抛顶层。
4. **固化逻辑放 finally** —— 无论正常结束、error delta、还是 abort,都要把本轮已生成的 textBuf/newToolUses 固化进 messages 并增量落盘。这是兑现"中断后内容不丢"的唯一办法。

### 3.4 中断(AbortSignal)
- Loop 接受外部 `AbortSignal`,透传给 Provider 的流式请求与工具执行。
- TUI 触发 `abortController.abort()` → 流抛 AbortError → Loop 的 try/catch 捕获,设 stopReason='aborted',**走 finally 固化已生成内容到 messages 并增量落盘**,然后 break。
- 注意:固化逻辑必须在 finally 里,否则 AbortError 的栈展开会跳过 `messages.push`,已生成内容丢失(早期版本把固化写在 try 外,承诺无法兑现)。

## 4. 内置分层服务

### 4.1 Config(用户级 + dev 覆盖)

**配置位置(解析决策 1):** 全局 CLI 主配置在用户级 `~/.ecode/config.json`(`os.homedir()` 解析,跨平台);`.env` 降为 **dev 专用**(`npm run dev` 时覆盖 config)。

**格式(解析决策 2):** **JSONC**(`jsonc-parser` 解析,支持注释 + 尾逗号)。完整样例见解析文档。

**优先级(高→低):**
- **`npm run dev`**(tsx 跑源码):CLI 参数 > 进程环境变量 > **`.env`** > `~/.ecode/config.json` > 默认
- **全局 `ecode`**(dist):CLI 参数 > 进程环境变量 > `~/.ecode/config.json` > 默认(**不读 `.env`**)

**config 结构:**
```jsonc
{
  "default": { "provider": "astron", "model": "glm-5.2" },   // 启动默认选中(model 用 API 字段)
  "providers": {                                              // 供应商 map:key=自定义 name
    "astron":   { "type": "anthropic", "baseURL": "...", "apiKey": "sk-...",
                  "models": ["glm-5.2","glm-4.7-flash"],     // GLM 经 Astron;API model 字段以官方为准
                  "temperature": 1.0, "topP": 0.95,           // 采样参数(per provider,temp/topP 二选一调)
                  "thinking": "max", "maxTokens": 8192 },     // GLM-5.x 推理强度:max|high|enabled
    "deepseek": { "type": "openai", "baseURL": "...", "apiKey": "sk-...",
                  "models": ["deepseek-v4-pro","deepseek-v4-flash"],  // OpenAI 兼容;型号按官方最新
                  "temperature": 1.0, "topP": 0.95, "maxTokens": 8192 }
  },
  "maxIterations": 50,            // 循环最大次数(可配)
  "bashMaxOutputBytes": 30720,    // bash 工具输出截断(默认 30KB,可配)
  "logLevel": "info"
}
```
> 型号会迭代(ECode 当前基准:**GLM-5.2 / DeepSeek-V4-Pro**,2026-08);`models` 填 API model 字段(如 `glm-5.2`/`deepseek-v4-pro`),按各厂商官方最新为准。主流模型双协议支持,**同一模型可配多个 provider 实例用不同 `type` 接入**(见解析文档「模型适配要点」)。

**密钥:** 进程环境变量(如 `ANTHROPIC_API_KEY`)优先 > `.env`(dev) > `config.providers[].apiKey`(明文落盘 → 文件权限 600 + 日志脱敏)。**禁止硬编码**。

**日志项(见 4.4):** `logLevel`(默认 `info`)/ `logDir`(默认 `~/.ecode/logs`)。

**首次运行向导:** `~/.ecode/config.json` 不存在时,TUI 弹最小向导(问 type/baseURL/apiKey/model),生成文件(权限 600),避免空配置报错。M1/M2 落地。

### 4.2 HistoryStore(对话持久化,增量落盘)
- **落盘时机:每轮 assistant 消息固化后增量 append**(JSONL 更稳),不等 Loop 结束——否则被中断的 Loop 会丢整段对话。主循环的 finally 块里调 `history.append(messages.tail())`。
- 落盘格式:每个会话一个文件,按会话 ID 组织,路径用 `os.homedir()` 解析(见 4.6 跨平台约定)。
- 启动时 `/history` 列出会话,选中即"继续"——把历史 `messages` 重新载入并喂给 Provider,进入 Loop。
- **密钥脱敏**:bash 输出、tool_result 内容若含密钥模式(如 `sk-`、`AKIA`、`*_API_KEY=`),落盘前由 Logger 的脱敏规则统一处理,HistoryStore 复用同一规则。

### 4.3 CommandRegistry(斜杠命令)
- 内置:`/help`(列出命令)/ `/clear`(清空当前会话)/ `/model`(**跨 provider 切换**)/ `/history`(列出/恢复会话)。
  - **`/model`(解析决策 5):** 平铺所有 `providers[].models` 的笛卡尔积,每项 `name / model`(如 `deepseek / DeepSeek-V4-Pro`),当前项高亮;选中改 `current={name,model}`,下次 `provider.run()` 用新配置。一键跨厂商切(glm↔deepseek↔openai)。
- **身份澄清**:CommandRegistry 在结构上与 Tool/Provider Registry 同构(都有 `interface.ts + registry.ts + builtin/`),名字也带 Registry。但 MVP 阶段它是**封闭**的——不开放用户/插件注册自定义命令,4 个内置命令写死。所以它**画在"分层服务"框里是对的**(YAGNI:不为不存在的扩展性建抽象)。未来若开放自定义命令,再把它升为第三个可插拔扩展面,届时需开 ADR 说明。这个"结构像 Registry 但 MVP 不开放"的取舍,记入附录 A。

### 4.4 Logger 与 LogStore(全量日志,调试用)

Logger 服务负责记录系统运行轨迹(trace),供事后调试。**与 HistoryStore 职责分离**:HistoryStore 存对话 messages(喂给 LLM、用户 `/history` 恢复),LogStore 存运行轨迹(给开发者调试,**不进 context**)。

#### 4.4.1 设计目标
- **可复现**:凭一份日志能重建一次会话的完整运行过程(loop 迭代、provider 请求/响应、工具入参出参、错误、中断)。
- **不污染 context**:日志永远不进 messages,不影响 LLM。
- **统一规范**:全系统一个 emit 入口、一套字段 schema、一套级别,禁止散落的 `console.log`。
- **性能不拖累 loop**:异步批量写,不阻塞主循环。

#### 4.4.2 日志格式(JSONL 结构化)
每行一个事件 JSON,字段 schema 固定:

```ts
interface LogEvent {
  ts: string                  // ISO8601 含毫秒,如 '2026-08-11T20:37:09.123Z'
  level: 'trace' | 'debug' | 'info' | 'warn' | 'error'
  category: 'system' | 'loop' | 'provider' | 'tool' | 'tui' | 'error'
  event: string               // 事件名,见 4.4.3 的事件清单
  sessionId: string           // 会话 ID(与 HistoryStore 对齐,便于交叉查)
  iterNum?: number            // loop 迭代号(系统/loop/provider/tool 类必填)
  duration_ms?: number        // 耗时(provider/tool 类必填)
  payload?: Record<string, unknown>   // 事件特定字段,已脱敏
}
```

> 全系统只有 `LogStore.emit(event: LogEvent)` 一个写入入口。Logger 是它的薄封装(绑 sessionId),注入 ToolContext 供工具调用。

#### 4.4.3 事件清单(关键事件,默认全记)

| category | event | level | payload 关键字段 |
|---|---|---|---|
| system | `startup` | info | provider/model/config 快照(脱敏)、cwd、node 版本、平台 |
| system | `shutdown` | info | 退出原因(normal/abort/fatal)、总轮数、总 token |
| loop | `iter_start` | debug | iterNum、messages 长度、tools 数量 |
| loop | `iter_end` | debug | iterNum、stopReason、本轮 token |
| loop | `limit_warning` | warn | iterNum、剩余轮数 |
| provider | `request` | debug | model、system 长度、messages 数、tools 数 |
| provider | `response_done` | debug | stopReason、usage(input/output/cache tokens)、duration_ms、重试次数 |
| provider | `retry` | warn | attempt、code(如 429)、backoff_ms |
| provider | `stream_error` | error | code、message、recoverable |
| tool | `invoke` | debug | name、input(脱敏)、readonly |
| tool | `invoke_result` | debug | name、is_error、duration_ms、output 摘要(截断) |
| tool | `validation_failed` | warn | name、ajv 错误 |
| tool | `confirm` | debug | name、result(yes/no/cancel) |
| error | `app_error` | error | code、message、recoverable、context、stack(fatal 时) |
| tui | `abort` | info | 来源(user_ctrl_c / confirm_cancel) |
| tui | `user_input` | debug | 输入类型(text / slash_command)、不含正文(隐私) |

> **delta 默认不记**。需要复现流式解析 bug 时,把 level 设 `trace`,LogStore 额外记 `provider.delta` 事件(每条 delta 一行,含 type 和 ts)。trace 级体积巨大,只临时开。

#### 4.4.4 落盘与轮转
- **位置**:`~/.ecode/logs/<sessionId>.jsonl`(与会话一一对应,便于整段排查)。
  - 路径用 `os.homedir()` 解析(见 4.6 跨平台约定)。
- **写入策略**:异步批量 flush(每 100 条或 500ms,先满足其一),进程退出前强制 flush。
- **轮转**:
  - 单会话文件超 50MB 时滚动(`<sessionId>.1.jsonl`),保留最近 3 个滚动文件。
  - 全局保留最近 20 个会话日志,超出按 mtime 删除。
- **崩溃兜底**:fatal 抛出前,LogStore 同步 flush(避免崩溃丢最后几条关键日志)。

#### 4.4.5 脱敏(全系统唯一规则)
所有 payload 入 LogStore 前走同一脱敏函数(HistoryStore 也复用,见 4.2):
- **密钥模式**:正则匹配 `sk-[A-Za-z0-9]{20,}`、`AKIA[A-Z0-9]{16}`、`*_API_KEY\s*=\s*\S+`、`*_TOKEN\s*=\s*\S+`、`*_SECRET\s*=\s*\S+`,命中替换为 `***REDACTED***`。
- **整字段脱敏**:`apiKey`/`api_key`/`authorization`/`password` 字段值整替。
- **bash 输出**:tool invoke_result 的 output 字段同样走脱敏。
- 脱敏规则集中在 `services/redact.ts`,Logger 和 HistoryStore 都引用,避免规则分叉。

#### 4.4.6 级别与配置
级别从 Config 读(见 4.1),env 可覆盖:
- `ECODE_LOG_LEVEL`(默认 `info`):`trace|debug|info|warn|error`。低于设定级别的事件不落盘。
- `ECODE_LOG_DIR`:覆盖默认 logs 目录(调试时定向到项目内便于查看)。
- 生产建议 `info`(只记里程碑 + 错误);开发调试设 `debug`;复现流式 bug 设 `trace`。

### 4.5 Permissions
- 危险工具(`write_file`/`edit_file`/`bash`)默认 `y/n` 确认;`read_file`/`glob`/`grep` 免确认。
- 通过 Tool 的 `readonly` 元数据驱动。

### 4.6 跨平台约定(M1 必须落地)
开发与首要运行环境是 **Windows**(Git Bash),代码必须跨平台。MVP 锁定以下约定:
- **路径**:
  - 统一用 `node:path`(`path.join`/`path.resolve`),内部表示一律正斜杠。
  - 用户目录用 `os.homedir()` 解析(**不要**依赖 shell 的 `~` 展开),Config 目录 = `path.join(os.homedir(), '.ecode')`。
  - 跨平台打印路径时用 `path.sep` 或规范化为正斜杠。
- **shell / bash 工具**:
  - bash 工具**显式依赖 Git Bash**(与开发环境对齐);`SHELL` 环境变量缺省时回退到 `bash.exe`(常见安装路径:`C:\Program Files\Git\bin\bash.exe`)。
  - 命令字符串按 POSIX shell 语义编写;非 Windows 平台直接用系统 shell。
- **glob/grep**:
  - `fast-glob` 在 Windows 默认大小写不敏感,需显式设 `caseSensitiveMatch` 按需而定。
  - glob 模式用正斜杠(跨平台通用),不用反斜杠。
- **换行**:文件读写通过工具选项控制,默认保留原文件换行;新增文件用 `\n`。

## 5. TUI 分支(Ink)

**技术栈(技术栈细化决策,见解析决策 2):** 标准 **Ink 7 + `@inkjs/ui`**(基础件:TextInput/Select/MultiSelect/Spinner/ConfirmInput/Badge/StatusMessage 等)+ **自建三件**:
1. **流式分阶段渲染**——灰字占位 → commit 时一次性 markdown 渲染(见 5.1)。
2. **终端 Markdown 渲染**——`marked` 解析 + `cli-highlight` 着色 + 自建终端宽度/换行处理(`tui/markdown.tsx`)。
3. **折叠 ToolCallView**——`useState` 条件渲染 + Ink `useFocus` 焦点切换,参考 wrxck/ink-tree 思路(不引依赖)。

**不走 Claude Code 式自建 React reconciler 路线**(它用纯 TS Yoga 移植 ~2700 行 + 自定义输入系统 + 完整 ANSI 解析器,数工程师·数月投入;MVP 不需要)。`@inkjs/ui` 虽提交不多但基础件稳定够用;[wrxck/ink](https://github.com/wrxck/ink) 停滞(9 提交/1 star)仅作思路参考,不引依赖。
**工作量估算:** M2(接 TUI + 流式 + Ctrl+C)~3-5 天,M3(折叠 + diff 确认 + 工具展示 + 焦点)~5-7 天。
**M2 烟测前置:** 核实 `ink-text-input`/`ink-spinner`/`@inkjs/ui` 已跟上 Ink 7;`<Static>` 在真实会话长度(几百条消息)下重绘 < 100ms;若不满足则评估切流式或增量渲染(解析决策 2 反驳点)。

**UI 方向(见 [`规范/2026-08-11_MVP-TUI设计规范`](../规范/2026-08-11_MVP-TUI设计规范_待审核.md)):** **全屏框架式(Claude Code 风)** + **品牌启动屏** + **适度色彩(暗色主题,关键状态色:错误红/成功绿/警告黄/工具青)**。本节为概览,完整界面原型 / 视觉规范 / 键盘交互 / 交互流程 / 组件规格见规范文档(M2/M3 据此实现)。

### 5.1 渲染策略(底层流式 + 分阶段渲染)
- **底层保留流式**:token 持续到达 → 可 Ctrl+C 中断 + 提供进度感。
- **TUI 分两阶段渲染**(解决"流式 markdown 表格/代码块乱跳"):
  - **流式期**:`streamText` 把增量写进灰色"占位"缓冲区,**不做 markdown 渲染**(原始文本,格式待定)。
  - **提交期**:`commitAssistantMessage` 把整段文本一次性 markdown 渲染(正确格式,代码高亮、表格、列表全对)。
- 工具调用过程显示:工具名 + 转圈 spinner + 完成后结果摘要。

### 5.2 组件结构
```
App
├── MessageList         # 渲染历史 + 当前消息(分阶段)
│   ├── UserMessage
│   └── AssistantMessage  # 流式期灰字占位 / 提交期 markdown
├── ToolCallView        # 工具执行进度与结果
├── ConfirmPrompt       # 危险工具 y/n 确认
├── InputStream         # 用户输入框(解析斜杠命令)
├── StatusBar           # 当前 provider/model · 剩余轮数 · 警告
└── ErrorBanner         # fatal 错误统一展示
```

### 5.3 中断控制(只用 Ctrl+C,不用 ESC)
- **Ctrl+C 第 1 次** → 中断当前请求(`abortController.abort()`),TUI 显示"已中断",已生成内容并入历史。
- **Ctrl+C 第 2 次**(1.5 秒窗口内)→ 退出程序。第 1 次后 StatusBar 显示"再按一次 Ctrl+C 退出",给视觉反馈。
- **ConfirmPrompt 期间的 Ctrl+C** → 取消该工具(返回 is_error 的"用户取消"),**不**退出程序、**不**中断 Loop。
- **"继续"** → `/history` 选会话 → 重载 messages → 重新进入 Loop。

### 5.4 关键 UI 样式
- **危险工具确认(带 diff 预览)**:write_file/edit_file 必须显示变更内容,不让用户盲签。
  ```
  ⚠ 执行 edit_file?  path: src/foo.ts
    --- 原文
    +++ 修改
    @@ -10,3 +10,3 @@
    -const x = oldFunc()
    +const x = newFunc()
    +// 新增注释
    [y] 确认   [n] 取消   [v] 查看完整文件
  ```
  - edit_file:显示 unified diff(`---`/`+++`/`@@`),cli-highlight 着色。
  - write_file:显示新增内容片段,超 N 行(默认 40)截断,尾部附 `[v] 查看完整`。
  - bash:显示完整命令字符串(不预览,但必须可见)。
- **接近轮数上限预警**(StatusBar):`轮数 46/50,即将达上限`。
- **达上限交互**:达到 MAX_ITERATIONS 时弹 `[c] 继续 10 轮  [q] 停止`,不硬终止。
- **token 用量**(StatusBar):本轮 input/output tokens + 累计成本(由 usage delta 驱动)。

## 6. 错误处理

### 6.1 统一错误格式
```ts
interface AppError {
  code: string                      // 机器可读,如 'NO_API_KEY' / 'TOOL_NOT_FOUND' / 'RATE_LIMIT'
  message: string                   // 人类可读
  context?: Record<string, unknown>
  recoverable: boolean              // true→转 tool_result 给 LLM / false→抛顶层中断 Loop
  retryable?: boolean               // true→Provider 层指数退避重试(见 6.3)
}
```

### 6.2 分类
| 类别 | recoverable | retryable | 处理 |
|------|-------------|-----------|------|
| 工具执行异常(debug/任务类,如文件不存在、命令非零退出) | ✅ true | — | 转 `tool_result(is_error:true)`,LLM 自处理 |
| 工具入参校验失败 | ✅ true | — | 同上 |
| 工具不存在 / 用户取消 | ✅ true | — | 同上 |
| 无 API Key(401) | ❌ false | ❌ | fatal,中断 + 提示配置 |
| 模型过期 / 不存在(404) | ❌ false | ❌ | fatal,中断 + 提示换模型 |
| **Token 过期(401)** | ❌ false | ❌ | fatal,中断 + 提示 |
| **限额 / 限流(429)** | ✅ true | ✅ | recoverable + 指数退避重试(见 6.3),仍失败再 fatal |
| **无网络 / 请求超时** | ✅ true | ✅ | recoverable + 指数退避重试(见 6.3) |
| **上下文超限** | ✅ true | ❌ | recoverable,TUI 提示"上下文超限,建议 `/clear` 或删除历史条目",**不挂 Loop** |
| 内容安全过滤(content_filter) | ✅ true | ❌ | recoverable,提示后等用户输入 |
| 流式 JSON 解析失败 | ✅ true | — | 转 is_error 的 ToolResult 交 LLM 自纠 |
| 轮数超 MAX_ITERATIONS | ❌ false | — | 触发"是否继续"交互(见 3.1),用户拒绝才终止 |

**原则:只要不是让系统崩的问题,都交给 LLM 自己处理(recoverable);系统级问题才中断。**
**修订(对标 Aider/Claude Code):网络抖动、限流、上下文超限不该让用户丢整轮对话——前两类退避重试,上下文超限把控制权交用户。**

### 6.3 重试策略(Provider 层)
- 触发条件:`AppError.retryable === true`(网络/超时/429)。
- 策略:指数退避,3 次,间隔 2s / 4s / 8s,抖动 ±20%。
- 429 优先读响应头 `Retry-After`,没有再走退避。
- 3 次仍失败 → 升级为 fatal 抛顶层,TUI 提示"网络不可用,已保留当前对话,/history 可恢复"。

### 6.4 副作用工具的自纠风险
- 原则"recoverable 转 is_error 交 LLM 自纠"对**只读工具安全**,但对**副作用工具(bash/write_file/edit_file)有放大伤害的风险**:LLM 可能把权限失败升级成 `sudo` 重试。
- MVP 约束:**副作用工具的 recoverable 错误,连续同类失败 2 次后强制人工确认**(TUI 高亮警告),不让 LLM 第三次自动重试。

### 日志系统决策(ADR-014)

| 决策 | 选择 | 理由 |
|------|------|------|
| 日志与历史分离 | LogStore(trace,调试)与 HistoryStore(messages,给 LLM)分两套 | 职责分离,日志不污染 context、不增 token 成本 |
| 全量程度 | 默认记关键事件(loop/provider/tool/error),delta 默认不记、trace 级可开 | 关键事件覆盖 80% 调试需求;逐 delta 体积巨大,按需开 |
| 格式 | JSONL 结构化,统一字段 schema | 便于 jq/grep 程序化分析;每行一事件 |
| 写入入口 | 全系统唯一 `LogStore.emit()`,禁止散落 console.log | 统一规范,保证字段/级别/脱敏一致 |
| 落盘策略 | 异步批量 flush(100 条或 500ms),fatal 前同步 flush | 不拖累 loop;崩溃不丢最后的关键日志 |
| 脱敏集中 | `redact.ts` 单一规则,Logger 和 HistoryStore 共用 | 避免规则分叉导致某处漏脱敏 |

### 技术栈细化决策(ADR-015 起)

| 决策 | 选择 | 理由 |
|------|------|------|
| 模块格式(ADR-015) | ESM | 现代标准、顶层 await、依赖栈 ESM-ready;4 坑已记入 0.2 |
| TUI 框架(ADR-016) | 标准 Ink 7 + `@inkjs/ui` + 自建三件,不走自建 reconciler | TS 唯一成熟组件化 TUI;Claude Code 路线投入过大,MVP 不需要 |
| grep 实现(ADR-017) | 纯 JS(fast-glob + RegExp) | 零外部依赖、跨平台一致(呼应 1.1);性能不足时后续切内置 rg |
| ls 工具(ADR-018) | 新增独立只读 ls,工具集 6→7 | bash 是副作用工具,ls 走它要确认;只读操作应免确认通道(对标 Claude Code LS) |
| glob 大小写(ADR-019) | 显式 `caseSensitiveMatch: true` | 跨平台行为一致(平台默认会 Win 不敏感/Linux 敏感) |
| bash 跨 OS(ADR-020) | coreutils 差异由 LLM 负责,MVP 只保证 Git Bash | 工具层不能保证命令语义跨 OS;注入 platform 供 LLM 适配 |
| JSON Schema | 扁平 type+properties+required | GLM 对复杂 schema 支持度未知,扁平最稳(支持度列为 M1 烟测) |

### 配置系统与多 Provider 决策(ADR-021 起)

| 决策 | 选择 | 理由 |
|------|------|------|
| 配置位置(ADR-021) | 用户级 `~/.ecode/config.json` + `.env` dev 专用 | 全局 CLI 任意目录启动能读到;`.env` 降为开发覆盖 |
| 配置格式(ADR-022) | JSONC(`jsonc-parser`) | 支持注释 + 编辑器友好;否决 JSON5/YAML/TOML |
| Provider 两层(ADR-023) | 实现(按 type)+ 配置实例(按 name) | 同一实现服务多实例(deepseek/openai 共用 OpenaiProvider) |
| MVP 两协议(ADR-024) | 实现 anthropic + openai 两协议 | 主流模型(GLM-5.2/DeepSeek-V4-Pro)**原生双协议支持**;两实现都做,让同一模型可选最合适协议/端点接入(两层 Provider 架构接住灵活性),`/model` 跨 provider 切换也生效 |
| `/model` 切换(ADR-025) | 跨 provider 平铺 provider×model | 一键切厂商;否决两步/只切 model 名 |

> 完整论证(含被否决备选:纯项目级 `.env`、项目级 `.ecode.json`、JSON5/YAML/TOML、单实例 Provider、只 anthropic 协议、两步切换等)见 [`解析/2026-08-11_MVP-配置系统与多Provider解析_待审核.md`](../解析/2026-08-11_MVP-配置系统与多Provider解析_待审核.md)。
