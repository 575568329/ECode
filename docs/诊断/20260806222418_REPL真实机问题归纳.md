## 二、根因归类：两条独立线

### 2.1 less pager 架构问题群（C / D / E / F / G）

**C / D / E / F / G 五个问题共享同一个根源 = `less pager` 这套方案**：
外部进程（`spawn less`）+ `alternate screen`（`\x1b[?1049h/l`）+ 纯文本输入。

less 的每一条固有特性都恰好踩中一个抱怨：

| 抱怨 | less 的固有限制 | 代码位置 |
|------|----------------|----------|
| C 双 `❯` | `alternate screen` 与 ink 全屏重绘冲突（切回主屏后 ink 重绘叠加） | `app.tsx:80-103`、`app.tsx:252` |
| D 内容多 | 默认 `sessionMessagesToTranscript(api.completedMessages)` 转录全会话 | `app.tsx:82` |
| E 无滚动条 | less 键盘翻页，鼠标滚轮取决于终端模拟器是否转发 | `pager.ts:18` |
| F 无 markdown | less 纯文本，不渲染 markdown（源码原样输出） | `format-transcript.ts:55-57` |
| G 退出键 | less 的 `q` + App 在 pager 期间 `useInput` 让位（esc 失效） | `pager.ts:9`、`app.tsx:108-126` |

### 2.2 独立 bug（A / B）

与 pager 无关，是 agent loop / 子进程编码层面的问题。

## 三、核心洞察：`less pager` → `ink 内联展开 toggle`

既然 C/D/E/F/G **同根**，最有效的修法不是逐个补丁，而是**换掉 less pager**：

| 维度 | 现状（less pager） | 改 ink 内联展开 toggle |
|------|--------------------|-----------------------|
| 退出 | less 的 `q`，esc 让位（G 不直觉） | 再按 Ctrl+O 收起（直觉 toggle） |
| 滚动 | 键盘翻页，无鼠标滚动（E） | 终端原生滚动（鼠标可用） |
| markdown | 纯文本源码（F） | 复用 `MarkdownRenderer`（已渲染态） |
| 内容范围 | 全会话转录（D 过载） | 只展开折叠组 + 被裁剪工具 |
| 屏幕管理 | `alternate screen` ↔ ink 全屏重绘冲突（C 双❯） | 全程 ink 单一渲染管线，无冲突 |
| 依赖 | 需系统装 `less`（spawn 失败要兜底） | 纯 ink，零外部依赖 |

**结论**：Ctrl+O 改为「ink 内联展开 toggle」可**一揽子解决 C/D/E/F/G 五个问题**，且消除 `less` 外部依赖。

技术要点（toggle 与 `<Static>` append-only 的协调）：
- 已冻结的折叠组要"展开"需重 mount → 切换展开态时 `staticKey++`（与现有 switchSession/clear 同机制，一次性重渲染，可接受）。
- 展开态下 `renderCompleted` 把 `tool_group` 渲染成各 `ToolDone`（完整 content + markdown），而非折叠摘要行。
- 退出（收起）= 再按 Ctrl+O → `staticKey++` 回到折叠态。

## 四、逐条 root cause + 代码位置

### A. 助手文本重复（PLAUSIBLE，待日志验证）

**推断根因**（基于 `reduce-agent-event.ts`）：
- `text_delta` 累加：`streamingText = (streamingText ?? '') + event.text`（`reduce-agent-event.ts:59`）
- `streamingText` **只在 run `completed` 时落地 + 清空**（`reduce-agent-event.ts:99-119`）
- agent 循环**多轮**（说话 → 工具 → 说话 → 工具 …），所有轮的 `text_delta` 累加成**一个** `streamingText`
- 多轮里模型若输出相似的开场/过渡文本，累加后用户看到一串相似内容 → "重复很多次"

**语义缺陷**：`streamingText` 跨轮累加假设"整 run 文本是连续一段"，但 agent 多轮中文本与工具是**交错**的，拼成一段不符合真实结构。

**⚠️ 诚实标注**：这是基于 reducer 语义的**推断**（PLAUSIBLE），未用运行时日志证实。可能是"模型真的重复输出"也可能是"累加导致拼接重复"，二者修法不同。

**验证方法**（动手前先做）：在 reducer 加临时日志——每次 `text_delta` 记录 `round` + 累加后 `streamingText.length` + 前若干字符，跑一次真机看是哪种。

**修法方向（验证后）**：让 `streamingText` 在**每轮助手文本段结束（模型转 tool）时落地**，而非只在 run `completed`。需要 agent-events 引入"text 段结束"或"round 边界"信号。

### B. 乱码

**根因**：
1. 模型用 Unix `find -name` 语法，但 Windows 的 `find.exe` 是文本搜索器（类 grep），非 Unix find → 命令语义错 + 报系统错误消息
2. Windows 中文系统消息是 **GBK** 编码，Node `child_process` 默认按 UTF-8 解码 → 乱码（`······`）

**性质**：模型命令适配 + 子进程编码问题，**非 UI bug**。

**代码位置**：`src/tools.ts`（bash 执行 + 编码处理）—— 待进一步确认当前是否已做编码转换。

**修法方向**：
- 编码：子进程 stdout 按系统代码页（Windows 中文 = GBK/CP936）解码，而非默认 UTF-8（运行时自探测代码页，呼应 §1.1 配置自探测）。
- 命令：`find` 等 Unix 命令在 Windows 的等价提示（属模型 system prompt 适配范畴，较长期）。

### C. 双 `❯` 提示符（Ctrl+O 退出后）

**根因**：
- `openPager`：`\x1b[?1049h` 进 alternate screen 保存主屏 → less 运行 → `\x1b[?1049l` 切回主屏（`app.tsx:89/99`）
- 切回后 `setInPager(false)` → InputBar 重新渲染（`app.tsx:252`）
- **ink 用全屏重绘（光标控制），不用 alternate screen**；pager 偏偏用 alternate screen
- 切回主屏时：主屏残留旧的 `❯ _`（alternate 保存的快照）+ ink 重绘新 `❯` → **两个**

**本质**：两套屏幕管理机制（ink 光标重绘 vs less alternate buffer）冲突。

**代码位置**：`app.tsx:80-103`（openPager）、`app.tsx:252`（inPager 三元）。

> 换 ink 内联展开 toggle（无 alternate screen）后，此 bug 自动消失。

### D. Ctrl+O 内容太多

**根因**：`openPager` 调 `sessionMessagesToTranscript(api.completedMessages)` 转录**全部**会话（`app.tsx:82`）。设计如此 = 全会话转录 pager。

**用户期望**：只展开"被收起的内容"（`tool_group` 的 tools + 被裁剪 `BlockTool` 的 omitted 行）。

**代码位置**：`app.tsx:82`、`format-transcript.ts:74`。

### E. 没滚动条 / 不好拖动（能键盘翻页）

**用户澄清**：less 能键盘翻页，只是没滚动条、鼠标不好拖动。

**根因**：less 键盘翻页是设计；鼠标滚轮能否用取决于终端模拟器是否把滚轮事件转成 less 的方向键输入，不可控。

**代码位置**：`pager.ts:18`（`spawn less`）。

> 换 ink 内联展开（终端原生滚动）后，鼠标滚轮原生可用。

### F. 无 markdown 格式

**根因**：`format-transcript.ts` 的 `assistant` case 把 markdown **源码原样输出**（`format-transcript.ts:55-57`：`${INDENT}${msg.text}`，注释明确"原文最真实"）。less 是纯文本 pager，无法渲染。

**代码位置**：`format-transcript.ts:55-57`。

> 换 ink 内联展开后，复用 `MarkdownRenderer`（chat-view 已在用）即可渲染。

### G. 退出键不直觉

**根因**：
- `pager.ts:9` LESS_PROMPT 写 "q退出"，less 标准 `q` 退出
- App 在 pager 期间 `useInput` 让位（`app.tsx:109`：`if (inPagerRef.current) return`）→ **esc 失效**
- 用户提到的 "p" 代码无绑定，疑为误按 / less 内部行为
- 核心：进入/退出 pager 是"开关外部进程"，非直觉的 toggle

**代码位置**：`pager.ts:9`、`app.tsx:108-126`。

> 换 ink 内联展开 toggle 后，退出 = 再按 Ctrl+O，最直觉。
