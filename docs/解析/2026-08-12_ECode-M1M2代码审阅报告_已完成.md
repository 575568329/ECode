## 0. 总体结论

**一句话**：心脏与分支面抽象是本项目最扎实的部分，铁律（无 `if provider === 'xxx'`）守得很干净；问题集中在三处——**M2 集成层的一批半成品（副作用工具免确认、signal 断链、回调丢 id、死代码）**、**心脏的健壮性边界未实现（retry/退避/abort 重试死循环/maxIterations 到顶）**、**工具与服务层过薄（2 工具、history/logger 全 stub、redact/permissions 只在规范里存在）**。这些都不是架构错误，而是"设计完成、实现未收口"的典型状态。测试 237 全绿但有系统性盲区（只测 happy path + 单步错误，不测 abort/重试/到顶/并发），是上述 bug 得以潜伏的直接原因。

## 2. 多角色视角评价

### 2.1 架构师视角
**强项**：融合架构（详设 §0.3）落地干净——`Tool`/`LLMProvider` 走"统一接口+注册中心"可插拔分支面，TUI/Config/History/Command 走分层直接接入（YAGNI 不套接口），这个二分判断非常成熟。心脏 230 行做到了"只认 Registry 接口"，铁律贯穿。Provider 两层架构（type 维度无状态实现 + name 维度配置实例）为多 provider 预留得当。

**短板**：
- 心脏还缺三个所有参考项目都有的能力：**retry/退避**、**context 压缩**、**步数到顶总结**（见 #4/#7 和 §5）。这三项不补，心脏只是"能转"而非"健壮"。
- `providerReq.apiKey` 进心脏（#12）是唯一明显的抽象泄漏。
- `CommandRegistry` 的 skill 预留接口（#28）是"假预留"——未来接 skill 必然破坏性改接口，不如现在不承诺。

### 2.2 资深开发视角
**强项**：代码可读性高——每个文件顶部有职责注释并标注详设章节号（如 `loop.ts:1-12`、`errors.ts:1-11`），复杂逻辑有 Why 注释（如 `anthropic.ts:113-115` 解释 usage 累积语义对齐 SDK 0.115+ 与 Vercel AI SDK）。防御式编程到位：`resolveGitBash` 多级回退、`spawnShell` 跨平台分流、流式 JSON parse 失败转 `__parse_error` 交 LLM 自纠。

**短板**：
- 魔法值仍有散落：`STREAM_MAX_LINES=5`、`TICK_MS=80`、bash 候选路径硬编码列表（可接受）。
- `ToolRegistryImpl` 的 ajv default interop 鸭子类型（`registry.ts:12-21`）略 hacky，但有注释说明，可接受。
- 并发只读工具的结果不保序（#5）是并发设计的常见坑，需补 id 回传。
- `cli/index.ts` 单次模式 `new AbortController().signal` 永不触发（#2 同源），单次模式不可中断。

### 2.3 前端 / TUI 视角
**强项**：分层清晰——纯逻辑（`cursor`/`mdparse`/`toolview`/`ansi`/`stream`）与渲染（`.tsx`）分离且都有单测。性能决策正确：`clock.ts` 共享单时钟 + `ActivityBar` 仅 `ActiveSpinner` 局部订阅（不波及 `TuiApp`）；`<Static>` 冻结历史 buffer 利于终端 scrollback；ANSI 中间态路线（`inline→ANSI→wrap→span`）是中文折行的合理选择。`cursor.ts` 的字素级（grapheme）光标模型对中文/emoji 安全，是不可多得的前端工程诚意。

**短板**：集成层"半成品"集中（#1/#5/#13/#14/#15/#17）。`store.ts` 设计了 Context 却走 props、`confirm`/`iter`/`expanded`/`WelcomeScreen` 备而不用——文档（各文件注释"留第 X 步"）印证 M2 第 6 步集成未完全收口。性能上 `items`/`Markdown` 零 memo（#13）是长会话隐患。

### 2.4 产品经理视角
**强项**：MVP 范围控制得当——心脏闭环优先，TUI 次之，工具/服务后置，符合"由内向外"构建顺序。Config 首次自动生成 JSONC 模板带注释引导（`config.ts:59-89`）是好的首次体验。单次模式（argv）保留 stdout 输出对脚本/管道友好。

**短板**：
- **"能用"门槛未达**：没有 edit/write 工具（只能 `bash echo` 改文件）、没有 history 落盘（重启丢全部对话）、没有 retry（网络抖动即崩）。这三项是 Agent CLI 的地板线。
- **成本/进度不可见**：有 `usage` 累加但不折算成本（StatusBar cost 永远空）、轮数不显示（#15）。
- **中断体验不完整**：provider 流不可中断（#2），用户按 Ctrl+C 后仍需等 LLM 跑完。

### 2.5 测试视角
**强项**：测试比 0.7:1（tests 2085 / src 2921），TDD 痕迹明显。翻译层单测（`anthropic.test.ts`）质量很高，特别是 message_start/message_delta usage 兼容性的正反例（:107-143）。纯逻辑层（cursor/ansi/stream/toolview/mdparse）单测齐全。

**短板**：**系统性边界盲区**（#6）——loop 测试只覆盖单步成功/单步错误，不测多步交互的边界。建议必补：①abort 中断（触发 `stopReason='aborted'`）；②recoverable 连续失败（验证有重试上限）；③`maxIterations` 到顶；④同轮多只读工具并发（验证结果按 id 正确配对）。集成测试（MockProvider 驱动 loop）思路对，但脚本只到"恰好成功"为止。

### 2.6 安全视角
**短板突出**：
- 副作用工具免确认（#1）：`bash rm -rf` 会自动跑。
- bash 无危险命令拦截、无输出截断（#10）。
- 无权限三态、无"always 记忆"（opencode `permission.ts` 范式）。
- 无脱敏落地（#9）：规范要求 `redact.ts`，代码无。
- `read_file` 无路径白名单/沙箱（读任意路径）。
MVP 阶段可接受"显式标注风险"，但 #1 必须在 M3 前补最小确认。

## 3. 分模块详评

### 3.1 心脏 `core/`（loop 230 / types 83 / errors 118）
**评价**：★★★★★ 设计，★★★☆☆ 健壮性。铁律守住，try/finally 固化、空 tool_use 防护、流式 JSON 拼接、停止判定多分支都到位。但 retry/退避/abort 死循环/maxIterations 交互四项健壮性边界全缺（#3/#4/#7）。`errors.ts` 分类完善（HTTP 码→recoverable/retryable 映射表正确），但 `retryable` 字段定义了却没人用——"纸面能力 > 实际能力"。

### 3.2 Provider `providers/`（anthropic 189 / interface 38 / registry 24）
**评价**：★★★★★ 抽象，★★★☆☆ 实现完整度。两层架构 + 纯函数翻译器 + 有状态 Translator 分离，单测友好，铁律零泄漏。`message_delta` usage 覆盖语义对兼容端点的处理（`anthropic.ts:111-119`）经过深思。短板：signal 未透传（#2）、`mapStopReason` 缺 content_filter/error（#16）、`max_tokens` 硬编码 8192（TODO M4）、`OpenaiProvider` 未实现（留 M3，建议先评估借 AI SDK 而非手写）。

### 3.3 工具 `tools/`（interface 41 / registry 54 / bash 108 / read_file 36）
**评价**：★★★☆☆。AJV 预编译缓存 + `readonly` 二分 + 只读并行/副作用串行，设计正确且执行到位。短板是"薄"：只有 2 工具，缺 edit/write/glob/grep（§5）；`read_file` 无行号/分页/截断（#20）；bash 无截断/拦截/缓存（#10/#19）。`Tool` 接口缺 `isReadOnly(input)`（可依赖输入）和 `toModelOutput`（控制回喂内容）——opencode/claude-code 都有。

### 3.4 服务 `services/`（config 156 / history 20(stub) / logger 28(stub)）

## 5. 过度设计 / 不必要的东西

ECode 还很薄（核心 < 600 行），大部分"抽象"是规划未实现，不算过度。真正值得警惕：

1. **TUI 投入与核心投入失衡**：自研 markdown/光标/ANSI ~535 行 vs 工具只有 2 个、history 是 stub。建议 TUI 暂停加新自研组件（markdown 已能跑就够用），精力转向补工具/history。
2. **死代码堆积**（#17）：`store.ts` 整文件零引用、`WelcomeScreen`/`AssistantMessage.streaming`/`groupByName`/StatusBar 死参数。违反 YAGNI，且让接口失真。建议要么接入要么删除。
3. **`CommandRegistry` skill 假预留**（#28）：当前同步接口接不下 skill，注释承诺是假的。建议删承诺或现在改 async。
4. **`StopReason`/`AppError.retryable` 纸面 > 实现**（#4/#16）：规范定义了实际用不到的分支。建议在规范标注"占位未接线"，避免维护者误以为 retry 已做。
5. **`providerReq` 进心脏**（#12）：不是过度设计而是泄漏，但同属"心脏知道得太多"。

**澄清不过度设计的部分**（不要砍）：AJV 校验、Translator 翻译类、readonly 二分并行、try/finally 固化、Provider 两层抽象——这些是合理的核心抽象。
