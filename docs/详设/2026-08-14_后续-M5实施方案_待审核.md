# ECode 后续 M5 实施方案：上下文压缩

> 日期：2026-08-14 · 状态：**草案待审阅 v2**
> **v2 修订**：原 v1 把压缩 + Skill + MCP 三特性打包，经架构师/资深开发/产品经理三角色审阅（见 [解析/2026-08-14_M5方案审阅意见](../解析/2026-08-14_M5方案审阅意见_待处理.md)），采纳建议**拆为独立里程碑**：
> - **M5 = 上下文压缩**（本文档；防止长对话超限崩溃）
> - M6 = Skill（后置；markdown 命令扩展，需求未紧迫）
> - M7 = MCP（大幅后置；成本最高 + Windows spawn 坑 + 用户基础未到）
>
> **M5 范围收窄**：手动 `/compact` 为核心（0 心脏主流程改动 + 0 新依赖），自动阈值触发作为**可选增量**（观察用户真频繁撞限再加）。
> 标 ★ 的决策点已拍板；审阅可推翻。

---

## 1. 为什么是「手动优先」（PM 审阅核心结论）

- ECode 是**终端 Agent CLI**，单次任务通常几轮工具调用就完成（MAX_ITERATIONS=50 是上限非常态）
- GLM contextWindow=128k，单次会话天然撞限的场景不多
- 唯一真触发场景：M4 的 `/history` 恢复长会话后继续——压缩需求**由历史恢复功能驱动**
- 现有超限处理（详设 §6.2）：`recoverable + 提示 /clear`——**不做压缩也不会崩**
- **手动 `/compact` 覆盖 80% 需求**，用户在长会话里自己判断；自动阈值触发 ROI 低（每轮全量计数 + 装依赖 + 估算误差）

**结论**：M5 先做手动压缩 + 修 400 误重试 bug（让现有「提示 /clear」链路正确工作）。自动触发作为文档附录的可选增量，实施与否看用户反馈。

---

## 2. 目标 & 验收

**目标**：用户可用 `/compact` 手动压缩对话历史；上下文超限时正确提示而非无意义重试。

**验收标准**：
- `/compact` 执行后：messages 替换为 `[summary, ...tail]`，UI 重建 committed 反映压缩后状态，HistoryStore 记 boundary
- 压缩后 LLM 仍能正确引用压缩前的关键上下文（文件路径、已做决定）——摘要质量验收（非仅「不崩」）
- 400 context-too-long 不再被退避重试（正确分类 + 走压缩或提示）

**不做**（后置）：
- 自动阈值触发（附录 D 记方案，待用户反馈）
- 多级管线（microcompact 折叠工具结果 / snipCompact 删整段 / reactive）
- Skill（M6）、MCP（M7）

## 3. 前置：修 errors.ts 的 400 context-too-long 误重试（P0）

**现状 bug**（审阅核实）：`src/core/errors.ts` 的 `fromHttpStatus` 对 400 无专门分支 → 落兜底 `HTTP_ERROR / recoverable:true` → `loop.ts:204` 对所有 recoverable 退避重试 → **context 超限（确定性 400）被无意义重试 3 次**。

**关键发现**（开发审阅）：`retryable` 字段当前是**只写不读的死字段**（errors.ts:108/111/114 设了，loop.ts 从不读）。文档原方案「loop 区分 retryable」=首次让它生效，但语义未定义。

**修订方案**（开发建议）：**不走 retryable 信号**，改用**错误码专属分支**，语义清晰：
```ts
// errors.ts：识别 context-too-long（各端点文案不同），打专属 code
if (status === 400) {
  const body = e.error?.error?.message ?? e.error?.message ?? e.message  // 防御性取 body（P1-7）
  if (/context|too long|prompt/i.test(body)) {
    return { code: 'CONTEXT_TOO_LONG', recoverable: true, retryable: false, message, context: { status, body } }
  }
}
```
loop.ts recoverable 分支加错误码判断（见 §4）。

## 4. 压缩算法（aider 递归 split-summarize）

新 `src/services/compact.ts`：
```ts
export interface CompactResult {
  messages: Message[]
  removedCount: number
  summaryTokens: number
}

/**
 * aider 递归 split-summarize（M5-D1）：
 *   1. 按 halfMax 切 head（旧）+ tail（新）
 *   2. summarize(head) → 独立 LLM 调用（强制无工具，maxTokens=1024 省额度 P2-6）
 *   3. 返回 [summary_msg, ...tail]
 *   4. 仍超 → 递归；深度 > 3 退化 summarize_all
 *
 * 摘要失败不重试（P1-2），降级硬截断（保留最近 N 条 + 「历史已截断」提示）——保证总产出可用 messages。
 */
export async function compactMessages(
  messages: Message[],
  opts: { provider: LLMProvider; providerReq: ProviderReq },
): Promise<CompactResult>
```

摘要 prompt（参考 claude-code prompt.ts + aider summarize）：
```
请总结以下对话历史的关键信息（用户意图、已做决定、工具调用结果要点、未完成事项）。
保留技术细节和文件路径，省略寒暄和重复。
<analysis>标签里分析，<summary>里给最终摘要。
[对话历史]
{{head_messages}}
```
产出后 strip `<analysis>`，包成 `{role:'user', content:[{type:'text', text:'[对话摘要]\n'+summary}]}`。

## 5. /compact 命令 + loop 集成（P0 契约修订）

### 5.1 CommandRegistry 注册 /compact

`action` 联合类型扩 `'compact'`，注册 `/compact` 命令（run → `{ action: 'compact' }`）。

### 5.2 TuiApp onCommand 分发

`onCommand` 加 `'compact'` 分支 → 调 `compactMessages(messagesRef.current, ...)` → **原地替换**（P0 修订，非重赋值）：
```ts
const result = await compactMessages(messagesRef.current, {...})
// P0 修订：原地 mutate 保持 messagesRef 引用（TuiApp/cli 都靠 mutation，不捕获 runLoop 返回值）
messagesRef.current.length = 0
messagesRef.current.push(...result.messages)
// P1-1 修订：重建 committed 反映压缩后状态
setCommitted(messagesToCommitted(messagesRef.current))
setSystemMsgs([`已压缩（移除 ${result.removedCount} 条）`])
```

### 5.3 400 context-too-long → 自动压缩（loop 内，可选但建议做）

loop.ts recoverable 分支加错误码专属处理（**非依赖 retryable 死字段**）：
```ts
if (streamError) {
  // P0 修订：CONTEXT_TOO_LONG 走专属分支（不走 retryable 信号）
  if (streamError.code === 'CONTEXT_TOO_LONG') {
    if (pushedThisRound) messages.pop()  // 回滚半截 assistant（P1-9 已修）
    // 压缩次数上限（P1-8）：避免压缩 summary 的 summary 退化循环
    if (++compactCount > MAX_COMPACTS) {
      opts.callbacks.onWarn?.('上下文已无法进一步压缩，建议 /clear 或 /history 起新会话')
      break
    }
    const r = await compactMessages(messages, { provider: opts.provider, providerReq: opts.providerReq })
    // 原地 mutate（P0-1）
    messages.length = 0; messages.push(...r.messages)
    opts.callbacks.onCompacted?.(messages)  // P1-1：通知 UI 重建 committed
    continue  // 压缩后重试本轮
  }
  // 其余 recoverable 走原有退避重试
  if (streamError.recoverable) { ... }
}
```

LoopCallbacks 加 `onCompacted?: (newMessages: Message[]) => void`（P1-1 修订）。

## 6. 压缩持久化（P0 修订：history boundary）

**问题**（审阅 P0）：HistoryStore 是 append-only，压缩替换内存后磁盘仍是全量 → 重启 /history restore 拿回未压缩历史 → 白压。

**修订方案**（开发建议方案 3，最小破坏 append-only 语义）：
- 压缩时：append 一条 `{compact_boundary: true, summary: '...', keptCount: N}` 标记行 + summary 消息
- `restore()` 遇到 boundary 行：**丢弃该行之前的所有消息**，从 summary 继续

HistoryStore 接口加：
```ts
/** 记压缩边界（append boundary 行 + summary；restore 遇到则丢弃之前的消息） */
appendCompactBoundary(summary: string, keptCount: number): void
```
restore 读到 `{compact_boundary:true}` → 清空已累积的 messages + push summary_msg。

## 7. 决策结论（v2 修订后）

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| **M5-D1** | 压缩算法 | aider 递归 split-summarize | 简单可测可照搬 |
| **M5-D2** | token 计数 | **M5 手动模式不装 tokenizer**（PM 建议）；自动触发模式才装 `gpt-tokenizer` | 手动 /compact 用户自决，不需每轮计数；附录 D 记自动方案 |
| **M5-D3** | 触发方式 | **手动 /compact 为主**；400 context-too-long 自动压缩作为配套（§5.3，非阈值预估） | 手动覆盖 80%；自动走错误捕获（非每轮预估），无性能陷阱 |
| **M5-D4** | 压缩产出 | 替换为 `[summary_msg, ...tail]` + compact_boundary 标记 | 协议兼容；boundary 让 restore 正确（§6）|
| **M5-D5** | messages 替换方式 | **原地 mutate**（`length=0; push(...)`），非重赋值 | P0 修订：TuiApp/cli 靠 messagesRef mutation，重赋值会丢失 |
| **M5-D6** | CONTEXT_TOO_LONG 处理 | **错误码专属分支**（loop 内），非依赖 retryable 死字段 | retryable 当前只写不读；错误码语义清晰 |
| **M5-D7** | 摘要失败 | **不重试，降级硬截断**（保留最近 N 条 + 提示） | 重试注定失败（head 仍溢出）；硬截断保证可用 |
| **M5-D8** | 压缩次数上限 | 单会话 MAX_COMPACTS=2 | 防 summary 的 summary 退化循环（P1-8）|

| 步 | 内容 | 依赖 | 心脏影响 |

## 9. 测试

### 单测
| 模块 | 场景 |
|---|---|
| errors | 400 context-too-long → CONTEXT_TOO_LONG / 各端点 body 文案 / 非 context 400 不误判 |
| compact | split-summarize（head/tail 切分）/ 递归（仍超再切）/ 深度>3 退化 / summary strip analysis / **摘要失败降级硬截断** |

### 集成测
- /compact：MockProvider → compactMessages → messagesRef 原地替换 + committed 重建（**断言 messagesRef.current 引用不变 + 内容已替换**，P0 验收点）
- 400 自动压缩：MockProvider 吐 CONTEXT_TOO_LONG → loop 压缩 + continue（**断言不退避重试 + messages 被压缩**）
- 持久化：append boundary → restore 过滤（断言恢复的是压缩后状态）

### 验收（含摘要质量）
- 压缩后 LLM 仍能引用压缩前的文件路径/决策（构造含具体路径的对话 → 压缩 → 新轮问路径 → 断言 LLM 响应含路径）
