# ECode 后续 M9 实施方案：改动安全网与质量闭环

> 日期：2026-08-15 · 状态：**设计稿 v1.1（待启动；2026-08-16 拍板扩容：+hooks 接线修复 P0、+权限系统首步、沙箱默认关确认）**
> 主题一句话：**改坏了能回去**（checkpoint + /rewind）、**改完自动验**（lint/test 回喂）、**权限有纵深**（沙箱模式 + 权限规则）；git 做轻量集成。
> 来源：功能差距盘点（四家成熟 CLI 对比）发现三个「四家全有、ECode 全无」的硬缺口中的两个半（安全网 / 质量闭环 / 沙箱纵深）。参考实现集中附录 B。

---

## 0. 目标与验收

**目标**：给「Agent 改文件」这个最高频高危动作建立纵深——事前有围栏（沙箱+权限规则）、事中有快照（checkpoint）、事后有验证（lint/test）、后悔有退路（/rewind 与 /undo）；顺带清偿 hooks 的四个接线缺口。

**验收**：
- **hooks 接线修复**（原观察区 D.5 四项）：SessionStart 的 additionalContext 注入首轮消息；PreToolUse verdict 全字段消费；dispatch 七处透传 AbortSignal；Stop 的 stop_reason 区分 aborted/turn-complete
- **checkpoint**：write_file/edit_file/bash 修改过的文件在改动前被快照；`/rewind` 面板选消息点 → 文件还原 + 对话回退（投影标记，不删历史）
- **lint/test 回喂**：编辑类工具成功后自动跑配置的 lint/test 命令，失败输出作为信息性 tool_result 回喂模型自纠；连续 2 次失败熔断
- **git 集成**：`autoCommit`（默认 **false**）开启时编辑轮末自动 commit（带 ECode 标记）；`/undo` 只回退 ECode 创建的 commit
- **沙箱**（**默认关，用户主动开**——default 档=现状确认弹窗，2026-08-16 拍板）：`/sandbox` 四档（default / read-only / workspace-write / **full-access 总放行**）；write_file/edit_file 越界拦截；read-only 下副作用工具整体拒绝；full-access 全免确认但**内置黑名单 + 用户可配 blockedCommands 通配清单仍硬拒**
- **权限系统首步**（M8 §11 储备前移）：三态规则引擎 + `Hook(owner)` 规则——扩展源 hook（skill/plugin）首次执行前查规则（allow/deny/ask），用户源 hooks 不问
- **快照治理**：每会话上限 100 个快照点（超限淘汰最旧）；>10MB 文件跳过快照并 warn；content hash 去重生效
- **还原安全**：还原前自动快照当前状态（撤销可撤销）；外部改动文件在确认弹窗中逐一标注，不静默覆盖

**不做**（后置）：进程级 OS 沙箱（codex 式 seccomp/Job Object——重基建，软沙箱先行）、diff 浏览器面板（会话级改动总览 UI）、LSP 诊断（§7 占位，M9 有余量才做否则 M10）、权限系统完整四维（Skill/Plugin/Mcp 规则与 UI 面板——M9 只做 Hook(owner) 首步）。

## 2. checkpoint 文件快照 + /rewind（P1，~3-4 天）

**问题**：edit_file/bash 改坏文件后没有任何退路——不总在 git 里、也不该被迫为 Agent 的每次尝试污染 git 历史。

**流程图（事中快照 + 事后反悔两条线）**：

```
【事中：每次改文件前先拍快照】
  LLM 要执行 write_file / edit_file / bash
    └─► 弹确认，用户同意
          └─► ★ 快照：把即将被改的文件当前内容复制到
                ~/.ecode/checkpoints/<会话ID>/<序号>/
                （附 meta：时间 / 工具 / 改了哪些文件）
                └─► 才真正执行修改

【事后：用户反悔了 /rewind】
  面板列出快照点（时间 + 当次改了什么）
    └─► 选一个点，界面再确认一次（列出将还原的文件）
          └─► 文件还原：从选中点往回按时间倒序放回去
                （后改的先还原，一层层退回去）
                └─► 对话回退：追加一行 rewind 标记
                      ★ 历史文件一个字不删——只是之后的对话不再喂给 LLM
                      （与压缩 boundary 同机制，/history 仍能回看全部）
                      └─► 回到那个时刻，继续聊
```

**详细讲解**：

**快照机制**（`src/services/checkpoint.ts`）：
- **触发点**：副作用工具（write_file/edit_file/bash）`execute` **前**、确认通过后——通过 `ToolContext` 注入可选 `onBeforeWrite?(paths: string[])` 回调，cli/TuiApp 的 makeDeps 装配（**心脏只在 ToolContext 透传，不认识 checkpoint 概念**）
- **快照内容**：「本次将修改的文件」的改动前副本（write/edit 从入参取 path；bash 不解析命令——快照 cwd 下**近修改集**：git 有则 `git status` 变更文件，无 git 则跳过 bash 快照并记 warn）
- **存储**：`~/.ecode/checkpoints/<sessionId>/<seq>/` 下原路径相对结构 + `meta.json`（消息 id / 工具 / 时间）。**copy 而非硬链接**（Windows 下工作区与 home 常跨卷，硬链接不可用；快照对象是文本文件，体量可接受）
- **治理**：每会话 100 点上限（淘汰最旧）；单文件 >10MB 跳过 + warn；会话保留跨重启（`/rewind` 恢复历史会话后仍可用）；**存储 content-addressed 去重**（2026-08-16 一手核读吸收，opencode `snapshot.ts` 同款）——快照按文件内容 hash 命名，同文件多轮未变只存一份，100 点 × 多文件的全量 copy 膨胀解药

**/rewind**（命令 + overlay 面板）：
- 面板列出快照点（时间 + 工具 + 文件摘要）→ 选中：
  1. **文件还原**：该点之后的全部快照按时间逆序还原（后改的先还原）
  2. **对话回退**：**投影派做法**——往 history 追加一行 `{"rewind_to": <seq>}` 标记，`buildContextMessages` 识别最后一个 rewind 标记截断投影（与 boundary 同机制、append-only 不删历史；`/history` 回看完整）
     **类型与 UI 配套**（审阅补）：`HistoryLine` 联合扩展 `RewindLine` 变体 + `isRewind` 守卫（core/types.ts，与 BoundaryLine 同层）；`commit.ts` 的 `messagesToCommitted` 对 rewind 行生成 `⇺ 已回退至 N` 标记（boundary 的 compacted 标记同款处理——否则新变体进 filter 会被当 Message 渲染炸 UI）
**/rewind 面板设计（2026-08-16 对照代码补全；overlay kinds 加 `rewind-panel`，PanelShell 基线零新键位）**：
- **行结构**：`HH:MM  工具名  文件摘要（≤3 个，多则 +N）`——meta.json 的时间/工具/文件列表直拼；空态「（本会话还没有任何改动）」；输入即搜索（工具名/文件名过滤）
- **二级确认页**（面板内导航，McpPanel 三级同款）——**不用 ConfirmPrompt**（2026-08-16 代码核读：其 `ConfirmState` 是纯字符串 preview 的工具授权语义，装不下文件清单与着色标注；还原确认是独立语义）：
  列出将还原的文件清单；外部修改的文件独立成组、黄色 ⚠ 标注「快照后有外部修改，还原将覆盖」；底部 `y 还原 / Esc 取消`
- **运行中守卫**（2026-08-16 补）：`runningRef` 为 true 时面板**可开可看但确认禁用**，底部提示「本轮运行结束后才能回退」（loop 与 rewind 同时写 messagesRef/history/文件会竞态——现有 runningRef 只守 submit，命令路径无守卫）
- **恢复会话快照跟随**（2026-08-16 补，断链修复）：restoreSession 起新 sessionId（TuiApp.tsx:581，M5 投影派）而快照按 `<sessionId>` 键控——恢复时同步把 `checkpoints/<旧id>/` 拷贝到 `<新id>/`（CC `copyFileHistoryForResume:922` 同款），否则「跨重启可用」落空
- **还原前先快照当前状态**（2026-08-16 吸收，opencode `revert.stage` 同款）：执行还原的那一刻先拍一个新快照点——回错了可以再 `/rewind` 回来（**撤销可撤销**），还原操作本身不留盲区
- **外部改动检测**（2026-08-16 吸收，CC `fileHistory.checkOriginFileChanged:600` 同款）：还原前比对该文件当前内容与最近快照基线——若快照后被用户手动改过（外部编辑器），确认弹窗里逐个列出「这些文件在快照后有过外部修改，还原将覆盖」，由用户决定——**绝不静默覆盖用户的手改**

## 3. 编辑后 lint/test 自动回喂（P3，~2-3 天）

**问题**：模型改完就说「完成」——编译错/测试红要等用户自己发现再贴回来。四家里 aider 的 auto lint/test 是质量闭环标杆，ECode 完全没有。

**流程图（改完自动验，红了自动修）**：

```
一轮对话中 LLM 改了文件（write_file / edit_file 成功）
  │
  ▼
等这轮工具都执行完再跑（★同轮改多个文件只跑一次）
  │
  ▼
自动跑 lint / test（命令自动从 package.json 的 scripts 里找，找不到即关闭）
  │
  ├─ 全绿 ──► 静默，不打扰任何人
  │
  └─ 有失败 ──► 失败输出作为提示信息喂回给 LLM
                  │
                  ▼
               LLM 看到具体报错，自己修
                  ├─ 修好了 ──────────► 回到「静默」
                  └─ 连续 2 次修不好 ──► 停止自动跑，提醒用户接手
                                          （防死循环烧钱）
```

**详细讲解**（`src/services/quality.ts`）：
- **配置**：`lintCommand` / `testCommand`（config 顶层；**默认自动探测**——package.json scripts 里的 `lint`/`test`，探测不到即关闭，零配置可用）
- **触发**：一轮工具执行中若有 ≥1 个编辑类工具成功（write_file/edit_file），**轮末聚合跑一次**（同轮多编辑不重复跑）——挂在 `executeTools` 返回后？不，**loop 零改动**：作为 `onToolResult` 的宿主侧逻辑（TuiApp/cli 的 callback 里检测编辑成功 → 轮末触发），或独立 `afterTools` 回调注入 opts（与 onCompacted 同款模式）
- **回喂**：输出作为**信息性 tool_result** 追加（`is_error: false` + `[lint] 失败输出...` 前缀）——模型看到即自纠；成功则静默（不打扰）
- **熔断**：连续 2 次 lint/test 失败且模型修复无效（输出无变化）→ 停止自动跑，onWarn 提示用户接手
- 超时 60s；输出截断复用 bash 截断（30KB 头尾中截）

## 4. git 轻量集成（P6，~2 天）

**问题**：想要干净历史的用户需要 Agent 改动可追溯；但 ECode 哲学是**不静默改用户 repo**——所以默认关、显式开。

**流程图（自动提交 + 安全撤销）**：

```
【自动提交】（config 开启后，默认关）
  LLM 改完文件 + lint/test 跑完
    └─► git add 改动文件 → git commit
          message 由模型一句话生成（失败用固定模板）
          ★打标记：commit 尾部带 Ecode-Commit: 会话ID

      ……用户反悔……

【撤销 /undo】
  用户敲 /undo
    └─► 检查最近一次 commit：带 Ecode-Commit 标记吗？
          ├─ 带（是 ECode 提交的）──► git 回退，文件还原 ✓
          └─ 不带（用户自己的提交）──► 拒绝并提示
                                       ★绝不动用户自己的提交
```

**详细讲解**（`src/services/git.ts`）：
- `autoCommit: true`（config，默认 false）时：编辑轮末（quality 跑完后）`git add <改动文件> && git commit`，message 由当前模型一句话生成（复用 callLLM 通道，失败 fallback 固定模板 `ecode: <工具与文件摘要>`），commit trailer 打 `Ecode-Commit: <sessionId>` 标记
- **/undo**：`git reset --soft HEAD~1` + 文件还原——**只对带 Ecode 标记的最近 commit 生效**（`git log -1` 查 trailer，非 ECode 的 commit 拒绝并提示，绝不动用户自己的提交）
- 与 checkpoint 互补：checkpoint 总在（不依赖 git/不污染历史）；git 模式给要干净历史的人。两者共存时 /rewind 优先（粒度到消息点）

## 5. 沙箱模式（P4，~2 天）

**问题**：现在的唯一防线是确认弹窗（人盯）——读多写少的日常场景里，一次误确认就是一次事故。需要模式级的纵深。

**流程图（三档各拦什么）**：

```
/sandbox 切换档位（StatusBar 常驻显示当前档），四档各拦什么：

  default（默认档）
    读文件 / 搜索      ✓
    写 / 改文件        ✓（限项目目录内，越界要确认）
    bash              每次弹确认

  read-only
    读文件 / 搜索      ✓
    写 / 改文件        ✗ 直接拒绝
    bash              ✗ 直接拒绝

  workspace-write
    读文件 / 搜索      ✓
    写 / 改文件        仅限项目目录内；越界 ✗ 直接拒绝（能拦 .. 逃逸）
    bash              弹确认

  full-access（总放行，2026-08-16 用户拍板新增）
    读 / 写 / 改 / bash   全部免确认 ✓
    例外（无条件硬拒 ✗）：① 内置八条危险黑名单（rm -rf / 等永远拦）
                        ② 用户自配 sandbox.blockedCommands 通配清单
                           （如 ["git push --force*", "npm publish*"]）
    （对齐 CC：bypass 模式下 deny 规则仍强制；codex danger-full-access 同位）

诚实声明（软沙箱的边界）：
  bash 命令无法可靠解析它要写哪 → 靠确认弹窗兜底，不假装拦得住
```

**详细讲解**（**软沙箱**——工具层路径校验，进程级围栏后置）：
- 三档（`/sandbox` 切换 + StatusBar 标识 + config 默认档）：
  | 档 | read_file/ls/grep/glob/WebFetch | write_file/edit_file | bash |
  |---|---|---|---|
  | `default` | ✓ | cwd 内 ✓（越界确认）| 确认（现状）|
  | `read-only` | ✓ | **整体拒绝**（is_error「只读模式」）| **整体拒绝** |
  | `workspace-write` | ✓ | **仅 cwd 内**（越界直接拒绝）| 确认 + 输出审计提示 |
  | `full-access` | ✓ | ✓ 免确认 | 免确认；**黑名单+blockedCommands 命中仍硬拒** |
- 实现：write_file/edit_file 的 execute 前置 `resolve()` + 前缀校验（路径净化防 `..` 逃逸）；bash 无法可靠解析目标路径——read-only 档直接拒绝、其余档维持确认（**诚实声明软沙箱边界**，不假装拦得住）
- **Tab 专职档位热键**（2026-08-16 拍板）：Tab 在主输入空闲态与 /sandbox 面板内直接循环切档（default → read-only → workspace-write → full-access → 环绕），StatusBar 闪示当前档；进 full-access 弹确认（M9-D12）；输入焦点/搜索态不拦截。**代价与清偿**（2026-08-16 已随键位改版落地）：①斜杠命令 Tab 补全删除——回车两段式本就逐字覆盖同功能（`InputStream.tsx` 已改+防回归测试）；②规范里的全局焦点循环**实现层面从未落地**，记载撤销，焦点态收敛为「输入框 ↔ 面板/弹窗」两态；③工具块展开从「Tab 聚焦+Enter」两步并为 Ctrl+O 一步（Ctrl+O 已在产）；④ ask_user 多问 chip 导航改 ←→（QuestionPanel 无 tabs 不冲突）——键位规范同步改
- **full-access 档**（2026-08-16 拍板新增，对标 codex `danger-full-access` / CC bypassPermissions）：跳过全部 ConfirmPrompt，但两道闸无条件保留——① `proc.ts` DANGEROUS_PATTERNS 八条（本就无条件 throw，任何档都拦）；② config `sandbox.blockedCommands: string[]` 用户通配清单（`*` 前后缀匹配，语义对齐 opencode wildcard；命中 is_error 硬拒非确认）。**与权限系统（P5）的合成规则**：deny 规则仍强制（CC 同款），ask 规则降级为 allow（bypass 语义）。切换进该档时 ConfirmPrompt 确认一次（防误切）
- MCP 工具：read-only 档下按其 `readonly` 元数据分流（M6 已有）
- 与 M8 WebFetch 的收口：read-only/workspace-write 档下 WebFetch 照常（已是只读+SSRF 拦截）

## 6. 权限系统首步（P5，~2-3 天）

> 2026-08-16 用户拍板前移（原 M8 §11 设计储备，"启动时机用户定"→ 定了：M9）。完整设计（双维模型/三态规则/三层存储求值/与沙箱正交）见 M8 方案 §11，本节只定 M9 首步范围。

**首步 = `Hook(owner)` 三态规则**（四维模型中离危险最近、M7 刚交付的扩展面）：
- 扩展源 hook（skill:xxx / plugin:yyy@mkt）**首次执行前**查规则：allow（放行）/ deny（跳过+告知）/ ask（ConfirmPrompt，可记住）
- **用户源 hooks 不问**——用户自己写的 config，所有者侧不是被管控对象
- 规则字符串式（可手编可 UI 列）：`Hook(owner)` + `prefix:*`，三层存储（local > project > user）
- 落点：HookRunner.dispatch 前置检查（装饰层 getter 之内、runOne 之前）；零心脏改动

## 10. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 快照磁盘膨胀 | 中 | 100 点上限 + 10MB 单文件跳过 + 文本文件为主（实测校准）；/rewind 后旧点可清 |
| bash 快照盲区（无 git 时）| 中 | 诚实降级：warn + 文档明示；有 git 的项目用 git status 兜 |
| /rewind 与运行中 loop 竞态（2026-08-16 代码核读发现）| 中 | runningRef 入口守卫：面板可看、确认禁用 + 提示 |
| 恢复会话起新 sessionId 致快照目录断链（2026-08-16 代码核读发现）| 高 | restoreSession 时拷贝 checkpoints/<旧id>→<新id>（CC copyFileHistoryForResume 同款）|
| lint/test 死循环（失败→修→再失败）| 中 | 连续 2 次熔断 + 60s 超时；输出无变化判定 |
| /undo 误伤用户 commit | 高 | trailer 标记强校验，非 ECode commit 一律拒绝 |
| 软沙箱被绕（bash 写 cwd 外）| 中 | 明示边界：bash 档位靠确认兜底；进程级沙箱后置声明 |
| full-access 被误切/滥用 | 中 | 切档 ConfirmPrompt 确认 + StatusBar 危险色常驻 + 黑名单无条件保留（连 CC 都在 bypass 下跑分类器，ECode 用静态黑名单兜底，不引 LLM 分类器——零依赖哲学）|
| rewind 与压缩交互 | 低 | rewind_to 与 boundary 同为投影标记，取「最后」语义天然共存（测试覆盖同存场景）|
