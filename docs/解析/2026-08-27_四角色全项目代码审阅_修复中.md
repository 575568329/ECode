## 汇总结论

**定性**：骨架健康——协议层是纯叶子、心脏零 provider 分支、两层宿主与 serve 设计经三角色独立确认方向正确且纪律真实成立（第三客户端飞书接入仅一天成本即协议化红利兑现）。本轮未发现 HTTP 面无需凭据的 P0（鉴权在先/loopback kernel 级不可伪造/CORS 缺省安全）。**真正的窟窿集中在三处**：① 飞书网关（对外第一张脸，鉴权最弱+审批回执丢失）；② daemon 异常脆弱面（四处单点异常可击落整个多项目 daemon）；③ 「命令管辖权」缺类型表达（项目级命令寄生在会话分发内，三个独立缺陷同源）。

### P2 与对标差距（择要）

**对标三件发布级缺口**（对标分析师，参照 opencode/codex/CC/harness 本地源码）：
- **审批模型缺「规则层+审计层」**：无 allow/deny 规则引擎（opencode ruleset 通配/CC permission modes）、「始终允许」仅 MCP 前缀（bash/edit once 批准零记忆）、审批 asked/decided 不落盘（daemon 重启 pending 全丢、零决策留痕——harness 成对 append 进会话日志）
- **拒绝不带反馈**：codex `Denied{rejection}`/opencode feedback 喂回模型；ECode reject 模型只能瞎猜（改法：respond 加可选 message 字段，成本小）
- **事件流无 id 无游标**：opencode EventV2 帧带单调 id+`/sync` 按 seq 补缺；ECode 断线只补当前选中会话，其余并发轮次内容永久丢失

**过度设计/偏离**（对标 B 组）：muxFilter 死参数+`void serveHost` 锚点 hack；裸命令兼容层「W5 移除」仍在线+单会话 events 端点双轨；**浏览即装配违背自家冷启动声明**（session/list·config/get 走 resolveHost→acquire，点过的项目全变常驻+锁到进程死）；Bearer/Basic 双凭据解析留一即可；usage stats 行逐帧落盘写入放大（P0 设计观察项）。

**工程质量 P2**（资深/架构师择要）：POST /api/projects 无 body 上限（cmd 有 1MB 预检，不一致）；凭据比较非常量时；serveStop 盲杀陈旧 PID（无 id 核对）；光标守卫 write 包装丢 encoding 两参形态；feishu dispose 未关 WSClient；SSE 工程细节两份拷贝（抽 sseWriter）；`session/read` 的 beforeSeq/limit 分页字段已入类型但宿主忽略（重连全量补拉带宽根源）；cli/index.ts 877 行四职责混杂（拆 assembly/serveMain）；created 帧早于 transcript 填充（恢复会话侧栏标题长期为空）；feishu 测试头注宣称覆盖三大路径实际仅 2 冒烟用例。

**已核验无问题面**（供勾销）：静态托管路径逃逸守卫、loopback 判定、跨项目审批越权（requestId 每会话私有不可猜）、飞书凭据日志脱敏、锁文件 TOCTOU、approval.ts fail-closed/级联/超时、XSS 面（react-markdown v10 默认剥 raw HTML+无 dangerouslySetInnerHTML+defaultUrlTransform 白名单）、图片 media_type 魔数白名单、全范围无 any 违例。
