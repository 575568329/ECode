### 2.2 数据流（工具执行前的权限检查）

```
LLM 返回 tool_use
   ↓
PermissionManager.check(toolName, input, mode)   ← 新规则引擎
   ↓ 返回 PermissionVerdict
   ├─ allow     → 直接执行（bypass 模式 / 命中 allow 规则 / 安全工具）
   ├─ deny      → 直接拒绝，is_error 回喂 LLM（命中 deny 规则 / 敏感文件 / 越界+非交互）
   └─ ask       → yield permission_request → UI 弹窗 → gate 返回三态
                    ├─ allow_once   → 本次执行，不记规则
                    ├─ allow_always → 本次执行 + 记内存规则（不写盘）
                    └─ deny         → 拒绝回喂
```

## 四、核心设计决策（8 条，源自交叉验证报告）

1. **三档模式**（砍 `plan`/`dontAsk`/`auto`）：`default` / `acceptEdits` / `bypass`。plan 用 deny 规则 `edit:{"*":"deny"}` 模拟，更灵活。（交叉验证 §4.2）
2. **命令分级用 opencode arity 字典**（非 tree-sitter，非从零写 200 行解析器）：维护「命令前缀 → token 数」字典，`git checkout main` 归约成 `git checkout`；原生二进制依赖与 §9.3 红线冲突，禁用 tree-sitter。（§4.3）
3. **扁平 + last wins 合并**（非 CC 5 层 source、非 deny 全局优先）：user + project 两层规则扁平合并，**最后一条匹配胜出**，比 deny 全局优先更易推理。（§4.7）
4. **2 层配置**：`~/.ecode/settings.json`（用户级全局）+ 项目 `.ecode/settings.json`（git 跟踪）。不读 `.claude/`（避免路径误导，§9.3）。（§4.6）
5. **allow_always 默认不写盘**：仅内存层（防误点永久放行）。用户主动编辑配置文件持久化。（§4.6）
6. **路径越界 + 敏感文件黑名单 = P0 硬安全网**：性价比最高，必须优先。抄 CC `DANGEROUS_FILES`/`DANGEROUS_DIRECTORIES` + opencode `external_directory`。（§4.4）
7. **保留 425ms grace period**：三源调研中 ECode 独有（CC/opencode/CCode 均未定位到独立 grace 常量），是已超过三源的设计点，**必须保留**。（§4.5）
8. **规则语法 2 种**：`Bash(npm run test)`（exact）+ `Bash(npm run *)`（wildcard），砍 CC legacy `Bash(npm:*)` prefix。（§4.7）

```ts
export type PermissionMode = 'default' | 'acceptEdits' | 'bypass';

/** 规则 action —— opencode 三原子 action */
export type RuleAction = 'allow' | 'deny' | 'ask';

export interface Rule {
  tool: string;            // 'bash' | 'edit_file' | '*' 等
  pattern: string;         // 'npm run test'（exact）| 'npm run *'（wildcard）| '*'
  action: RuleAction;
  source: 'user' | 'project' | 'session';  // 来源层（last wins 排序用）
}

/** check() 返回值 */
export type PermissionVerdict =
  | { action: 'allow'; reason: string }
  | { action: 'deny'; reason: string }
  | { action: 'ask'; reason: string };

/** gate 返回三态（修 🔴-2 的关键） */
export type GateDecision = 'allow_once' | 'allow_always' | 'deny';
```

```ts
// src/permission/rule-engine.ts

export function matchPattern(pattern: string, input: string): boolean;
```

| 危险命令拦截 | `rm -rf /` → deny |
