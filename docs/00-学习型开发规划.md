# ECode 学习型开发规划

> **本项目的第一目的是学习，不是交付。** 每一步都必须先回答"这一步我要学会什么"，技术任务只是学习目标的载体。
> 求职定位：AI 应用方向的全栈工程师。这个项目是简历核心项目，要能在面试时把每个模块的设计原理讲清楚。

---

## 一、项目定位（North Star）

用 TypeScript + Node.js **手写**一个生产可用的 AI coding agent（对标 Claude Code / opencode），**拒绝框架黑盒**，理解 agent 的每一个环节。

**三个不可动摇的原则：**
1. **理解优先** — 每个模块动手前，先讲清楚"为什么需要它、它解决什么问题、别人怎么做的"。写不出原理就不动代码。
2. **手写核心** — agent loop、Provider 适配、上下文管理都自己写。可以用工具库（如 ai-tokenizer），但核心逻辑不假手于框架。
3. **能讲清楚** — 每个里程碑结束，能对着代码给面试官讲 15 分钟不卡壳。

---

## 二、已确定的产品决策（8 个）

| # | 决策点 | 选择 | 理由 |
|---|--------|------|------|
| 1 | 定位 | 生产可用工具 | 能解决实际问题公司才看重 |
| 2 | 技术路线 | 手写 loop + 逐步模块化 | 学习价值最高，求上得中 |
| 3 | 模型策略 | 多模型 + 配置驱动 + CLI 切换 | AI 方向核心能力 |
| 4 | Provider | 2 个核心（Claude + OpenAI-compatible） | 各家兼容 OpenAI/Anthropic 协议，无需为每个模型写代码 |
| 5 | 预置模型 | GLM-5.2 + DeepSeek（其他用户自配，Gemini 暂不支持） | 参考 cc-switch 思路，配置即扩展 |
| 6 | 工具集 | 实用 MVP（read/write/edit/list/grep/glob/bash/ask_user） | 够用，后续加 |
| 7 | 交互 | 持续对话 + Session 持久化 + 上下文自动整理（LLM 摘要压缩） | 求上得中，生产级核心能力 |
| 8 | 权限 + 输出 | 分级权限系统 + 混合流式（文本流式/工具非流式） | 都做成技术亮点 |

**关键技术调研结论：**
- **Token 计数无通用 tokenizer**，跨模型差异 ±30%（中文更大）。方案：`ai-tokenizer` 库（离线、90+ 模型、97%+）为主，Claude 官方 count_tokens API 校准，阈值设 80%。
- **OpenAI-compatible ≠ tokenizer 兼容** — GLM/DeepSeek 别盲目套 tiktoken。
- **模型工具支持度要探测不能假设**（continue.dev 的 `PROVIDER_TOOL_SUPPORT` 模式）。

## 三、认知盲区清单（调研发现的"我不知道我不知道"）

> 这是本次调研最大的价值。以下模块是初版规划遗漏的，但真实生产 agent 缺了会直接不可用。

### P0 — 缺了 agent 直接不可用/不安全
- **P0-1 System Prompt 工程** — 分层拼装（行为约束+工具说明+项目上下文），非一坨字符串。Claude Code 系统提示约 4200 token，恒在最前、永不进 history。
- **P0-2 文件编辑正确性** — 难点不是替换，是**匹配失败后的恢复**：把文件真实行回喂给 LLM 重试。aider 数据：编辑格式选对能把重构得分从 20% 拉到 61%。
- **P0-3 Tool result 截断** — 一次大文件读取就能撑爆上下文导致死循环。基准：Bash 30000 字符、Read 2000 行/单行 2000 字符。
- **P0-4 错误恢复** — API 退避（区分 429/529/500/504）+ 工具失败回喂 `is_error` + 死循环防护（迭代上限 25-50 + 重复动作检测）。
- **P0-5 强制后置验证** — 别信模型自报"完成"（22.6% 失败源于此），强制跑 build/test/lint。

### P1 — "能用"到"好用/可维护"
- **P1-1 项目记忆（CLAUDE.md 类）** — 启动注入 + 压缩后重注入。
- **P1-2 Repo Map** — tree-sitter + 图排序表示大代码库（v1 用简化版：文件树+关键签名）。
- **P1-3 中断机制** — Ctrl+C 用 AbortController，难在中断后保持 tool_use/tool_result 配对。
- **P1-4 并行工具调用** — 只读工具 Promise.all 并发。
- **P1-5 成本追踪** — 用 API 返回的 usage，别用本地估算。
- **P1-6 可观测性** — Run>Step>Message 三层结构化日志，debug 生命线。
- **P1-7 可测试性** — Provider 层依赖注入 + LLM VCR（record/replay）。temperature=0 测不出确定性。

### P2 — 预留接口，v2 实现
- **P2-1 Subagent** — 独立上下文的子 agent（架构预留"loop 可递归 fresh context"）。
- **P2-2 MCP client** — 工具注册表预留"外部工具源"抽象。
- **P2-3 Hooks / P2-4 Git 自动化**

## 四、推荐分层架构

```
┌─────────────────────────────────────────────┐
│  UI / Entry 层  (CLI/REPL, 可选 HTTP server)  │
├─────────────────────────────────────────────┤
│  Agent Core 层                                │
│   - AgentLoop (状态机: gather→act→verify)      │
│   - SessionManager (state + 持久化)            │
│   - ContextManager (compaction/prune/token)   │
│   - Orchestrator (subagent, P2 预留空壳)       │
├─────────────────────────────────────────────┤
│  Tool 层                                       │
│   - ToolRegistry (注册/schema/能力探测)         │
│   - ToolExecutor (并发 + 截断 + is_error 回喂)  │
│   - PermissionGate (分级权限)                  │
│   - 各工具: read/write/edit/grep/bash/...      │
├─────────────────────────────────────────────┤
│  Provider 层                                   │
│   - ProviderAbstraction (统一 stream 接口)      │
│   - ProviderTransform (消息规范化)             │
│   - ClaudeProvider / OpenAIProvider           │
│   - RetryPolicy (指数退避 + jitter)            │
└─────────────────────────────────────────────┘
   横切: Observability │ CostTracker │ SystemPromptBuilder │ RepoMap
```

**参考项目分工：**
- **Claude Code** — context 管理、subagent 隔离、截断策略的数值基准
- **opencode** — Provider 抽象（transform 层）、Session/Message/Part 状态模型、目录分包
- **aider** — repo map、编辑格式正确性（最硬核两块）
- **cline** — Plan/Act 双模式、per-mode 模型切换
- **continue.dev** — 工具能力探测（别假设所有模型支持 tool）

## 五、里程碑规划（学习目标驱动）

> 每个里程碑 = 一组紧密相关的学习目标。**先学原理，再写代码，最后能讲清楚。**
> 每个里程碑内部走 TDD：先定义"什么算完成" → 写测试 → 实现 → 重构 → 能复述原理。

### 🎯 M1：理解 Agent 的心脏 —— 最小可运行 loop
**学习目标（这一步要学会）：**
- LLM 工具调用的完整协议：`tool_use` / `tool_result` / `stop_reason` 如何往返
- 为什么 agent 是个 `while` 循环，终止条件是什么
- messages 数组如何累积（为什么是 append 不是重建）
- tool_use 和 tool_result 的 id 配对约束（漏了会 400）

**技术产出（学习目标的载体）：**
- 单一 ClaudeProvider（先不管多模型，专注理解协议）
- 2 个工具：`read_file` + `bash`
- 一个能跑通的 `while (stop_reason === 'tool_use')` 循环
- CLI 一次性模式：`ecode "读一下 package.json 告诉我依赖"`

**验收（能讲清楚才算过）：**
- 能手画出一次"读文件"任务的完整消息流转图
- 能解释如果不回传 tool_result 会发生什么

---

### 🎯 M2：理解多模型适配 —— Provider 抽象层
**学习目标：**
- 不同 LLM 的工具调用协议差异（Claude `tool_use` vs OpenAI `function_call`）
- 为什么"OpenAI-compatible"能让一套代码接多个模型，边界在哪
- 抽象接口怎么设计才能既统一又不丢各家特性（transform 层的意义）
- 模型能力探测：为什么不能假设所有模型都支持 tool calling

**技术产出：**
- `ModelProvider` 统一接口 + `ProviderTransform` 规范化层
- ClaudeProvider + OpenAIProvider 两个实现
- 配置系统：预置 GLM-5.2 / DeepSeek，用户可自配
- CLI 切换：`ecode --model deepseek "..."`、`ecode --list-models`

**验收：**
- 能讲清楚同一个"写文件"任务在 Claude 和 OpenAI 协议下的报文差异
- 能解释为什么加一个新模型只需改配置不用改代码

---

### 🎯 M3：理解"记不住"问题 —— 上下文管理 + Session
**学习目标：**
- 为什么 agent 会"越聊越傻"（上下文窗口 + tool result 撑爆）
- Token 计数为什么没有通用方案，跨模型差异从哪来
- 上下文压缩的策略取舍（滑动窗口 vs LLM 摘要），如何保护 tool_use 配对
- Tool result 截断为什么是"救命"而非"优化"

**技术产出：**
- `ai-tokenizer` 集成 + 分层 token 计数
- ContextManager：80% 阈值触发 LLM 摘要压缩
- Tool result 截断（Bash 30000 字符 / Read 2000 行基准）
- Session 持久化（先 JSON）+ REPL 模式 + `--continue`

**验收：**
- 能讲清楚一次上下文压缩的完整过程（保留什么、压缩什么、如何不破坏 tool 链）
- 能解释为什么 tiktoken 算 GLM/DeepSeek 会不准

---

### 🎯 M4：理解"信任问题" —— 安全 + 正确性 + 健壮性
**学习目标：**
- 为什么 coding agent 最大的失败是"违反约束"和"谎报完成"
- 分级权限的设计哲学（default/acceptEdits/plan/bypass）
- 文件编辑为什么难在"匹配失败恢复"而非"替换本身"
- 错误恢复的三条路径（API 退避 / 工具回喂 / 死循环防护）

**技术产出：**
- 完整工具集（补齐 write/edit/list/grep/glob/ask_user）
- edit 工具的"匹配失败回喂真实行 + 重试"闭环
- 分级权限系统 + allowlist + 危险命令黑名单
- 错误恢复 + System Prompt 工程 + CLAUDE.md 注入 + 强制后置验证
- 混合流式输出

**验收：**
- 能讲清楚 edit 匹配失败时 agent 如何自我纠正
- 能演示权限系统拦截 `rm -rf`

---

### 🎯 M5+：进阶（可观测性 / 测试 / Repo Map / Subagent）
留待前四个里程碑跑通、工具真正能日常使用后，按面试需要和使用痛点迭代。
- 并行工具调用、中断机制、成本追踪、结构化日志、DI+VCR 测试
- Repo Map（v1 简化版 → v2 tree-sitter）
- Subagent、MCP client、Hooks

## 六、技术栈与工程约定

- **语言**：TypeScript，strict 模式，禁止 `any`（不得已用 `unknown`）
- **运行时**：Node.js（多端运行，暂不用 Bun 以降低环境复杂度）
- **测试**：Vitest，核心逻辑 TDD
- **提交**：Conventional Commits（feat/fix/refactor/docs/chore）
- **关键依赖**：`@anthropic-ai/sdk`、`openai`、`ai-tokenizer`
- **配置**：`~/.ecode/config.json`（模型配置）+ 项目根 `ECODE.md`（项目记忆，类比 CLAUDE.md）

---

## 七、工作节奏

1. 每个里程碑开始：先讲这一批的学习目标和原理（对应认知盲区清单）
2. 原理讲清楚 → 定义验收标准 → TDD 实现
3. 里程碑结束：自测"能不能讲清楚"，不能则回炉
4. 每完成一个里程碑更新本文档的进度勾选
5. 重要原理沉淀到 `knowledge/ai-agents/`（CCode 线知识库）
