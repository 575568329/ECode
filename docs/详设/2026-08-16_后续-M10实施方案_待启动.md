# ECode 后续 M10 实施方案：感知扩展与配置可视化

> 日期：2026-08-16 · 状态：**设计稿 v1（待启动）**
> 主题一句话：让 Agent **看得见图**（多模态输入）、**搜得到网**（WebSearch）、**配置不用手编 JSON**（/config 面板）。
> 来源：2026-08-16 用户排期拍板（多模态要排期 / WebSearch 调研可行 / config 面板可以做但要设计好 TUI）+ 观察区吸走。WebSearch 可行性调研结论：Bing API 已死（2025-08-11 退役）、Anthropic/OpenAI 服务端搜索走不通（Astron 兼容端点）、**智谱 Web Search API 首选**（¥0.01-0.03/次、国内直连、与 GLM 同 key 体系）。

---

## 0. 目标与验收

**目标**：扩展 LLM 的输入通道（图像、全网搜索）+ 配置的可视化修改（不再手编 JSON）。

**验收**：
- **多模态**：`read_file("截图.png")` 返回 ImageBlock → 双协议 Provider 正确翻译 → 模型能描述图片内容；图片消息在 TUI 显示占位行；压缩序列化不炸（图片转占位文本）
- **WebSearch**：`web_search("query")` 返回标题+URL+摘要列表回喂；未配置 key 时工具不注册（零配置不炸）；配额/失败 recoverable 回喂
- **/config 面板**：`/config` 打开三页签面板；常用项可视化改（provider/模型/参数）；**未覆盖的键原样保留**（jsonc 非破坏性修改，保注释）；底部永久"打开原始文件"逃生口

**不做**（后置）：图片粘贴/拖拽进终端（剪贴板图像协议复杂，路径引用 MVP 够用）、视频/音频输入、Tavily 适配（接口位留，等真实需求）、多模态输出（模型生图）、keychain（用户拍板：key 无法被完全保护，优先级极低，维持观察区）。

## 1. 多模态输入 ImageBlock（P0，~3-4 天）

**问题**：用户想让 ECode 看截图/UI 图/报错截图——模型有视觉能力（GLM-4V 系列），ECode 的管道只传文本。types.ts 从 M1 就留了 ImageBlock 占位，本节把血肉写上。

**流程图（一张图从文件到模型）**：

```
用户：「看下这个截图哪里错了 D:\shot.png」
  │
  ▼
LLM 调 read_file("D:\shot.png")
  │
  ├─ 文本文件（现状路径）：读内容 → TextBlock → ……不变
  │
  └─ 图片（按扩展名/Magic Number 判定 png/jpeg/webp/gif）
        │ 守卫：≤5MB / 格式在支持列表（超限 is_error 提示压缩）
        ▼
      ImageBlock { type:'image', source:{ base64, media_type } }
        │
        ├─ TUI 渲染：占位行 [图片 D:\shot.png]（终端显示不了图，诚实占位）
        │
        ├─ Anthropic 翻译：content 项 { type:'image',
        │     source:{ type:'base64', media_type, data } }
        │
        ├─ OpenAI 翻译：content 数组项 { type:'image_url',
        │     image_url:{ url:'data:image/png;base64,…' } }
        │
        └─ 压缩序列化（M5 serializeMessage）：ImageBlock → '[图片 shot.png]'
           （摘要不吞 base64——几十 KB 的编码串进摘要只会污染）
```

**详细讲解**：
- **入口只有 read_file 路径引用**（MVP 拍板）：`@文件` 语法、终端粘贴、拖拽都后置——路径引用零新基建，且粘贴/拖拽在 Windows 终端的剪贴板图像协议（OSC 52/bracketed）各家实现不一，是坑不是特性
- **限制对齐 Anthropic 上限**：单图 ≤5MB、格式 png/jpeg/webp/gif、长边超 1568px 服务端自动缩放（token 按 (w×h)/750 估，写入成本估算）；GLM-4V 系列同量级
- **system prompt 教学**：加一行"read_file 支持图片路径（png/jpeg/webp/gif），用户让你看图/截图时直接读"
- **models.dev 探测视觉能力**：contextWindow 探测同通道，模型无视觉 → read_file 图片返回 is_error"当前模型不支持图像输入"（防 GLM-4 非V系列白花 token）

## 2. WebSearch 工具（P1，~2 天）

**问题**：模型对"最新的库版本/端点行为/新闻"只能猜或靠 web_fetch 碰运气——fetch 需要 URL，不知道 URL 时无路可走。

**流程图（一次搜索的完整路径）**：

```
LLM：需要最新信息 ──► 调用 web_search("vite 8 breaking changes")
  │
  ▼
启动时装配：
  config.webSearch = { provider:'zhipu', apiKey? }
  ├─ 有 apiKey（或 provider baseURL 命中 bigmodel.cn 回退复用）──► 注册 web_search 工具
  └─ 没配 key ──► 工具不注册，零配置不炸（模型不知道有这能力）
  │
  ▼
执行（readonly 免确认）：
  POST open.bigmodel.cn/api/paas/v4/web_search
    { search_engine:'search_pro', search_query, count:5 }
  ├─ 成功 ──► search_result[] → "1. 标题\n   URL\n   摘要" 拼接回喂
  │            （LLM 下一步常自己调 web_fetch 抓最相关那篇全文）
  ├─ 429/限流/网络 ──► recoverable is_error（模型自纠：换个问法/放弃）
  └─ key 无效 ──► 提示配置路径（不重试）
```

**详细讲解**：
- **provider 首选智谱**（调研定稿）：与 GLM 同开放平台、**同一把 API key**（Bearer 体系通吃 chat 和 search）、国内直连、search_std ~¥0.01/次 / search_pro ¥0.03/次、返回就是为 LLM 设计的（标题+URL+摘要+来源媒体）；`provider:'tavily'` 留接口位不实现（备选，等真实需求）
- **config 形态**：`webSearch: { provider, apiKey?, engine? }`；apiKey 缺省回退规则——当前 provider 的 baseURL 含 `bigmodel.cn` 时复用其 key（智谱用户零额外配置），否则要求显式配
- **防滥用**：description 写明"优先本地代码/文档，真需要最新线上信息才搜索"；count 默认 5 条（摘要足够定位，不贪多）
- **成本透明**：每次调用 ¥0.01-0.03，/cost 不计（外部 API 非 LLM token）——在工具结果尾部带一行"(web_search 1 次)"

## 3. /config 应用内面板（P2，~2-3 天）

**问题**：`/config` 现在用 $EDITOR 打开 config.json 手编 JSON——字段名记不住、JSON 语法易错、改完才发现键名拼错。

**TUI 设计约束（用户拍板：设计好界面，避免太长、避免覆盖不全）——两个问题的解法是同一个：分层 + 非破坏性**：

```
/config 打开面板（PanelShell tabs，←→ 切页签）
  │
  ├─ 页签①「常规」：高频项可视化改
  │    当前 Provider（列表选）→ 模型（该 provider 的 models 列表选）
  │    → temperature / maxTokens / thinking（枚举选，不手敲数字）
  │
  ├─ 页签②「Providers」：provider 列表 → 详情页
  │    baseURL / apiKey（输入框，保存时脱敏显示）/ models 增删
  │
  └─ 页签③「高级」：兜底覆盖，两层设计
       ├─ 已知高级键（mcpServers/webSearch/hooks/plugin 启用态）
       │  → 只读展示 + 回车跳 $EDITOR 定位到该键（引导不代编）
       └─ 底部永久项：「打开原始 config.json」（$EDITOR 逃生口）
  │
  ▼
保存 = jsonc modify 只改目标键（PluginLoader.setEnabled 同款先例）
  ├─ 用户注释原样保留
  ├─ 面板没覆盖的键一个字节不动   ← "覆盖不全"的结构性解药：
  │     面板不需要覆盖所有内容——改常用项，其余键非破坏性保留
  └─ 超长防抖：页签分组 + PanelShell 既有 12 行窗口滚动 + 详情页单键单页
```

**详细讲解**：
- **非破坏性是本节的命根**：面板永远不重写整个 config.json——jsonc-parser 的 `modify(text, path, value)` 只动目标路径（M7 PluginLoader.setEnabled 已在生产用它保注释），未识别键、注释、格式全部原样。所以面板"覆盖不全"不构成数据风险，只构成便利性梯度——高频项点选，低频项 $EDITOR
- **输入组件**：枚举/列表用 PanelShell 既有交互；字符串/数字复用 ask_user 的 TextInput 形态（M8-P1 交付）；apiKey 输入显示 `•` 脱敏（getMaskedConfig 同规则）
- **即时生效边界**：provider/模型/参数改完即生效（下一轮请求读 config 内存态）；baseURL/apiKey/models 改完提示"重启生效"（Provider client 缓存按 name 存）——诚实提示，不假装热更新

## 6. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 图片 token 撑上下文（4V 模型图片单张可达 1k+ token）| 中 | 尺寸/数量守卫 + 计入压缩估算 + read_file 教学写明按需读图 |
| 智谱 API 变更/价格调整 | 低 | 接口位 provider 抽象，Tavily 备选路径已调研 |
| 面板改坏 config | 中 | jsonc modify 非破坏 + 保存前 JSON 合法性校验 + 写前备份 .bak（一次性）|
| base64 图片进 HistoryStore 撑大历史文件 | 中 | history 落盘时 ImageBlock 存路径+哈希引用而非 base64（恢复时按路径重读，文件没了显示占位）|

## 7. 决策表

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| M10-D1 | 多模态入口 | read_file 路径引用（@语法/粘贴/拖拽后置） | 零新基建；终端剪贴板图像协议是坑不是特性 |
| M10-D2 | 图片限制 | 对齐 Anthropic：≤5MB、png/jpeg/webp/gif、1568px 服务端缩放 | 双协议里最严的一方作为通用上限 |
| M10-D3 | 压缩与历史的图片形态 | 序列化/落盘均不存 base64（占位/路径引用） | 摘要污染与历史文件膨胀同源，一次决策两处受益 |
| M10-D4 | WebSearch 供应商 | 智谱首选（同 key 体系/国内直连/¥0.01-0.03 每次）；Tavily 接口位 | 调研定稿：Bing 已死、Anthropic 服务端搜索走不通、Tavily 备选 |
| M10-D5 | 未配 key 行为 | 工具不注册（模型无感知） | 零配置不炸；不给模型一个必然失败的按钮 |
| M10-D6 | /config 面板形态 | 三页签 + jsonc modify 非破坏 + $EDITOR 逃生口 | 用户约束"别太长、别覆盖不全"——分层解决长度，非破坏性消解覆盖义务 |
| M10-D7 | keychain | 维持观察区不排期 | 用户拍板（2026-08-16）：key 无法被完全保护，优先级极低 |
| M10-D8 | 面板热更新边界 | 参数类即时生效，连接类（baseURL/key/models）重启生效 | Provider client 缓存按 name 存，诚实提示优于假热更 |
