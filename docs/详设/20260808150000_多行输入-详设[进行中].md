# 多行输入（Shift+Enter / Alt+Enter / `\`续行）— 详设

> 支点16「多行输入」的完整设计。功能架构设计原文仅一句提及，本详设补齐技术方案。
> 关联：`docs/功能方案/功能架构设计[进行中].md` 支点16；M3.5 Phase 3。

## 1. 背景与目标

InputBar 当前是**纯单行**：`text: string` 单字符串，所有编辑都是末尾操作（`setText(t=>t+input)` append、`t.slice(0,-1)` 末尾删除），无光标概念，上/下键被历史导航独占。无法换行、无法中间编辑。

**目标**：多行编辑——换行插入、光标在文本中间移动/编辑、上下键不与历史冲突。覆盖多端终端（WT / Mac / Linux / 经典控制台）。

## 2. 关键技术发现：ink 7.1.1 原生支持 Kitty 键盘协议

> ⚠️ 此发现**反转**了基于 CCode（ink **6.8.0**）的旧判断。旧判断"标准 ink 拿不到 Shift+Enter，要走 CC 的 fork-parser 路线"对 ink 6 成立，**对 ECode 的 ink 7.1.1 不成立**。

ECode 用 ink `^7.1.1`（`package.json`），内置完整 Kitty 键盘协议链路：

| 环节 | 源码位置 | 证据 |
|---|---|---|
| 独立模块 | `parse-keypress.js:2` | `import { kittyModifiers } from './kitty-keyboard.js'` |
| 解析 CSI u | `parse-keypress.js:125` | `kittyKeyRe = /^\x1b\[(\d+)(?:;(\d+)...)u$/` 匹配 Shift+Enter 的 `\x1b[13;2u` |
| return 码点 | `parse-keypress.js:307` | `codepoint===13 → name='return', isPrintable=true` |
| shift 修饰位 | `parse-keypress.js:272` | `shift: !!(modifiers & kittyModifiers.shift)`（shift=1） |
| useInput 透传 | `use-input.js:53` | `shift: keypress.shift` |
| render 开关 | `render.d.ts:90` | `kittyKeyboard?: KittyKeyboardOptions` |
| 自动检测 | `ink.js:824` | auto 模式发查询序列探终端支持 |
| 自动启用 | `ink.js:865` | `enableKittyProtocol(flags)` 发 `\x1b[>1u` |
| 自动清理 | `ink.js:930` | 卸载发 `\x1b[>N u` 还原 |

**结论**：Shift+Enter 发的 `\x1b[13;2u`，启用 Kitty 后被 ink 原生解析成 `{ name:'return', shift:true }`。**不需要自研 parser**——只传一个 render 选项，ink 全自动（检测→启用→卸载还原）。

### Alt+Enter 的真实支持情况（分层看）

`parse-keypress.js:414-419` 非 Kitty 路径原生识别 `\x1b\r`（ESC+CR）为 `{ name:'return', meta:true }`（注释 "meta+return on macOS"）。但"灵不灵"取决于**终端发不发**：

| 终端 | 按 Alt+Enter 发什么 | 能用 |
|---|---|---|
| macOS Terminal / iTerm2 | 发 `\x1b\r` | ✅ |
| Linux 现代终端（Alacritty/WezTerm/Kitty/GNOME） | 多数发 `\x1b\r` | ✅ |
| Windows Terminal | 截获为「全屏切换」快捷键，不发 | ❌ |
| Windows 经典 conhost（cmd/PowerShell） | 截获为「Alt+Enter 全屏」 | ❌ |

→ Alt+Enter 在 Windows 主流终端是摆设；但**多端适配**场景下 Mac/Linux 用户受益，故仍接入（零成本：一个 `||` 条件）。

## 3. 技术方案

### 3.1 启用 Kitty（`src/index.ts:129`）

render 第二参数加 `kittyKeyboard`：

```ts
render(
  React.createElement(App, { model, cwd: projectRoot, system, version }),
  { kittyKeyboard: { mode: 'auto', flags: ['disambiguateEscapeCodes'] } },
);
```

- `mode:'auto'`：终端支持才启用，不支持静默跳过（不误伤老终端）。
- `flags:['disambiguateEscapeCodes']`（=1）：最基础 flag，足以区分 Shift+Enter 与 Enter。无需 reportEventTypes/reportAssociatedText（YAGNI）。
- ink 在 unmount 时自动发还原序列，无需手动清理。

### 3.2 数据模型（`src/ui/input-bar.tsx`）

```
现: text: string                      纯末尾操作，无光标
改: text: string
    cursorIndex: number               线性 codepoint offset，[0..text.length]
```

- 所有编辑操作（插入/删除/换行/移动）都以 cursorIndex 为锚点，操作后同步推进/回退 cursorIndex。
- cursorIndex 是 **codepoint offset**（string index），非显示宽度。ink 的 `<Text>` 渲染本身用 string-width 处理中文/全角占 2 列，故无需自引 string-width 依赖。
- 已知限制：emoji 复合序列（ZWJ）cursor 可能偏移 → 列 P2，MVP 不做 grapheme。

### 3.3 换行触发（三键全接）

| 触发 | 判定 | 终端覆盖 |
|---|---|---|
| **Shift+Enter** | `key.return && key.shift` | Kitty：WT v1.22+ / iTerm2 / WezTerm / Ghostty / Kitty / Alacritty |
| **Alt+Enter** | `key.return && key.meta` | Mac/Linux 现代终端 |
| **`\`续行** | `key.return && !shift && !meta && text[cursorIndex-1]==='\\'` | **全平台**（纯应用层） |
| **Enter**（裸） | `key.return && !shift && !meta` | 提交 |

换行动作：在 cursorIndex 处插 `\n`，cursorIndex 移到新行首（=插入位置+1）。

### 3.4 `\`续行细节（抄 CC）

行尾打 `\` 再按 Enter → 删掉 `\` 插 `\n`。
- 判定：`text[cursorIndex-1] === '\\'`（cursor 前一字符是反斜杠）+ Enter 无修饰。
- 动作：`text.slice(0,cursorIndex-1) + '\n' + text.slice(cursorIndex)`，cursorIndex 留在新行首。
- 边界「想提交以 `\` 结尾的文本」：续行后光标到新空行，再按一次 Enter → 新行非 `\` 结尾 → 提交（此时 text 含 `\n` 但末段非 `\`，正常提交）。可接受。

### 3.5 多行渲染 + cursor 反白 + maxHeight

- 按 `\n` 拆 `displayed` 成 `lines[]`；cursorIndex 换算成 `(cursorRow, cursorCol)`。
- 第一行带 `❯` 提示符，后续行缩进对齐（`SYMBOLS.user` 占位空格）。
- cursor 反白：cursor 所在字符用 `<Text backgroundColor={T.muted} color={T.inverseText}>{char}</Text>`；cursor 在行尾则反白一个空格。行内其余字符正常 `<Text>`。ink 按字符显示宽度布局，中文自动占 2 格。
- **maxHeight = 6 行**（抄 opencode `max(6, 终端高/3)` 下限）：总行数超 6 时只显示 cursor 所在窗口，`startRow = clamp(cursorRow-5, 0, total-6)`，防止长输入顶掉对话历史区。

### 3.6 键位全表

| 键 | 行为 |
|---|---|
| Shift+Enter / Alt+Enter | cursor 处插 `\n`，cursor 到新行首 |
| `\`+Enter | 删 `\` 插 `\n` |
| Enter | 提交（trim 后为空不提交） |
| ← | cursorIndex-1（行首则到上行末，跨行） |
| → | cursorIndex+1（行尾则到下行首，跨行） |
| ↑ | **首行**→历史上一条；否则 cursor 上移一行同列 |
| ↓ | **末行**→历史下一条；否则 cursor 下移一行同列 |
| Home | cursor 到当前行首 |
| End | cursor 到当前行尾 |
| Backspace | 删 cursor 前一字符（行首删 `\n` → 合并到上行末） |
| Delete | 删 cursor 字符（行尾删 `\n` → 合并下行到本行） |

**上下键门控**（抄 opencode）解决「上下键被历史独占」冲突：只有 cursor 贴在首/末行时才翻历史，否则跨行移动光标。`isCursorOnFirstLine`/`isCursorOnLastLine` 由 cursorRow 判定。

### 3.7 picker 与多行

picker（斜杠补全）只在**单行 `/` 开头无空格**时出现。多行（含 `\n`）自动关闭：判定加 `&& !text.includes('\n')`。picker 可见时 Enter 执行命令（picker 可见 ⟹ 单行，不冲突）。

## 4. 降级与多端覆盖矩阵

| 终端 | Shift+Enter | Alt+Enter | `\`续行 | 粘贴 |
|---|---|---|---|---|
| Windows Terminal v1.22+ | ✅ Kitty | ❌ 全屏键截获 | ✅ | ✅ |
| iTerm2 / WezTerm / Ghostty / Kitty / Alacritty | ✅ Kitty | ✅ | ✅ | ✅ |
| 经典 cmd / conhost | ❌ | ❌ | ✅ | ✅ |

三条换行路径任一可用即可多行；最差环境（经典控制台）仍有 `\`续行 + 粘贴兜底。零配置：不要求用户改终端键位绑定（违反 §1.1 配置方向）。

## 5. YAGNI（不做）

- ❌ 粘贴折叠 `[Pasted ~N lines]`（opencode）—— maxHeight 已兜底，defer P2。
- ❌ grapheme 级光标（emoji ZWJ）—— 罕见，defer P2。
- ❌ reportEventTypes / reportAssociatedText 等 Kitty 高级 flag —— disambiguateEscapeCodes 已够。
- ❌ 续行符 `\` 之外的智能换行识别。

## 6. 测试策略（`tests/ui/input-bar.test.tsx`）

范式不变：`ink-testing-library` + fake timers + `advanceTimersByTimeAsync(0)`。`parseKeypress` 是纯字节解析，**测试不依赖运行时是否启用 Kitty**——直接 stdin.write 序列即可：

- Shift+Enter：`stdin.write('\x1b[13;2u')`（Kitty CSI u）→ `{return, shift:true}`
- Alt+Enter：`stdin.write('\x1b\r')` → `{return, meta:true}`
- Enter：`stdin.write('\r')`
- ↑：`stdin.write('\x1b[A')`

新增用例：
1. Shift+Enter / Alt+Enter 在 cursor 处插 `\n`
2. `\`+Enter 续行（删 `\` 插 `\n`）+ 边界（续行后再 Enter 提交）
3. ←/→ 移动 cursorIndex（中间插入字符落到正确位置）
4. ↑ 门控：首行翻历史、中间行 cursor 上移
5. ↓ 门控：末行翻历史、中间行 cursor 下移
6. 多行 Enter 提交（含 `\n` 的文本整段提交）
7. Backspace 跨行合并（行首删 `\n`）
8. 空白多行不提交

现有用例（显示/Enter 提交/空不提交/↑历史）保留，但「↑调出历史」需注意：单行时首行↑即翻历史，行为不变，应仍绿。
