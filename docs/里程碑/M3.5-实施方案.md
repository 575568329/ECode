## 二、选型理由(精简,详析留三件套)

### 2.1 UI:Ink + React(官方,不 fork)

- **对标 CCode**(Node 20 + Ink 6 + React 19),同栈有现成参照。
- **OpenTUI 出局**:OpenTUI 核心是 **Zig native**,Node 下需 **Node 26+ 的 `--experimental-ffi`**(实验特性)。ECode 用 Node 22,走不通;opencode 选 Bun 正是被此架构逼的(详见 `M3.5-CLI工具调研对比.md` §3.3,已同步更正:koffi→Zig native + 运行时 FFI)。
- **已知风险**:`ink-multiline-input` 不成熟(L2 单行规避)、ink 默认实现可能需打补丁。**两段式兜底**:阶段 ① UI 无关,UI 层选错能换。

### 2.2 权限:档 A(CCode 式极简)

- **参考依据**:CCode 同栈实践,权限 + CLAUDE.md 合计 **3-4 天**可落地(实测估计)。
- **策略**:工具自声明 `dangerous` 二元标记 + 单一弹窗 + allow 白名单(仅 allow)+ session 级 yes-always(内存)。
- **不做**(留演进):四档模式(default/acceptEdits/plan/bypass)、plan 模式、deny/ask 规则、per-arg 细粒度审批、危险命令识别(`rm -rf` 和 `ls` 一样弹窗)、yes-always 持久化、读 `.claude/settings.json`。
- **为什么不真兼容(档 B/C)**:用户选档 A。ECode 是独立开源产品,**自建 `.ecode/` 配置主权 + CLAUDE.md fallback 已满足"兼容"诉求**;真兼容 `.claude/` 格式留作后续演进(见 §十)。

### 2.3 CLAUDE.md:4 层 fallback 读取

- **直接读 `CLAUDE.md`**(满足"兼容 claude.md")。
- 4 层路径(参考 CCode `instructions-loader.ts`)。
- `<instructions source level>` 标签注入 system prompt。
- **不做** @import 递归、不做子目录递归、不读 `CLAUDE.local.md`(YAGNI,后续可加)。

### 2.4 两段式骨架

阶段 ①(agent core 事件化,UI 无关)+ 阶段 ②(Ink REPL 外壳)**正交**。阶段 ① 做完,现有 one-shot `ecode "任务"` 立刻享受逐字流式,独立交付价值;阶段 ② 才上 Ink。UI 选错,agent core 不返工。

type AgentEvent =

## 四、权限系统(档 A · CCode 式)详解

> **设计原则**:CCode 证明了"dangerous 二元 + 单弹窗 + allow 白名单"足够跑。ECode 已有声明式 tool registry(M3 P1),加 `dangerous` 字段成本极低。

### 4.1 dangerous 二元标记

**改造**:`src/tools/types.ts` 的 `ToolDefinition` 加字段:

```ts
export interface ToolDefinition {
  name: string;
  description: string;
  parameters: { type: 'object'; properties: Record<string, unknown>; required?: string[] };
  dangerous?: boolean;  // ← 新增。true = 执行前需权限审批
}
```

**各工具声明**(参考 CCode `src/tools/core/*.ts`):

| 工具 | dangerous | 参考 CCode |
|------|:---------:|-----------|
| bash | ✅ true | `bash.ts:17` |
| write_file | ✅ true | `write-file.ts:9` |
| edit_file | ✅ true | `edit-file.ts:8` |
| git | ✅ true | `git.ts:49` |
| read_file | ❌ false | `read-file.ts:10` |
| grep / glob | ❌ false | `grep.ts:11` / `glob.ts:7` |

> ECode 现有工具集按上表标 dangerous(实际工具名以 `src/tools/` 现状为准,实施时核对)。

### 4.2 权限判定流程(单一插入点)

**插入点**:`src/agent.ts:248`(`executeTool` 调用前)。参考 CCode `src/core/tool-pipeline.ts:92-116`:

```
对每个 toolUseBlock:
  needsPermission = toolDef.dangerous && !isPipeAutoYes
    ├─ 否 → 直接 executeTool
    └─ 是 → 三段式判定(CCode useChat.ts:465-475):
        ① allow 白名单命中(.ecode/settings.local.json)→ 放行
        ② session yes-always Set 命中 → 放行
        ③ 都没命中 → yield {type:'permission_request', resolve}
            ├─ UI 调 resolve('allow') → 放行
            ├─ UI 调 resolve('allow_always') → 放行 + 加入 session Set(内存)
            └─ UI 调 resolve('deny') → 不执行,回喂 isError tool_result
```

**deny 回喂 LLM**(参考 CCode `tool-pipeline.ts:110-113`):

```ts
// 复用现有 ECodeToolResultOutput 的 error variant
const output: ECodeToolResultOutput = { type: 'error', value: 'rejected by user' };
messages.push({ role: 'user', content: [{ type: 'tool_result', tool_use_id: toolUse.id, output }] });
```

LLM 下一轮看到"这个工具被用户拒绝",自行调整策略。

### 4.3 allow 白名单配置

**文件**:`.ecode/settings.local.json`(ECode 已用 `.ecode/` 放 sessions/config,一致)。默认模板(参考 CCode `initializer.ts:28-33`):

```json
{ "permissions": { "allow": [] } }
```

**规则格式样例**(参考 CCode `permissions.ts:45-62` `parseRule`,底层 3 种匹配逻辑:精确/前缀通配/正则):
- `Bash(*)` / `Read(*)` — 工具级通配
- `bash` — 精确内部名
- `mcp__*` — MCP 前缀通配(未来 MCP 用)
- `mcp__server__tool` — 精确 MCP

> **档 A 只有 allow,没有 deny/ask**(CCode 同款简化)。

### 4.4 session 级 yes-always(内存,不持久化)

**档 A 的明确取舍**(参考 CCode `useChat.ts:203-214`):选 "Yes, and don't ask again" 只加入**内存 `Set<string>`**,重启失效。想永久允许须手编 `.ecode/settings.local.json`。

> 持久化写回 settings 是档 B 的内容,留演进(§十)。

### 4.5 工作区信任(可选,低成本)

启动时检测 cwd 是否为敏感目录(主目录 `/`、根目录),若是则警告/拒绝(参考 CCode `workspace-trust.ts:14-61`)。防误在 `$HOME` 跑 agent 改一堆文件。

### 4.6 Pipe 模式的 `-y`(可选)

现状 `src/index.ts` 是 `ecode "任务"`。若加 Pipe 模式(`ecode -p "..." -y`),dangerous 工具全自动放行(参考 CCode `bin/ccli.ts:47`)。**MVP 可不做**,REPL 交互审批即可。

## 五、CLAUDE.md 兼容(4 层 fallback)详解

### 5.1 读取(新建 `src/instructions-loader.ts`)

参考 CCode `src/config/instructions-loader.ts:72-116`(`CANDIDATE_NAMES = ['CCODE.md', 'CLAUDE.md']`,同层前者优先)。ECode 对应 `['ECODE.md', 'CLAUDE.md']`——**已定:要 `ECODE.md` 品牌别名**(对齐 CCode `CCODE.md` 模式)。4 层路径,全局去重:

| 层 | 路径(同层 ECODE.md 优先 → CLAUDE.md fallback) | 说明 |
|----|------|------|
| 全局 | `~/.ecode/ECODE.md` → `~/.claude/CLAUDE.md` | 用户全局指令 |
| 项目根 | `<gitRoot>/ECODE.md` → `<gitRoot>/CLAUDE.md` | 项目级(入库) |
| 配置目录 | `<gitRoot>/.ecode/ECODE.md` → `<gitRoot>/.claude/CLAUDE.md` | 项目配置目录 |
| cwd | `<cwd>/ECODE.md` → `<cwd>/CLAUDE.md`(仅当 cwd ≠ gitRoot) | 当前目录 |

- gitRoot 通过 `git rev-parse --show-toplevel` 拿(3s 超时,失败降级到 cwd)。
- **同层 fallback 语义**:同层先找 `ECODE.md`,没有则 `CLAUDE.md`(ECode 品牌主权 + 兼容用户既有 Claude 文件)。

### 5.2 注入(`src/system-prompt.ts:32`)

`buildSystemPrompt()` 加一层 CLAUDE.md 拼装(参考 CCode `instructions-loader.ts:150-166`):

```
<instructions source="/abs/path" level="project">
  ...CLAUDE.md 内容...
</instructions>
```

- 单文件超 N 行截断,末尾提示「用 read_file 读完整: <path>」(让 LLM 按需拉,参考 CCode `MAX_INSTRUCTION_LINES`)。
- bootstrap 启动时加载一次,会话内不热更新。
- 空文件 / 读取失败静默跳过,不阻塞启动。

### 5.3 不做的(YAGNI)

- ❌ @import 递归(CCode 也不做)
- ❌ 子目录递归 CLAUDE.md(CCode 一期不做)
- ❌ `CLAUDE.local.md`(私有项目指令,后续可加)
- ❌ `.claude/rules/*.md` 条件规则(Claude 本尊特性,过重)

## 六、关键技术原理(精简,详析留「方案解析」文档)

1. **中断保配对** ⚠️:中断发生在「工具执行后、result 回传前」时,为已 `tool_call_start` 未回传的 tool_use **合成 `tool_result`**(isError:"用户中断")再终止——防 API 400(配对断裂)。
2. **流式 markdown**:流式期渲染纯文本(避免不完整语法),`stop` 事件后 full markdown render。
3. **AgentEvent 判别联合**:exhaustive switch,新增事件类型编译期强制处理。
4. **Windows 输入**:`process.stdin.prependListener('data')` 拦原始字节处理 Ctrl+C/Esc(参考 CCode),ink `useInput` 实测。
5. **渐进式 protocol**:`AgentEvent ↔ NDJSON` 序列化函数预留,未来切 client-server 零成本(仿 codex)。
