## 二、format-transcript 新逻辑（核心）

遍历 `completedMessages`，**按 user 提问分组**：

| 消息类型 | 处理 |
|---------|------|
| `user` | **新分组锚点**：`━━━━━━━━ 对话 N ━━━━━━━━` + `❯ 提问首行摘要`（醒目分隔） |
| `tool_group` | 展开各工具完整内容（归入当前组） |
| `tool`（`read_file`/`glob`/带 omitted 的 `bash`/`grep`/`write_file`） | 完整 content（归入当前组） |
| `assistant` / `edit_file` diff / 单行完整工具 / `warning` / `error` | **跳过**（主界面已完整显示） |

规则：
- **只保留有折叠工具的分组**——某轮若无被折叠工具（都完整显示了），整轮跳过（精简，避免空锚点）。
- **空结果 → 空串**（调用方据此不进 pager，提示「暂无折叠内容」）。
- 分组编号 N = 该 user 在「有折叠工具的轮次」中的出现序号（1, 2, 3…）。

效果：less = 「按对话分组的、被折叠工具的完整细节」，明显区分哪次对话，内容量大降。

## 三、C 修法（双❯）

根因：`openPager` `setInPager(true)` 后**同步**紧跟 `\x1b[?1049h`——React state 异步，setInPager(true) 的重绘（InputBar 卸载）未完成就保存了 alternate 快照，快照含旧 `❯`。退出 1049l 恢复旧❯ + ink 重绘新❯ = 双❯。

修法（已实施）：`setInPager(true)` 后 `await` 一帧（`setTimeout(0)`）等 ink 重绘落地（InputBar 卸载）再 `\x1b[?1049h`——快照即不含 `❯`，退出恢复 + 重绘只剩单个 `❯`。

> 双❯涉及 ink/alternate 实际行为，ink-testing-library 不模拟 alternate 快照、无法单测；代码改 + 不破坏现有 3 个 pager 测试，**真机确认留 #40**。
