# Esc/Ctrl+C 横向分工 — 详设

> 任务 #10（E-Esc/Ctrl+C 横向分工）。用户原话：「esc和ctrl+c的处理一下」。
> 本文档列三方案，**推荐方案 A（已实施）**，B/C 备选——明天审核若不认可 A 的 breaking 影响，可切 B/C。

---

## 一、现状（`src/ui/app.tsx:112-130`）

| 键 | 行为 |
|----|------|
| Esc | `isRunning && !pendingPermission && !resumeOpen` → `abort` 中断流；其余态无效 |
| Ctrl+C 单击 | 更新 `lastCtrlCRef`；若 `isRunning` → `abort` 中断 |
| Ctrl+C 双击（2s 内） | `process.exit(0)` |

**问题**：Esc 与 Ctrl+C 单击在 streaming 时**都能中断**——职责重叠，用户不确定按哪个；「中断」没有唯一入口。这正是「横向分工」要解决的：让两个键各司其职、语义不重叠。

---

## 二、三方案

### 方案 A（推荐，已实施）：彻底分工

- **Esc = 软中断 / 取消（专职）**：streaming → `abort`；modal（permission/resume/picker）内由各组件 `useInput` 自处理（Esc → deny / 取消 / 关 picker），App 层不抢。
- **Ctrl+C = 硬退出（专职）**：双击（2s 内）`process.exit`；单击**只进退出窗口**（StatusBar 提示「press ctrl+c again to exit」），**不再中断流**。
- 配套：phase 优先级修订为 `exit-window > streaming`——让 streaming 态按 Ctrl+C 单击也能看到「再按退出」提示（否则 streaming 时 phase 仍是 streaming，单击 Ctrl+C 无任何可见反馈）。

**⚠️ breaking**：streaming 时 Ctrl+C 单击不再中断（旧行为是中断）。影响：习惯用 Ctrl+C 中断的用户需改用 Esc。
**引导（已在）**：InputBar disabled 文案 `esc to interrupt` + StatusBar `press ctrl+c again to exit`。
**回退**：恢复 `app.tsx` Ctrl+C 分支的 `if (api.isRunning) api.abort();` 一行即恢复旧行为。

**为什么 breaking 可接受**：InputBar disabled 态已持续显示 `esc to interrupt`，用户已被引导用 Esc 中断；Ctrl+C 中断路径实际使用率低。分工后语义可预测（Esc 永远=停，Ctrl+C 永远=走），学习成本一次性。

### 方案 B（备选，温和不 breaking）

保持 Ctrl+C 单击中断，仅文档化「Esc = 轻中断 / Ctrl+C = 重（中断 + 可退出）」语义，不改代码。
**缺点**：重叠仍在，未真正分工——「处理一下」流于文档。

### 方案 C（备选，idle 增强）

在 B 基础上，idle 时 Esc 清空输入框（对齐 shell Ctrl+C 清行习惯）。
**代价**：需把 InputBar 的 `text` state 提升到 App，或加 `onClear` 回调——改动中等，且 idle Esc 清空与「Esc=中断」语义又添一层。

---

## 三、方案 A 行为矩阵

| 场景 | Esc | Ctrl+C 单击 | Ctrl+C 双击 |
|------|-----|------------|------------|
| streaming | abort 中断 | 进退出窗口（**不中断**） | exit |
| idle | 无（modal 内各自处理） | 进退出窗口 | exit |
| pendingPermission | PermissionDialog → deny | 进退出窗口 | exit |
| resumeOpen | SessionPicker → 取消 | 进退出窗口 | exit |
| InputBar picker 开 | 关 picker | 进退出窗口 | exit |
| inPager | 让位 less | 让位 less | 让位 less |

> modal（permission/resume/picker）内 Esc 由组件自身 `useInput` 处理；App 全局 useInput 的 Esc 分支有 `!pendingPermission && !resumeOpen` 守卫，modal 期间不触发。Ctrl+C 无此守卫——任意态双击都能退出（一致：Ctrl+C 永远=退出语义）。

---

## 四、改动清单（`src/ui/app.tsx`）

1. **useInput Ctrl+C 分支**：删除 `if (api.isRunning) api.abort();`（中断专职交给 Esc）。
2. **phase 优先级**：`exit-window` 提到 `streaming` 之前：
   ```ts
   const phase = api.pendingPermission
     ? 'permission'
     : Date.now() - lastCtrlCRef.current < DOUBLE_CTRL_C_MS
       ? 'exit-window'   // Ctrl+C 退出窗口优先（含 streaming）：单击后无论 running 都提示「再按退出」
       : api.isRunning
         ? 'streaming'
         : 'idle';
   ```
