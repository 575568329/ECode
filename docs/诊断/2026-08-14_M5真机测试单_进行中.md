## 准备

### 0.1 备份 + 配小窗口（让压缩容易触发，免灌 20 万 token）
```bash
cp ~/.ecode/config.json ~/.ecode/config.json.bak
```
编辑 `~/.ecode/config.json`，在当前 provider（如 `default`）加 `contextWindow`：
```jsonc
"default": {
  "type": "anthropic",
  "baseURL": "...",
  "apiKey": "...",
  "models": ["glm-5.2"],
  "contextWindow": 30000   // ← 加这行，触发阈值 = 30000×0.9-20000 = 7000，很容易超
}
```
> 测完恢复：`cp ~/.ecode/config.json.bak ~/.ecode/config.json`

### 0.2 看日志的位置
- 对话历史：`~/.ecode/sessions/<sessionId>.jsonl`
- 运行 trace：`<cwd>/.ecode/logs/<sessionId>.jsonl`（grep `compaction`/`CONTEXT_TOO_LONG`）

### 0.3 启动方式
- TUI 交互：`npm run dev`
- argv 单次：`npm run dev -- "你的问题"`

## A. 压缩触发

### T1. 阈值自动摘要（pressure 触发）
**操作**：TUI 模式连续多轮对话（每轮让 LLM 读大文件或输出长文本），累积到超 7000 token。
 quickest：让 LLM `读 src/core/loop.ts 并逐行讲解`（loop.ts 本身 ~10k token），几轮就超。
**预期**：某轮开始前，StatusBar/输出出现 `⚠ 上下文超限，已压缩对话后重试`（或 TUI 的 onCompacted 重建 committed）。
**通过**：① 看到压缩提示；② 压缩后 LLM 仍能续答（没崩）；③ session jsonl 末尾出现 `{"compact_boundary":true,...}` 行。
**失败排查**：`.ecode/logs` grep `compaction`；若没触发——估算偏低（chars/4 偏低 10-30%），再多灌几轮；若崩——看是否 CONTEXT_TOO_LONG fatal（P0-2 没修好）。

### T2. 连续两次压缩不暴涨（★ P0-1 验证）
**操作**：T1 后继续多轮，触发**第二次**压缩。
**预期**：第二次压缩后，对话仍能正常进行（不会"越压越多"导致每轮都超）。
**通过**：第二次压缩后连续 2 轮不再立即触发压缩（说明投影真的缩小了，不是泄漏累加）。
**失败排查**：若每轮都压缩 → P0-1 索引翻译失败（`orchestrator.ts` 的 indexOf anchor 逻辑）。看 session jsonl 两个 boundary 的 `tailStartIndex` 是否合理（第二个应 > 第一个）。
> 这个 case 单测 `hook.test.ts`「连续两次压缩」已覆盖（白盒），真机是端到端确认。

### T3. 400 兜底可达（★ P0-2 验证）
**操作**：把 `contextWindow` 改更小（如 8000），单轮塞超大输入（直接粘贴 ~50k chars 文本进去）。
**预期**：LLM 返 400 context-too-long → ECode 自动压缩 → 重试成功（不 fatal 中断）。
**通过**：① 看到 `⚠ 上下文超限，已压缩对话后重试`；② 重试后正常回复（不是报错退出）。
**失败排查**：若直接报错退出（`✗ 上下文超限`）→ P0-2 没修好（loop catch 还在 fatal throw CONTEXT_TOO_LONG）。若压缩失败仍退出 → 看 `⚠ 上下文超限且压缩失败`（P1-4 break，说明 summarize 没压成功，看日志）。

## B. 命令

### T4. /compact（手动压缩）
**操作**：TUI 模式，几轮对话后输入 `/compact`。
**预期**：committed 区重建（旧消息收起，可继续对话）；session jsonl 追加 boundary。
**通过**：① `/compact` 不报错；② jsonl 末尾出现 boundary 行；③ 续问 LLM 仍知道之前话题（摘要生效）。
**失败排查**：若 `/compact` 无反应 → commands registry 注册（`registry.ts`）；若 boundary 没落盘 → P0-3（orchestrator history 注入）。

### T5. /cost（成本明细）
**操作**：TUI 模式，对话几轮后 `/cost`。
**预期**：systemMsgs 显示
```
本轮 token：input X / output Y / cache_read Z / cache_creation W
会话累计成本：¥0.xxxx（或 成本未知）
```
**通过**：① 显示四维 token；② 成本有值（glm-5.2 已收录）或"成本未知"（glm-5.3 等未收录）。
**失败排查**：若全 0 → onUsage 没收到（provider usage 翻译）；若成本一直未知 → `pricing.ts` 表 + `lookupPricing`。

### T6. /model 切小窗口检测
**操作**：TUI 模式，积累一定对话后 `/model` → 选一个窗口小的模型（或同模型，因 config contextWindow 小）。
**预期**：若当前对话超新窗口 → 顶部 banner：
```
当前对话（约 Xk tokens）超出 <model> 窗口（30k）。建议 /compact 压缩后继续（注意：压缩有损...），或 /clear 起新会话。
```
**通过**：超限时 banner 出现；不超时无 banner（或清 banner）。
**失败排查**：banner 没出 → `checkModelWindow`（TuiApp.tsx）+ `resolveContextWindow`；banner 误报 → 估算不准。

### T7. restore 长历史不立即压缩（★ 投影派核心）
**操作**：T2 压缩过的 session → 新会话 `/history` → 选那个 session 恢复 → 立即问个简单问题。
**预期**：恢复后 UI 显示完整历史（含压缩前的旧消息）；问问题时不立即触发压缩（投影天然不超限）。
**通过**：① 恢复成功，UI 有内容；② 第一轮提问正常回复，没有"已压缩"提示。
**失败排查**：若恢复后立即压缩 → P0-3 的 restoreSession 是否用了 `restoreFull`（不是 `restore`）；若恢复内容缺消息 → `restoreFull` 读全量。

## C. 数据完整性

### T8. boundary 落盘（★ P0-3 验证）
**操作**：T1 或 T4 压缩后：
```bash
tail -5 ~/.ecode/sessions/<最新sessionId>.jsonl
```
**预期**：文件末尾有 `{"compact_boundary":true,"summary":"...","tailStartIndex":N,"preTokens":M}` 行；且它**前面**的原始消息还在（append-only 不删）。
**通过**：① 有 boundary 行；② boundary 前的旧消息行仍在；③ boundary 后是新消息。
**失败排查**：若没有 boundary 行 → orchestrator 没调 `history.appendCompactBoundary`（P0-3）；若旧消息被删 → 不是 append-only（bug）。

### T9. restoreFull vs restore
**操作**：对同一个含 boundary 的 session 文件，验证两个接口：
- `restoreFull`（恢复用）：返回含 boundary 的全量
- `restore`（M4 兼容）：返回过滤 boundary 的纯 Message
（这个已被 `history.test.ts` 单测覆盖，真机可跳过，除非怀疑 history 损坏）

## D. 速查：失败时看什么

| 症状 | 先看 |
|---|---|
| 没触发压缩 | `.ecode/logs` grep `compaction`；config contextWindow 是否生效；估算是否偏低（多灌几轮）|
| 压缩后崩/报错退出 | 是否 `✗ 上下文超限`（P0-2 fatal throw 没修）；`CONTEXT_TOO_LONG` 日志 |
| 每轮都压缩（不收敛）| P0-1 索引翻译；session jsonl 两个 boundary 的 tailStartIndex |
| /compact 无效 | commands registry；orchestrator history 注入 |
| 恢复后立即压缩 | restoreSession 是否 restoreFull（不是 restore）|
| 成本全 0/未知 | provider usage 翻译；pricing 表 + lookupPricing |
| boundary 没落盘 | orchestrator.appendCompactBoundary 调用链（P0-3）|
