## 1. 目标架构：client/server 反转

```
┌────────────────────────── daemon（宿主进程）──────────────────────────┐
│  runLoop（心脏，零改动）+ 全部 services 装配：                          │
│  Tool/Skill/MCP/Hooks·Plugin/压缩链/checkpoint/history（唯一写者）/     │
│  权限·沙箱执行/后台任务/子代理 + 事件总线 + 审批挂起队列 + 写仲裁        │
│  ProjectRegistry：path → ProjectHost（冷启动 acquire / 空闲回收）       │
└──────────────┬────────────────────────────────┬──────────────────────┘
        内存 channel（阶段1）            HTTP+SSE（阶段2+）
        ┌─────┴─────┐                    ┌─────┴─────┐
        │ TUI 客户端 │                    │ Web 客户端 │（M13；手机=同款）
        │ （Ink 壳） │                    │ React 页  │
        └───────────┘                    └───────────┘
```

**职责切分**：daemon 拥有一切状态与执行（会话、审批决策的挂起点、历史写入、命令展开）；客户端只剩渲染与输入（键位/主题/粘贴编辑留在客户端，TUI 本地偏好存客户端侧不进 daemon）。

**四条铁律**（三家殊途同归，本方案全程遵守）：

1. **协议即唯一契约，进程内不绕**——阶段 1 同进程直连也走协议语义（内存 channel 传纯数据事件，不共享对象引用）；codex `in_process.rs` 的哲学："transport-local but not protocol-free"。
2. **审批是请求不是事件+命令配对**——server→client 的可答帧（带稳定 id、可挂起、fail-closed、答案广播全端、重连重放 pending）；spike 已实测多标签收敛与断线恢复。
3. **插话语义协议化**——`TurnInputMode` 三态 + 返回值明确告知路由结果（M11 双时点插话升格为协议）。
4. **渐进次序**——先收口协议（不动进程），再拆进程，再加客户端；opencode 实证：先 worker 内嵌跑稳、两个月后才 daemon 化。

## 3. 阶段 1：协议收口（同进程直连）

### 3.1 协议数据结构（双枚举）

集中在新模块 `src/protocol/types.ts`（规范模型单向外指，禁反向依赖——codex「协议 crate 垃圾场」反例的教训）：

```ts
/** daemon → client 事件（全部纯数据可序列化，不携带函数/对象引用） */
type ProtocolEvent =
  | { type: 'delta'; seq; turnId; text }                    // ← loop onText
  | { type: 'item/started'; seq; itemId; kind: 'tool'; name }   // ← onToolStart
  | { type: 'item/completed'; seq; itemId; name; isError; summary } // ← onToolResult（summary=截断预览）
  | { type: 'usage'; seq; input; output; cache?; cost? }     // ← onUsage；cost 由宿主按其权威定价算好下发（审阅补：定价迁宿主后客户端算不了钱）
  | { type: 'turn/started' | 'turn/completed'; seq; turnId }
  | { type: 'thread/status'; seq; busy; waitingOn: 'approval' | 'userInput' | null; iter }
  | { type: 'approval/requested'; requestId; kind: ApprovalKind; tool; preview; decisions: ('once'|'always'|'reject')[] }
  | { type: 'approval/resolved'; requestId; decision }
  | { type: 'askUser/requested' | 'askUser/resolved'; requestId; questions }
  | { type: 'askSelect/requested' | 'askSelect/resolved'; requestId; title; options: string[] } // 通用单选可答帧（skill 蒸馏确认/S-P7/MCP 批准，审阅补）
  | { type: 'interjection/enqueued' | 'interjection/injected'; text }
  | { type: 'queue/snapshot'; items: string[] }
  | { type: 'notice'; level; text }                          // ← 告警中心
  | { type: 'systemMsg'; seq; text }                         // 输入框上方命令反馈（read-only 拒绝提示/hook systemMessage 等——与 notice 双通道区分，审阅补）
  | { type: 'subagent/progress'; agents: SubagentStatus[] }
  | { type: 'todo/snapshot'; todos }
  | { type: 'warn'; text }                                   // ← onWarn
  | { type: 'error'; seq; message; code? }                   // ← fatal → ErrorBanner（审阅补：原枚举缺失）
  | { type: 'activity'; seq; state; text?; retrying?: boolean } // ← ActivityBar 文本与重试态（loop 重试文案，审阅补）
  | { type: 'compacting' | 'compacted' | 'compactFailed'; seq; detail? } // ← 压缩三态提示（审阅补）
  | { type: 'config/changed'; seq; config: ConfigView }      // /model·/config·/setup 后客户端刷新（config 权威在宿主，审阅补）
  | { type: 'mcp/status'; seq; servers: McpServerStatus[] }  // MCP 实时状态（StatusBar 与面板数据源，审阅补）

/** client → daemon 命令（提交型，返回结果或回执） */
type ProtocolCommand =
  | { op: 'prompt'; text: string; mode: 'StartOrSteer' | 'StartIfIdle' | { Steer: { expectedTurnId } }
    ; images?: ImagePayload[] }        // → { routed: 'Started'|'Steered'|'Queued'|'Rejected' }
  | { op: 'approval/respond'; requestId; decision: 'once'|'always'|'reject' }
  | { op: 'askUser/respond'; requestId; answers }
  | { op: 'askSelect/respond'; requestId; choice: string | null }
  | { op: 'interrupt' } | { op: 'interjection/clear' }
  | { op: 'command/exec'; name; args? }   // 斜杠命令 host 化（见 3.6）
  | { op: 'session/list' } | { op: 'session/read'; sessionId; beforeSeq?; limit? }
  | { op: 'session/restore'; sessionId } | { op: 'session/clear' } // restore=宿主状态切换；clear 动 messagesRef+skill hooks，非纯 UI（审阅订正归属）
  | { op: 'rewind/list' } | { op: 'rewind/exec'; target }    // RewindPanel 数据与执行（审阅补）
  | { op: 'panel/data'; panel: 'skill'|'mcp'|'plugin'|'doctor' } // 面板数据出口，宿主下发前过脱敏（审阅补）
  | { op: 'model/set'; provider; model } | { op: 'sandbox/set'; mode }
  | { op: 'config/get' | 'config/patch'; ... }
```

设计约束：**seq 会话级单调**（顺序/去重/分页游标三用）；**瞬态事件（delta/queue 快照）不落史，整条消息/tool_result 带 seq 落史**（快照+增量二分，spike 验证）；**wire 对账字段（requestId/rpcId）绝不写进会话 JSONL**（harness 反例：时区/rpcId 渗 transcript）；**requestId 一律 `crypto.randomUUID()`**（阶段 2 暴露 HTTP 面，禁自增可猜 id——安全审阅补）；**approval 帧 preview 宿主侧生成并消毒、带帧级截断**（buildPreview/sanitizePreview 整体迁宿主，edit diff 分支加 4-8KB 上限，协议测试断言「帧内 preview 已消毒」）；**提权命令门槛**（`sandbox/set` 提档 full-access、`config/patch` 改安全位）宿主侧对提档动作仍发审批帧（有订阅者）或拒绝（无订阅者）；**类型归属**：SubagentStatus/ImagePayload/McpServerStatus 等协议引用的类型迁入 protocol/types.ts 定义（防 services↔protocol 环，架构审阅补）。

### 3.2 ClientContext（transport 抽象）

```ts
interface ClientTransport {
  send(cmd: ProtocolCommand): Promise<CommandResult>   // 上行
  onEvent(ev: ProtocolEvent): void                     // 下行订阅（多订阅者 fan-out）
  dispose(): void
}
// 阶段1 实现：InMemoryChannel（同一进程，协议语义）
// 阶段2 实现：HttpTransport（fetch + SSE），TuiApp 零改动换管道
```

TuiApp 全部数据访问收口到 ClientContext（opencode `TuiInput` 同款第一刀）。现有 `active.confirm/askUser/subagents/interjectQueue` 等 setState 驱动点改为事件消费；`submit/doConfirm/permissionAsker/桥` 改为发命令。

### 3.3 审批挂起化（confirm / ask_user / 权限 ask）

模型 = opencode `permission/index.ts` 的 Deferred + spike 验证形态：

- daemon 侧 `ApprovalBroker`：pending Map（requestId → Deferred）、**fail-closed**（无应答者/超时=拒绝）、`always` 级联放行同会话同类、`reject` 级联拒绝同会话全部 pending；
- loop 的 `opts.confirm` 改由 Broker 实现（工具执行停挂在 Deferred 上——替代现 TuiApp 的 queueConfirm 单槽+串行队列，串行语义保留在 daemon 侧）；
- askUserBridge / permissionAsker（模块级 setter 单例）撤销，同走 Broker；
- requestId 带**会话与来源归属**（harness apiproxy 全局认领反例：多端时防抢答错会话）。
- **分策略表（D6，安全审阅 P0 修订）**：Broker 按 `ApprovalKind` 分治——`tool-confirm`（bash/edit/write/MCP 副作用）可交互可 `--yes`；`sensitive`（敏感路径读取）**永远要求交互，无订阅者一律拒绝，`--yes` 不覆盖**（否则 argv 模式下 .env/id_rsa/config.json 的 fail-closed 被放开，密钥外泄面重开）；`mcp-permission`（扩展 hook 首次执行）`--yes` 下保持拒绝（第三方面不可控）。argv policy 参数只作用于 tool-confirm 类。
- **always 级联粒度矩阵（安全审阅 P1-6）**：现状 always 仅 MCP server 前缀维度（TuiApp confirmAlwaysRef）——Broker 保持该粒度不扩：**内置副作用工具（bash/write/edit）只提供 once/reject**，always 仅对 MCP server 前缀开放（比现状宽的任何扩展都要单独决策）。
- **UI 反馈不丢（资深审阅 P1-7）**：read-only 档 MCP 拒绝等宿主侧策略反馈经 `systemMsg` 事件下发（输入框上方提示位），不走告警中心。

### 3.4 插话/中断协议化

M11 的 `pollUserInput` 步间注入 + 插话队列 + 轮末兜底整体升格：`prompt.mode=StartOrSteer`（空闲起轮/忙时入插话队列=现行为）、`StartIfIdle`（忙时 Queued 排队）、`Steer{expectedTurnId}`（防竞态：仅指定轮在跑才插）。`interrupt` 映射现 AbortController 链（含子代理级联取消）。返回值 `routed` 让客户端明确知道输入去了哪。

### 3.5 会话接口粒度（harness 七动词裁剪）

daemon 内 SessionHandle：`followup / steer / inject / cancel / whenIdle / readLog / status`——客户端可调动词到此为止，UI 词汇零进入。

### 3.6 斜杠命令 host 化拆分

- **迁 daemon（RPC `command/exec`）**：动服务端状态的——/rewind /undo /compact /cost /model /sandbox /config /doctor /skill（展开）/history（恢复）/tasks 系；
- **留客户端**：纯 UI——清屏/主题/帮助/面板开合（/plugin /mcp 面板的**数据**走 RPC，开合留本地）；
- 迁移清单在实施 P4 时逐命令过一遍（开放问题 O-2）。

### 3.7 四桥实例化

`setSubagentBridge` / `setPermissionAsker` / `askUserBridge` / `taskRegistry` 四个模块级单例全部撤销：桥能力改为 ClientContext/SessionHandle 的实例字段（依赖注入）。TUI 单会话时代遗产在此还清；多项目并发（阶段 2）依赖此改造完成。

### 3.8 验收 G1

- 既有 1127 测试全绿（改造过程测试驱动：先给 TuiApp 测试换注入 ClientContext 的 fake transport，再动实现）；
- spike 的 8 组协议断言转正进 `tests/protocol/`（InMemoryChannel 直跑）；
- pty 真机清单逐项过：confirm 三态、ask_user 选项、插话（F2/Ctrl+U/Ctrl+C 不弃队列）、Alt+V 粘贴、Tab 沙箱切档、/rewind、子代理进度条、todo 折叠、中断后轮末续投。

## 4. 阶段 2：daemon 化

### 4.1 入口与进程模型

- `ecode serve`：常驻 daemon + 托管静态资源（M13 起）；`ecode-web` 注册为等价别名（npm 多 bin）。
- `ecode`（默认）：**优先私有 in-process 宿主**（单机体验与今天完全一致：一条命令、无端口、无鉴权）；检测到共享 daemon 注册文件时提示可附着（是否默认附着=开放问题 O-1）。
- serve 模式完全不初始化 Ink（非 TTY raw mode 崩溃，M12 调研 §6.1.1）。

### 4.2 多项目主机级

- `ProjectRegistry`：path → ProjectHost；项目列表 = 会话 meta.**cwd 反推**（零配置，§5 的 meta 加 cwd 成为本节前置）+ 显式注册（serve --add / Web 端添加，M13）。
- **acquire 三段式 resolver**（harness `agent-lookup.ts` 蓝本）：live 实例直接复用 → 冷恢复单飞去重（并发 acquire 只触发一次装配）→ 所有权栅栏（子代理/互斥拒绝）。
- **acquire 路径校验三件套（安全审阅 P1-5）**：loadDeps(cwd) 会加载项目级 ECODE.md/hooks/MCP——hooks 即命令执行面，恶意仓库 + cwd 曾入史 → serve 列表出现 → prompt 即静默执行其 hooks。故历史反推出的 cwd **首次拉起实例前必须发审批帧确认**（显式注册的除外）+ 路径存在性校验 + `realpath` 规范化（顺带防同目录多形态绕过互斥）。
- 冷启动语义：浏览项目/历史只读 JSONL **零实例**；`prompt` 才拉起 ProjectHost（loadDeps(cwd) 每项目独立：config 合并/ECODE.md/.ecodeignore/项目级 MCP/hooks）。
- 空闲回收：N 分钟无请求 dispose（杀后台任务、断 MCP、清桥）；**审批悬置不回收**（Q12）。

### 4.3 项目实例级互斥（单写者）

占用标记放会话同目录 `~/.ecode/sessions/`（用户级平铺，跨项目恢复同一会话也覆盖）：serve acquire 项目时占坑；TUI 恢复/打开该项目活跃会话时验坑，冲突双向提示「该项目正被 Web 端/终端使用」。跨进程防线，同会话并发由 queue/steer（Q10）管。

### 4.4 daemon 生命周期（opencode `cli/src/services/daemon.ts` 蓝本，~190 行）

注册文件 `~/.ecode/server.json`（id/version/url/pid，0600）；TUI/客户端启动轮询 `/api/health`（50ms×100）；版本失配杀旧起新；注册 id 每 10s 校验防脑裂（输了自杀）；杀前先鉴权再 kill（防 PID 复用误杀）。**ready 单行 JSON 契约**（orca 式）：`{type:'ready', schemaVersion, boundEndpoint, advertisedEndpoint}`——监听地址与对外宣告地址分离（`--advertise` 支持反代/Tailscale 场景）。

### 4.5 鉴权与安全位

- **daemon token（M12 即做，安全审阅 P0-2）**：无密码 loopback ≠ 进程隔离——本机任意进程（**含 ECode bash 工具产生的进程**）可连 SSE 看 pending 审批并代答（注入 → `curl 127.0.0.1/respond` 自我放行，审批防线整体旁路）。故 B7 起 daemon 启动即生成随机 token 写入 0600 的 server.json，**所有端点（除 health）强制携带**（Bearer/Basic 均可）；TUI 从注册文件读取；stdout 不打 token。零配置体验不变，per-client 会话过滤仍留 M13。
- **loopback 判定要点（安全审阅 P1-1）**：逐请求校验 `socket.remoteAddress`（127.0.0.1 / ::1 / ::ffff:127.0.0.1 白名单），**禁止**信任 X-Forwarded-For / X-Real-IP / Host 头（node:http 下 Host 伪造极易）；非 loopback 显式绑定 + 无密码 = **拒绝启动**（不是警告）；`--advertise` 只改宣告地址，daemon 本体仍绑 loopback。
- Basic Auth（env 密码）与 token 并存；公网引导反代 TLS（文档）。M13：配对码 per-device token、per-client 会话过滤（harness mux 全广播零过滤的反例）、initialize 能力协商。
- 互斥占坑文件用 `fs.open 'wx'`（O_EXCL）原子创建 + 0600（一并防 TOCTOU 与预置 symlink 覆写，安全审阅 P2-1）。

### 4.6 Windows 坑（文档化进 /doctor 与部署说明）

首次监听防火墙弹窗提示；不用 unix socket；graceful shutdown 不依赖 SIGUSR*（用 SIGINT/SIGTERM + 任务 dispose）；**文档写 IP 不写 localhost**（Node ≥17 解析 `::1` 而监听 `127.0.0.1` 直连失败）。

### 4.7 验收 G2

TUI 经 HttpTransport 行为与 G1 逐项一致；daemon 注册/健康/防脑裂/版本失配单测；两个客户端同时附着（TUI + curl SSE）事件一致、审批任一端可答另一端收敛；项目互斥双向提示实测。

## 附录 C：被否决的备选（论证纪律）

- **一步到位反转（M12 同时 daemon+TUI 重写+Web）**：三个大件同动，任何一出问题定位不了；opencode/codex 均渐进。

- **审批=事件+命令配对**：比请求式少挂起/超时/拒绝语义，多端一致性难做（三家一致用请求式）。
- **409 拒绝忙时会话**：与 M11 插话同构能力白白丢弃（Q10 拍板）。
