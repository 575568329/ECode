# 折叠组延迟冻结详设（工具折叠根治）

> 承接：`docs/20260806213000_工具折叠-详设.md` §八（原「纯函数 `collapseReadSearchGroups`」方案已否决，见第二节）。
> 范围：M3.5 工具折叠**根治**——连续只读工具合并成一个折叠摘要行（对标 CC `utils/collapseReadSearch.ts`）。
> 现状代码：`src/ui/reduce-agent-event.ts` / `src/ui/types.ts` / `src/ui/chat-view.tsx` / `src/ui/tool-panel.tsx` / `src/ui/format-transcript.ts`。
> **本文件为设计文档，审阅通过后 TDD 实施**（项目约定：先文档审阅，后 TDD）。

---

## 一、目标

连续的只读工具调用（如 9 个 read_file 探索代码库）在 UI 上**合并成一个折叠摘要行**（"Read 9 files"），减少视觉噪声；`Ctrl+O` 进 pager 仍可看每个工具的完整内容。

**合并范围**（用户已定）：`read_file` + `grep` + `glob` + bash 搜索类。

**破坏组（组结束）**：助手文本（`text_delta`）/ 非只读工具（edit/write/非搜索 bash）/ `completed` / `user` / `warning` / `error`。

---

## 二、为什么原 §八 纯函数方案不可行

原方案：纯函数 `collapseReadSearchGroups(messages: DisplayMessage[]): DisplayMessage[]`，在 **渲染层**（completedMessages 之后、`<Static>` 之前）合并。

**致命问题**：ink `<Static>` **append-only**（踩坑 [#009]）——每条 `tool_result` 进 `completedMessages` 后，`<Static>` **立即写 stdout 冻结**。渲染层事后把 "9 条 tool" 合并成 "1 条 tool_group"，`<Static>` 看不到（已逐条冻结输出）。CC 能事后合并是因为它**自绘渲染层可重绘**；ECode 用 ink Static 不能。

**结论**：合并必须在**进 Static 之前**完成 → 只能是 **reducer 层挂起 + 破坏时合并 flush**。

---

## 三、延迟冻结核心思想

```
只读工具完成（tool_result）
  ├─ 不进 completedMessages（Static）
  └─ 挂起 pendingReadSearch（动态区，实时显示折叠摘要 "· · · Read N files"）

组被破坏（text_delta / 非只读 tool / completed / user / warning / error）
  ├─ pendingReadSearch 合并成一条 tool_group
  ├─ flush 进 completedMessages（Static，冻结）
  └─ pendingReadSearch 清空
```

**关键**：Static 收到的是**已合并的单条**，append-only 无矛盾。动态区 `pendingReadSearch` 可变（实时更新计数）。

## 四、详细设计

### 4.1 只读工具判定（含 bash 搜索类识别）

新增纯函数模块 `src/ui/read-search-group.ts`（可单测）：

```ts
const READ_SEARCH_TOOLS = new Set(['read_file', 'grep', 'glob']);
const SEARCH_BASH_CMDS = new Set(['grep', 'rg', 'find', 'ls', 'fd', 'ag', 'cat']);

/** bash 命令是否搜索类：取首个 token 的 basename 匹配搜索命令集。
 *  /usr/bin/grep → grep；管道/复合命令保守判否（漏判=不合并，不破坏正确性）。 */
function isSearchBash(input?: Record<string, unknown>): boolean {
  const command = String(input?.command ?? '').trim();
  if (!command) return false;
  const firstToken = command.split(/\s+/)[0];
  const base = firstToken.split('/').pop() ?? firstToken;
  return SEARCH_BASH_CMDS.has(base);
}

/** 工具结果是否属于「只读可合并」组。 */
export function isReadSearchTool(name: string, input?: Record<string, unknown>): boolean {
  if (READ_SEARCH_TOOLS.has(name)) return true;
  if (name === 'bash') return isSearchBash(input);
  return false;
}

/** 合并摘要：按工具类型分组计数 → "Read 3 files · Searched 2 patterns · 1 glob"。 */
export function summarizeGroup(
  tools: { name: string }[],
): string {
  const counts = new Map<string, number>();
  for (const t of tools) counts.set(t.name, (counts.get(t.name) ?? 0) + 1);
  const parts: string[] = [];
  const r = counts.get('read_file'); if (r) parts.push(`Read ${r} file${r > 1 ? 's' : ''}`);
  const g = counts.get('grep');      if (g) parts.push(`Searched ${g} pattern${g > 1 ? 's' : ''}`);
  const gl = counts.get('glob');     if (gl) parts.push(`${gl} glob${gl > 1 ? 's' : ''}`);
  const b = counts.get('bash');      if (b) parts.push(`${b} search${b > 1 ? 'es' : ''}`);
  return parts.join(' · ');
}
```

### 4.3 reducer 事件处理（`src/ui/reduce-agent-event.ts`）

抽纯函数 `flushReadSearch`（可单测）：

```ts
/** 把挂起的只读组合并（多条）/ 直通（单条）后追加进 completedMessages，清空 pending。 */
function flushReadSearch(state: StreamState): Pick<StreamState, 'completedMessages' | 'pendingReadSearch'> {
  const pending = state.pendingReadSearch;
  if (pending.length === 0) {
    return { completedMessages: state.completedMessages, pendingReadSearch: [] };
  }
  // 单条：不合并，直接进 Static（避免 "Read 1 files" 尴尬文案）
  if (pending.length === 1) {
    return { completedMessages: [...state.completedMessages, pending[0]], pendingReadSearch: [] };
  }
  // 多条：合并成 tool_group
  const tools = pending
    .filter((m): m is Extract<DisplayMessage, { kind: 'tool' }> => m.kind === 'tool')
    .map((t) => ({ name: t.name, content: t.content, isError: t.isError, input: t.input }));
  const group: DisplayMessage = { kind: 'tool_group', id: nextId(), tools };
  return { completedMessages: [...state.completedMessages, group], pendingReadSearch: [] };
}
```

`tool_result` 分支：

```ts
case 'tool_result': {
  const activeTools = state.activeTools.filter((t) => t.id !== event.id);
  const fallbackInput = state.activeTools.find((t) => t.id === event.id)?.input;
  const msg: DisplayMessage = { kind: 'tool', id: nextId(), name: event.name, content: event.content, isError: event.isError, input: event.input ?? fallbackInput };

  if (isReadSearchTool(event.name, msg.input)) {
    // 只读 → 挂起 pendingReadSearch（不进 Static）
    return { ...state, activeTools, pendingReadSearch: [...state.pendingReadSearch, msg] };
  }
  // 非只读 → 先 flush 挂起组，再把这个工具进 Static
  const flushed = flushReadSearch(state);
  return { ...state, activeTools, completedMessages: [...flushed.completedMessages, msg], pendingReadSearch: flushed.pendingReadSearch };
}
```

**破坏时机**（都在处理前先 `flushReadSearch`，且仅当 pending 非空时才操作，避免高频 text_delta 无谓计算）：
- `text_delta`：`if (state.pendingReadSearch.length) { state = flushReadSearch(state); }` 再累加 streamingText
- `completed`：flush 后再落地 assistant
- `warning` / `error`：flush 后再追加系统消息

## 五、边界场景

| 场景 | 处理 |
|------|------|
| 单条只读工具 | 不合并，直通 Static（避免 "Read 1 files"）— `flushReadSearch` 单条分支 |
| 空 pending | flush 无操作 |
| 组内含错误 | `tool_group.isError = any`；摘要行用 error 色（InlineTool 的 isError） |
| bash 搜索识别漏判（管道/别名） | 保守判否 → 不合并，单独显示，**不破坏正确性** |
| resume 恢复历史 | `tool_group` 已是 DisplayMessage，messages-to-display 直接还原渲染，**无需改** |
| 挂起 → Static 交接闪烁 | 两者都是折叠摘要行，样式对齐；瞬时交接，真机验证 |

## 七、风险与决策

| # | 决策 / 风险 | 理由 / 对策 |
|---|------|------------|
| ① | 合并放 reducer 层（延迟冻结），非渲染层 | 渲染层事后合并在 `<Static>` append-only 下失效（§二） |
| ② | 单条不合并 | 避免 "Read 1 files" 尴尬；单条本就简洁 |
| ③ | bash 搜索识别用「首个 token basename 匹配」 | 简单可测；漏判=不合并（保守），不破坏正确性 |
| ④ | 挂起态动态区 muted 灰 + Static 亮 | 对标 CC 哲学：进行中低调、完成亮（见 CC 设计哲学对比文档） |
| ⑤ | 挂起 → Static 交接可能瞬时闪烁 | 两态样式对齐；真机验证，必要时给挂起态加过渡 |
