# ECode M3 工具与确认实施方案

> 日期：2026-08-13 · 状态：**草案待审阅**
> M1（心脏 + read_file/bash）、M2（Ink TUI 最小 Static）已完成。
> M3 扩展工具集（write_file/edit_file/ls/glob/grep）+ bash 安全 + ConfirmPrompt + .ecodeignore。
> 本文整合散在 MVP 详设 §2.3/§3.2/§5.3/§5.4/§6.4/§7 的 M3 设计，拍板 P0，排实施步骤。
> 标 ★ 的决策点已经拍板（§3）；审阅时若不认可再议。

---

## 1. 目标 & 验收

**目标**：Agent 获得「写文件 + 编辑 + 目录浏览 + 模式匹配 + 内容搜索」能力，副作用工具带 diff 确认，bash 有安全护栏。

**验收标准**：
- 5 个新工具（ls/glob/grep/write_file/edit_file）register 后心脏零改动跑通
- 只读四件套（read_file/ls/glob/grep）免确认、可并行
- 副作用工具（write_file/edit_file/bash）走 ConfirmPrompt：edit_file 显示 unified diff，write_file 显示新增片段，bash 显示命令
- bash 输出超 30KB 头尾各半中截；危险命令（`rm -rf /`/`sudo`/fork bomb/`curl|sh`）正则拦截直接 is_error
- `.ecodeignore`（gitignore 兼容）三工具共用，默认忽略 node_modules/.git/.env*/dist/build
- ConfirmPrompt 期间 Ctrl+C 取消该工具（不退出 Loop、不中断）

## 2. 范围

**M3 做**：
- 5 个新工具：`ls` / `glob` / `grep` / `write_file` / `edit_file`
- `bash` 安全补全：输出截断（30KB 头尾中截）+ 危险命令正则拦截
- `ConfirmPrompt.tsx`：副作用工具 y/n 确认 + diff 预览
- `services/ignore.ts`：`.ecodeignore`（gitignore 兼容）加载，ls/glob/grep 共用
- TUI 集成：ActiveState 加 confirm 字段 + TuiApp 传 confirm callback
- system prompt 补「四工具职责区分」（ls/glob/grep/read_file）

**M3 不做**（留后续）：
- §6.4「副作用工具连续失败 2 次强制确认」（D6 推迟，先做「每次副作用都确认」基线）
- bash 安全命令白名单（免确认 git status/npm test；YAGNI，烦了再加）
- grep 切 ripgrep（M3 纯 JS，留接口）
- ConfirmPrompt 的 `[v] 查看完整文件`（M3 超长 diff 直接全显 + 截断提示，不交互展开）
- OpenAI 协议 Provider（M4）
- **argv 单次模式的 confirm**（P1#6）：`cli/index.ts` 的 `runOnce` 不传 confirm，单次模式下副作用工具（write_file/edit_file/bash）**无确认直接执行**（非交互场景，脚本式，用户自负）。M3 只覆盖 REPL 的 confirm；如需 argv 也禁用副作用，后续加 `--allow-side-effects` 标志。

## 3. 决策结论（已拍板 ★）

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| **D1** | edit_file 替换语义 | **string_replace**：`{path, oldString, newString, replaceAll?}` | opencode 验证过；扁平 schema（§2.3 行 220 合规）；diff 库直接对 old/new 生成 unified diff |
| **D2** | diff 库 | **npm `diff`**（`createTwoFilesPatch`） | opencode 同款；一行生成 unified diff（`---/+++/@@`）；cli-highlight 着色 |
| **D3** | .ecodeignore 格式 | **gitignore 兼容**（用 `ignore` npm 包解析） | 用户零学习成本；标准 gitignore 语法 |
| **D4** | bash 危险命令 | **正则黑名单**（命中直接 is_error，不让 LLM 重试） | 详设 §2.3 行 225 已定；白名单会卡正常开发 |

| **D7** | glob `caseSensitiveMatch` | **固定 `true`**（修详设行 569 措辞冲突） | 跨 OS 一致（详设行 232 已定）；行 569「按需而定」与 232 冲突，统一为 true |

## 4. 工具接口设计（5 工具 schema，扁平化 §2.3 行 220）

> 全部 `type: object` + `properties` + `required`，无 oneOf/anyOf/$ref（GLM 兼容）。

### 4.1 ls（只读，免确认，可并行）

```jsonc
{
  "type": "object",
  "properties": {
    "path": { "type": "string", "description": "目录绝对或相对路径" },
    "depth": { "type": "integer", "minimum": 1, "maximum": 3, "default": 1, "description": "递归深度" },
    "all": { "type": "boolean", "default": false, "description": "是否含隐藏文件（. 开头）" }
  },
  "required": ["path"]
}
```

返回：每行 `name\t[type]\tsize\tmtime`（type: file/dir；不显示权限，Windows chmod 语义不同 §2.3 行 230）。`.ecodeignore` 过滤后。

### 4.2 glob（只读，免确认，可并行）

```jsonc
{
  "type": "object",
  "properties": {
    "pattern": { "type": "string", "description": "glob 模式，如 **/*.ts（正斜杠，跨平台）" },
    "path": { "type": "string", "default": "cwd", "description": "搜索根目录" }
  },
  "required": ["pattern"]
}
```

实现：`fast-glob` + **`caseSensitiveMatch: true`**（D7）+ `ignore: loadEcodeIgnore()`。返回：匹配路径列表（每行一个，超 500 截断 + 计数）。

### 4.3 grep（只读，免确认，可并行）

```jsonc
{
  "type": "object",
  "properties": {
    "pattern": { "type": "string", "description": "正则表达式" },
    "path": { "type": "string", "default": "cwd", "description": "搜索根目录" },
    "glob": { "type": "string", "description": "文件名过滤，如 *.ts（等同 -g）" }
  },
  "required": ["pattern"]
}
```

实现：`fast-glob`（取文件 + `.ecodeignore` 过滤）+ `RegExp` 匹配。返回：`path:line: 内容`（每匹配一行；超 100 匹配截断 + 计数）。**MVP 不支持 -A/-B/-C 上下文**（简化；LLM 可用 read_file 看上下文）。

### 4.4 write_file（副作用，串行，确认）

```jsonc
{
  "type": "object",
  "properties": {
    "path": { "type": "string", "description": "文件路径（新建或覆盖）" },
    "content": { "type": "string", "description": "完整文件内容" }
  },
  "required": ["path", "content"]
}
```

确认：显示新增内容片段（超 40 行截断 + `…（共 N 行，已截断）`，D4/§5.4 行 627）。原子写（先写 .tmp 再 rename，中断不留半截）。

### 4.5 edit_file（副作用，串行，确认）

```jsonc
{
  "type": "object",
  "properties": {
    "path": { "type": "string", "description": "文件路径（必须已存在）" },
    "oldString": { "type": "string", "description": "要替换的原文（必须唯一匹配，否则报错）" },
    "newString": { "type": "string", "description": "替换为的内容" },
    "replaceAll": { "type": "boolean", "default": false, "description": "true=替换所有匹配；false=仅首个（且必须唯一）" }
  },
  "required": ["path", "oldString", "newString"]
}
```

行为：
- `replaceAll:false` 且 oldString 在文件中出现 ≠ 1 次 → `is_error`（"oldString 必须唯一匹配，实际 N 处"）
- `replaceAll:true` → 替换全部
- 文件不存在 → `is_error`

确认：读原文件 → `diff.createTwoFilesPatch(path, path, old, new)` → unified diff（cli-highlight 着色，§5.4 行 626）。

**校验**（参考 opencode `edit.ts:127-135`）：
- `oldString === ''` → `is_error`（"oldString 不能为空"）
- `oldString === newString` → `is_error`（"oldString 与 newString 相同，无变更"）

**⚠ Windows 换行符归一化（P1#5，Windows 首要运行环境必踩）**：Windows 文件常是 CRLF（`\r\n`），LLM 给的 oldString/newString 多用 `\n` → `indexOf` 匹配失败误报「0 处」。实现必须：
- 读文件后检测换行符（`content.includes('\r\n')`）
- 把 oldString/newString 按文件实际换行符归一化（`\n` → `\r\n`）再匹配
- 参考 opencode `edit.ts:65-67` 的 `normalizeLineEndings`

## 5. bash 安全补全（§2.3 行 222-227）

M1 已做：超时 30s / cwd 约束 / 退出码非 0 正常返回。**M3 补**：

### 5.1 输出截断（行 224）

`bashMaxOutputBytes` 默认 30720（可配）。stdout+stderr 合计超限 → **头尾各 ~15KB + 中间标记**：

```
<head 15KB>
…（中间 N 字节已截断，需要完整用 read_file/grep，不要编造）…
<tail 15KB>
```

实现：`bash.ts` execute 后，`Buffer.byteLength(combined) > bashMaxOutputBytes` 时 slice 头尾 + 插标记。

### 5.2 危险命令正则拦截（行 225，D4）

命中直接返回 `is_error`（**不进 y/n，不让 LLM 重试**）。黑名单（M3 初始清单，可扩）：

```js
const DANGEROUS_PATTERNS = [
  /rm\s+-\w*r\w*f?\s+\/(\s|$)/,        // rm -rf /
  /rm\s+-\w*r\w*f?\s+--no-preserve-root/, // rm -rf --no-preserve-root
  /\bsudo\b/,                           // sudo（提权）
  />\s*\/dev\/sd[a-z]/,                 // 写裸盘
  /:\(\)\{\s*:\|\s*:&\s*\};:/,          // fork bomb :(){:|:&};:
  /\|\s*(sh|bash)\b/,                   // curl|sh
  /mkfs/,                               // 格式化
  /dd\s+.*of=\/dev\/disc/,              // dd 写盘
]
```

实现：`bash.ts` 入口 `if (DANGEROUS_PATTERNS.some(re => re.test(command)))` → `{content: '危险命令已拦截', is_error: true}`，不 spawn。

> ⚠️ **P1#4（架构修正）**：confirm 先于 execute（`loop.ts:302-307` 在 execute `:310` 之前），所以 REPL 里 bash 会**先走 y/n**（用户能拒绝），execute 的正则拦截是**兜底双保险**（即使用户误点 y，危险命令仍被拒）。「不进 y/n」措辞不成立——第 3 步（小切片，confirm 未接）时 execute 拦截独立生效（那时没 y/n）；第 4 步接 confirm 后，bash 命令必先过 y/n，execute 拦截兜底。**双保险**：y/n + execute 拦截。

> 黑名单不可能穷举（变形见 §11 风险），MVP 接受「正则粗筛 + 命中拒绝 + y/n 兜底」三层。建议正则收紧：`rm -rf /*` / `rm --recursive --force` / `| /bin/sh` / `| zsh` 等变形也加（P2#8）。

## 7. ConfirmPrompt + TUI 集成（D5）

### 7.0 展示规则总览（动态区 vs Static）

三类工具三种处理（核心：**动态区极简防触顶，Static 完整不怕长**）：

| 工具类型 | 动态区（当前轮，途中） | Static（commit 后，事后） |
|---|---|---|
| **只读**（read_file/ls/glob/grep） | ② 三行灰色 preview + Ctrl+O 展开（M2 机制） | 完整输出 |
| **副作用**（edit_file/write_file） | ② 只摘要（✓/✗，**无 diff**）；diff 走 confirm 弹窗（③，临时 y/n 后清除） | 完整 diff（标注文件名） |
| **bash** | ② 只摘要；命令走 confirm 弹窗（③） | 完整命令 + 输出 |

关键约束：
- **动态区不残留 diff/输出**：副作用工具的 diff 只在 confirm 弹窗临时显示（y/n 决策），y/n 后弹窗清除，动态区 ② 只留摘要（✓/✗）。防动态区膨胀触顶。
- **Static 完整展示**：read_file 完整输出 / edit_file 完整 diff（标注文件）/ bash 完整输出。Static 是 scrollback，不占动态区，不怕长。
- **diff 本地算**（`diff.createTwoFilesPatch` from `use.input`），零 LLM 调用、零额外轮次。
- **M2「当前轮可展开」不受影响**：只读工具动态区三行 + Ctrl+O 展开（M2 机制保留）；副作用工具的 diff 走弹窗/Static 独立通道，不占动态区展开位。

### 7.1 ActiveState 加 confirm 字段

`src/tui/types.ts` 的 `ActiveState`：

```ts
interface ActiveState {
  userInput: string
  tools: ActiveTool[]
  streamingText: string
  expandedTools: Set<string>
  /** 等待用户确认的副作用工具（非 null 时 ConfirmPrompt 渲染，loop 挂起） */
  confirm: ConfirmState | null
}

interface ConfirmState {
  use: ToolUseBlock
  /** 预览内容：edit_file=unified diff（着色 ANSI）；write_file=新增片段；bash=命令字符串 */
  preview: string
  /** resolve 用（onConfirm/onCancel 调它） */
  resolve: (ok: boolean) => void
}
```

> ⚠️ **P0#2**：`createActive()`（`types.ts`）必须同步加 `confirm: null`，否则 TS strict 报错（返回类型缺字段）。

### 7.2 TuiApp 传 confirm callback（P0#4 修复）

`TuiApp.submit` 的 `runLoop` 配置补 `confirm`：

```ts
confirm: async (use) => {
  // D5：callback 内部读原文件算 diff（不污染 Tool 接口）
  // P1#3：buildPreview 内部 catch（读不存在文件等异常不杀 Loop，返回 fallback preview）
  //   —— confirm 在 invokeTool 的 try/catch 外（loop.ts:302-307 在 :309 之前），
  //      不 catch 的话异常会逃逸到 runLoop 外层 → 整轮 Loop 中止。
  const preview = await buildPreview(use).catch(
    (e) => `⚠ 无法生成预览：${e instanceof Error ? e.message : String(e)}`,
  )
  return new Promise<boolean>((resolve) => {
    setActive((a) => ({ ...a, confirm: { use, preview, resolve } }))
  })
},
```

`buildPreview(use)`（策略 Map，非 if-else，呼应 AGENTS §1.3）：
- `edit_file`：读 `use.input.path` 原文件 → apply oldString/newString 得新 → `diff.createTwoFilesPatch` → cli-highlight 着色
- `write_file`：`use.input.content`（超 40 行截断 + 提示）
- `bash`：`use.input.command`（完整字符串）

### 7.3 ConfirmPrompt 渲染位置（动态区）

动态区顺序调整（confirm 期间 streamingText 为空，③ 让位）：

```
① userInput
② ToolGroupView（执行中的工具，含待确认的）
③ GrayStreaming（无 confirm 且有流式时）
  ConfirmPrompt（有 confirm 时，替代 ③ 位置）
④ UI（ActivityBar / 输入框 / 底行）
```

`ConfirmPrompt.tsx`：显示 `⚠ 执行 {use.name}? path/command` + preview（diff/片段/命令）+ `[y] 确认 [n] 取消`。`useInput` 监听 y/n/Ctrl+C：
- `y` → `confirm.resolve(true)` + `setActive(confirm=null)`
- `n` / Ctrl+C → `confirm.resolve(false)` + 清（loop 收到 false → `is_error: 用户取消`，§5.3 行 611）

> ⚠️ **P0#1（Ctrl+C 归属，必须先解）**：`useInterrupt`（TuiApp 全局 Ctrl+C → `abortRef.abort()` 中止整个 Loop）会和 ConfirmPrompt 的 Ctrl+C **同时触发**（Ink 7 多个 `useInput` 都收事件）。必须协调，否则「Ctrl+C 只取消该工具」做不到：
> - **方案**：`useInterrupt` 加 `isActive` 守卫（读 `active.confirm`，非 null 时**不 abort**），由 ConfirmPrompt 独占处理 Ctrl+C（只 `resolve(false)` 取消该工具）。
> - 实现：`useInterrupt` 的 onInterrupt 回调内判 `activeRef.current.confirm != null` → 跳过 abort；ConfirmPrompt 的 useInput 抓 Ctrl+C → resolve(false)。`activeRef` 用 ref 同步（避免 stale closure）。

> P2#11：confirm 期间，待确认工具在 ToolGroupView 显示为 `pending`（非 `running`），避免「工具在跑」+「等你确认」视觉歧义。需 `ActiveTool.status` 加 `'pending'` 值（types.ts），M3 可做或留小切片后。

### 7.4 Conversation 改（加 ConfirmPrompt 区）

```tsx
{active.confirm ? (
  <ConfirmPrompt
    state={active.confirm}
    onConfirm={() => { active.confirm.resolve(true); setActive(a => ({...a, confirm: null})) }}
    onCancel={() => { active.confirm.resolve(false); setActive(a => ({...a, confirm: null})) }}
  />
) : (
  active.streamingText !== '' && <GrayStreaming text={active.streamingText} />
)}
```

### 7.5 Static 最终组合（UI 样例）

commit 后，Static 按 LLM 输出顺序排列（`commit.ts` 的 `messagesToCommitted` 原序）：

```
❯ 读 foo.ts，把 oldFunc 改成 newFunc，跑测试     ← user

我先读一下 foo.ts。                               ← LLM 文本（Markdown）

● read_file  foo.ts  ✓                            ← 只读工具（完整输出）
  const x = oldFunc()
  const y = bar()

找到 oldFunc，开始改。                             ← LLM 文本

● edit_file  foo.ts  ✓                            ← 副作用（完整 diff，标注文件）
  - const x = oldFunc()
  + const x = newFunc()

跑测试确认。                                       ← LLM 文本

● bash  npm test  ✓                               ← bash（完整命令 + 输出）
  PASS  src/foo.test.ts
  Tests: 1 passed

全部完成，测试通过。                               ← LLM 文本
```

组合规则：按 `message.content` 原序（`user → text → tool → text → ...`），LLM 文本和工具分开按序排列，连续多个工具合并 `tool-group`。

Static 渲染 tool-group 时，按工具类型展示（`renderCommitted`）：
- `read_file`/`ls`/`glob`/`grep`：完整 `result.content`
- `edit_file`：`createTwoFilesPatch(use.input)` 的 unified diff（标注文件名 `edit_file  src/foo.ts`），**不要**「▸ 已更新 (30B)」摘要行
- `write_file`：`use.input.content`（新增内容）
- `bash`：完整命令 + `result.content`（输出）

diff 本地算（零 LLM）：edit_file 的 diff 从 `use.input`（oldString/newString）调 `diff.createTwoFilesPatch` 生成，纯字符串处理，不调 LLM、不增轮次。

## 11. 风险 & 开放问题

| 风险 | 影响 | 缓解 |
|---|---|---|
| grep 大仓库慢（纯 JS） | >1万文件秒级 | `.ecodeignore` 必须先过滤；留 ripgrep 切换接口 |
| 危险命令黑名单绕过 | 变形命令（`r""m -rf /`） | 正则粗筛 + 非黑名单的 bash 仍走 y/n 兜底 |
| GLM 对工具 schema 支持 | 扁平 schema 已避坑（§2.3 行 220），但 5 工具同时传未知 | 烟测 + 真 LLM 验（第 5 步） |
| edit_file oldString 不唯一 | LLM 给的 oldString 模糊 | is_error 提示「实际 N 处，需更上下文」交 LLM 自纠 |
| ConfirmPrompt 阻塞 loop | confirm 期间 loop await，用户不响应则卡 | Ctrl+C 取消；无超时（MVP 接受阻塞，用户必须响应） |
| .ecodeignore 不向上查找 | 子目录的 .ecodeignore 不生效 | MVP 只读 cwd 一份；后续加向上合并 |

**开放问题**：
1. write_file 的 40 行截断盲签风险（§5.4 行 627）——M3 接受 + 明确截断提示，`[v] 查看完整` 留后续
2. bash 安全命令白名单（免确认 git status）——M3 不做，烦了再加
3. grep 是否加 -C 上下文——M3 不做，LLM 用 read_file 看上下文
