## 一、claude-code（多级管线，工程最复杂）

文件：`D:\study\claude-code-main\src\services\compact\`

### 多级管线（成本递增、破坏性递增）
- **microCompact**（每 turn 前，`microCompact.ts:253`）：不做摘要，只清工具结果 content。time-based（cache 过期就清）+ cached MC（cache 热时用 API cache_edits 不破坏前缀）。
- **autoCompact**（turn 后，`autoCompact.ts:241`）：超阈值先试 sessionMemoryCompaction（便宜无 LLM）→ 失败再全量 compactConversation（贵，LLM 摘要）。
- **reactiveCompact**（API 413 时，`query.ts:1119`）：单次守卫防死循环。
- **snipCompact**（模型主动调用的工具，非自动管线）。

### 摘要 prompt（`prompt.ts`，最重要）
**`<analysis>` 草稿 + `<summary>` 9 段结构**。强约束不调工具：
```
CRITICAL: Respond with TEXT ONLY. Do NOT call any tools.
Your entire response must be plain text: an <analysis> block followed by a <summary> block.
```
9 段：1.Primary Request and Intent / 2.Key Technical Concepts / 3.**Files and Code Sections（含完整代码片段+为何重要）** / 4.Errors and fixes / 5.Problem Solving / 6.**All user messages（列所有非工具结果的用户消息）** / 7.Pending Tasks / 8.Current Work / 9.Optional Next Step（含原文直接引用防漂移）。

### 保留策略
- microCompact：`COMPACTABLE_TOOLS={FileRead,Shell,Grep,Glob,...}`，保留最近 `keepRecent` 条（floor 1），其余 content 替换 `'[Old tool result content cleared]'`。
- 全量后重注入最多 5 个最近读过的文件（`POST_COMPACT_TOKEN_BUDGET=50000`）。

### ★ API 不变量保护（`adjustIndexToPreserveAPIInvariants` `sessionMemoryCompact.ts:232`）
**绝不切断 tool_use/tool_result 对**（保留区有 tool_result 就回溯带 tool_use）；同 message.id 的 thinking 块必须和 assistant 一起保留。**避免压缩后 API 400，ECode 必抄。**

### summary 格式
- `formatCompactSummary`：regex 删 `<analysis>...</analysis>`，`<summary>` 替换成 `Summary:\n<content>`。
- 包 user message，前缀「This session is being continued from a previous conversation that ran out of context. Recent messages are preserved verbatim. Continue... do not acknowledge the summary... Pick up the last task as if the break never happened.」
- boundary marker（SystemMessage，含 compactMetadata）。

### 失败/降级
- 熔断器：连续 3 次失败停（`MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES=3`）。
- compact 本身 413：`truncateHeadForPTLRetry` 按 round 分组从头删。
- fork 复用 cache → 失败回退流式。

## 二、opencode（select 切分 + 滚动 summary，设计最优雅）

文件：`D:\study\opencode\packages\core\src\session\compaction.ts`（单文件 240 行，四家最干净可抄）

### 算法：从后往前累加 token 切分
`select`（`:128`）：recent 预算 8000 token，从尾部吃满；切分点那条消息按字符精确劈开。head 过滤掉旧 compaction 消息。

### ★ 摘要 prompt（`SUMMARY_TEMPLATE` `:16`，结构化 + 强制保留路径）
```
Output exactly the Markdown structure shown inside <template> and keep the section order unchanged.
<template>
## Objective
- [用户想完成什么]
## Important Details
- [约束/偏好/决策及原因/重要事实；"(none)"]
## Work State
### Completed / ### Active / ### Blocked
- [各自状态]
## Next Move
1. [立即的下一步]
## Relevant Files
- [文件路径: 为什么重要]
</template>
Rules:
- Keep every section, even when empty.
- Preserve exact file paths, symbols, commands, error strings, URLs, and identifiers when known.
- Do not mention the summary process or that context was compacted.
```

### ★ 滚动 summary（`buildPrompt` `:161`，处理多次压缩的关键）
```ts
previousSummary
  ? `Update the anchored summary below using the conversation history above.
     Preserve still-true details, remove stale details, and merge in the new facts.`
  : "Create a new anchored summary from the conversation history."
```
上一条 compaction 的 `.recent`（上次原样保留的尾部）拼进这次摘要的 context → **滚动重摘要，解决「上轮 recent 这轮变旧」**。

### summary 格式
独立消息类型 `Compaction`（`:192`）：`{ type:"compaction", summary, recent }`，双字段供下轮滚动。LLM 请求时 compaction 后的真实消息才进 context。

### 失败/降级
`if (!summarized || failed || !summary.trim()) return false` —— 失败啥也不做，下个 turn 自然重试。朴素但有效。

## 三、aider（递归 split-summarize，算法最经典）

文件：`D:\study\aider\aider\history.py`（`ChatSummary`，120 行）

### 算法：递归二分
`summarize_real`（`:33`）：
1. 尾部留 `half_max_tokens`（max_tokens//2）原样，头部摘要。
2. 摘要+尾部仍超 → 递归（depth+1）。
3. base case：`len<=min_split(4)` 或 `depth>3` → `summarize_all`（整段摘要）。
4. head 超模型 max_input → 顺序累加到 `max_input - 512` 再 summarize_all。

### ★ 摘要 prompt（`aider/prompts.py:46`，第一人称用户口吻）
```
*Briefly* summarize this partial conversation about programming.
The summary *MUST* include the function names, libraries, packages that are being discussed.
The summary *MUST* include the filenames referenced inside ```...``` fenced code blocks!
Phrase the summary with the USER in first person. Write *as* the user. Start with "I asked you...".
```
**绝妙：第一人称用户口吻**——摘要写成「我之前问你…」，自然塞进 user-role 消息，不需特殊 system 包装。

### 失败/降级
多模型兜底（`:114`）：`for model in self.models: try ...`，weak model 摘要，全失败上抛。

## 四、codex（Rust，三策略 + hooks 生命周期）

文件：`D:\study\codex\codex-rs\core\src\compact*.rs`

### 三策略
1. **inline/local**（`compact.rs`）：跑摘要 prompt 当普通 turn，取最后一条 assistant 当摘要。
2. **remote**（`compact_remote.rs`）：服务端 compact endpoint。
3. **token-budget**（`compact_token_budget.rs`）：**完全跳过摘要，开新空窗口**（保系统提示+最近 user 消息）——终极兜底。

### 摘要 prompt（`prompts/templates/compact/prompt.md`，极简 handoff）
```
You are performing a CONTEXT CHECKPOINT COMPACTION. Create a handoff summary for another LLM that will resume the task.
Include: Current progress and key decisions / Important context, constraints, or user preferences / What remains to be done / Any critical data, examples, or references needed to continue
Be concise, structured, and focused on helping the next LLM seamlessly continue the work.
```
`SUMMARY_PREFIX`（接力 framing）：「Another language model started to solve this problem and produced a summary...」

### ★ 反应式裁剪（`trim_function_call_history_to_fit_context_window` `:370`）
从最旧开始，tool output 整体替换成 `"Output exceeded the available model context and was truncated"`，按 group 保完整。

### 失败/降级
- compact 调用本身 ContextWindowExceeded → `remove_first_item`（删最旧保 cache）重试。
- 三策略统一 pre/post compact hooks 生命周期。

## 五、对比表 + ECode 组合建议

| 维度 | claude-code | opencode | aider | codex |
|---|---|---|---|---|
| 算法 | 多级管线 | select 切分+滚动 | 递归 split-summarize | 三策略 |
| 保留策略 | 工具结果 content-clear 保最近 N | 尾部 8K 原样+工具截断 2K 字符 | 尾部约一半原样 | 最近 20K user 消息+工具输出替换占位符 |
| prompt 风格 | 9 段详尽+analysis 草稿 | 固定 Markdown 模板 terse | 第一人称用户口吻 | 极简 handoff |
| 滚动续摘要 | 否 | **是**（previousSummary+previousRecent）| 否（递归内部）| 否 |
| 失败处理 | 熔断器+PTL 删头+fork 回退 | 静默 no-op 下轮重试 | 多模型兜底 | 删最旧重试+remote fallback |
| API 不变量 | tool_use/result 配对保护（精细）| serialize 抹平 | 无 | fork 层修 |

### ★ ECode M5 组合借鉴（最终方案）

**主体 = opencode（骨架）+ claude-code（保留策略与不变量）+ aider（兜底）**：

1. **核心算法照抄 opencode `select`**（从尾累加切分 + 字符级精确劈分），单文件起步，最易正确。

2. **prompt = opencode `SUMMARY_TEMPLATE`（结构化）+ claude-code `<analysis>` 草稿剥离**。字段补 claude-code 的 "All user messages"（保留用户原始意图）+ "Errors and fixes"。analysis 草稿提升质量再剥离省 token。

3. **★ 滚动 summary 必抄 opencode `buildPrompt`**：previousSummary + previousRecent 重摘要——处理「多次压缩」的关键（单次全量重摘要会信息逐级丢失）。

4. **保留策略三层**：
   - **L1 microCompact**（每 turn，无 LLM）：工具结果超 N 条，旧的 content 替换占位符，保最近 K 条（claude-code）。
   - **L2 全量摘要**（超阈值）：opencode select + 滚动 summary。
   - **L3 兜底**（摘要都塞不下）：aider 递归 split-summarize，或 codex「开新窗口」终极兜底。

5. **★ API 不变量保护必抄 claude-code `adjustIndexToPreserveAPIInvariants`**：保留区有 tool_result 必带回 tool_use，绝不切断对。避免压缩后 API 400。

6. **失败降级**：
   - 摘要 prompt 自身超限 → opencode 预检闸 `estimate(summaryPrompt) > context - output` 放弃。
   - LLM 调用失败 → aider 多模型兜底 + opencode 静默重试。
   - 熔断器（claude-code 连续 3 次停）。
   - compact 调用本身 413 → codex remove_first_item / claude-code 按轮删头。

7. **不抄**：claude-code fork 复用 cache（厂商绑定）、cached MC cache_edits、session memory 持续抽取；codex remote endpoint。

**最小可行实现顺序**：opencode select + SUMMARY_TEMPLATE + 滚动 summary（240 行级）→ 加 claude-code microCompact L1 + API 不变量保护 → 补 aider 递归 L3 兜底 + 熔断器。
