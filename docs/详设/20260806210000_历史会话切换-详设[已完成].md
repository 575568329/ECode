## 一、目标与范围

**做**：REPL 运行中敲 `/resume` → 弹出**会话选择器**（Modal 替换 InputBar），列出本项目历史会话（**排除当前会话**）；`↑↓` 选中、**Enter 切换**（软重置：载入该会话历史 + 续接上下文，后续对话复用同一会话）、**Esc 取消**（对齐 A 的 picker 取消键）。

**不做**（YAGNI，留后续）：跨项目会话、会话删除/重命名、会话搜索/过滤、合并会话、Ctrl+V 预览、fork/树形、分页 enrich（ECode 会话少，同步读盘够快）。

## 二、现状与约束（已查证）

- `src/session.ts`（纯数据层，完备）：`listSessions()→ECodeSessionSummary[]`（**updatedAt 倒序**，对齐 CC mtime 降序）、`loadSession(id)→ECodeSession`（含完整 `messages`）、`saveSession()`（原子写，同 id 覆盖）。会话 ID 已用 UUID（debugging #007 闭环，选择器无需处理碰撞）。
- `src/ui/app.tsx`：`/resume`（`handleCommand` line 145）目前走「尚未实现」分支；`/sessions` 已实现（纯文本列表，line 130）。**Modal 替换机制**已有先例：`api.pendingPermission ? <PermissionDialog/> : <InputBar/>`（line 174-181）——SessionPicker 走同一模式。
- `src/ui/use-agent-stream.ts`：`sessionRef: useRef<ResumeContext|null>` 是续接真相源（line 55）。`submit` 经 `resumed: sessionRef.current` 传 agent（line 90）；`completed` 回写 `sessionRef`（line 99-106）；`/clear` 重置 `sessionRef=null + completedMessages=[]`（line 140-144）。**切换会话 = 把 sessionRef 换成目标会话 + 用历史软重置 completedMessages**。
- `src/ui/picker-list.tsx`（A 已建）：`<PickerList items selectedIndex hint/>` 纯展示组件，A/C 共用。
- `src/ui/reduce-agent-event.ts`：`completedMessages` 是**逐事件增量累积**的。**无现成的 `ECodeMessage[] → DisplayMessage[]` 转换**——切换会话要还原历史，须新写转换函数。

### ⚠️ 核心约束

1. **严禁反向重建**（`types.ts` line 1-3 注释）：`DisplayMessage[]` 是渲染层类型，**不得**用它反向重建 LLM `messages`。
   → **推论：切换前不主动保存「当前会话」**。UI 层没有干净的当前 `ECodeMessage[]`。当前会话最新状态 = 最后一次 `completed` 时 `agent.ts` 已 `saveSession` 落盘的状态。**CC 印证**：`/resume` slash 模式 `filterResumableSessions` 把当前 session 排除出列表，其 jsonl 文件继续在盘上不动——ECode 同理，切换不动当前会话文件。
2. **切换是 idle 操作**：running 时 InputBar `disabled`，敲不出 `/resume`；SessionPicker（idle）与 PermissionDialog（running 中授权）**状态互斥**，不会同屏。**CC 印证**：picker 仅在非 running 时出现。

## 三、接口设计

### 3.1 触发与 Modal 机制（App 层）

App 新增状态：
```ts
const [resumeOpen, setResumeOpen] = useState(false);
const [resumeIndex, setResumeIndex] = useState(0); // 选中索引
```
`/resume` 命令分支：
```ts
case 'resume': {
  const currentId = api.currentSessionId();                 // 新增 getter（只读 sessionRef.current?.id）
  const sessions = listSessions().filter(s => s.id !== currentId);  // 过滤当前会话（对齐 CC filterResumableSessions）
  if (sessions.length === 0) {
    api.addMessage({ kind: 'warning', id: `sys-resume-${Date.now()}`, text: '暂无历史会话。' });
    return;
  }
  setResumeIndex(0);
  setResumeOpen(true);
  return;
}
```
Modal 渲染（picker 优先于 permission——二者互斥不会同时真值，显式优先更清晰）：
```tsx
{resumeOpen ? (
  <SessionPicker
    sessions={resumeSessions}   // 已过滤当前会话，缓存进 state（避免重渲染重算）
    selectedIndex={resumeIndex}
    onConfirm={...} onCancel={() => setResumeOpen(false)}
  />
) : api.pendingPermission ? (
  <PermissionDialog ... />
) : (
  <InputBar ... />
)}
```

### 3.2 SessionPicker 组件（Modal + 自带 useInput）

交互模式与 A 不同：A 是 InputBar 内嵌 overlay（边输边过滤）；C 是 **Modal 替换 InputBar**（参照 PermissionDialog「单一活跃 useInput」）。SessionPicker 自带 `useInput`：

- `Enter` → `onConfirm(sessions[index].id)`
- `Esc` → `onCancel()`（对齐 A/E：关 picker 归 Esc；CC slash 模式 `onDone('Resume cancelled')` 回 REPL）

Props：`{ sessions: ECodeSessionSummary[]; selectedIndex; onConfirm(id); onCancel }`。sessions 已过滤当前会话且非空。

### 3.4 切换语义（核心）—— 过滤当前会话 + switchSession 软重置

**过滤当前会话**（CC `filterResumableSessions` 印证，关键）：列表**排除当前会话**（`sessionRef.current?.id`），避免切换到自己（无意义）+ 防误操作。CC `/resume` slash 模式正是这么做的——当前 session 不在列表里，其文件继续在盘上不动。需 `useAgentStream` 暴露只读 getter：
```ts
/** 当前会话 id（sessionRef.current?.id）；null = 新会话未建立。/resume 过滤用。 */
currentSessionId: () => string | null;
```

**switchSession 软重置**（CC「`switchSession` 改全局 id + `initialMessages` 重 mount REPL」的对应物——ECode 不重 mount，直接替换 state）：
```ts
// useAgentStream 新增
switchSession: (resume: ResumeContext, history: DisplayMessage[]) => void;
// 实现（对齐 /clear 的「重置 sessionRef + completedMessages」模式）
const switchSession = useCallback((resume, history) => {
  sessionRef.current = resume;   // 后续 submit 经 resumed 复用该会话（session id 复用 + messages 传承，对齐 CC）
  setState(prev => ({
    ...prev,
    completedMessages: history,
    streamingText: null,
    activeTools: [],
    usage: { inputTokens: 0, outputTokens: 0 },  // 新会话视角，/cost 不串台（对齐 /clear）
  }));
}, []);
```

App `onConfirm`：
```ts
const session = loadSession(id);                        // 完整 ECodeSession（含 messages）
const history = messagesToDisplayMessages(session.messages);
api.switchSession(
  { id: session.id, task: session.task, createdAt: session.createdAt, messages: session.messages },
  history,
);
setResumeOpen(false);
setStarted(true);   // 进 ChatView 显示历史（/resume 可在欢迎屏触发）
```

### 3.5 历史还原转换函数（纯函数，可单测）

`messagesToDisplayMessages(messages: ECodeMessage[]): DisplayMessage[]`：
- 遍历 messages，维护 `toolCallMap: Record<id, {name, input}>`（从 assistant 的 `tool_call` block 收集）。
- `role:'user'`：
  - `content:string` → `{kind:'user', text}`
  - `content:blocks`：`text` block → user 消息（罕见）；`tool_result` block → 查 `toolCallMap[tool_use_id]` 补 name/input → `{kind:'tool', content: output.value, isError: output.type==='error', input}`
- `role:'assistant'`：
  - `content:string` → `{kind:'assistant', text}`
  - `content:blocks`：合并所有 `text` block 为一条 assistant 消息；`tool_call` block → 记入 `toolCallMap`（不直接产消息，等配对的 result）
- **孤儿处理**（YAGNI 兜底）：无配对 result 的 `tool_call` → 跳过（会话中断在工具调用中的罕见态）；无配对 call 的 `tool_result` → name 用 `tool_use_id` 兜底。
- **丢失字段**（可接受）：assistant 的 `durationMs`/`model` 历史无存 → `durationMs` 留 undefined（MetaLine 不显示耗时，符合「历史无耗时」语义）；`model` 可选从 `session.model` 补。

> 决策点①（见 §五）：历史还原走**方案 A（完整还原 user/assistant/tool）**，而非轻量提示。理由：resume 的诉求就是「接着之前的事」，看不到历史是劣体验（CC `loadConversationForResume` 还原全量 messages + `initialMessages` 灌进 REPL，所有 IDE 都还原）。

### 3.6 逻辑链路（对照 CC）

```
/resume
  → listSessions()                          // session.ts: updatedAt 倒序（对齐 CC mtime 降序）
  → filter(s.id !== currentSessionId())     // 对齐 CC filterResumableSessions（防误选自己；当前会话文件不动）
  → 空? 提示「暂无历史会话」（对齐 CC NoConversationsMessage）
    : setResumeOpen(true)
  → SessionPicker ↑↓ 循环选 → Enter onConfirm(id)
    → loadSession(id)                        // session.ts: 完整 messages
    → messagesToDisplayMessages(messages)    // ECodeMessage → DisplayMessage（§3.5）
    → api.switchSession(resume, history)     // 软重置：sessionRef 换目标 + completedMessages=历史（对齐 CC 重 mount + initialMessages）
    → setStarted(true)                       // ChatView 渲染历史
  → 后续 submit → resumed=目标会话 → agent 复用同 id（同文件覆盖）  // 续接本质，对齐 CC switchSession + 同 jsonl append
```

- **数据源**：`listSessions()` 同步读盘。ECode 会话少（单项目几十内），无需 CC 的 stat-only + 分页 enrich（CC `getSessionFilesLite` + `INITIAL_ENRICH_COUNT=50` 是为海量会话设计，YAGNI）。
- **当前会话不丢失**：切换不动当前 session 文件（agent 每轮 completed 已 saveSession 落盘），对齐 CC「当前 session 文件继续在盘上没动」。
- **续接本质**：sessionRef 换成目标会话 → submit 带 resumed → agent 复用同 id + messages 传承 → 同文件覆盖。对齐 CC「session id 复用 + messages 传承，新对话写同一会话文件」。

## 五、关键决策汇总

| # | 决策 | 推荐 | 理由 |
|---|------|------|------|
| ① | 切换后历史可见性 | **方案 A：完整还原 user/assistant/tool 历史** | resume 核心诉求；CC `loadConversationForResume` 还原全量；转换函数纯可测 |
| ② | 切换前保存当前会话 | **不主动保存，依赖 completed 落盘** | types.ts 禁反向重建；CC 印证：当前会话排除出列表 + 文件不动 |
| ③ | 当前会话是否在列表 | **排除**（`filter(s.id !== currentId)`） | 对齐 CC `filterResumableSessions`；防误选自己 |
| ④ | 空会话列表 | **不弹 picker，提示「暂无历史会话」** | 复用 /sessions 空态；对齐 CC NoConversationsMessage |
| ⑤ | 取消键 | **Esc**（与 A 一致，对齐 CC） | 方向 E 横向分工：Esc 关面板，C 不被 E 阻塞 |
| ⑥ | usage 计数 | 切换后归零 | 新会话视角，/cost 不串台（对齐 /clear） |
| ⑦ | 列表项排版 | **两行制（扩展 PickerList `twoLine`）** | task 标题完整显示；CC 印证两行清晰；`twoLine` 默认 false 不影响 A |
| ⑧ | ↑↓ 导航 | **循环**（首项 ↑ 跳末项） | 对齐 CC `use-select-navigation` 循环 |

> **决策点①备选（方案 B 轻量）**：切换只设 sessionRef + 一条「已切换到会话『X』」提示，不还原历史。MVP 更快，但 UX 差（看不到之前对话）。**不推荐**。

## 八、风险

- **历史还原保真度**：tool_call/tool_result 跨消息配对，孤儿/中断态需兜底。转换函数单测（§6.1）守住各 block 组合。
