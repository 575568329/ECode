## 二、本轮发现与修复（提交 5fad166）

### 真 bug ×2（已修）

**R2-1（P1）rewind 对新建文件失效**：checkpoint 对「快照时刻不存在的文件」原语义是「无基线可拍，跳过」——`write_file` 新建文件的 onBeforeWrite 快照为空 → revert 无从删除 → **/rewind 回退了消息但新建文件全部残留**。真机 dogfood 复现（写 rewind-target.txt → rewind/exec ok → 文件仍在）。修复：ENOENT 记 **absent 基线**（`CheckpointFileRef.absent`），revert 到该点=删除该路径（还原前自动快照闭环「撤销撤销」）；detectExternalChanges 跳过 absent 项；+2 回归锁。

**R2-2（P2）审批零应答者文案误导**：serve 会话无可应答客户端（canAnswer 订阅）时副作用工具 fail-closed 返回裸 false → loop 冠「用户已取消」——模型向用户转述「你取消了」（dogfood 实证模型原文「写入被取消」）。修复：`APPROVAL_NO_CHANNEL_FEEDBACK` 专用反馈串（D-T8 超时串同款透传语义），如实说明无应答渠道并引导模型换只读方式推进。

**R2-3（P2，并行会话遗留）hook context 双重前缀**：e268776 归属根治把 hook context 改为预注入消息时，session 侧预加一次 `[hook context]` + preInjected 统一包装再加一次 → 模型侧看到双重前缀。修复+断言锁。

### 驱动侧经验（非产品问题，记录防复发）

- `?project=` 查询参数形式被 /api/cmd **静默忽略**（落默认宿主）——项目路由只有路径形式 `/api/p/<path>/cmd`（API 契约如此，但静默回退对脚本客户端是可用性陷阱——记入审阅账）
- 副作用工具在 serve 会话需 **canAnswer=1 订阅者**应答审批；纯观察订阅（无 canAnswer）= 零应答者 fail-closed（产品语义，见 R2-2 文案修复）
- pending 审批对新 canAnswer 连接重播=设计内（多端审批语义+15min 超时收敛），非泄漏
- 并行会话 34 笔新提交到达后主干带 4 红（归属 meta 化后旧字符串形态测试没跟上）——本轮顺手适配修复（commitThinking×2/ScrollbackDesign/TuiAppHooks）
